## ⚑ 根因一：UIA 遍历漏节点（这是「按钮时有时无」的真因）
本机实测同一时刻两种遍历的结果**都不是对方的子集**：
    从主窗口 win.descendants()        1055 节点
      → 过滤到插件容器内 267 个，**「生成预览」一个都没有**
    从容器元素 container.descendants()  134 节点
      → **「生成预览」在里面** Button (2362,1271)
⇒ SolidWorks 的 UIA provider 在**主窗口深层遍历时会截断/折叠**，
  页面越复杂越容易丢尾部控件。
⇒ ``_controls()`` 改为**两种根取并集**（按 类型+名字+粗位置 去重）。
  此前试过的「放宽查找条件」「截图兜底」都是症状级补丁 —— 根因在遍历。

## ⚑ 根因二：三种页面的卡片标签不同名
    分类结果页   Text '代码：HGH20HAZ0C'
    搜索结果页   Text '型号：BSGY-C7-25'    ← 我只找「代码：」，永远找不到
⇒ ``CARD_PREFIXES = ("型号：", "代码：")`` 两种都认。

## ⚑ 根因三：自由输入框的三个必要条件（用户报的「重复输入 0」）
  ① **取值不能截断小数**：`str(int(0.5))` = `'0'`，低于下限 `[0.5~20]` ⇒ 插件拒收
     ⇒ 改 `_fmt_value()`：取下限、按 step 定小数位、不截断。
  ② **提交键是 Enter 不是 Tab**（实测同一字段同一个 0.5：
     Tab → 型号行仍 `L【去填写】`；Enter → `L0.5` 生效）
  ③ **值必须落在范围内**，否则插件弹模态框「请输入指定范围内的数字!」，
     **该弹窗挡掉之后所有点击**（此前 Edit 分支漏查模态，是死循环的真凶）
⇒ 另加**同字段连续失败 3 次即放弃**，不再无限重打。

## ⚑ 全部改为结构判据（零坐标、零偏移阈值）
  · 搜索框   = 「搜索」按钮的**父 Pane** 里的 Edit（实测二者同父）
  · 搜索按钮 = 按名字
  · 结果卡   = 同一 Pane 下**同时**含「型号/代码：」与「更新于：」的 Text
  · 参数行   = 同一 Pane 下的 Edit + 范围 Text（`[195~1500]/1`）
  · 型号值   = 「产品型号：」的**父 Pane** 下「非标签、非中文」的 Text
              （`_has_cjk` 先剥掉占位符 `【去填写】`，否则型号值被误判成中文）
  · 范围读取 = 插件自报，**不用记忆**；无范围时用**探测候选**（含小数）+ 验收
⇒ 全仓已无 `cr.top + N` / `cr.bottom - N` 这类相对偏移。
