## 真正的根因（前几轮一直在治症状）

报错原文：
    ImportError: cannot import name 'set_com_member' from '<unknown module name>' (unknown location)

★ 那个 `<unknown module name>` + `(unknown location)` **不是**「半初始化模块」，也不是循环导入
（★ 核过：`sw_connect.py` 顶层只 import 标准库）。它说的是：

    **同一个模块被以两种口径各载入了一次** —— 一次 `scripts.sw_connect`、一次 `sw_connect`
    ⇒ sys.modules 里出现**没有 __file__ 的残缺条目**

★ 而两种口径的来源是本仓**自己混用**：
  · `scripts/` 内模块用 `try: from .sw_connect import … / except: from sw_connect import …`（双模式）
  · 三十多个测试写 `from scripts import sw_xxx`（包内口径）
  · 另一些测试写 `sys.path.insert(scripts); import sw_sketch`（顶层口径）
  · 而 `scripts/__init__.py` 有 **eager import**（导入包就触发一串子模块）
  · 还有 2 处在包内却用绝对包路径（`from scripts.sw_part import …`）

## 落地了什么（4 组，全部实测）

|---|---|---|
| 1 | `tests/__init__.py`（新增，空包标记） | ★ pytest 官方推荐（`explanation/pythonpath.html` 逐字引在文件里）|
| 2 | `scripts/__init__.py` **去掉 eager import** | ★ 消除"导入包就触发子模块"这个污染入口；★ 已核：`from scripts import <那 12 个名字>` **0 处**、`from scripts.<子模块> import` **204 处**（★ 子模块导入不经过本文件）⇒ 安全 |
| 3 | `scripts/sw_sketch.py` / `sw_drawing_view.py` 两处包内绝对路径 → **相对优先** | ★ 口径统一 |

## 还有一组：**19 个契约测试的猴补丁目标要跟着实现一起改**

★ 那些测试名写着 `..._is_property_not_method` / `..._sets_expected_properties` ——
  **它们的意图正是"写属性走属性赋值形态"**，★ 而本仓 2026-10-03 刚把 98 处写从
  `get_com_member(obj, 名, 值)` 改成 `set_com_member(obj, 名, 值)` ⇒ 它们锁的是旧形态 ⇒ 必须跟。

★ 修法三件套（16 个文件）：
  ① 假模块加 **PEP 562 的模块级 `__getattr__`** 转发真 `sw_connect`
     ⇒ ★ 原先只手装一两个名字，被测模块顶层 import 别的时候就报
       `cannot import name 'call_com_member' from 'sw_connect' (**unknown location**)`（★ 指不到真因）
  ② 假模块与真模块**都装** `set_com_member`
  ③ `_record` 类助手**两个名字都补**
  ④ `sys.modules.setdefault(...)` → `sys.modules[...] = ...`（★ setdefault 在已被污染时**不生效**）
