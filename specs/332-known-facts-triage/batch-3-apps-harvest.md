## §3 ★★ 交付门禁（★ 逐字，`automation-queue-protocol.md`）

**状态流转**：
```
queued -> running -> passed | review_required | failed | cancelled
queued -> approval_required -> queued | cancelled
review_required -> passed | failed
```

**★★ 三条硬判据（★ 逐字）**：

1. ★★ **Reviewer Gate 为 `warning` 时写入 `review_required`，不能显示「完成」**；
   **只有门禁为 `pass` 才写入 `passed`**
2. ★★ **真实 CAD handler 必须在写入 `passed` 前完成文件存在性检查** ——
   **不能把占位文件、AI JSON 回执或旧文件标为可制造交付**
3. ★★ **`save_queue_job` 仅接受不存在的 `queued` 新任务**；已存在任务一律拒绝覆盖

**★ 其余（逐字）**：
- ★ **`passed` / `failed` / `cancelled` 是终态**；`review_required` **必须由用户明确
  「通过复核」或「驳回」**
- ★ 成功任务回写 `artifactLedgerPath` + `artifacts`（★ 存在性、大小、**hash**）
- ★ 成功任务回写 `reviewGatePath` + `reviewGate`

**★★ 第 2 条与我这轮学到的事实 556/557 同源**：
★ 「**返回 ok ≠ 产出存在**」 —— ★ 而它这里写成了**交付级**的硬判据。
