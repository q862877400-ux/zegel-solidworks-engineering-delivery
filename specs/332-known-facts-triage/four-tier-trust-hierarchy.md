## §1 ★★★ 四级信任层级（★ 逐字）

```
做完任何一个建模操作，按顺序问：
□ L1：调用返回非 null 吗？              （★ 不够）
□ L2：特征数增长了吗？                  （★ 不够）
□ L3：★ 实体数变了吗？包围盒合理吗？体积符合理论值吗？   ← ★ 至少到这层
□ L4：★（批量/交付前）导出 PNG 三视图，我亲眼看过吗？
```

**★★★ 判据（★ 逐字）**：

> **L1 / L2 会放过这个错误 ⇒ ★ 不能用它们宣布「做对了」**
> L3 通过数字对不上「发现可疑」⇒ ★ 至少要能算理论值
> **L4 通过「看见形状不对 + 看见悬空草图」直接定位 ⇒ ★★ 最强**

**★ 成本**：一次建模验证多花 **~15 秒**（3 张 PNG + 读图），
★ **但能抓住 L1~L3 全部放过的错误**。

## §2 ★★★ 三类静默失败（★ 逐字）

> 工具返回 `COMPLETED`、特征名也建出来了，**但什么都没发生**。
> **比直接报错危险得多** —— 调用方会信任 `COMPLETED`。

**★ 实测到 13 例**（★ 全部已修），★ 关键的三类：

| 类 | 形态 | 例 |
|---|---|---|
| **① 什么都没发生** | `COMPLETED` 而零产出 | `edit_feature delete` 什么都没删 · `auto_dimension_drawing` `dimension_count=0` · `design_check` **零报告文件** |
| **② 几何没变** | `COMPLETED` + 特征名，但 0 实体 0 面 | `extrude_feature` · `add_edge_feature` · `sheet_metal_feature` · `add_reference_geometry`（特征不在树里） |
| **③ ★★ 发生了我没要求的事** | `COMPLETED`，但几何**朝错误方向**变 | ★ **圆角削料却「增料」**（★ 体积 73,498 → 73,625，**增加 127 mm³**） |

### ★★★ 第 ③ 类最危险（★ 逐字）

> ★ **新的一类静默失败**：不是「什么都没发生」，
> 而是「**发生了一件我没要求的事**」。
> ⇒ 这类**只能靠「物理上必须怎样」的判据发现**（★ 圆角必然削料 ⇒ 体积必减）。
> ⇒ **判据要写成带方向的**：不是「体积变了」，是「体积**减少**了」。

**★★★ 这条直接改写我这两轮的判据设计** ——
★ 我写的「特征树是否新增」**只到 L2**，★ 而它要求 **L3 带方向**。

## §6 ★★ L4 的**可执行路径**（★ 逐字，本机已跑通）

```powershell
# ① 导出三视图 PNG
foreach($v in 'isometric','front','top'){
  Call 'export_document' @{ format='PNG'; file_path="$out\view_$v.png" } -TimeoutSec 120
}
# ② 直接读图（多模态）
read_image <path>
# ③ 肉眼查：形状对不对 / 有没有悬空草图（蓝色矩形）/ 方向反没反
```

**★ 观察要点（★ 逐字）**：
```
· 蓝色线框 = 【悬空草图】★ 最常见的"切了但没切到东西"的证据
· 轮廓完整性：圆/柱应该完整，缺一块就是切到了
· 三视图交叉：一个视图正常、另一个异常 ⇒ 特征方向/位置错
```

**★★★ 「蓝色线框 = 悬空草图」这一条** ——
★ 与业主 2026-10-12 批注的「**全是蓝线**」**是同一件事**（★ 一个在草图层、一个在特征层）。
