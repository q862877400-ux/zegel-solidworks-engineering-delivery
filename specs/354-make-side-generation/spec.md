## 背景（这一节决定本 spec 的范围）

### 上一轮跑偏在哪

上一轮我一直在解决**买**的环节（标准件从哪来、嘉立创插件能不能反推）。用户指出：**买是查表，造是算。要攻的是造。**

### 造与买的本质区别

| | 买 | 造 |
|---|---|---|
| 输入 | 型号 | **需求**（传多大扭矩、装多宽、多久换） |
| 动作 | 选型 → 取模型 | **参数推导 → 校核 → 生成几何** |
| 谁定义尺寸 | 厂商目录 | **公式 + 国标表** |
| 失败模式 | 选错型号 | **参数不合法 / 几何算错** |

### 造的范围：14 类，归纳为 6 种几何原语

**用户已确认按「几何原语」组织，不按零件族组织**——一种原语通了，用它的族一次覆盖。

| # | 原语 | 覆盖零件族 | 难度 | 首攻 |
|---|---|---|---|---|
| 1 | **闭合轮廓 + 拉伸** | 齿轮、链轮、同步带轮、V 带轮、花键、键槽 | 中 | ✅ |
| 2 | **旋转（轮廓绕轴）** | 轴、轮毂、法兰、弹簧端部 | 低 | ✅ |
| 3 | **螺旋线 + 扫掠** | 螺纹、弹簧 | 高 | 后 |
| 4 | **圆周/线性阵列** | 齿、槽、孔、螺栓孔 | 低 | ✅ |
| 5 | **布尔（并/差/交）** | 内齿、键槽、退刀槽、减重孔 | 低 | ✅ |
| 6 | **放样/曲面** | 锥齿、蜗杆、凸轮轮廓 | 高 | 后 |

**原语 1/2/4/5 覆盖 14 类中的 11 类**；3/6 只服务螺纹、弹簧、锥齿、蜗杆、凸轮。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 非专业用户用两句话得到一个齿轮 (Priority: P1)

一个不懂机械的用户说「我要减速 3 倍，两根轴之间能塞 40 毫米」，系统问 2~3 个他能答的问题，然后给出一整套齿轮参数，每个参数标着来源与含义。

**Why this priority**: 这是「造」的最小可用价值——不问专业术语也能出件。

**Independent Test**: 只用 `derive()`，不碰 SolidWorks，检查输出表是否含 13 行参数、每行有来源标记、末尾有未覆盖清单。

**Acceptance Scenarios**:

1. **Given** 用户答「减速 3 倍、中心距 40」，**When** 系统推导，**Then** 输出 m=1/z1=20/z2=60/a=40，且每行标「问/算/选/查/锁/假设」
2. **Given** 用户答「减速 3 倍、中心距 30」，**When** 无解，**Then** 输出最小可行中心距 34 mm 与三条出路，不抛异常
3. **Given** 用户说「不知道」，**When** 系统降级，**Then** 换成人话重问，不停在同一句
4. **Given** 用户说「你定」，**When** 系统代决，**Then** 输出五项假设清单

---

### User Story 2 - 工程师锁定参数，其余自动重算 (Priority: P1)

一个机械工程师说「z1 我用 20，有现成刀具」，系统锁定该节点，其余参数重新推导，并标出「锁」而不是「算」。

**Why this priority**: 这是「工程师能用」的门槛——不能锁的生成器没人敢用。

**Independent Test**: 传入 `pin_z1=20`，检查表里 z1 的来源变成「锁」、依据变成「工程师指定」，且 m/z2/d1/d2 全部重算。

**Acceptance Scenarios**:

1. **Given** 需求 i=2.5、a=43、锁定 z1=20，**When** 推导，**Then** m=1.25/z2=50/a=43.75，z1 来源=锁
2. **Given** 锁定后参数组合不合法，**When** 校核，**Then** 报告谁卡住并给候选，不静默通过

---

### User Story 3 - 计划在无 SolidWorks 的机器上可验证 (Priority: P1)

把参数变成一份纯数据的 FeaturePlan，含草图实体、特征、预期体积与包围盒，可在没有 SolidWorks 的环境里单测。

**Why this priority**: 现已做到（8 条测试），是本 spec 的基线，不能退化。

**Independent Test**: `pytest proto/`，检查 `test_plan_has_no_solidworks_dependency` 通过。

**Acceptance Scenarios**:

1. **Given** 一个齿轮参数集，**When** 生成计划，**Then** 输出 **120 条真曲线**（z=20，每齿 6 条：真摆线齿根过渡 + 真渐开线齿面 + 真圆弧齿顶 + 真圆弧槽底）+ 拉伸 10 mm + 预期体积 **3092.02 mm³**，且不导入任何 COM 模块
2. **Given** 坐标值，**When** 检查量级，**Then** 全部落在 1~1000 之间（防 1000× 单位事故）

> ★ 2026-11-07 更正：原文写「700 条线段 / 3064.56 mm³」，那是**折线模拟渐开线**的方案，
> 已按业主令删除（AGENTS.md §十四之五）。折线把齿面切成 700 段直线，齿廓不再是共轭
> 渐开线，段数可调还会让同规格建出不同齿形。现值 120 条真曲线、体积 3092.021 mm³
> （真机实测，与解析截面积 309.2 mm² × 10 吻合 0.03%）。

---

### User Story 4 - 计划变成真模型，且经得起量 (Priority: P1) ★核心

执行器把 FeaturePlan 送进 SolidWorks 建成实体，然后回读体积与包围盒与计划比对，偏差 <1%。

**Why this priority**: **这是「造通了」的唯一判据。** 前面三条已验证，这一条没做，所以整个造环节还不成立。

**Independent Test**: 真机跑一次齿轮建模，读回体积与包围盒，与计划值比对。

**Acceptance Scenarios**:

1. **Given** 计划 m=1/z=20/b=10，**When** 真机建，**Then** 实测体积 **3092.02**±1%、包围盒 22×22×10 mm
2. **Given** 建模完成，**When** 导三视图 PNG，**Then** 无悬空草图、无缺面
3. **Given** 建模失败，**When** 捕获异常，**Then** 留截图 + 状态 JSON + 明确报错，不静默往下

---

### User Story 5 - 第二个原语证明架构可复制 (Priority: P2)

用轴（旋转体）做第二族，验证「参数→计划→执行」这套骨架不是齿轮专用。

**Why this priority**: 一族的成功可能是巧合，两族才能证明抽象成立。

**Independent Test**: 写 `plan_shaft()`，复用同一套 FeaturePlan 与执行器，测试通过。

**Acceptance Scenarios**:

1. **Given** 轴的需求（扭矩、跨距、有无冲击），**When** 推导，**Then** 输出轴径与台阶，来源可追
2. **Given** 轴的 FeaturePlan，**When** 真机建，**Then** 体积偏差 <1%

---

### User Story 6 - 标准号必须是现行版 (Priority: P2)

任何引用的国标，先查现行版再取数。

**Why this priority**: 上一轮复核发现 1.4% 错误，全部来自「引用了废止版」。

**Independent Test**: 跑 `_recheck.py`，检查所有标准号都有现行版。

**Acceptance Scenarios**:

1. **Given** 引用 GB/T 1356，**When** 核验，**Then** 确认 -2001 现行
2. **Given** 引用 GB/T 1239.6，**When** 核验，**Then** 判为废止并指向 GB/T 23935-2009

### Edge Cases

- **参数越界**（齿数 <17 会根切）：报错并给变位建议，不生成勉强能用的模型
- **无解**（中心距太小）：给最小可行值与三条出路
- **SolidWorks 未启动**：执行器报「连不上」而不是超时挂死
- **中文路径**：中间文件落纯 ASCII 临时目录（项目已知坑）
- **COM 单进程**：不并发建模（项目已知事实 24）
- **超范围输入弹模态框**：先清弹窗再操作（`sw_gui_input` 已有此约束）
- **建模中途失败**：截图 + 状态 JSON + 中止，不继续下一步

## Requirements *(mandatory)*

### Functional Requirements

**参数与推导**

- **FR-001**: 系统 MUST 从 2~3 个非专业用户能回答的问题推导出完整参数集
- **FR-002**: 系统 MUST 为每个参数标注六类来源之一：问/算/选/查/锁/假设
- **FR-003**: 系统 MUST 允许工程师锁定任意推导节点，锁定后其余节点重算且来源改为「锁」
- **FR-004**: 系统 MUST 在无解时输出最小可行值与至少两条出路，MUST NOT 抛异常
- **FR-005**: 系统 MUST 在用户答「不知道」时降一级重问，在答「你定」时直接决定并输出假设清单

**校核**

- **FR-006**: 系统 MUST 在生成几何前校核参数域（根切、干涉、超出标准表）
- **FR-007**: 系统 MUST 在引用任何国标前查询其现行版本，引用废止版时 MUST 报错

**计划**

- **FR-008**: 系统 MUST 把参数集转成纯数据计划，含草图实体、特征、预期体积、预期包围盒
- **FR-009**: 计划 MUST 在无 SolidWorks 的环境里可单测，MUST NOT 导入任何 COM 模块
- **FR-010**: 计划内所有长度 MUST 为毫米，单位转换 MUST 只发生在唯一一处出口函数
- **FR-011**: 系统 MUST 在计划阶段算出预期体积，MUST NOT 等到建模后才知道对不对

**执行与验证**

- **FR-012**: 系统 MUST 有且只有一个模块直接调用 SolidWorks COM
- **FR-013**: 执行器 MUST 在建模后回读体积与包围盒，与计划值比对，偏差 >1% MUST 判失败
- **FR-014**: 执行器 MUST 在失败时留截图与状态文件，MUST NOT 静默继续
- **FR-015**: 系统 MUST 支持导出三视图用于目视检查

**交付**

- **FR-016**: 系统 MUST 在交付物末尾列出未覆盖项（强度、变位、公差），MUST NOT 省略
- **FR-017**: 系统 MUST 让每个参数都能追到它的来源与依据

**可复制性**

- **FR-018**: 系统 MUST 用第二族（轴）验证同一套骨架，MUST NOT 让骨架只服务齿轮

### Key Entities

- **需求对象（Request）**：2~3 个必答项 + 可选锁定项；代表用户真正关心的东西
- **参数行（Row）**：参数名、含义、值、来源、依据、怎么改；代表一个可追溯的决定
- **计划（FeaturePlan）**：草图实体、特征、预期体积、预期包围盒、溯源信息；代表「要建什么」
- **验证结果（Verification）**：实测体积、实测包围盒、偏差百分比、三视图路径；代表「建对了没有」

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 非专业用户用 2 句话 + 2~3 个回答，在 1 分钟内得到完整参数表，且表里每个参数他都能看懂含义
- **SC-002**: 工程师在参数表上锁定任意一个参数，系统在 1 秒内重算其余全部参数，并标出哪些跟着变了
- **SC-003**: 真机建出的模型体积与计划值偏差 <1%，包围盒三个方向全部对上
- **SC-004**: 导出的三视图里悬空草图 0 个、缺面 0 处
- **SC-005**: 参数表里 100% 的参数都有来源标记，0 个无来源的值
- **SC-006**: 引用的国标号 100% 通过现行版核验，0 个废止版
- **SC-007**: 参数表末尾 100% 列出未覆盖项，0 次省略
- **SC-008**: 第二族（轴）复用同一骨架时，代码改动量 <30%（证明抽象成立）

## Assumptions

- SolidWorks 2026 本机可启动，版本在 `verified_versions` 覆盖范围内
- 齿轮族作为首件，因为参数最清楚、国标表最全、数学最现成
- 强度校核不在本次范围（材料与热处理未定，无法取 [σH]/[σF]）
- 变位、修形、公差不在本次范围，写进未覆盖清单
- 装配级（行星/多级）不在本次范围
- 「买」的环节不在本次范围（上一轮已完成调研）
- 几何一律来自前人代码（cq_gears 等）或国标表，不自推公式
- 方法层落在 `research/` 的 `proto/` 下，搬进 `scripts/` 前不改主项目模块
