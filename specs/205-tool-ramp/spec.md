## 一 · 为什么"数量"能当第一目标（而不违背铁律）

```
★ 铁律 1（只缝合不发明）要求"每加一个能力要能指认出处"——
  ★★ 而本规格**不新造能力**：★ 它把**能力层里已经写好、已经有测试、部分已有真机证据的公开函数**
    挂成工具（ToolSpec）。★ 这正是本仓既有做法：批次 26 的原文写着「**有就直接挂**」✓
★ 所以数量目标与铁律不冲突：★ 冲突只发生在"**为了凑数而发明功能**" —— 本规格明令禁止（见 FR-002）✓
```

## 二 · 功能需求（FR）

| # | 需求 | 依据 |
|---|---|---|
| **FR-001** | 每个新工具 MUST 指向**已存在**的能力层函数（`module` + `function` 能解析到），MUST NOT 在工具层写实现逻辑 | 铁律 1 · 批次 26「有就直接挂」 |
| **FR-002** | MUST NOT 为凑数发明新功能；★ 若某候选**能力层没有**，**记进"不做 + 原因"**，不许现编 | 铁律 1 / 5 |
| **FR-003** | MUST 遵守**规则 3**：工具参数**不得收裸坐标** —— 形参名匹配 `^(x\|y\|z\|pos\|point\|pt\|coord\|center\|origin\|location)` 且非 `_mm`/`_deg` 的候选，**须先用声明式选择器包一层**或**不做**（记原因） | `docs/union-conventions.md` 规则 3 |
| **FR-004** | MUST 遵守**规则 2**：长度参数带 `_mm`、角度带 `_deg`；★ 单位换算只在 `derived_args` 里**做一次** | 同上 规则 2 |
| **FR-005** | MUST 遵守**规则 1**：工具名 `solidworks_<域>_<动作>`，且与上游 45 个**不重名** | 同上 规则 1 |
| **FR-006** | ★ MUST **按域去重**：★ 不得暴露"域内已有工具覆盖同一件事"的 raw 实现（★ 判据：该域已有工具名含该域关键词且功能同名） | 避免"数字虚高" |
| **FR-007** | ★ **不得**把**基础设施**函数挂成用户工具（`connect_solidworks` / `close_owned_solidworks` / `create_empty_dispatch_variant` / `import_com_dependencies` …）—— ★ 它们是内部管道，暴露会造成误用 | 实测：`sw_connect` 27 个里绝大多数属此类 |
| **FR-008** | ★★★ **本规格开工前**的既有 MUST：**装配爆炸视图**与**宏/VBA 执行**必须可用（规格 202 的 FR-008 原文）⇒ ★ 本规格**优先**做这两块 | `specs/202-user-coverage-gaps/spec.md` FR-008 |
| **FR-009** | 新工具背后的**能力**若尚无真机证据 ⇒ ★ 该能力条目 MUST NOT 标 `verified`（★ 工具存在 ≠ 能力已验证） | 规格 202 FR-009 |
| **FR-010** | ★ 引入**第三方来源**（如需下载）MUST 逐份读 LICENSE，白名单外**只读思想不抄代码**；Apache-2.0 带 NOTICE 义务 | 铁律 6 |
| **FR-011** | 每批 MUST 过全部门禁（`check_param_binding` / 规则 1·2·3 / `check_union_conventions` / `release_check` 全链） | 铁律 2 · 收尾链 |
| **FR-012** | ★ 每批 MUST 附**可核对的测试**（注册得到 + 目标函数解析得到 + 参数绑定正确 + 该域**不重名**） | 批次 78 的样板 |

## 三 · 非目标（明确不做）

```
★ 不发明新能力（FR-002）· 不暴露裸坐标（FR-003）· 不暴露内部管道（FR-007）
★ 不为凑数把同一功能换名字挂第二遍（FR-006）
★ ★ **暂不碰 `/jlcfa` 与 `/gui` 域**（合计 ~70 个候选）—— ★ 理由：
   ① 它们大量是**鼠标键盘坐标自动化**（`click_rect` / `goto(x,y)` / `drag`），★ 按 FR-003 需重包装；

   ⇒ ★ 本规格把它们列为 **P4 待定**，先核来源再决定（★ 不因为"能凑 70 个"就上）✓
```

### 7.5 ★★★ 5 路探针的实测结论（★ 直接改掉了本规格的批序）

★ 用户在派 60 路之前要求**先派 5 路试**，结果**救了一次大返工**：★ 那 5 路全部判

| 原批 | 域 | 探针结论（**逐字要点**） |
