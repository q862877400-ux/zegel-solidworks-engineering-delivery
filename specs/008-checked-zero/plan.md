## 一、与既有实现的关系（**不重造**）

**零新增门禁**。本特性只：
1. 写一个**复现探针**（`tools/probe_checked_zero_skip.py`）；
2. 改 `check_signature_audit_freshness.py` 的**一个分支**（`checked == 0`）；
3. 修 `tools/probe_skip_semantics.py`（`007` 交付物）里的**一个假用例**。

## 二、步骤

### 阶段 0 · 把"必然性"论证清楚（**不是猜**）
能走到 `checked == 0` ⇒ `refs` 必然非空（上游 L238 已 SKIP 掉"拿不到反射"）；
而表里模块是本仓库自己的 `.py` ⇒ 全区解析不出 = **故障**。
⇒ **FAIL**（写进代码注释，让下一个人不必再推一遍）。

### 阶段 1 · 复现（**先复现，再改**）
`tools/probe_checked_zero_skip.py`：`--repo` 指向**空临时目录** + `--raw` 用**真反射**
⇒ 逼出「`refs` 13 份、6 个模块全跑不了」⇒ 实测**修前 exit 0（SKIP）**。
★ 复现是修的必要前提 —— 否则改完不知道改的是不是那条路径。

### 阶段 2 · 改（**一句话的语义修正，理由写足**）
```
if checked == 0:  ⇒  print("[FAIL] 反射转储在（N 份），但表里 M 个模块一个都解析不出来")
                    列出解析失败的模块名 + 指向 resolve_module 的解析顺序
                    return 1
```

### 阶段 3 · 两边都测
* 正例（真仓库 + 真反射）⇒ exit 0；
* **负例**（空仓库 + 真反射）⇒ **exit 1**；
* **便携性**（`--raw` 不存在）⇒ **仍 SKIP exit 0**。

### 阶段 4 · 修那个假用例（**回看 007 的产物**）
`probe_skip_semantics.py` 的"删表"正则**没匹配上** ⇒ 用例不成立却显示 `[PASS]`
⇒ 改成「造一份只有标题、不含表的文档」。

### 阶段 5 · 收工
13 道门禁 · 全量回归 · 两仓库 commit。

## 三、风险与对策

| 风险 | 对策 |
|---|---|
| 把**真的便携性**（没有反射转储）也改成 FAIL ⇒ 别的机器上无条件红 | 只改 `checked == 0`；上游「拿不到反射」那条 SKIP **不动**；**负例测便携性那一侧** |
| 复制探针时把源码文本当路径传（第一次就踩了）| 从源码抽**引号里的真路径**；失败时打印取到的值 |
| 探针用例不成立却显示通过（007 的假用例）| **用例必须自己先证明"输入真的坏了"**（本次：打印坏文档字节数 + 断言不含表）|
| **同一处反复修补**（已知事实 53）| 本次改的是**另一个分支**；且是**查证后的一次性修正**，不是试参数 |
