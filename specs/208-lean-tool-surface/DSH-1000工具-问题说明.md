## 1. 现状（全部为实测，口径见 §5）

工具定义经 `schemas()` 投影后进入每次请求的 `tools` 字段。实测 4 个真实会话：

| 会话 | 工具数 | 工具定义 | 首轮工具占该请求 | 末轮工具占该请求 | 末轮请求 | 末轮 input tokens |
|---|---|---|---|---|---|---|
| A | **589** | **174 KB** | **50%** | 10% | 1,671 KB | **235,674** |
| B | 77 | 27 KB | 27% | 2% | 1,488 KB | 183,754 |
| C | 77 | 27 KB | 27% | 3% | 1,085 KB | 131,896 |
| D | 77 | 27 KB | 27% | 2% | 1,362 KB | 148,360 |

会话 A 共 71 轮，同一份 174 KB 的工具定义被**逐轮重发 71 次**。

**工具定义的构成**（对 `docs/tool-catalog.md` 中 72 个 shipped tool 的 schema 逐字段归类）：

| 组成 | 合计 | 每工具 | 占比 |
|---|---|---|---|
| 工具级 description | 16,886 B | 235 B | **39%** |
| 参数级 description | 14,365 B | 200 B | **33%** |
| 参数结构（type/enum/required） | 10,124 B | 141 B | **24%** |
| 参数名 | 1,660 B | 23 B | 4% |

**同一信息的两条官方投影**（均由本库代码生成）：

| 投影 | 合计 | 每工具 | 信息 |
|---|---|---|---|
| `schemas()` → JSON Schema（native function calling） | 58,626 B | 814 B | 完整 |
| `renderToolsSdk()` → TypeScript 声明（PTC） | 51,772 B | **719 B** | 完整（description 转为 JSDoc） |

⇒ **仅换编码的上限是 11.7%。** `ts-types.ts` 自述二者是 *two projections of the same store*。

### 三条与本题直接相关的契约

**(a) wire 白名单**（`index.ts:1383-1391`）—— 上线的只有三个字段：

```ts
/**
 * Project visible definitions onto the allowlisted model-facing schema fields,
 * excluding execution and presentation callbacks.
 */
schemas(scope?: ScopeKey): ToolSchema[] {
  return [...this.view(scope).visible.values()].map(d => this.schemaOf(d, true))
}
```
（`index.ts:262` 亦注明：`schemas()` whitelists only name/description/parameters）

**(b) 动态注册 / 注销，且天然支持 per-agent 作用域**（`index.ts:1183-1213`）：

```ts
/**
 * Register globally or in the calling agent scope. Scoped tools shadow
 * globals; duplicates within one layer and the reserved `run_code` name fail.
 * @returns the exact disposer that unregisters the tool.
 */
register(definition: ToolDefinition): () => void
```

**(c) 按 agent 限定可见集**（`index.ts:1223`，另有 `guard` 做单调 deny）：

```ts
restrict(filter: ToolRestriction): () => void   // 必须 scoped；allow/deny，deny 优先；空 filter 报错
```

另：`system-prompt/assemble` 是可拦截瀑布，**返回值即权威**且作用域过滤分发 —— 故"这一轮让模型看见哪些工具"可在装配点决定。

## 3. 需求

**R1（硬）** 1000+ 工具**同时可见**时，选对工具、参数通过真实 schema。**全部工具必须可达**，不接受"用不到那么多"。

**R2（硬）** 系统指令（AGENTS.md）的遵循度不随工具数量下降。

**R3（硬）** **不得以"预先分组 / 每轮只挂一部分"作为解法** —— 若能减量，用现有模式即可，本题不成立。

**R4（软）** 在满足 R1–R3 前提下，token 越少越好。**任何以 R1/R2 换 token 的方案不接受。**

## 4. 已排除（均已实测或已论证）

| 方向 | 依据 |
|---|---|
| 裁剪 description / schema | 端到端可调用率实测 **89.9%（裁剪） vs 95.0%（完整）** |
| 在系统指令区追加工具目录或索引 | 直接违反 R2 |
| 预先分组、按需挂载 | 违反 R3 |
| 改用 PTC（写代码调用） | 其 SDK 段**同为 O(N)**（实测 719 B/tool），未解决规模问题 |
| 仅更换更紧凑编码 | 上限 11.7%（§1），量级不足 |

## 附录：测量口径

- 数据源：框架自身落盘的会话记录（每轮 `request/header.data.header.tools` 与 API 返回的 usage）。
- **工具占该请求** = `tools` 字段字节 ÷ (`tools` + `system/message` + 截至该轮的消息字节)。
- token 取 API usage 的 `inputTokens + cacheReadTokens`。
- §1 构成解剖：对 `docs/tool-catalog.md` 中 72 个工具的 JSON Schema 逐字段归类求和。
- §1 两条投影：由 `schemas()` 与 `renderToolsSdk()` 分别生成同一份输入。
- **口径警告**：工具定义为常量，逐轮完整存在。以"整场对话平均占比"评估会系统性低估其影响；应**以单轮为口径**。
