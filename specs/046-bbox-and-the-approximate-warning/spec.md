# 046 · 补 `bbox` —— 数值冒烟抓到一处单位错，并查出一条**与其它接口不同**的单位

**Status**: Implemented（轮 127）

## 一、为什么挑 `bbox`
它在「真缺」档里，而且**可以用精确数字验证**：建一个**已知尺寸**的盒子，量出来的
`size` 应当与设计尺寸相符。★ 这是最强的一档证据。

## 二、★ 数值冒烟：**先 7/8，修完 8/8**
```
✓ 新建临时零件 · start_sketch · 矩形(0,0→80,60) · extrude_boss(50)
✗ ★ get_bounding_box      NameError: name 'mm' is not defined      ← 第 1 处
     ⇒ 修：sw_part 里 mm 只出现在**文档串示例**里，模块没导入
✗ ★★ size 等于 80×60×50   got=[0.05, 0.06, 0.08] want=[50,60,80]  ← 第 2 处
     ⇒ 真因：**把 `mm()` 用在了输出上**（它是**输入方向**：毫米→米）
✓ 收尾无残留模态框
```
修完：**8/8**，`size = [80.0, 60.0, 50.0]`，**偏差 `0.00e+00`**。

## 三、★★ 顺手查出一条**与其它几何接口不同**的单位
```
建 80 × 60 × 50 mm 的盒子，直读 COM：
  GetBodyBox 原始 = [0.0, 0.0, -50.0, 80.0, 60.0, 0.0]
⇒ **原始值就是 80 / 60 / 50** ⇒ 单位是**毫米**（不是官方其它几何接口惯用的米）
⚠ 官方文档**没写单位** ⇒ 这条是量出来的（已知事实 71）
```

## 四、★★★ 本轮最微妙的一点：**官方那句「近似」，实测偏差却是 0**
官方同一份文档有 IMPORTANT 段：
> The values returned are **approximate** and **should not be used for comparison or
> calculation purposes**. Furthermore, the bounding box **may vary after rebuilding the model**.

⚠ **实测偏差为 0 并不推翻这句**：
```
实测只证了：「**这一个盒子、这一次**」的偏差是 0
官方说的是：「**不要依赖它**」+「重建后**可能变**」
⇒ **两者说的是不同的事** —— 一个有界样本压不过一条适用范围声明。
```
⇒ 已把官方原文**照抄进源码**与能力条目，并在 docstring 里点明
「返回只适合给人看个大概，**不要**拿去驱动别的特征」。
