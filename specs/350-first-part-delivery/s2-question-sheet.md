# S2 冻结问卷：八项首件要求，及其仓库现有证据

**日期**: 2026-10-25

**用途**: 把 `requirements.md` 里八个空白框变成**可以直接回答的问题**。

★ 本文件**不填任何值**。每项只写三件事：
  ① 这一项决定什么 ② 仓库里现在有没有依据 ③ 回答时需要什么格式（因为要能机器核对）。

---

## 一、先说清楚「为什么不能我自己填」

`docs/ENGINEERING-PATH.md` 第 85 行逐字：

> 尺寸缺失就问；**材料、功能孔型、配合、制造约束、影响承载的工况不得偷偷填默认值**。

`AGENTS.md` 停止条件第 8 条：

> 首件硬要求（孔数/孔型/位置、材料、图样、配合）在方案里没有承担节点
> ⇒ 该方案是**未完成方案**，不能当候选。

所以这八项**必须由工程负责人（或业主）给**。我给的是「问题 + 现在的证据 + 回答格式」。

---

## 二、八项逐条

### 1. `material` 材料牌号 + 标准号 + 版本

| | |
|---|---|
| **决定什么** | 强度/刚度校核的许用值、表面处理、采购与替代规则 |
| **仓库现有依据** | **无**。全仓搜索未见首件材料定义 |
| **回答格式** | 牌号 + 标准号（含年号），例：`Q235B / GB/T 700-2006` |
| **为什么要求标准号** | 只有「钢」「45 钢」无法核对许用应力 —— `shape_problems()` 会报「不可核」 |

### 2. `load_case` 载荷工况（含量纲与数值）

| | |
|---|---|
| **决定什么** | 强度/刚度/疲劳校核的输入；决定板厚与孔边距是否够 |
| **仓库现有依据** | **无** |
| **回答格式** | 每个工况：名称 + 类型 + **数值 + 量纲**，例：`安装预紧 500 N`、`自重 2 MPa 面压` |
| **注意** | 首件是**静态**件（`ENGINEERING-PATH` E4 行写明「静态首件不承担运动全域承诺」）⇒ 给静态工况即可 |

### 3. `safety_level` 安全等级

| | |
|---|---|
| **决定什么** | 安全系数取值、失效后果的容忍度、验证强度 |
| **仓库现有依据** | **无** |
| **回答格式** | 等级名 + 出处（内部规范号或标准条款），例：`II 级 / 公司《机械设计安全分级》3.2` |
| **注意** | 我**不预设枚举** —— 等级口径由你定；判据只要求「非空且能追到出处」 |

### 4. `process` 工艺路线种类

| | |
|---|---|
| **决定什么** | E6 的适用检查项（刀具可达、孔深/刀具、壁厚/余量、装夹空间） |
| **仓库现有依据** | ✅ **部分**：`ENGINEERING-PATH` E6 行写明「首件只选**已确认机加工路线**」 |
| **回答格式** | 首件限定 `machined`；若要细分请给具体路线（车/铣/钻/磨） |
| **★ 这是唯一有仓库依据的一项**，但它只是**路线限定**，不是业务选择 |

### 5. `datums` 设计基准（语义角色）

| | |
|---|---|
| **决定什么** | 图样标注的基准体系（A/B/C）、装配定位、测量基准 |
| **仓库现有依据** | ⚠️ **只有实现侧痕迹，不是需求**：现有 `build_plan` 用 `Front Plane` 起草图、原点在板角 |
| **回答格式** | 每个基准：名称 + **语义角色**（主基准/导向/测量），例：`底面 A / 主基准` |
| **★ 不能反过来填** | 拿「现在怎么建的」当「要求」是倒因为果 —— 那会让 S2 变成「建了什么就要求什么」 |

### 6. `interface` 接口：孔型 / 孔位 / 配合面

| | |
|---|---|
| **决定什么** | 孔规格与位置公差、配合面、可装配性 |
| **仓库现有依据** | ⚠️ **只有测试用例值，不是需求**：`run_stage2_plate.py` 的 `CASES` 里 case1 = `100×60×20`、`4×⌀6` 通孔 @ `(10,10)/(90,10)/(10,50)/(90,50)`；而 case2 是 `80×50×12`、`2×⌀8`；case3 又是另一组 |
| **回答格式** | 孔数 + 孔径（含公差）+ 位置（含公差）+ 配合面要求 |
| **★★ 三个用例尺寸不同** | 说明这些是**测试值**不是需求。若确认 case1 就是首件，请明说「以 case1 为准」 |

### 7. `drawing_scope` 必要图样的范围

| | |
|---|---|
| **决定什么** | E5「必要标注清单」从哪来；决定要出几张图、哪些视图、哪些公差 |
| **仓库现有依据** | **无**（`ENGINEERING-PATH` 只说「由功能/制造/检验要求生成必要标注清单」，没说范围） |
| **回答格式** | 视图清单 + 必须标注的项目类别（尺寸/形位公差/表面粗糙度/技术要求） |

### 8. `delivery_purpose` 交付目的

| | |
|---|---|
| **决定什么** | **全部判据的严格度**。练习件与真实设备件的要求差一个量级 |
| **仓库现有依据** | **无** |
| **回答格式** | `练习件` 或 `真实设备件`（+ 若真实设备，说明用途） |
| **谁能定** | **业主**（这一项连工程负责人都不能替你定） |

## 三、回答之后会发生什么

1. 我把八项写入 `specs/350-first-part-delivery/requirements.md` 的冻结表
2. 跑 `missing_confirmations()`（查有没有填）+ `shape_problems()`（查填的能不能核）
3. 两者都空 ⇒ `can_freeze()` 才允许冻结；任一有输出 ⇒ **不得冻结**
4. 冻结后按 `ENGINEERING-PATH` 第 101 行「编译前检查硬要求覆盖」：
   孔数/孔型/位置、材料、图样、配合各有承担节点

## 四、★ 本轮顺带补的判据（不依赖你的回答）

`scripts/engineering/acceptance/s2_requirements.py` 新增 `shape_problems()`：

| 字段 | 要求 | 为什么 |
|---|---|---|
| `material` | 要有**标准号形态** | 「钢」无法核对许用值 |
| `load_case` | 每项要有**数值 + 量纲** | 「大」「按经验」无法计算 |
| `datums` | 每项要有**语义角色** | 空角色后续图样/装配无从绑定 |

★ 它**只验「能不能作为依据」，不验「值对不对」、不给默认值**。
  `tests/test_s2_shape_problems.py`（26 条）两侧都钉：
  该报的（`钢`/`大`/空载 magnitude/空基准角色）与**不该误伤的**
  （`GB/T 700-2006`/`ASTM A36`/`500 N`/`12.5 kN`/`15%`）。

★ 它与 `missing_confirmations()` **互补不重叠**：
  全空契约 → 缺项检查报五项，形状检查报 **0 项**（空不是形状问题）。
  合并成一个「缺 N 项」会让人分不清「还没填」与「填了但不可用」。
