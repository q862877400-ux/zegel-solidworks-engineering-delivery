## 三、E2 为什么没过（三层原因，逐层有证据）

### 层 1：孔确实没随板宽移动

```
板宽 100 → 120：包围盒 X 100.0 → 120.0 mm      （板变了）
四个孔心：(10,10) (10,50) (90,10) (90,50)       （一个没动）
位移 = [0.0, 0.0, 0.0, 0.0]
```

★ 这份读数**先排除了「读数失败」**：`tools/probe_s3_hole_center_diagnose.py`
逐张草图量到孔心可读（`草图2..5` 各 1 段、圆心可读），
说明不是探针读不到，而是**孔真的没动**。
（第 18 轮第一次跑出 `位移=[]` 时我差点误判，靠这个诊断才分清。）

### 层 2：孔位参数化只有「加尺寸」一条路，而它在本机崩

| 手段 | 真机结果 |
|---|---|
| `AddHorizontalDimension2`（单段 / 两点） | ❌ 会崩或空加（第 13 轮 2 次、第 14 轮 4 次崩） |
| `AddDimension2`（孔心+边线、孔心+角点） | ❌ 同样崩 |
| 仓库自己那个已验探针复跑 | ❌ **也失败**（判据 `still_no_dimension`，成 0/3） |

⇒ 结论：`sketch_dimension_horizontal` / `sketch_dimension_vertical` **本机已退化**。
   记在 `known-facts.md` **事实 560**，并写进两个能力的 `limitations` 首项。

### 层 3：换用 `FullyDefineSketch` 加关系 —— 更差

本轮最后试的一条（不依赖上面那个方法族）：

```
一张草图：矩形 100×60 + 4 个孔圆
FullyDefineSketch(True, 1023, 1023, True, 1, Nothing, 1, Nothing, 0, 0)
  ⇒ ok=True · 状态 2 → 3 · 尺寸 0 → 1
  ⇒ 但那个尺寸是 D1@草图1 = **6.0 mm**（孔直径）
  ⇒ **板宽根本不是尺寸**
```

⇒ 孔与轮廓同草图时，`FullyDefineSketch` 把**孔直径**尺寸化，**板宽反而丢了**
  （矩形单独时 `AutoDimension2` 给的是 100mm = 板宽）。
  ⇒ 这条路**比原路更差**：改不了主参数，连 E1 的「驱动尺寸」也会指向孔的直径。

## 五、E2 要过，需要什么

按「不硬推」的纪律，这里**只列前置条件，不假装能绕过**：

| 前置 | 为什么 |
|---|---|
| **修好 HV 尺寸能力** | 孔位必须靠「孔心到边」的尺寸；而该能力本机不可用 |
| 或：换用**特征阵列** | `linear_pattern` 已知卡在方向基准（事实 321），未通 |
| 或：改用**方程式**绑板宽 | 但方程式要引用尺寸名，而孔心位置**不是尺寸** ⇒ 回到同一前置 |

★ 三条都指向同一件事：**孔心必须先是一个尺寸**。这是 E2 的硬前置，绕不过去。
