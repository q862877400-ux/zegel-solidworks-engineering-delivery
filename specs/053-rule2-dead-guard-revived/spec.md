# 053 · 找出并接上一个**死守卫**：规则 2 的长度那一半从未生效

**Status**: Implemented（轮 134）

## 一、怎么发现的
`052`（轮 133）证明了「脚本层的单位无人守」。顺着去看**工具层**那条守卫：
```
`mcp-server/tool_registry.py`
  L78:  _LEN_SUFFIX = "_mm"                   ← 定义了
  L251: if p.name in _BARE_COORD_NAMES:       ← 只有**裸坐标**那条在用
⇒ `_LEN_SUFFIX` **只在定义处出现一次** —— **死常量**
```
★★ 这正是**已知事实 40**：
> 「一个**存在但没人用**的守卫与没有守卫等价，**且更糟**（让人以为防住了）」

⚠ 而更糟的是：规则 2 **一直被算进「五统一门禁通过」**（A3 的判据之一）。

## 二、先**证明**它确实是死的（事实 62：负例是唯一的证明）
```
造一个故意违规的 ToolSpec（参数名 `thickness`、不以 `_mm` 结尾）：
  ✗ 接上之前 `check_spec` **不拒**        ⇒ 断言「不生效」⇒ 3 passed
  ✗ `_LEN_SUFFIX` 只在定义处出现 1 次
✓ 对照：**同一段的裸坐标规则（规则 3）是生效的** ⇒ 不是"整段都没实现"，而是少了长度那一半
```

## 三、接上它
```python
_LEN_WORDS = ("radius","diameter","depth","thickness","distance",
              "width","height","length","offset","spacing","pitch")
#: ⚠ 刻意**不含** size / w / h（非几何语境同样常用，见事实 74）
#: ⚠ `bool` 不是长度（`use_default_radius` / `reverse_thickness` 是**标志**）
if p.kind is not bool and any(w in low for w in _LEN_WORDS) and not low.endswith("_mm"): ...
```
### 3 个**真例外**走显式豁免（不是把它们改绿）
| 工具 | 参数 | 为什么 `_mm` 会说错话 |
|---|---|---|
| `solidworks_mold_core_cavity_split` | `thickness` | 文档写明「**0.0 = 用文档默认**」|
| 同上 | `offset` | 同上 |
| `solidworks_mold_parting_surface` | `distance` | 同上 |
⇒ 照 `MANUAL_MAP` 的先例：**每条带理由**，没依据的不许进来。

## 四、★ 判据有效的证明：**同一个负例，换个方向**
```
接上之前：assert not rejected            ⇒ 3 passed（证明"不生效"）
接上之后：with pytest.raises(GateError)  ⇒ 5 passed（证明"生效"）
```
★★ **"把断言翻过来"这个动作本身就是判据被接上的证据** ——
而那个方向**是我写那条测试时就预留好的**（测试 docstring 里写着
「一旦规则 2 被接上，这条会红，那时就该把它改成『必须被拒』」）。
⇒ ★ **判据的"死"与"活"能被同一条负例表达**，只是断言方向不同。

## 六、⚠ 这次修的不是"一个 bug"
```
接上后 `check_specs(all_specs())` ⇒ 0 问题
⇒ ★ **没有"正在违规"的工具** —— 修的是「**以后再犯会被拦**」。
```
★ 与 `029`/`032`/`037`/`052`（"做不成门禁"）**方向相反**：
那几次是**否决一个判据**；这次是**救活一个判据**。
⇒ 两者合起来才完整：**判据要么被负例证明有效，要么被证明不成立 —— 不能"存在但没人用"。**

## ⚠ 明确记下的限度
* 词表是**有界选的** ⇒ 只覆盖"几乎必然是长度"的词；`size` / `w` / `h` 这类**故意不收**；
* 3 个豁免是**人工判**的（照 `MANUAL_MAP` 先例）⇒ 新出现同类要**人工加**；
* ⚠ 本轮**没有**去查其它规则是否也有"死守卫"（那是另一轮的事）。
