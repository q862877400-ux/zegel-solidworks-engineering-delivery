# 规格 212 · 单位纪律机械化

> **来源**：`docs/union-conventions.md` **规则 2**（本仓既有约定）· 用户 2026-10-07 指令：
> 「**认同你给规则 2 补三条，并且要在每个工具上加机械判断，不能每次都靠 LLM 工具去判断单位**」✓
> ★★ **本规格的中心思想**：**单位纪律必须是"机器卡口"，不是"每次现场判断"** ✓

## 一、要解决什么

用户观察到「**很多地方输入尺寸数字时存在米/毫米混淆**」⇒ 我实测后，把问题**分成两侧**（★ 归因要准）：

| 侧 | 现状（★ 实测） | 缺口 |
|---|---|---|
| **输入**（AI → 工具） | ★★ **已有硬约定且门禁是活的** —— 规则 2「长度 `_mm` / 角度 `_deg`」+ `check_spec` 强制；★ 因"过不了就整体不注册"，**448/448 都通过** | ★★ **词表是"有界"的**（刻意不收 `size`/`w`/`h`）⇒ **不在词表里的长度词不被查** ✗ |
| **输出**（COM → AI） | ★★ **完全没有门禁** —— 单位靠各模块自己写 `UNITS` 字典 / `"units": "mm"` | ★★ **这是我们真正的洞** ✓ |

★★ **归因（重要）**：今天那条"1000 倍"发生在**输出侧**（官方 `IFace2.GetArea` 说 `square meters`，
真机端面读 400 对应 20×20 **mm²**）—— ★ **不是输入错** ✓

## 二、本规格做什么（三条，★ 全部要**机械判据**）

### ① 规则 2 补"**逆向一半**"（输入侧闭环）

★ 现在只有单向：「**名字含长度词 ⇒ 必须有 `_mm`**」。
★★ 补上反向：**「描述里声明了长度/角度单位 ⇒ 名字必须有对应后缀」** ✓
★ 判据：★ 读 `ToolSpec` 的 `Param.description`，★ 出现 `mm`/`inch`/`meter`/`degree` 等单位 ⇒ 名字必须带 `_mm`/`_deg`
★ **豁免仍走显式表**（★ 每条带理由，★ 理由必须自洽 —— 见 ③）

### ② 新增 **规则 2b · 输出侧单位门禁**（★★ 本规格的核心）

★★ **每个工具返回的数值字段**，键名必须满足二者之一：
- ★ 带**单位后缀**：`_mm` · `_mm2` · `_mm3` · `_deg` · `_px` · `_s` · `_kg` · `_m2` …
- ★ 或在**无量纲键白名单**里：`ok` · `count` · `ratio` · `status` · `index` · `error` · `notes` …

★ 落地位置：★ **返回出口的守卫**（★ 每个工具都经过 ⇒ **加一次就覆盖全部 448 个** ✓）
★★ 判据是**机械的**：★ 扫**顶层数值键名** —— ★ 不调 LLM、不猜语义 ✓

### ③ "未确证"成**仓级约定** + **冲突登记**

- ★ 凡返回值带 `units_verified: false` ⇒ ★ **必须同时带 `unit_caveat`**（★ 可静态查 ✓）
- ★★ 新建 `docs/unit-conflicts.md`：登记「**官方声明 vs 真机读数**」冲突，★ **第 1 条** =
  `IFace2.GetArea`（官方 `Returns` 写 `square meters`；★ 真机端面读 **400** = 20×20 的 **mm²**）✓
- ★ 每条冲突要带：**官方页 · 官方原话 · 真机读数 · 证据文件 · 处置**（★ 与"查不到就说查不到"同一纪律）✓

## 三、本规格**不做**什么

- ★★ **不做"值里带单位字符串"**（如 `depth: "20mm"`）——
  ★ 理由：**MCP 只传 JSON 值**；★ 值带单位 = **字符串** ⇒ ★ **失去类型检查**，★ 而且**单位只在下游可见** ✗
  ★★ 而**后缀在形参名/键名上** ⇒ ★ **能被静态门禁强制** ✓（★ 这正是用户要的"机械判断"）
- ★ **不碰 COM 后端** · ★ **不装不改系统层**（★ 铁律 2）
- ★ **不靠启发式下结论**：★ 我为审计写的 `tools/audit_unit_suffixes.py` **假阳性太多**
  （把"Converted to the metres"这种**正确说明**判成矛盾）⇒ ★ 按**事实 53** 停手，
  ★ **本规格一律用"确定性判据"**（后缀名 / 白名单 / 显式表），★ 不用"猜语义的词表" ✓
- ★ **不动 21 项功能攻关的成果**（★ 那个目标暂停等本规格做完）✓

## 四、硬约束

1. ★ **只缝合不发明**（铁律 1）：本规格的每条约定都**指得出仓内出处**（规则 2 / `UNITS` / 今天的实测）✓
2. ★ **判据一律机械**：★ 能用"名字/白名单/显式表"判的，★ **不许**改成"LLM 看一眼" ✓
3. ★ **豁免必须显式 + 每条带理由**（照 `MANUAL_MAP` 与两张 `*_EXEMPT` 表的先例）✓
4. ★ **不许为了过门禁说假话** —— ★ 该扩门禁就扩门禁（★ 这条是本仓已有的纪律，见
   `test_rule2_exemptions_are_explicit_and_reasoned` 的 docstring L84）✓
5. ★ **只读优先、改动单独提交可回退** ✓
6. ★ **长文本先落文件再搬运**（事实 48）✓
