# 规格 207 · Union 缺口逐条核实（把「假阳性率」从**引用**变成**测量**）

> **读法**：本文件定判据（SC）与决策（D）；`plan.md` 定顺序、依赖、派活与写盘边界；
> `tasks.md` 是逐任务的 checklist 与达成记录。

## 一 · 为什么有这条规格（★ 上一轮的错，逐字记下来）

规格 206 的支线把四家 MCP 的 349 个操作与我们的 183 个工具做了一次分诊，
产出 `output/union-gap-v3.json`：**①已有等价物 273 · ②需人工核 19 · ③强候选 57**。

★★★ **而它的"已有等价物"是 `best_cov` 阈值判的，不是逐条读的** —— 自述逐字：
「v3：349 全集 × 域映射(§五) × **183 个已有工具当负样本** · 三层判据 · **7 条回归**」，
且三档的 cov 边界是 **①≥0.500 · ②0.111~0.429 · ③=0.000**。
⇒ ★ **cov=1.0 只说明「这个操作名的词全出现在某个工具名里」** —— 那正是仓里早就写过的
「名字级差异**约 59% 是假阳性**」那个信号，**它两个方向都会错**。

★★ **而我在上一轮把它当"实测结果"引用了**，写下「假阳性率**实测**是 78%（273/349）」——
**我没测过任何一条**。⇒ ★★★ **这与本仓刚诊断过的病是同一个**（相信一条写着"实测"的文档），
**在同一场对话里又犯了一遍** ⇒ 本条规格的存在理由就是**把这个数真正测出来** ✓

## 二 · User Scenarios

- **US-1**：作为业主，我要看到「349 个操作里到底有多少是假阳性」是**逐条读出来的数**，
  而不是某个阈值分类器的自述 —— 因为我要用它决定**该不该继续投人**。
- **US-2**：作为业主，我要**每一个操作都有一条独立的判断记录**（谁读的、读了什么、凭什么），
  因为批量结论一旦错了，我会照着它砍掉真正该做的活。
- **US-3**：作为接手的人，我要能**复核任意一条**：拿到 op 名就能找到它的记录与证据。

## 三 · 判据（SC）

| # | 判据 | 怎么验 |
|---|---|---|
| **SC-1** | **349 个操作每个都有一条记录**（覆盖率 100%） | `output/union-verify-349.json` 的 `records` 长度 == 349，且 op 集合与 `output/union-gap-v3.json` 的 rows 完全一致 |
| **SC-2** | ①档 **273 条逐条验证**，产出**真实假阳性率** | 逐条 `verdict ∈ {已有, 其实没有}` + `evidence`；★ 真值 = 「已有」条数 / 273 |
| **SC-3** | ②③档 **76 条逐条学透 + 官方对照**，产出候选 | 每条给 `official_member` / `official_signature` / `dead_ends` / `proposed_name` / `recommendation` |
| **SC-4** | ★★ **两个数必须并列报**：分类器自述 78% **与** 逐条实测值 | 报告里同一行给出两者与差值；★ 只报一个即不达标 |
| **SC-5** | ★ **返回体必须是合法 JSON 且 < 256 KB**（枚举化） | `json.loads` 通过 + 字节数断言；★ 上一轮 1.8 MB 被截断、JSON 非法 ⇒ 本条是硬门禁 |
| **SC-6** | 全程**离线静态**：零 SolidWorks 调用 | 跑完后 `solidworks_session_busy_status` 或 `GetDocumentCount` 与开工前**一致** |
| **SC-7** | 每批**落盘 + 提交**，只 add 自己这一线 | 4 次 `tools/commit_mine.py`（★ 链完不许直接 commit，事实 555） |
| **SC-8** | ★ 我自己的**假"实测"声明**全部清掉 | grep 全仓，凡我写的「假阳性率实测」类表述，改为「分类器自述」或「本轮实测」并挂证据 |

## 四 · 决策（D）

| # | 决策 | 理由 |
|---|---|---|
| **D-1** | ★★ **判据以「bunny 逐条读」为准**；分类器的 `tier`/`cov`/`top` **只作线索**，不作结论 | 业主裁定；且实测已证分类器两个方向都错（`wrap` / `sketch_construction` / `connect`） |
| **D-2** | ①档 273 条**只做验证**（不写实现）；②③档 76 条才做「学透 + 起草」 | 成本；且①档若真有假阳性会**回流**成候选 |
| **D-3** | 本轮**不做真机验证**；一切真机结论标「未实测」 | ★ 几十个 agent 并发，而本机只有一个 SolidWorks 实例 ⇒ 抢 COM 会**死锁**（事实 24） |
| **D-4** | 采纳与否由 **Lead 逐条裁**（本规格不做自动采纳） | 「你做主裁判」 |
| **D-5** | **不搬别家代码**；实现从**官方文档**重推；别家只当「该做哪个操作」的路标 | 铁律 1 + 铁律 6（许可红线） |
| **D-6** | 批大小 **≤60**，一条一个 bunny | 业主给定；且与仓里「5 路 → ≤60 路，一个 job 一批次」一致 |
| **D-7** | ★ schema **必须用 `enum` 限死** `verdict` / `recommendation`；散文由 bunny **自己写文件**，不进返回体 | 上一轮的返回体 1.8 MB 被截断、JSON 非法 ⇒ 根因是自由文本字段 |

## 五 · Acceptance Scenarios

- **AS-1**（SC-1 + SC-5）：跑完 `tools/verify_union_349.py` ⇒ 报「349/349 条记录、op 集合与 v3 完全一致、返回体合法且 < 256 KB」。
- **AS-2**（SC-2 + SC-4）：跑 `tools/report_false_positive_rate.py` ⇒ 报「分类器自述 273/349 = 78.0%；逐条实测 X/273 = Y%；差 Z 条」。
- **AS-3**（SC-3）：跑 `tools/list_adoptable.py` ⇒ 列出 ②③ 档里建议采纳的条数与名字，每条带官方成员与判据。
- **AS-4**（SC-6）：开工前后各跑一次文档数，两次相同。
