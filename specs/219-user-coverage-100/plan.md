# 规格 219 · 实施计划（plan）

## 一、技术路线（★ 五步，前两步不许跳）

```
① 去伪：对 12 项逐条裁定（A 真缺口 / B 假阴性 / C 不可做）
   证据来源（按序）：all_specs() 工具名 · scripts/ 实现 · capabilities.yaml · docs/dead-ends.md
   输出：specs/219-user-coverage-100/verdicts.md（一张 12 行的裁定表，每行带可复算依据）
② 先摘"低垂果实"：B 类（假阴性）——★ 绝大多数只需把已有能力接上/正名，★ 成本最低、数字立刻动
③ 再攻 A 类（真缺口）：逐个照官方签名实现 + 真机验证
④ C 类（不可做）：写"不做 + 原因"，并把地图对应行改成带引用的说明
⑤ 收口：重跑生成器 --check ⇒ 11 个域逐格核 ⇒ 写最终账
```

## 二、★ 各类的具体手法

### B 类（匹配器假阴性）—— ★ 首选，因为"能力本来就有"

- ★ **先查该能力在源码/工具表里的真实形态**（★ 例：焊件角撑板 ⇒ `solidworks_weldment_gusset_create` ✓）
- ★ **再看地图的关键词是什么**（★ 地图 §二 说按功能项关键词**子串**命中工具名）
  ⇒ ★ 若已有工具名不含该关键词 ⇒ ★ **两条合法路**：
  - ★ ① 给该 `ToolSpec` 加**别名/正名**（★ 本仓有 `tool-aliases.md` 这一层机制，★ 别名进 `all_specs()` 的名集合吗？
    ⇒ ★ **必须先查生成器取的是哪个名集合**：地图 §十 逐字「本仓库工具名 : `register_capabilities.all_specs()` + `mcp-server/server.py` 的 `name=`」✓）
  - ★ ② 若该能力**确实没暴露**（如 `surface_revolve`）⇒ ★ 走"纯暴露"那套（★ 判据参考规格 217 第 7 轮的闸：
    ★ **函数体是否要求先选中**）✓
- ★★ **红线**：★ **不许只加一个好看的名字而不接真实实现** ✓

### A 类（真缺口）—— ★ 慢工，逐个过

- ★ 强制顺序（`AGENTS.md` §十四）：★ ① 官方页（签名 + `## Remarks` + CHM 例）→ ② `docs/dead-ends.md`
  → ③ 该能力 `limitations` → ④ `known-facts.md` → ⑤ 动手 ✓
- ★ 每个都写 `*_report` 形态（★ 带回读判据），★ 并**真机验证**（走 `tools/sw_guard.py`，用完关 SolidWorks）✓
- ★ 三件套齐：`all_specs()` 行 + `capabilities.yaml` 归属 + 契约测试 ✓

### C 类（不可做）

- ★ 引用既有裁定（★ 如 `docs/union-coverage-matrix.md` 的「不做 + 原因」段：PDM 需许可证 + 296/4683 成员）✓
- ★ 并在 `verdicts.md` 写明"★ 若将来拿到许可证，第一步应查哪一页"✓
