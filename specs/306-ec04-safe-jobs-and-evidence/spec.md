## 一、★★★★★ 目标（★ 逐字承计划 §5 EC04）

★★★ **执行不抢同一个 COM；★ 失败可恢复；★ 验收绑定正确版本。**

★★ **一句话**：★ EC03 说「**怎么做**」；★★★ **EC04 保证「**做的过程可信**」—— ★ 谁在做 · ★ 能不能改 · ★ 证据算不算数。**

---

## 二、★★★★★ 用户故事与验收场景

### US1（P1）★ 双客户端争抢**只能一个**得执行权

| # | ★ 验收场景 |
|---|---|
| S1-1 | ★ 一个会话同时**只有一个**租约持有者 |
| S1-2 | ★★ 租约**过期**后可以让出 ⇒ ★ **令牌递增** |
| S1-3 | ★★★ **过期 worker 不能继续修改**（★ 围栏令牌挡住） |

### US2（P1）★ **超时未回读不重试**

| # | ★ 验收场景 |
|---|---|
| S2-1 | ★ 超时/语义不明的 COM 错误 ⇒ ★ **`uncertain`** |
| S2-2 | ★★★ **`uncertain` **不能**回 `running`**（★ 状态机层面的保证） |
| S2-3 | ★ `uncertain` **可以**去 `validating`（★ 先回读） |

### US3（P1）★ **旧证据不能放行新模型**

| # | ★ 验收场景 |
|---|---|
| S3-1 | ★ 批准**绑 contract/plan/model 三个版本** |
| S3-2 | ★★ **任何一个变了 ⇒ 立即失效** |
| S3-3 | ★ 失效原因**具名**（★ 哪几个变了） |

### US4（P1）★ **失败不丢用户文件**

| # | ★ 验收场景 |
|---|---|
| S4-1 | ★★★ **不宣称 COM 有数据库式全局事务**（★ 它没有） |
| S4-2 | ★ 用**阶段检查点 + 前向补偿** |
| S4-3 | ★★★ **补偿绝不删用户文件** |

### US5（P1）★ 没有许可/权限的动作**停在设计建议**

| # | ★ 验收场景 |
|---|---|
| S5-1 | ★★ **独立验收器只读**最终模型 |
| S5-2 | ★★★ **不把同一 Agent 自评当放行者** |
| S5-3 | ★★ **无许可 ⇒ `design_advice_only`**（★ **不是 pass、也不是 fail**） |

### US6（P2）★ 证据**可防篡改** + **不泄漏**

| # | ★ 验收场景 |
|---|---|
| S6-1 | ★ 证据**链式**（★ 改中间一条 ⇒ 断链） |
| S6-2 | ★★ **敏感字段替换成 `***REDACTED***`**（★ **不是删键**） |
| S6-3 | ★ **工件用相对路径**（★ 绝对路径泄漏本机结构） |

## 三、★★★★ 功能需求（★ 承计划 §5 EC04 的 T01–T08）

| ID | 要求 | 故事 | ★ 必须证据 |
|---|---|---|---|
