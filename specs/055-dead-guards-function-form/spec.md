# 055 · 死守卫的**第二种形态**：定义了却从没被调用的函数

**Status**: Implemented（轮 136）

## 一、为什么扫这个形态
`053`/`054` 扫的是**常量**形态（规则 2 的两半都定义了却没人用）。
★ 本轮扫**函数**形态：**门禁/工具模块里定义了却全仓库没人调的辅助函数。**
⚠ 已知事实 61 的定则④就说过这一类：「好用的工具函数要用在**所有**同类场合」。

## 二、判法（有界、可复核）
```
① 只看 6 类文件：scripts/check_*.py · audit_*.py · gen_*.py · tools/*.py
② 取模块级的 def（含 `_` 私有）
③ 排除入口点：main / register / run
④ 数名字在**整个仓库**里的出现次数（除定义行与注释）⇒ **0 次**即可疑
```

## 三、★ 结果：**164 扫过 · 1 可疑 · 1 真**
| 可疑 | 判定 |
|---|---|
| `tools/propose_capability_sources.py:133` `match_modules(kws, files)` | ✗ **真的死代码** —— 它是 `stems_only()` 的**旧版**（会**扫文件体** `body = f.read_text(...)[:1200]`），而 `stems_only()` 的 docstring 明写「**只按文件名主干**匹配（**不再扫文件体**）」「⚠ 第一版还扫了文件体 ⇒ **命中面进一步失控**」 |

⇒ ★★ **被取代的旧版，作者留了说明却没删函数。**

### 处置：删除 + **墓碑注释**
在原处留一段注释写明它是谁、为什么删 ——
⚠ **留注释而不是无声删掉**：读代码的人该知道这里发生过什么。

## 四、★ 假阳性 0% —— 但**样本只有 n=1**
```
164 扫过 · 1 可疑 · 1 真 ⇒ 表面假阳性率 0%
⚠★ 但 n=1 **不足以**说"这个探针可靠" —— 一个数据点估不出率
⇒ ★ **不升成硬门禁**（那会挡住发布）；**先做成回归测试** + 显式豁免表（每条带理由）
```
★ 与此前几次**方向相反但克制相同**：`052`/`054` 是"假阳性太高 ⇒ 不成门禁"；
本轮是"**假阳性低，但样本太少 ⇒ 先不进硬门禁**"。

⇒ ★ 那不叫"测到了工具" —— 测的是"测试自己写的一份"（事实 62 的精神）
