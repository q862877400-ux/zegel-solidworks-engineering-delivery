# 027 · 其余程序集的枚举覆盖 —— 结论是「**已覆盖**」，外加一处注释错名

**Status**: Implemented（轮 108）

## 背景
`026` 解决了 `sldworks` + `cosworks` 两个程序集的枚举覆盖，但留了：
> **还有没有别的程序集**的枚举被我们用到 —— 其余 interop **未逐一检查是否有对应转储**。

本轮把这件事量出来。

## 做法
`tools/probe_enum_assembly_coverage.py`（**只读探针**）：
1. 从代码注释抽官方成员名（**90** 个）；
2. 列出 `_raw` 下**已有的**枚举转储（**17** 份）⇒ 算出它们合起来覆盖什么
   （**11,486** 个成员 + **1,521** 个枚举类型名）；
3. 对**没覆盖**的名字，逐个去 `api\redist` 的 17 个 interop DLL 里**纯字节搜索**
   ⇒ 定位它真正属于哪个程序集。

## ★★ 结论：**转储覆盖是完整的**
```
未覆盖的名字   ⇒  最终只剩 4 条，且**全是噪声**：
  `swconst`                —— 程序集名本身
  `sw_know` / `swapi`      —— 工具名，不是官方成员
  `swPatternObjectType_e`  —— 它出现在一句「**该枚举名查不到**」的查证注释里（用法是对的）
⇒ 现有 17 份转储**已覆盖代码里用到的全部官方成员**。
```

## ⚠⚠ 我的探针**连着两版都是假阳性**（这才是有价值的部分）
| 版 | 我写的判据 | 假阳性 |
|---|---|---|
| 1 | 只看转储的**成员行**（`    swFoo = 0`）| 把代码引用的**枚举类型名**（`## swFoo_e` 标题）全报成未覆盖（**16 条**）|
| 2 | 再加枚举类型名 | 把**我们自己的模块/函数名**（`sw_jlcfa_*`）当成官方成员 |
| 3 | 剔掉自有名 | 把**「这句里那个名字是错的」注释里的名字**当成"在用那个名字" |

★ **三轮才收敛。** 这与 `020`/`021`/`022` 的教训一致：
**按名字做的自动检查在这个项目里反复产生假阳性**。

## ★ 顺带查出一处**真错**（小但真实）
```
我们的注释写：  `# swExportPDFData`
官方真名：      `swExportDataFileType_e.swExportPdfData = 1`   （**Pdf，不是 PDF**）
两源一致：      `enum_values_sldworks.txt` + `C:\swapi\types\ISldWorks\GetExportFileData.md`
```
⚠ **代码一直是对的**（传的字面量 `1` 正是该值）—— **错的只是注释里的名字**。
★ 但一个**不存在的官方名字**写在注释里，会让下一个人以为它存在。
⇒ 已更正，并在该处补了一个**函数体内的来源块**（本仓库允许，且溯源门禁要求）。
