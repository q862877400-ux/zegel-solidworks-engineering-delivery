# 规格 217 · 把「已实现但没暴露」按域补进 MCP

> ★ 触发：2026-10-07 用户问「工具数和实现功能是否覆盖所有开源项目」，核对后确认**两层口径不同**：
> ★ **MCP 暴露面**（我 459/470 · 四家∪我 = **795** · 缺口 **310**）与
> ★ **能力面**（`scripts/sw_*.py` 公开函数 **1262**，矩阵几乎每格标 `⚠`「多半不是能力缺口，只是没暴露」）。
> ⇒ ★ 用户选定第一条路：**先把"已实现但没暴露"那批按域补进 MCP**（数字动得最快、且是纯暴露工作），
> 并**授权全自动**、按 Spec Kit 施工、可代其拍板 ✓

## 一、要解决什么（问题陈述）

★ 本仓的**能力面**远大于**暴露面**：`scripts/sw_*.py` 里 1262 个公开函数中，**至少 792 个（1262 − 470）**
没有被任何 MCP 工具引用；其中 **263 个是"孤立能力"**（既没暴露、也没被别处调用）✓

⇒ ★ 后果：**模型看不到它们**。★ 一个能跑、能读回、有官方依据的函数，只要没挂成 `ToolSpec`，
  ★ 对使用者就等于**不存在** —— ★ 这与"能力已经实现"是**两件事**（★ 挂柜台定则：
  「暴露成功 / 可运行 / 返回语义已验证」是**三件事**）✓

## 二、范围（★ 只做暴露，不做发明）

★ **做**：把**已实现且可调用**的公开能力补成声明式 `ToolSpec`；必要时加**薄 wrapper**（不改业务逻辑）。
★ **不做**：
  · ★ 不新写 COM 调用、不改既有实现语义
  · ★ 不为"凑数"暴露内部件（★ 见 §四 的排除判据）
  · ★ **不把"暴露成功"记成"能力已验证"**（★ 台账 `level` 不动，除非另有自有运行证据）
  · ★ 不碰需许可证 / 无官方签名来源 / 红线那几类（★ 见 `docs/union-coverage-matrix.md` 的「不做 + 原因」）

## 四、★ "该不该暴露"的判据（★ 本规格的核心判断，逐条写明）

★ **暴露 ✓** 当且仅当**五条全中**：
1. ★ 是**面向使用者的动作或读数**（不是内部管线件）
2. ★ **首参可注入**（`model` / `sw_app` / `study` —— 探针已标 `first_param_is_injectable`）
3. ★ **无裸坐标形参**（规则 3），或能改成**声明式选择**而不改语义
4. ★ **不与既有工具语义重复**（★ 需先查重名与近名 —— 同模块常已有 `*_report` 版）
5. ★ **给得出回读判据**（★ 优先 `*_report` 形态；★ 若只有裸 `create_*` 且踩已知事实 ⇒ 不暴露）

★ **不暴露 ✗** 的典型（★ 已在候选里识别的）：
- ★ `require_*` 前缀 ⇒ **前置守卫**（★ 例：`sw_mass_property.require_section_document`）
- ★ `get_*manager` / `get_extension` / `get_selection_manager` ⇒ **内部入口访问器**
- ★ 裸 `sw_surface.create_*_surface` ⇒ ★★ **踩已知事实 40**（`IModeler.Create*Surface` 返回值不可靠）
  ⇒ ★ 应改暴露 `sw_surface_features` 的 **`*_report`**（带回读判据）✓
- ★ 已被同义 `*_report` 覆盖的实现（★ 例：`insert_offset_surface` vs `insert_offset_surface_report`）

## 六、非目标（★ 明确写清，防"越做越大"）
