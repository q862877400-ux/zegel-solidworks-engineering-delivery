# 规格 210 · 施工计划

> ★ 每批给出：**做什么 · 落点 · 判据（可跑的命令或可读的回读）· 风险与回退**。
> ★ 顺序按外部评审给的优先级：**先动"声明"，因为它同时服务另外两件**。

## B1 · 效应声明的静态版（先做，因为它是另外两件的地基）

**做什么**：给 448 个工具补上机器可读的**效应声明**，五项：

1. `writes`：**可能改**哪几类状态 —— 类别固定七类：**文档内容 · 文件系统 · 选区 · 激活文档 ·
   编辑态 · 视图 · 重建或解析**（评审给的分类）。
2. `requires`：**依赖**哪几类状态（前置）。
3. `idempotent`：三态（**未声明 / 是 / 否**），并记**来源**（`static` / `observed` / `human`）。
4. `destructive`：三态，★ 与"写"**分开**（破坏性 = 删除、覆盖保存、清空）。
5. `read_only`：★ **从 `writes` 派生**，不再是一个独立手填的布尔
   （"纯读" = 前两类为空）—— ★ 这条直接修掉"76 个只读工具被记成非只读"的根因。

**怎么做**（机械初判，不人工逐条填）：
- 来源一：**底层成员动词**（取/查 判读；建/插/加/设/删 判写）—— ★ 评审说这是**高可信的保守规则**。
- 来源二：**官方类型库的读写标记**（`propget` / `propput`）——
  ★ 但评审提醒：**普通方法没有读写标记**，所以对方法仍只能靠名字，**别指望它比动词强**。
- ★ **两个来源有任何一个说"写"，就不许标只读**（保守方向本来就安全）。

**落点**：能力层不动；工具层加字段与派生逻辑；★ 分析脚本进 `tools/`。

**判据（先只读、后改声明，两步分开）**：
- 第 1 步（只读）：产出一份**初判报告** —— 448 个工具各自的 `writes` 提案 + 覆盖率
  （★ 有多少工具能判、多少判不出）+ **`requires` 的签名种类**（预期仍是**几十种**量级）。
- 第 2 步（改声明）：把结论写进声明；★ 单一值安全字段门禁必须**零命中**；
  ★ `read_only` 由 `writes` 派生后，**只读工具数应显著多于现在的 23 个**。

**风险与回退**：★ 初判可能把"读"判成"写"（★ 那只是保守，安全）；★ 但**绝不能反过来**。
⇒ 回退：一次提交只改声明字段，`git revert` 即可。

## B2 · 指纹与灵敏度校准

**做什么**：定义**状态指纹**（一组廉价读数）：选区计数 · 编辑态 · 文档修改标志 · 特征数 ·
体数 · 面数 · 显示状态 · 活动配置 · 重建状态。
★ 然后做**灵敏度测试**：为每一类状态挑一个**已知会改它**的写工具，指纹**必须**检测到变化；
★ 检测不到的类别 ⇒ **补进指纹**，或**明写"这类写入当前不可见"**（不许默认它没问题）。

**判据**：每一类状态都有灵敏度证据或明确的"不可见"记录 ⇒ 指纹这个"量具"被校准过。
★ 这与本仓"回读的量具要校准"是同一个思路。

**风险**：★ 指纹读本身可能有副作用（如解析轻量化组件）⇒ ★ 指纹的每个读数都要先在合成件上
确认它**只读**。

## B3 · 存活普查（448 个）

**做什么**：按**前置签名分组**（★ 26 种，已实测），每组**只建一次状态**，把组内的只读工具连着调完；
会改模型的工具之间用**副本重载**隔开。每次调用**前后抓指纹**，差分与声明比对。

**输出**：★ **"声明 vs 观察"差异表**，四类 —— 声明与观察一致 / 声明保守（说写其实没写）/
★ **声明漏报（说读其实写了）** / 未判定（前置没备成，★ 单列第三态，不算通过也不算失败）。

**判据**：448 个工具**至少跑过一次**；★ 且"声明只读却观察到指纹变化"的条目 **= 0**（或逐条定性）。

**风险**：★ 真机昂贵、要独占机器 ⇒ ★ **按前缀分组省时间就是这一批的全部意义**；
★ 且必须先有 **B5 的预检门禁**（否则会在用户会话里跑）。

## B4 · 自动重试与"不适用"

**做什么**：
1. 结构化"不适用"码集（**6–8 个**，封闭小集合）：无活动文档 / 文档类型不对 / 缺少某类选区 /
   编辑态不对 / 参数无效 / 本版本不支持 / **不是这个工具**（附更合适的）。
   ★ 预检由**共享装饰器按声明的 `requires` 自动生成**，作者不手写。
2. 编排层只做"**代码 → 动作**"映射：能自动满足的前置就调构造器工具；参数错让模型改；选错就重选。
   ★ **编排层不许有任何工具专属知识**。
3. 自动重试**开启条件**：静态不判写 **且** 观察无指纹变化，**两者一致**；不一致进人工复核，**不用多数决**。
4. ★ **运行时保险**：重试前先比对指纹 —— 没变才重试；变了**不重试**，先对账。

**判据**：★ 存在一个测试证明"静态与实证不一致时不开启重试"；★ 并有一个测试证明
"指纹变了就不重试"（用假指纹注入即可，不必真机）。

## B5 · 隔离与预检（我方施工，方向已定）

**做什么**（评审已给全套做法）：
1. **`copy-in / run / copy-out`**：所有会打开文档的入口**只接受沙盒内路径**（外部路径自动复制进来再用副本），
   跑完由我们把结果拷到**配置的输出根目录**（带 run id 防重名）。
2. **预检门禁**：开始前枚举已打开文档，★ **有不是我方打开的就拒绝开始**；★ 且要在**启动 SolidWorks 之前
   先问一次、连上之后再问一次**。
3. **"文档分类 + 未保存检查"提成共用助手**：现在这套逻辑在回收脚本里，护栏**没有复用**（★ 本仓反复吃过的亏）。
4. ★ **输出根目录独立配置**：产品模式（用户让智能体改他的模型）下，**分析类产物进一个明确命名的子目录**，
   ★ 并在**工具返回值里报出实际路径**，不再静默落在零件旁边（★ 业主已拍板选这条）。
5. **夹具一次性快照 + 哈希清单**：真实件一次性复制到测试专用夹具库、冻结哈希；★ 此后测试**不再引用原目录**。

**判据**：★ 一条可跑的命令证明"给定沙盒外路径会被复制进来而不是被打开"；
★ 一条测试证明"预检门禁在检测到非我方文档时拒绝开始"。
