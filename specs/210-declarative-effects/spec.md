# 规格 210 · 声明式效应与存活普查

> ★ 立项：2026-10-06。★ 来源：外部评审对「三件真正卡住的事」的判决（见 `docs/reports/` 下的答复文档）。
> ★ 本规格**不发明新能力**，只把"怎么验证 448 个工具、怎么兜底、怎么验证建模"这三条落成机器。

## 一、要解决什么（三条，按评审给的优先级）

**① 448 个工具无法一个一个真机验。** 现在每条能力的真机验证都是人手设计的一次性脚本（590 个），
各自配夹具与判据；真机要独占一台机器；很多工具需要前置。★ 评审的判决：
**成本主项是"建立前置状态"，不是调用本身** ⇒ ★ 按前置签名分组、每组只建一次状态，耗时随
**"不同前置的数量"**增长，不随工具数增长。★ 我已实测：**前置签名只有 26 种**（宿主对象 × 只读 × 幂等），
所以这条路成立。

**② 选错工具之后没有兜底。** 我们把力气全花在"让它第一次选对"，**没有设计"选错之后怎么办"**。
★ 评审的判决：兜底**分三层**（工具层只声明"我不适用"· 编排层只做"代码→动作"映射 · 模型侧只处理
"需求理解错"）；**回退与重选正交**（只有真改了模型才需要回退）；★ 并要一道
**独立于标签的运行时保险**：重试前先比对状态指纹。

**③ 建模的"思路"从哪来，以及怎么验证"建得对"。** ★ 评审修正了我的前提：
"不在预训练里"说得太满 —— 通用启发式很可能在里面，**缺的是三件**：落到我们这套工具词汇上、
为具体零件选策略、对结果做质量判断。★ 判决：**把"建模计划"做成中间表示，与执行分开**；
顺序优劣用**字典序**（硬闸门 → 扰动重建稳健性 → 引用脆弱度 → 简约度 → 重建耗时 → 意图对齐）。

## 二、本规格做什么

★ **第 0 件（已完成，2026-10-06）**：把两个对外**误报**修掉 —— `idempotent` 与 `destructive`
改成**三态**、未知就不发注解；加"单值安全字段"门禁 + 负例测试。★ 提交 `26fd977`。
⇒ 证据：注解里 `idempotentHint` **一条都不发**；`destructiveHint` 只对 23 个只读工具明说 `False`。

★ **本规格的四个批次**（详见 `plan.md`）：

- **B1 · 效应声明的静态版**：给 448 个工具补上**机器可读**的 `writes`（改哪些状态类别）与
  `requires`（依赖哪些状态类别），★ 且**机械初判、不人工逐条填**（底层成员动词 + 官方类型库的读写标记）。
  ★ "重算 `idempotent`/`read_only`"**并进这一批**（评审：这两件事合成一件做）。
- **B2 · 指纹与灵敏度校准**：定义状态指纹，并做**灵敏度测试** —— 每个状态类别挑一个已知会改它的写工具，
  指纹**必须**检测到；检测不到的类别，补进指纹，或**明写"这类写入当前不可见"**。
- **B3 · 存活普查（448 个）**：按前置签名分组、只建一次状态、组内连续调用、写工具之间用副本重载隔开；
  每次调用前后抓指纹差分；输出 **"声明 vs 观察"差异表**。
- **B4 · 自动重试与"不适用"**：静态提案 ∩ 运行实证**一致**才开自动重试；结构化"不适用"码集（6–8 个）；
  重试前比对指纹的运行时保险。
- **B5 · 隔离与预检（我方自己的施工，评审已定方向）**：`copy-in / run / copy-out`、
  预检门禁（有非我方文档就拒绝开始）、"文档分类 + 未保存检查"提成共用助手、
  **输出根目录独立配置**（产品模式走明确命名的子目录，并在返回值里报路径）。

## 三、本规格**不做**什么

- ★ **不碰几何正确性判据**（那是 B3 之后的事，读侧已有回读体系）。
- ★ **不做建模计划中间表示**（评审的第三条）—— 它是独立一块，**不在本规格**，
  避免本规格同时改验证体系与生成体系。
- ★ **不动上游文件**（`mcp-server/server.py` 里那份硬编码注解块属上游）。
- ★ **不为了"看起来完整"而补能力**（这一条是本仓一以贯之的纪律）。

## 四、硬约束（沿用本仓既有纪律，逐条**不许违背**）

1. **判据一律回读**，不看被调成员的返回值。
2. **"选不上"与"选了也没用"分开记**（前置未备成 ≠ 能力无效）。
3. **未知不冒充已知**：三态字段里"未声明"就是未声明；注解里**未知不发**（依赖 MCP 缺省语义）。
4. **不给不存在的语义造词**：声明字段只表达我们真能观测的东西。
5. **真机一律走弹窗护栏**；★ 且按评审的新要求：**开始前先做预检**（有非我方文档就拒绝）。
6. **不许把"一个实例"推广成"一族"**（评审指出的"结论强度超标"）：
   ★ 全称断言必须带**同等数量的运行记录**。
7. **事实 53**：同一启发式连续修补 ≥3 次就停；★ 但"**定性为墙**"是另一个动作，要过评审给的清单。
8. **只读优先**：B1/B2 的机械初判**先只产出报告、不改声明**；改动单独提交、可回退。

## 五、验收判据（本规格的"完成"是什么）

- **B1 完成**：448 个工具里，★ **每个都有一个 `writes` 结论**，且该结论标明了**来源**
  （`static` / `observed` / `human`）；★ 并有一份**单一值字段门禁**守着（安全字段不许被默认值填满）。
- **B2 完成**：★ 每一类状态都有**灵敏度证据**（或明确记录"不可见"）—— 即指纹这个"量具"被校准过。
- **B3 完成**：★ 448 个工具**至少跑过一次存活调用**，产出"声明 vs 观察"差异表；
  ★ 且"声明只读却观察到指纹变化"的条目 **= 0**（或逐条定性）。
- **B4 完成**：自动重试**只在静态与实证一致时**开启；★ 且有一道"重试前比对指纹"的保险。
- **B5 完成**：★ 真机跑**不可能写到用户目录**（`copy-in/copy-out` + 预检门禁 + 输出根目录独立配置三者齐）。

★ 另：**每批的完成都必须带一条可跑的命令**（本仓纪律：验收必须是可跑的命令，"我检查过了"不算）。
