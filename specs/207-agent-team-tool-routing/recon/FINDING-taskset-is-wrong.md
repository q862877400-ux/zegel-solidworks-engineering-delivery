## 四、⇒ 病根：**任务集选错了**

★ 我的任务取自官方示例的 `## Description`，逐字样例：
> `This example shows how to access edges on a rip feature.`

★★ **这是【API 用法演示】，不是【用户请求】。**
它描述的是「某个 API 成员怎么用」，而**不是**「用户想完成的一件建模工作」。

⇒ ★★ 于是：
* 很多这样的"任务"**在我们的工具面里本来就没有对应工具** ⇒ 模型**正确地弃权**
* 剩下能对上的，也常是**API 成员级**的细活，而我们的工具是**任务级**的（一个工具包几个成员）
⇒ ★★★ **`15.7%` 量的是「官方示例的 API 用法描述能不能在我们的工具面里找到对应」——
不是「用户的建模请求能不能找到对的工具」。★ 后者才是我们要的量。**

## 五、★ 顺带给出一条**有效**的证据

★ 与 pick-test（85.4%）的差异现在**有了更可能的解释**，且**可检验**：

| 维度 | pick-test | 本规格 |
|---|---|---|
| 任务来源 | ★ **人写的、面向用户意图**（「查实体数量和是否已算过成本」） | ★ **官方示例的 API 用法描述（英文）** |
| 呈现 | ★ **真实的 DSH 工具列表**（`mcp__solidworks__*`） | ★ **提示词里的文本清单** |
| 结果 | 85.4% | 15.7% |

★ **两个维度都不同 ⇒ 不能归因。** 下一步必须**只变一个**。
