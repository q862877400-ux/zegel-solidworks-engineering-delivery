## 一 · 口径（★ 先说清量的是什么，否则数字没有意义）

**口径 = 能操作 SolidWorks 的「功能」数** —— 不是工具名数，也不是 API 成员数。

清单共 **145** 项，按 SOLIDWORKS 用户的 CommandManager 心智模型组织
（画直线 / 画圆 / 拉伸 / 切除 / 拔模…这种粒度），分 11 个域。

⚠ **本表只量第一列**。三列要分开看，**不可互相替代**：

| 列 | 问的是 | 本表有吗 |
|---|---|---|
| ① **有入口** | 有没有这么个工具/名字 | ★ **本表量的是这个** |
| ② **能建成** | 真跑一次，特征树真的长了吗 | ❌ 见 §五 |
| ③ **真机验过** | 有没有留下我们自己的运行证据 | ❌ 见 `capabilities.yaml` 的 `level` |

★ 这与 `docs/metrics.md` 的纪律②一致：「任何『覆盖广 / 全覆盖』的说法，**必须带那个真机数**」。

## 二 · 方法（★ 与它的已知局限）

```
① 本仓库侧：`register_capabilities.all_specs()` 的 name ∪ `server.py` 的 name= 抽名
② 四家侧：  `tools/union-sources.json` 的 sources[].tools

⚠★ **关键词匹配必然会误配。** 本脚本的 3 处假阳性是**逐条看过命中项**后人工判定的；
**残余误差估计在 ±5% 量级**，不足以改变 §三 的结论（差距都在 10 个百分点以上）。

⚠ 更重要的是：**它量不到「能不能用」**（§一 的第②列）。四家在这一点上完全空白；
本仓库有 `capabilities.yaml` 的 `level` 可以回答，但**本表没把它算进覆盖率**。

## 六 · 人工剔除的假阳性（★ 每条写明依据）

| 域 / 功能 | 为什么不算 |
|---|---|
| 特征 / 缩放/变形 | 命中的是 `drawing_set_sheet_scale`（**工程图比例**），不是实体缩放。本仓库**没有**实体缩放/变形。 |
| 钣金 / 展开/折叠 | 命中的是 `weldment_create_sub_weld_folder`（子焊件**文件夹**里的 'fold'），不是钣金展开。本仓库的展开 DXF **已回退注册**。 |
| 焊件 / 角撑板（焊件） | 命中的是 `sheet_metal_create_gusset`（**钣金** gusset）。照已知事实 36，钣金与焊件的 gusset 是**两个不同接口**，不可互认。 |

另有两项是**能力面有、工具面没有**（两列并存，不合并）：

| 域 / 功能 | 说明 |
|---|---|
| 曲面 / 旋转曲面 | 能力 `surface_revolve` 是 `verified`，但**未暴露成 MCP 工具**（`scripts/sw_surface.py` 的 `create_revolution_surface`）。 |

**三条纪律**（防这份文件自己腐坏）：

| 纪律 | 为什么 |
|---|---|
| **WIP = 1** | 同时只允许一个阶段是 🟡。多开就没人知道该恢复哪个 |
