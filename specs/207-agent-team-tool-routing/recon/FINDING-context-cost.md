# ★★★ 上下文成本：真正的短板在【成本】，不在【准确率】

> 起因：用户 2026-10-05 问「p(414) 的话，那 lead 的上下文长度岂不是要爆炸？」
> ★ **这个问题把两件被混淆的事分开了** —— 本文件给出实测答案。
> ⚠ 不含行号。

## 一、实测：一个 picker 会话的完整用量

会话 `3ffc9631-…`（已确认是真 picker）· **510 个工具** · ★ **工具定义 JSON = 715,004 字节**

| 字段 | min | max |
|---|---|---|
| ★★ **`cacheReadTokens`** | **196,608** | **291,456** |
| `cacheWriteTokens` | 0 | 0 |
| ★ **`inputTokens`**（新鲜） | **138** | **19,372** |
| `outputTokens` | 57 | 14,445 |
| ★★ **`totalTokens`** | 216,047 | ★ **293,714** |

## 二、⇒ 直接回答

### 2.1 ★ 「会不会爆炸」—— **不会炸到不可用，因为工具定义那一大块被【缓存】了**

* ★★ 每次调用有 **~20–29 万 token 是从缓存读的**，而**新鲜 input 只有 138–19,372 token**
* ⇒ ★ **那 414–510 个工具的定义是一个【被缓存的前缀】**，不是每轮重新付全额

### 2.2 ★★ 但代价是真实的，而且比我先前说的**大 5.7 倍**

| 我先前引用的 | ★ 实测 |
|---|---|
| 「全部 schema 的 doc 合计约 **12.5 万字符**」 | ★★ **工具定义 JSON = 715,004 字节**（含 `name`+`description`+**`parameters`**）<br>⇒ ★ **12.5 万只是 doc 字符串，不含 schema** ⇒ **先前低估 5.7 倍** |
| 「每轮常驻」 | ★ **是"每轮缓存读 ~20–29 万 token"** —— ★ **缓存读不是免费的**（通常按输入价 ~10% 计），且**有 TTL，冷掉就要重付** |
| — | ★★ **`totalTokens` 峰值 293,714** ⇒ **那是真的占在上下文窗口里** |

## 三、★★★ 这彻底改变了"架构要不要做"的问题形状

| 轴 | 现状 | 结论 |
|---|---|---|
| ★ **准确率** | `p(414) = 85%`（池已核验） | ★★ **不需要为它做架构** |
| ★★ **每轮成本** | ~20–29 万 token 缓存读 + ~1–2 万新鲜 | ★★ **这才是真问题** |
| ★★ **上下文窗口占用** | 峰值 **293,714** token | ★★ **也是真问题** |

⇒ ★★★ **那套「护士」架构如果还有价值，价值在【省 token / 省窗口】，不在【提高准确率】。**

### 3.1 ★★ 而且它让"热集"这个想法从可选变成**正解**

用户先前提的「**热集内联 + 长尾丢给护士**」现在目标明确了：
* ★ 它直接砍掉**常驻工具块**（bytes/tokens）—— 正是坏掉的那条轴
* ★ 而且**不伤准确率**（热集覆盖多数任务；实测**前 10 个域覆盖 83% 的任务**）
⇒ ★★ **它同时打中"成本"且不碰"准确率"。**

### 3.2 ★★★ 也顺带把 `dsh-mcp-lens` 的位置摆正了

| | 常驻成本 | 检索准确率 |
|---|---|---|
| **全暴露（现状）** | ★ **715 KB / 每轮 20–29 万 token 缓存读** | ★ **好（85%）** |
| **Lens** | ★ **1,114 B** | ★★ **差（Recall@5 = 0.25，Hit@5 = 0.36）** |

⇒ ★★★ **Lens 是拿"本来就好"的那条轴去换"坏掉"的那条轴，而且在好的那条上损失巨大。**
⇒ ★ **对我们的情形，"砍常驻 + 保准确率"的热集混合严格优于 Lens。**

## 四、⚠ 本文件的限度

* ⚠ **只详查了 1 个 picker 会话的完整 usage**（另有 1 个会话只看到首条）⇒ ★ **n=1，需多会话复核**
* ⚠ **`cacheWriteTokens = 0`** 全程为 0 —— ★ **原因未查明**（可能是缓存由别的请求写入、或该字段不报）
* ⚠ **`maxTokens: 256000` 是【输出上限】还是【窗口】** —— ★ **未确认**；
  而 `totalTokens` 峰值 **293,714 > 256,000** ⇒ ★ **这本身就说明 256000 不是窗口上限**（但仍需查清窗口到底多大）
* ⚠ **缓存计价**（~10% 输入价）是**行业惯例，不是我实测** ⇒ ★ **本文件没有算钱**
* ⚠ **另一条线（规格 205）曾测到 `request/header.tools` 647,962 B → 27,401 B** ——
  ★ 那是**拍字节**，而本文件说的是**token 与缓存**；★ **两者不是同一个量，不许并列引用**
