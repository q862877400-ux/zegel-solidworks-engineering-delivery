## 二、**实测记录**（本节才是价值所在）

### 2.1 ★ 门禁的"有牙齿"用的**真实缺陷**，不是为测试造的样本
```
修复前: [FAIL] **1/1** 处「造负例输入」的变换**没有自证**：── probe_skip_semantics.py  L96
修复后: [PASS] 1 处「造负例输入」的变换**全部自证**（比对/字节数/断言）
```
★ 这与本项目已知事实 62 记的手法同源（**用 `git show <修复前>:<path>` 取真实原文当负例**），
只是这次**不必回 git**：那个缺陷**当时就在工作树上**（我在同一轮里发现并修）。

### 2.2 那处**碰巧是对的**，但**没有自证**
实测变换**确实生效**：
```
变换生效吗: **是**（内容变了）   41954 -> 41897 字节
变换后的那行: > 偏离上游： · 工作区 clean
```
⇒ 它当前**没有产生假用例**；但**它没有任何东西阻止它变成假用例** ——
正则一改、报告格式一调，就会**静默**退回「坏输入 == 真输入 ⇒ 用例空转 ⇒ 显示通过」。
⇒ 修法：**先算 → `assert new != old` → 再写 → 打印前后字节数**（现在输出带「自证 ✓」）。

### 2.3 ⚠⚠ 本轮**未覆盖**：`tests/` 下的用例**没扫**
本门禁只扫 `tools/*.py` —— 因为**轮 84 那个假用例发生在探针里**。
⚠ 而 `tests/`（**970 个通过**）里是否也有「变换没生效」型假用例，**本轮未扫、未查**。
⇒ 按铁律 5 **如实记录**，作下轮候选。**不因为"扫了 tools 就算普查完了"**。

### 2.4 ⚠ 类型 2/3/4 **明确不判**（且门禁自己声明）
| 类型 | 是否能判 | 本轮处置 |
|---|---|---|
| 1 · 变换没生效 | ✅ 判了 | 写成门禁 |
| 2 · 坏的理由不对 | ❌ 需语义 | **不假装**；门禁在 `[PASS]` 时**也打印**这条声明 |
| 3 · 负例与正例结果相同 | ❌ 需语义 | 同上 |
| 4 · 断言打在恒定字段 | ❌ 需语义 | 同上 |

★ **门禁主动声明自己的覆盖面** —— 否则「有 15 道门禁」会让人以为"假用例这事儿已经防住了"，
而那正是本项目反复记录的**「一个门禁写了不等于有效/覆盖不全反而有害」**（已知事实 62 + 第 40 轮教训）。

### 2.5 ✓ 普查的**实际规模**（不夸大）

其中含「造负例输入」特征   8 个

### 2.6 ⚠ 验收命令门禁的**又一处局限**（本轮撞到，**未修，如实记录**）
我在 `tasks.md` 里先写了一条验收判据：**「验证 `tools/audit_negative_input_selfproof.py` 已移除」**
（用 `Test-Path …`，期望结果为 `False`）—— 那是**合法**的验收判据，
而 `check_spec_acceptance_paths` **只认"文件存在"**
⇒ 把那个路径报成 `[missing-in-repo] …仓库里没有这个文件`。

⇒ 本轮处置：**改写为仓库内可达的等价命令**（`python scripts/check_negative_input_selfproof.py`，
它扫的就是 `tools/`，副本移除后仍 `[PASS]`）。

⚠ **但该局限仍在**：门禁**无法表达"期望某物不存在"**。

但这一类（**否定式验收判据**）需要**解析语义**才能判 —— **本轮不修**，按铁律 5 记录。
