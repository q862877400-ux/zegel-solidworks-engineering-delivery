# 056 · 死守卫的**第三种形态**：登记了却没接上 —— 本轮**零发现**，但拿到了一条分界线

**Status**: Implemented（轮 137）

## 一、三种形态，到此扫全
```
常量形态（053/054）：`_LEN_SUFFIX` · `_ANGLE_SUFFIX` —— 规则 2 的两半，都定义了却没人用
函数形态（055）    ：`match_modules` —— 被 `stems_only()` 取代后一直留着
注册形态（本轮）    ：**登记表 / 解析器 / 批次清单** —— 有没有"登记了却没接上"
```

## 二、★ 结果：**零发现**（这是好消息）
| 方向 | 结果 |
|---|---|
| 磁盘上的 `tool_specs_batch*.py` **没登记进 `BATCH_MODULES`** | **0**（10 个全登记）|
| 登记了、**文件却不在** | **0** |
| 批次 `SPECS_*` 声明的工具**没进 `all_specs()`** | **0**（41 条全在）|
| 用了某个 `inject` 名却**没有解析器** | **0** |
| 登记了 `RESOLVERS` 却**没人用** | **0**（`model` 31 · `sw_app` 6 · `study` 1）|

⇒ ★ **接线是一致的。**
### ⚑ 零发现也要说清扫了什么、没扫什么
* **扫了**：三个方向 + 双向；
* ⚠ **没扫**：`server.py` 的 dispatch 表本身 · `sw_api_*.py` 名字登记表 · `subskills/` 清单。

## 三、★★ 为什么这一种可以当**回归**，前两种不行
```
名称/语义类（052/054）：假阳性 50%~100% ⇒ **只出清单、人工判**
结构类（本轮）        ：**集合比对** —— 磁盘文件 vs 清单项、用的名字 vs 解析器
⇒ ★ 结构类**没有"解释空间"**：一个文件要么在清单里、要么不在。
```

## 四、★★★ 本轮最值钱的一条：**「能不能被故障注入验证」就是那条分界线**
```
① 基线                                  : exit=0 · 5 passed
② **造故障**（放一个没登记的假批次文件）  : exit=1 · **1 failed** ⇒ 判据确实会红（事实 62）
③ 复原（删掉假文件）                     : exit=0 · 5 passed
```
⚠ **名称/语义类判据做不到这一步** ——
要"注入一个假故障"，**先得说清"什么叫错"**，而那正是它判不了的东西。
⇒ ★★ **能注入的是结构判据，不能注入的是语义判据。**

## 五、判据
| ID | 判据 |
