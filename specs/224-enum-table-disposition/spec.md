# Spec — 枚举表盲区收口：表级出处声明 + 转储成员前缀放宽

**Feature**: `specs/224-enum-table-disposition/`
**日期**: 2026-10-09
**上游**: `specs/223-enum-fabrication-and-gate-boundaries/`（把 44 张「自称官方却无标注」的表**变可见**）
**本轮只做一件事**：把「可见」升级为「**已受检 / 已表态**」，并让「未表态」从**静默**变成**红**。

## 一、问题（223 留下的口子，逐条实测）

223 让门禁**打印**了「自称官方却无 `# swXxx` 标注」的模块级整数表（44 张），
但**退出码不变** —— 它的定位是「要的是可见，不是判罪」。⇒ 留下的口子是：

> **一张表可以不表态，而门禁照样绿。** 44 张里有多少是**真的官方枚举**、有多少**根本不是枚举**，
> 没有任何机器可查的记录；下一个人（或下一轮）仍要重新人肉判一遍。

本轮先量了一次（**这是本 spec 的事实基线**）：

| 读数 | 值 | 怎么量出来的 |
|---|---|---|
| 模块级整数表 | **101** 张 | `find_int_tables()` |
| 已被「值 + `# swXxx`」覆盖 | **33** 张 | `parse_code()` 行落在表内 |
| 未覆盖 | **68** 张 | 101 − 33 |
| 其中**自称官方**（门禁盲区） | **44** 张 | `find_uncovered_claimed_tables()` |
| 44 张的条目总数 | **409** 条 | AST 逐表取值 |
| 其中**键就是官方成员名**的条目 | **27** 条（= 26 + 1，几乎全在 `ANNOTATION_TYPE_BITS`） | 键 ∈ 转储成员集 |

★★ **这 27/409 是本轮最重要的一个数**：它说明**「逐行补 `# swXxx`」对 42 张表是错的解法** ——
那些表的键是**本地语义键**（`"edge": 1` / `"solved": 1`），官方成员名**不在键里**，
硬补注释只能靠人把「本地键 ↔ 官方成员」一一对上，**成本极高且极易写错**（正是 223 抓的那类「冒官方名」）。
它们真正的出处是**表级**的：表上面那行注释写着 `#: ★ 官方 swViewEntityType_e`。

⇒ **本轮的正确解法是承认「表级出处」是一种合法的出处形态**，并让它**机器可查**。

### 1.1 顺带量出的第二个口子（反射转储自己读漏了）

`swsTopologyIterationOption_e` / `swsTopologyPreservedRegionOption_e` 这两节，
**在转储里明明有成员**，但门禁读成**空**：

```
## swsTopologyIterationOption_e
  IterationOption_Auto = 0          ← 成员名不带 `sw` 前缀
  IterationOption_UserDef = 1
## swsTopologyPreservedRegionOption_e
  PreservedRegion_LoadsOnly = 0     ← 同上
```

根因：`DUMP_ROW` 的成员名是 `(?P<member>sw\w+)` —— **只认 `sw` 开头** ⇒
**整节被读成空** ⇒ 门禁对它们一律回「查不到」。
⇒ 这是**同一个病**（边界外的数据静默漏过），只是这次漏在**转储解析**侧。

## 二、需求（每条带来源与许可）

> 许可：全部为本仓库自身产物（MIT），**无第三方代码引入**；来源三源为
> `C:\swapi`（官方 API 页）、`_raw/reflect/*`（出厂反射转储）、`_raw` 解包产物。

### FR-001 反射转储成员前缀放宽
`DUMP_ROW` 的成员名从 `sw\w+` **放宽到** `[A-Za-z_]\w*`（仍在 `## <Enum>` 节内、仍要求缩进 ≥ 2 与 `= <int>`）。
- **来源**：`_raw/reflect/enum_cosworks.txt` 第 2707–2721 行（实测成员名 `IterationOption_Auto` / `PreservedRegion_LoadsOnly` 无 `sw` 前缀）。
- **为什么是「放宽」而不是「特例」**：`## <Enum>` 节内的 `名字 = 整数` **就是**成员定义，前缀是**命名习惯**不是语法。
- **实测影响**（本轮量过，写进 acceptance）：成员 **10588 → 10664（+76）**，
  `ok` **175 不变** · 值不符 **0 不变** · 查不到 **2 不变** · 两源冲突 **3 不变** ⇒ **不制造任何新红**。

### FR-002 表级出处声明（新形态）
在模块级整数表**紧邻上方**引入一行声明：

```python
#: enum-gate: <code> <arg>
```

**三种 code（封闭词表，认不出即 FAIL）**：

| code | 语义 | 门禁怎么校验 |
|---|---|---|
| `enum <swXxx_e>` | 表里的**值是**命名官方枚举 `swXxx_e` 的取值 | ① 该枚举须能在**反射转储**里解析到（解析不到 ⇒ FAIL）② 表内**每个值 ∈ 该枚举的取值集**（否则 FAIL） |
| `member <MemberName>` | 值来自**该官方成员的页内文档**（`## Parameters` / `## Remarks` / 官方示例），官方**没有**命名枚举 | 该成员名须在 `C:\swapi\types\*\` 下**有页**（拿不到 `C:\swapi` ⇒ SKIP，不判罪） |
| `not-enum <sub>` | **不是**官方枚举值 | `sub` 须 ∈ `{arity, index, mark, derived, observed}`（否则 FAIL） |

- **来源**：44 张表**每张上方本来就有**一行表级出处注释（如 `#: ★ 官方 swViewEntityType_e`）—— 本 FR 是把它**形式化**，不是发明新概念。
- **归属规则（必须无歧义）**：声明只属于**紧邻其下**的那张表 —— 从表起始行的**上一行**向上扫
  **连续的注释/空行块**，取该块里**最后一条** `#: enum-gate:`；块里没有则再看表体行内（`[lo, hi]`）的第一条。
- **为什么只认「最后一条」**：`scripts/sw_ref_geometry.py` 里相邻表的注释块**会连成一片**
  （`REF_POINT_ALONG_CURVE_TYPES` 的注释块与 `GLOBAL_BBOX_FIT_OPTIONS` 的相邻）⇒
  取「块里第一条」会把声明错配给上一张表。**本轮已按「插在表起始行正上方」落地**，该规则下归属唯一。

### FR-003 未表态即红（本轮的实质）
自称官方（`CLAIM` 命中）且无 `# swXxx` 覆盖的模块级整数表：
- **有**表级声明 ⇒ 计入「已表态」，逐张打印 `code + arg`；
- **无**表级声明 ⇒ 计入「未表态」，**逐个打印，并 `exit 1`**。

- **为什么这次要判红**：223 的「只可见不判罪」在本轮已**被消费完** ——
  44 张全部表态后，剩下的「未表态」**只可能是新写的表**。
  那时**静默通过**才是错的：一张新表自称官方却不表态，正是 223 那张伪造表的**复发形态**。
- **判据是「表态存在」而不是「值对」** ⇒ 与 `not-enum` 类**不冲突**（`not-enum` 本身就是一种表态）。

### FR-004 44 张盲区表逐张表态
按下面的分类表落地（**分类是逐张读源码 + 三源核对得出的**，不是批量套模板）：

| 分类 | 张数 | 判据依据 |

**`enum` 分类里有两处必须写清楚的裁决**：
1. `sw_sketch_relations.RELATION_TYPES` → `enum swConstraintType_e`。
   ★ 键**不是**官方成员名（`"COINCIDENT"` vs `swConstraintType_COINCIDENT`），
   故只能做**值集包含**校验，**不能**做键名校验 —— 这一点在声明行下方的注释里写明。
2. `sw_topology` 的四条 `sws*` 枚举 → 依赖 FR-001 才解析得到
   （`swsTopologyStudyGoalType_e` / `swsTopologyStudyMassConstraintOption_e` / `swsTopologyIterationOption_e` / `swsTopologyPreservedRegionOption_e`）。
   ★ 源码注释里写的 `swsTopologyGoalType_e` **少了 `Study`**（真名见 `enum_cosworks.txt:2908`）
   ⇒ 本轮的声明行**写真名**，并把订正写进注释。
