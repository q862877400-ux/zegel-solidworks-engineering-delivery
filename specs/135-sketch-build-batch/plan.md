## 二、★ 本特性**跳过了探针**这一步，理由要写清

```
W1/W2/W3 都是"先写真机探针再设计"，因为那些族的**取对象方式**是未知的。
★ 而本族的四个函数**已经在 W1/W2/W3 的证据脚本里真机跑过了**（每次都成功）：
   `sw_part.start_sketch` · `sketch_line` · `sketch_circle` · `end_sketch`
   —— W1 的 `capture_sketch_evidence.py` 就是这么建出「1 条线 + 1 个圆」的。
⇒ ★★ 所以**探针那一步已被既有证据覆盖**，不必重跑；本特性直接进设计。
★ 但**仍有未知**（不在"取对象"上，在**行为**上）⇒ 那些放进**证据脚本**里**如实记录、不断言**：
   · 不先 `start_sketch` 就画几何 ⇒ 会怎样？
   · 基准面名给错 ⇒ 会怎样？
```

## 三、单位（规则 2 的落地）

```
★ `sw_part` 的模块单位是**毫米**（既有事实 73，本机实测）⇒ 该模块里**不该**再调 `mm()`。
★ 四个函数的 docstring 都**明写**「单位: 毫米」⇒ 与事实 73 一致 ✓
⇒ ★ 本特性**不做换算**，只把参数名改成 `_mm`（规则 2 的命名要求），
  换算本就无需发生 —— 这比"先乘 1000 再除 1000"更安全。
```

## 四、分层落点

| 逻辑 | 落在哪 | 为什么 |
|---|---|---|
| 建草图 / 画几何 | ★ **复用 `scripts/sw_part.py` 既有函数**（不改） | 它们已真机跑过；★ 本特性只做"对外表面" |
| 工具声明 + **参数改名** | `mcp-server/tool_specs_batch21.py` | `param_alias` 把 `start_x_mm`→`x1` 等映射过去 —— ★ **能力层一行不改** |

★ **为什么用 `param_alias` 而不是改能力层的形参名**：
  改形参名会**动到既有调用点**（`sw_part` 被很多地方用）⇒ 风险大且与本特性无关。
  `param_alias` 正是为"对外名与对内名不同"设计的 ⇒ ★ **用对工具，不动无辜的代码**。

## 五、验证方式：**读写配对**（本阶段判据的延伸）

```
★ 只读批（W1）验证 = "读出来的数对不对"。
★ 本批是**写**批 ⇒ 验证 = **写完再用只读工具读回来断言**：
   建草图 → 画线/圆/矩形 → ★ **用 W1 已挂的 `solidworks_sketch_count_*` 回读**
⇒ ★★ **两批工具就此接上** —— 这比"写完之后截个图看看"强得多：
   断言是**数字**（1 / 1 / 5），可复跑、可进 CI。
```

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| ★ **不 start 就画几何是静默的**（实测） | 工具说明里**明写**必须先 `solidworks_sketch_start`；★ 目前**没有机器守卫** ⇒ 已写进 capability 的 `limitations`，**不假称有守卫** |
| 面名随 UI 语言变（事实 9） | 参数说明里**中英文都列出**；能力层既有实现已支持两种 |
| 画几何要给坐标 ⇒ 与规则 3 的字面冲突 | ★ 用**语义名 + `_mm`**，并在工具说明里**注明豁免依据**（见 spec 的四） |
| `sketch_rectangle` 与 `sketch_corner_rectangle` 语义重叠 | **只挂对角那个**（无歧义） |
| 参数改名写错 ⇒ `TypeError` 或静默改语义 | ★ 证据脚本里**逐条核 `param_alias`**（把每个声明的 `aliases` 记进证据）|

## 七、★ 门禁盲区（如实记，不在本特性修）

```
`_BARE_COORD_NAMES` **只查参数字面名** ⇒ 能力层的 `x1`/`y1`/`x2`/`y2` **溜过去了**。
★ 即：门禁"没拦住"**不是因为允许，而是因为它只看名字**（与事实 153 同族）。
⇒ ★ 本特性**不动门禁**（不为通过而放宽判据）；把盲区记进 known-facts，**留后续单独开特性**。
```
