## 二、★ 本特性补的是**最底层的短板**，而且它解释了此前一堆"挂着却用不了"的工具

```
★ 此前 MCP 里跟草图有关的**只有** `add_sketch_relation` + W1 那 4 个**只读** ⇒ 建不了草图。
★ 后果不只是"少几个工具"，而是：**已经挂出去的建模工具全都用不了** ——
    `revolve_boss`（batch17）· `create_hole_feature` · 钣金 `base_flange`（batch4）…
    它们都要一个「已存在的草图」。
⇒ ★★ 本仓库此前是「**会旋转、会打孔、会钣金，却连一条线都画不出来**」。
★ 这条是**核缺口本身**（照 W2/W3 的教训）连着掀三层才露出来的 —— 见 `spec.md` 的第二节。
```

## 三、★★ 本特性两个**方法上**的看点

```
① ★ **它跳过了"写真机探针"这一步 —— 而且理由要写清**：
   W1/W2/W3 都先写探针，因为那些族的**取对象方式**是未知的；
   而本族四个函数**已在 W1/W2/W3 的证据脚本里真机跑过**（每次都成功）
   ⇒ ★ 探针那一步**已被既有证据覆盖**，不必重跑。
   ★ 但**行为上的未知**仍在（不 start 就画线 / 坏面名）⇒ 放进证据脚本**如实记录、不断言**。
   ⇒ ★ 定则：**"要不要探针"本身是个判断，不是流程的固定一段**。

② ★ **能力层一行未改** —— 用 `param_alias` 做"对外语义名 → 对内形参名"的映射：
     `start_x_mm` → `x1` · `center_x_mm` → `cx` …
   ★ 为什么不去改能力层的形参名：那会**动到既有调用点**（`sw_part` 被很多地方用），
     风险与本特性无关 ⇒ ★ **用对工具，不动无辜的代码**。
```

## 四、★ 验证方式：**读写配对**（本阶段判据的延伸）

```
建草图 → 画线/圆/矩形 → ★ **用 W1 已挂的只读工具回读断言**：
   after_line      count_lines = **1**
   after_circle    count_arcs  = **1**
   after_rectangle count_lines = **5**   ← ★ 1 条线 + 矩形 4 条边
   after_end       count_lines = **5**   ← ★★ **草图关闭后仍读得到**（W1 的按名取路线）
⇒ ★★ 这比"写完之后看看截图"强得多：断言是**数字**，可复跑、可进 CI。
⇒ ★ 而且它让 **W1（只读）与本批（写）接上了** —— 这正是 A/B 配对判据的本意。
```

## 八、给下一批（W5 或"建特征"批）的可复用套路（增至 10 条）

```
① 先写真机探针答"对象怎么取" —— ★ 但**先判断要不要探针**（已有证据就别重跑）
② **先核缺口本身**（缺口名是名字级匹配）③ 能力落 scripts/，不改生成物
④ 证据走工具真实路径 ⑤ 证据必带负例 ⑥ 期望值本身也要被怀疑
⑦ 长文本进源码立刻 ast.parse ⑧ 判据用"行为"不用"类型"
⑨ 可用性看"封送形状"，不看"代数新旧"
⑩ ★ **对外名与对内名不同时，用 `param_alias`，别去改能力层的形参名**（不动无辜的代码）
```
