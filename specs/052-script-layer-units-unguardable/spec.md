# 052 · 给「脚本层的单位声明」装守卫 —— **试了，做不成，而且原理不成立**

**Status**: Implemented（轮 133）

## 一、起因（`051` 留的尾巴）
`051`（轮 132）实测发现 `sw_part.py` 的 **14 处** docstring 写「单位: 米」，实际是**毫米**。
★ 关键不是"写错了"，而是：**脚本层的单位声明没有任何机器约束** ——
工具层有规则 2（`_mm` 后缀 + `mm()` 换算）守着，**脚本层不受那条规则约束**。
⇒ 本轮去试：能不能给脚本层也装一个。

## 二、判法（**有界、可复核**）
```
① 显式的**长度词表**（radius / diameter / depth / thickness / distance / width /
   height / length / offset / spacing / pitch / cx cy cz / dx dy dz / x1 y1 z1 x2 y2 z2 / size）
② 公开函数的**形参名**命中词表 ⇒ 认为"带长度参数"
③ 源码里有没有**单位声明**（单位 / 毫米 / 米 / mm / meter …）
```
结果：**已声明 10 个 · 一处都没声明 4 个**。

## 三、★★ 那 4 个**逐条人工看** —— **4/4 全是假阳性**
| 模块 | 命中词 | 真相 |
|---|---|---|
| `sw_costing.set_lot_size(lot_size)` | `lot_size` | **批量大小**（件数）|
| `sw_jlcfa_gui.drag(x1,y1,x2,y2)` | `x1 y1 x2 y2` | **屏幕坐标** |
| `sw_jlcfa_gui.find_node(depth)` | `depth` | **树的深度** |
| `sw_jlcfa_select.crop_region(dx,dy,…)` | `dx dy` | **像素** |
| `sw_view.set_view_frame(width,height)` | `width height` | **窗口几何**（像素）|
| `sw_view.translate_view(dx,dy)` | `dx dy` | **像素** |

⇒ ★★ **假阳性率 4/4 = 100%**，比此前几次都高（`029` 26% / `032` 50% / `037` 59%）。

## 四、★★ 为什么这次是**根本做不成**（不是"假阳性多"）
```
`size` / `depth` / `width` / `dx` 在**非几何**语境里同样常用
⇒ ★ 「长度词表」**无法区分「几何长度」与「同名的非几何量」** —— 那是**语义**判断
⇒ 若把词表缩小到只认 radius/diameter，覆盖面就太小，**漏的比抓的多**
```
★ 这反过来解释了 `051` 那个错**为什么能活那么久**：
**不是没人管，而是"管不了"。**

## 五、处置
1. **不做成门禁**（假阳性 100%）；
2. 探针**保留**（`tools/probe_unit_declarations.py`）供**人工**扫；
3. ★ **探针源码里写明结论**（免得下一个人拿它当判据）；
4. ★ **真正的守卫是"实测"** —— `051` 能改对靠的是**真机量了一遍**（圆 → 边界框）。
