# 074 · 回读着 mark 计数把实体真的选上 —— 查到**卡点**，按纪律强停止

**Status**: Implemented（轮 155）· ⚠ **能力不升级**（但卡点已查明）

## 一、做法（沿用前几轮的纪律）
`073` 的结论：判「选上没有」**一律回读** `GetSelectedObjectCount2(<mark>)`（事实 94）。
⇒ 本轮**每一次选完都回读**，**只有计数对了才去调功能**。

## 二、★ 6 种选法（这一轮补齐了「草图实体」这一类）
```
① 草图**整体** × 2（**官方示例原样**，按名 + mark=1）        ⇒ False
② 实体**边** × 2（`Select4`，`(-1)`=2 但 **mark=0**）        ⇒ False
③ 实体边（**按点** + mark=1）⇒ `SelectByID2` 返回 True 但 `(1)`=**0**（事实 94）
④ ★ **草图段** × 2（`Select4`，**`(-1)`=2 回读确认**）        ⇒ False   ← 本轮新的
⑤ ★ 草图段（按名 + mark=1）⇒ **命中 0**
⑥ 按名选边 ⇒ 0（事实 32）
```

## 三、★★★ 卡点查明
```
`IEntity.Select4(Append, Callout)` **没有 mark 参数** ⇒ 选完 mark 仍是 **0**
而 `SelectByID2` 需要**名字**，可是 ——
★ 实测：**草图段的 `GetID` 返回的是端点对**（`'(0, 1)'` / `'(1, 2)'`），**不是** `Line1` 那样的名字
⇒ ★★ 边与草图段**都没有可用名字** ⇒ `SelectByID2` 那条路对它们**走不通**
⇒ ⇒ **「选中 2 个实体 + mark=1」这个官方前提，在这条后端上我没能同时满足。**
```

## 四、★★ 按**事实 53 强停止**
`53` 说「同一个启发式连续修补 ≥3 次就该停下」—— 本轮已 **6 种**。
⇒ ★ **候选解释一律列为未验证**，例如「该后端下 `InsertCompositeCurve` 结构性不可用」
（与事实 47 那族同类：`AccessSelections` 等**进程内非托管指针接口**在 pywin32 下到不了）。
⚠ **但这只是候选，本轮没有证据** ⇒ **不写进结论**。

## 五、★ 两条可复用的
```
① **草图段没有名字**（`GetID` 是端点对）⇒ **按名选段不可能**
② **`Select4` 与 mark=1 二者不可兼得** ⇒ 凡官方要求 mark 的地方，
   **必须走 `SelectByID2` 那条路** —— 而那条路要求有名字
```
