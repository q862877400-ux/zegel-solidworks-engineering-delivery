## 一、★★★★★ 目标（★ 逐字承计划 §5 EC01）

★★★ **把「做一个支架」变成能计算、规划、验收的工程需求。**

★★ **一句话**：★ EC00 让「**工具执行可信**」；★★★ **EC01 让「工程意图可计算」**。

---

## 二、★★★★★ 用户故事与验收场景

### US1（P1）★ 工程师**明确表达**工程意图，系统分清「已知/假设/待确认/必需缺失」

★ 作为工程师，我把「做一个支架」交出去时，★ **想知道系统到底**缺什么**** ——
★★ 而不是让它**猜一个**默认值就把模型建出来。

| # | ★ 验收场景 |
|---|---|
| S1-1 | ★ 给定需求信息，★ 系统必须**分四类**标注：★ `known` / `assumed` / `needs_confirmation` / `required_missing` |
| S1-2 | ★★ **`required_missing` 非空 ⇒ 不得进入冻结**（★ 也不得进 COM） |
| S1-3 | ★ `assumed` 必须**逐条**给出**依据**（★ 不能「我觉得」） |
| S1-4 | ★★ **可保守假设项**与**禁止假设项**必须**分开列**（★ EC01-T07） |

### US2（P1）★ 工程对象有**单一权威**定义（★ 不是三份 schema 各写一份）

★ 作为接手方，我需要**一处**权威定义，★ 而不是在三个 schema 里找同一个字段。

| # | ★ 验收场景 |
|---|---|
| S2-1 | ★ `Quantity`/`CoordinateFrame`/`Datum`/`LoadCase`/`MaterialRef`/`ProcessIntent`/`Fit`/`ParameterDomain` **各有唯一权威** |
| S2-2 | ★★ **`Quantity` 直接复用 EC00 的定义**（★ 不另建一套量纲） |
| S2-3 | ★ 新增字段必须**指向**权威定义（★ 不复制字段表） |

### US3（P1）★ **非法量纲和缺关键工况在 COM 前阻断**

★ 作为验收者，我不能接受「先建出来再说」。

| # | ★ 验收场景 |
|---|---|
| S3-1 | ★ **非法量纲**（★ 如长度字段收到角度）⇒ ★ **COM 前拒绝** |
| S3-2 | ★★ **缺关键工况** ⇒ ★ **不得默认「普通工况」**（★ EC01-T03 逐字） |
| S3-3 | ★★ **安全等级缺失** ⇒ ★ **不得默认「普通」** |
| S3-4 | ★ 阻断必须给**可执行的**下一步（★ 缺哪个字段、怎么补） |

### US4（P1）★ 契约有**状态机**，且**新版本不能借用旧批准**

★ 作为审签人，我需要知道一份契约**现在是哪个状态**，★ 以及**旧批准还算不算数**。

| # | ★ 验收场景 |
|---|---|
| S4-1 | ★ 状态机：★ `draft` → `needs_clarification` → `frozen` → `superseded` |
| S4-2 | ★ **只有 `frozen` 才能进 COM** |
| S4-3 | ★★ **`superseded` 的批准不得沿用**（★ 内容哈希变了就失效） |
| S4-4 | ★ 冻结时产生**内容哈希**（★ 与 EC00 的 `EvidenceManifest.artifact_version` 同族） |

### US5（P2）★ **两个不同表述的同意图归一到同语义**

★ 作为调用者，我换个说法描述同一个东西时，★ 系统该认出**那是同一个意图**。

| # | ★ 验收场景 |
|---|---|
| S5-1 | ★ 「80 毫米的板」与「0.08 米的板」⇒ ★ **归一后同语义** |
| S5-2 | ★★ 归一必须**可解释**（★ 给出归一了哪几处，★ 不是黑箱） |
| S5-3 | ★★ **不同意图不得被归一**（★ 负例） |

### US6（P2）★ **旧设计计划能受控迁移**

★ 作为现有调用者，我需要知道旧 `design_plan` 怎么进新契约。

| # | ★ 验收场景 |
|---|---|
| S6-1 | ★ 旧 `design_plan.schema.json`（★ 10 个字段）**能适配**成新契约 |
| S6-2 | ★★ **旧信息不足 ⇒ 保留 `unknown`**（★ **不编一个默认值**） |
| S6-3 | ★ 适配**不改变**旧的公开契约（★ 承 `DSH_DECISIONS.md` **D-001**） |

## 三、★★★★ 功能需求（★ 承计划 §5 EC01 的 T01–T08）

| ID | 要求 | 故事 | ★ 必须证据 |

## 五、★★★ 非目标（★ 本版**刻意不做**）

- ✗ ★ **不做规则计算与标准适用性** ⇒ ★ **EC02**（★ 本特性只**表达**需求，★ 不判「行不行」）。
- ✗ ★ **不做方法库与规划编译** ⇒ ★ **EC03**（★ 本特性只**冻结契约**，★ 不选方法）。
- ✗ ★ **不做作业租约/围栏/证据链** ⇒ ★ **EC04**（★ 复用 EC00 的兼容字段）。
- ✗ ★ **不做实际建模** ⇒ ★ **EC05**（★ 本特性**不碰 COM**）。
- ✗ ★ **不做装配/机构/工程图/CAE** ⇒ ★ EC06–EC09。
- ✗ ★★ **不另建一套 `Quantity`** ⇒ ★ **复用 EC00 的**（★ 铁律 1）。
- ✗ ★ **不改旧 `design_plan` 的公开契约** ⇒ ★ 承 **D-001**（★ 只**适配**，★ 不改）。
