# 样例对比：3 种写法，请选一版

**用途**：你批注「用矩形工具画一个草图，标注上长和宽」——
**但「尺寸怎么进到模型里」有三种做法**，我判不了该用哪种（那是机械工程判断）。
**所以我用同一道题（L1-001）写了三版**，你选一版，我照那版批量改 21 条。

**选题**：`L1-001 · 建一块 100×60×20 的矩形板`

---

## 先看事实：工具的真实参数

我查了工具声明（**不是我编的**）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `sketch_start` | `plane_name`（默认 `Front Plane`） | 在哪个面上画 |
| `sketch_add_rectangle` | **`x1_mm` `y1_mm` `x2_mm` `y2_mm`（全必填）** | ★ **两个对角点的坐标**，**没有「长/宽」参数** |
| `sketch_add_circle` | `center_x_mm` `center_y_mm` `radius_mm`（全必填） | 圆心 + 半径 |
| `sketch_end` | 无参数 | 退出草图 |
| `add_dimension` | `x_mm` `y_mm`（必填，尺寸文字放哪）+ `selector` + `kind` | 给**选中的实体**加显示尺寸 |
| `auto_dimension_sketch` | 无参数 | 自动标尺寸 |
| `extrude_boss` | `sketch_name` `depth_mm`（必填） | 拉伸 |
| `part_mass_properties` | 无参数 | 读体积 |

**★ 关键事实**：**`sketch_add_rectangle` 吃的是坐标，不是长宽。**
所以「100×60」必须先**算成坐标**才能用 —— 这就是三版的分歧点。

---

## 方案 A · 坐标即尺寸（不额外标注）

**思路**：坐标已经定死了形状，**再标尺寸是冗余**。

### 人话步骤

| # | 做什么 | 参数 |
|---|---|---|
| 1 | 在**前视基准面**上开始画草图 | `plane_name="Front Plane"` |
| 2 | 画一个矩形：**左下角 (-50, -30)、右上角 (50, 30)** | `x1=-50, y1=-30, x2=50, y2=30` |
| 3 | 退出草图 | — |
| 4 | 把草图**拉伸 20mm** 成凸台 | `depth_mm=20` |
| 5 | 读质量属性 | — |

### 尺寸从哪来

```
板宽 100 →  x 从 -50 到 +50   （居中）
板高  60 →  y 从 -30 到 +30   （居中）
板厚  20 →  拉伸深度 20
```

### 回读判据

- 体积 = 100 × 60 × 20 = **120000 mm³**（±1e-6 相对误差）
- 包围盒 = **100 × 60 × 20**

### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---|---|
| **最少步骤**（5 步） | **模型里没有「可读的尺寸」** —— 工程图上要重新标 |
| 与工具真实参数一致 | 改尺寸要改坐标（不是改尺寸值） |
| 判据是**几何量**（体积/包围盒），最硬 | **不能**用 `config_update_dimension` 改它（因为没具名尺寸） |

## 方案 B · 坐标画图 + 显式标注尺寸

**思路**：坐标定形状，**再调 `add_dimension` 加两个尺寸**，让模型里有「可读的 100 和 60」。

### 人话步骤

| # | 做什么 | 参数 |
|---|---|---|
| 1 | 在**前视基准面**上开始画草图 | `plane_name="Front Plane"` |
| 2 | 画矩形：**左下角 (-50, -30)、右上角 (50, 30)** | `x1=-50, y1=-30, x2=50, y2=30` |
| 3 | **选中矩形的下边，加一个显示尺寸**（标注长度 100） | `selector="index:0", kind="EDGE"`，文字放 `(0, -40)` |
| 4 | **选中矩形的右边，加一个显示尺寸**（标注高度 60） | `selector="index:1", kind="EDGE"`，文字放 `(60, 0)` |
| 5 | 退出草图 | — |
| 6 | 拉伸 **20mm** 成凸台 | `depth_mm=20` |
| 7 | 读质量属性 | — |

### 回读判据

- 体积 = **120000 mm³**
- 包围盒 = **100 × 60 × 20**
- **草图里有 2 个显示尺寸**（可数出来）

### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---|---|
| 模型里**有可读尺寸**（符合工程习惯） | **多 2 步**（7 步） |
| 工程图上能直接引用 | ⚠️ **我查到一个真限制**：本仓 `add_dimension` 有**未隔离的失败案例** —— 在「板 + 凸台」模型上失败（纯盒体上 8/8 成功） |
| | 尺寸要**选边**（`index:0` 是哪个边，**不确定**） |

**★ 这一版的坑**：`selector="index:0"` 到底指哪条边 —— **我判不了**（要真机试）。
**如果你选 B，我需要先真机验一次「矩形 4 条边的 index 顺序」。**

## 方案 C · 坐标画图 + 自动标注

**思路**：画完矩形，**调 `auto_dimension_sketch` 让软件自己标**。

### 人话步骤

| # | 做什么 | 参数 |
|---|---|---|
| 1 | 在**前视基准面**上开始画草图 | `plane_name="Front Plane"` |
| 2 | 画矩形：**左下角 (-50, -30)、右上角 (50, 30)** | `x1=-50, y1=-30, x2=50, y2=30` |
| 3 | **让软件自动给草图标尺寸** | — |
| 4 | **读草图的完全定义状态**（确认标全了） | — |
| 5 | 退出草图 | — |
| 6 | 拉伸 **20mm** 成凸台 | `depth_mm=20` |
| 7 | 读质量属性 | — |

### 回读判据

- 体积 = **120000 mm³**
- 包围盒 = **100 × 60 × 20**
- **草图完全定义状态 = 已完全定义**（★ 这是自动标注**成功**的证据）

### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---|---|
| **不用猜「哪条边」** —— 软件自己找 | **标出来的是哪几个尺寸，不由我们控制** |
| 有「完全定义」这个**机器可判**的证据 | 可能标出**你不想要**的尺寸（如对角线） |
| 7 步，比 B 稳（不依赖 index 顺序） | 若软件标不全，**完全定义状态**会暴露（这是优点） |

## ★ 我的建议：**A + C 组合**

**理由**：

1. **主链用 A**（5 步，最简，判据最硬）—— 因为**语料测的是「检索能不能找对工具」，不是「工程图完不完整」**
2. **对需要「模型里有尺寸」的条目**（如 L1-059「改一个轴系接口参数」），**用 C**（不依赖 index）
3. **B 暂时不用** —— 它依赖「边的 index 顺序」，而**那个顺序官方未承诺稳定**（本仓已知事实）

**但这是技术判断，工程上该用哪版由你定。**

## 顺带：这次暴露了我语料的**一个结构缺陷**

我原来的链**只写「动作」，没写「参数从哪来」**。

**所以我打算给语料加一个字段**：

```yaml
params:
  - step: 2
    tool: solidworks_sketch_add_rectangle
    values: {x1_mm: -50, y1_mm: -30, x2_mm: 50, y2_mm: 30}
    derive: "板宽 100 居中 ⇒ x 从 -50 到 +50；板高 60 居中 ⇒ y 从 -30 到 +30"
```

**这个字段是「可编译」的关键** —— 没有它，检索判据只能测「工具选对没」，**测不了「参数算对没」**。

**要不要加？**（加的话我一起改，21 条的工作量差不多）
