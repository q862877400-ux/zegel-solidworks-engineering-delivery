# Spec — 散文式出处自称的收口：探测器认不出「本机/DLL/实测/手册」这类写法

**Feature**: `specs/226-prose-provenance-claim/`
**日期**: 2026-10-09
**上游**: `specs/223`（造出盲区探测器）→ `specs/224`（44 张逐张表态 + 未表态判红）→
`specs/225`（修探测器：认 `sws[A-Z]` 名族与「反射/转储/CHM/`_raw`」）
**本轮只做一件事**：把 225 **登记的**头号未过门——「**散文式出处自称仍看不见**」——**先量后收口**。

---

## 一、问题（先量后改，量到几就改几）

### 1.1 探测器现状与 225 留下的口子

`scripts/check_enum_values_vs_reflection.py`：

```python
CLAIM = re.compile(r"官方|swapi|sws?[A-Z]\w+|反射|转储|CHM|_raw")   # spec 225 放宽后的形态
```

判据仍是「该表**未被 `# swXxx` 标注覆盖**」**且**「表起始行上方 15 行窗口里 `CLAIM` 命中」
⇒ 命中即「自称有出处」，就必须有一行 `#: enum-gate: …`（224 FR-003：未表态**判红**）。

★ 225 自己写明的**诚实边界**：`CLAIM` 是**启发式** ——
**用散文（不含上述词）声称出处的表仍看不见**，登记为未过门。本轮就是来收这个口子。

### 1.2 先量：到底有多少张？（★ 先量后改，不猜）

一次性探针（`output/_probe_prose_claim.py`，**不进仓库代码**）：对每张**未覆盖**的模块级整数表，
取其上方 15 行窗口，看有没有「散文式出处自称」而 `CLAIM` 不命中。**实测**：

```
总表 101 · 已覆盖 33 · 未覆盖 68 = 盲区 54（已全部表态）+ 非盲区 14（不自称出处，探测器有意不看）
非盲区 14 张里，带散文出处线索的 = **1 张**
```

⇒ ★ **量 = 1**。且这 1 张是**真自称**，不是噪声：

| 文件:行 | 表 | 项 | 表上方注释（散文式自称，`CLAIM` 全部不命中） |
|---|---|---|---|
| `sw_import_mesh_reference.py:69` | `SW_LENGTH_UNITS` | 8 | `# 本机 SolidWorks 2024 swconst.dll 验证值。使用整数常量可以避免脚本依赖…` |

★ 为什么它逃得过：`本机` / `swconst` / `.dll` / `验证值` **四个词一个都不在** `CLAIM` 里；
而 `swconst.dll`（`sw` + 小写 `c`）也**不**命中 `sws?[A-Z]\w+`（那条要求 `sw` 后是 `s` 或**大写**）。
⇒ 这张表「**自称有出处**（本机 swconst.dll 验证）」却**从没进过盲区清单**，
224 的「未表态即红」对它**完全无效** —— 与 225 修掉的那族**同型**。

### 1.3 先量爆炸半径：加词会不会拖一堆表进来？（★ 225 的教训）

225 放宽 `CLAIM` 后**新暴露 10 张**，当场要逐张表态。本轮**先量**候选词集的爆炸半径：

| 候选词 | 新增入盲区 |
|---|---|
| `本机` | **1** |
| `\.dll` | **1** |
| `验证值` | **1** |
| `swconst` | **1** |
| `本机\|本地\|\.dll\|swconst\|实测\|真机\|观测` | **1** |
| `手册\|文档\|帮助\|参考\|摘自\|取自` | **0** |
| `本机\|本地\|实测\|真机\|观测\|\.dll\|swconst\|手册\|帮助\|文档\|摘自\|取自`（定稿） | **1** |

⇒ 定稿词集的爆炸半径 = **1 张**（就是 §1.2 那张）⇒ **安全**，不会制造未预期的新红。

### 1.4 残余：定稿之后还剩多少看不见的？

定稿词集**只覆盖「能指认的散文形态」**。理论上仍可能存在**完全不含这些词**的散文自称
（例如「照官方说法」——但 `官方` 已在 `CLAIM` 里）。
本轮**在实测层面**把残余压到 **0**：把定稿词集当作「散文自称」的**可操作定义**，
逐张核过 14 张非盲区表 ⇒ **没有第 2 张**（其余 13 张的注释里**根本没有出处自称**，
它们是本地语义映射，例如 `{"part": 1}` / `{"C3D4": 4}`）。

★ **诚实边界（登记，不冒充已解决）**：这不是「证明不存在散文自称」，
而是「**在这棵树上、按这个可操作定义，残余 = 0**」。
判据里用**下界断言**（`BASELINE_BLIND`）而不是等号，正是为了不把「当前读数」当永久真理。

## 二、需求（每条带来源与许可）

### FR-001 探测器必须认得出「真机观测 / DLL 反射 / 离线文档」这三类散文式自称

`CLAIM` 追加：**`本机|本地|实测|真机|观测|\.dll|swconst|手册|帮助|文档|摘自|取自`**。

按**语义分类**（每类都是本仓**真实存在的出处来源**，不是凑词）：

| 类 | 词 | 指什么 |
|---|---|---|
| ① 真机/运行观测 | `本机` · `本地` · `实测` · `真机` · `观测` | 值来自**运行观测**（★ 对应 `not-enum observed` 子类） |
| ② 程序集/反射 | `\.dll` · `swconst` | 值来自对**类型库/程序集**的反射（★ 本仓 `_raw` 反射转储的机制） |
| ③ 离线文档 | `手册` · `帮助` · `文档` | 值来自**离线文档**（★ 与 `CHM` 同族） |
| ④ 摘录动词 | `摘自` · `取自` | 显式声明**从别处摘录** |

- **来源**：本仓库自身门禁 `scripts/check_enum_values_vs_reflection.py`（本仓 MIT，自研）。
- **官方依据（判据侧）**：`_raw/enum_values_sldworks.txt` · `_raw/reflect/enum_cosworks.txt`（反射转储）
  · `C:\swapi\enums\*.md`（官方 SDK 解包）· `_raw/chm_cosworks/`（CHM 解包）—— 本仓三源。
- **许可**：本仓库 MIT。无第三方代码引入。
- **实测依据**：见 §1.3（爆炸半径 **1** 张）· §1.2（该张真自称）。

★ **不含**的形态（**有意排除**，附理由）：
- `参考` —— 歧义太大（「仅供参考」**不是**出处自称）⇒ 排除，避免噪声。
- `据` / `按` —— 单字、过宽（「按需」「按名」）⇒ 排除。
★ 这条边界写进判据（`test_claim_does_not_match_ambiguous_prose`），防止将来被顺手加宽。

### FR-002 新暴露的 1 张表必须表态：`enum swLengthUnit_e`

在 `SW_LENGTH_UNITS`（`scripts/sw_import_mesh_reference.py`）**表起始行正上方**补一行
`#: enum-gate: enum swLengthUnit_e`（形态沿用 224 FR-002）。

- **来源**：`specs/224-.../spec.md` FR-002（声明形态）+ 本轮的实测清单。
- **官方依据（两源独立核对，无冲突）**：
  - ① `C:\swapi\enums\swLengthUnit_e.md`：`swMM=0 · swCM=1 · swMETER=2 · swINCHES=3 · swFEET=4 · swFEETINCHES=5 · swANGSTROM=6 · swNANOMETER=7 · swMICRON=8 · swMIL=9 · swUIN=10`（11 项）
  - ② `_raw/enum_values_sldworks.txt`（第 959–970 行）：**逐条一致**
  ⇒ 表内值集 `{0,1,2,3,4}` **⊆** 官方取值集 ⇒ `check_dispositions()` 的「值集包含」会**通过**。
- **许可**：本仓库 MIT。
- ★ **不做**：**不逐行补 `# swXxx`** —— 键是**本地语义键**（`"mm"` / `"meter"` / `"in"`），
  官方成员名（`swMM`/`swMETER`/`swINCHES`）**不在键里**；且该表**有意允许同义键**（`m`/`meter`/`meters` → 2）。
  224 已判过这个结论，本轮沿用。
- ★ **附带收益**：把一行**散文**（`# 本机 … 验证值`）变成一行**机器可核**的声明
  —— 这正是 225 交接单 §④ 说的「把出处从注释升级为**可核**的东西」，
  ★ 但**只对真需要的那 1 张做**，不搞全仓形态改造（1 张不值得，见 §三）。

### FR-003 端到端负例：散文自称「本机…验证值」却未表态 ⇒ 门禁必须红

合成一棵树，放一张**注释自称「本机 … swconst.dll 验证值」**的整数表、**不给** `#: enum-gate:` ⇒
`check_enum_values_vs_reflection.py` 必须 **exit 1** 且**点名该表**、理由含「未表态」。

- **来源**：`specs/224` / `specs/225` 同类负例的镜像。
- **为什么必须有**：★ 否则「放宽正则」这件事**没有可红的判据** ——
  改前改后门禁都能 exit 0（未覆盖本来就不判罪）⇒ 正是 223 判过的「**空判据**」形态。
- **官方依据**：不适用（本项目自身门禁的契约）。
- **许可**：本仓库 MIT。

### FR-004 表态可核性沿用 224/225 机制，**不新造**

`enum` 声明必须能在**出厂反射转储**里解析到 + 值集包含；`not-enum` 子类必须在封闭词表内。
**不新增** code、**不新增** `not-enum` 子类、**不改**退出码语义（未覆盖仍**不**判罪，只判「未表态」）。

- **来源**：`specs/224-.../spec.md` FR-002/FR-005 · `specs/225-.../spec.md` FR-005。
- **许可**：本仓库 MIT。
- ★ 后果：224 的 54 条声明 + 225 的 10 条声明**零影响**（本轮只**新增 1 条**）。

### FR-005 旧探针不许丢

放宽**不许**让 225 之前已能认出的写法失效（`官方` · `swapi` · `swXxx_e` · `swsXxx_e` · `反射` · `转储` · `CHM` · `_raw`）。

- **来源**：`specs/225-.../tests` 的 `test_claim_still_matches_legacy_official_probes` 同型。
- **为什么**：放宽正则最常见的事故是**改坏了原来的** —— 那会让已表态的 54 张**掉出清单**、
  于是 224 的判红对它们**静默失效**。判据必须当场抓住。
- **许可**：本仓库 MIT。

## 三、不做（明确划界）

| 不做 | 原因 |
|---|---|
| 全仓「出处」形态改造（表级 YAML 旁挂 / 装饰器 / 强制逐表出处行） | ★ 实测**只有 1 张**真需要 ⇒ 形态改造是**过度工程**（成本 >> 收益）；本轮只对那 1 张补声明 |
| 逐行补 `# swXxx` | 键是本地语义键，硬补要靠人工对表，易写错（224 已判） |
| 把「未覆盖」也判红 | 68 张里 14 张不自称出处（本地语义映射）⇒ 判红是**噪音**（223 已判） |
| 加 `参考` / `据` / `按` 进 `CLAIM` | 歧义太大（「仅供参考」不是出处自称）⇒ 有意排除，见 FR-001 |
| 改 `#: enum-gate:` 的 code 词表 / `not-enum` 子类 | FR-004；改了就要重核 224+225 的 64 条声明 |
| 修 223 登记的 8 条 `HEAD` 即红既有失败 | 权属落在他人未提交改动内，**先确认权属** |
| `HEM_POSITIONS` 真机复核 | 需业主另行授权 COM |
| 提交 / 部署 / 打 tag / 调 COM / 删文件 | 硬约束 |
