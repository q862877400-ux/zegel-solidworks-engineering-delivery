## 一、★★★★★ 目标（★ 逐字承计划 §5 EC03）

★★★ **模型选择成熟方法与解释，★ 不直接拼底层 API。**

★★ **一句话**：★ EC01 说「**要什么**」· ★ EC02 说「**行不行**」；
★★★ **EC03 说「**怎么做**」—— ★ 且给出**可审计的计划**。**

## 二、★★★★★ 用户故事与验收场景

### US1（P1）★ 方法**可解释**：为什么选它、替代方案是什么

★ 作为设计者，我要知道系统**为什么**选这个方法。

| # | ★ 验收场景 |
|---|---|
| S1-1 | ★ 每个 `MethodSpec` 带：★ 目标 · 适用域 · 前后置 · 步骤 · **禁止条件** · 复杂度 · 修改域 · 验证义务 · **失败域** |
| S1-2 | ★★ 选法必须记**原因**与**替代方案**（★ 不是「就它了」） |
| S1-3 | ★ 方法**不适用**时 ⇒ ★ 明确拒绝（★ 不硬套） |

### US2（P1）★ 编译**不需要 COM** 就能验计划正确性

★ 作为验收者，我要在**不启动 SolidWorks** 的前提下知道计划对不对。

| # | ★ 验收场景 |
|---|---|
| S2-1 | ★★ 编译器**纯离线** —— ★ **不 import 任何 COM 模块** |
| S2-2 | ★ 编译产物是**结构化 IR**（★ 不是一串 API 调用） |
| S2-3 | ★★ 计划正确性检查（★ 越权/欠约束/循环）**在编译期**完成 |

### US3（P1）★ 编译器能拒绝**越权 / 欠约束 / 循环依赖**

★ 作为审签人，我不要一个「先跑跑看」的编译器。

| # | ★ 验收场景 |
|---|---|
| S3-1 | ★ **越权**（★ 动冻结域之外的东西）⇒ ★ **编译期失败** |
| S3-2 | ★ **欠约束**（★ 参数没定域）⇒ ★ **编译期失败** |
| S3-3 | ★★ **循环依赖**（★ A 要 B、B 要 A）⇒ ★ **编译期失败** |
| S3-4 | ★★ **非法路由** ⇒ ★ **编译期失败**（★ 不是执行期才报） |

### US4（P1）★ **同一编译器**吃两个模型的合法意图

★ 作为集成者，我不要每个模型一套编译器。

| # | ★ 验收场景 |
|---|---|
| S4-1 | ★★ 编译**只吃** EC01 的 `EngineeringContract`（★ **不吃**自由文本） |
| S4-2 | ★★ 两个模型给出**同一份契约** ⇒ ★ **编译结果一致** |
| S4-3 | ★ **模型无关** —— ★ 编译器不认「谁生成的」 |

### US5（P1）★ **冻结计划不能被执行器静默改写**

★ 作为审签人，我批准的**必须**是执行的那份。

| # | ★ 验收场景 |
|---|---|
| S5-1 | ★ 计划冻结时产生**内容哈希** |
| S5-2 | ★★ 执行前**校验哈希** ⇒ ★ **不符就拒绝** |
| S5-3 | ★★★ **静默改写 ⇒ 拒绝**（★ 不是警告） |

### US6（P2）★ **`unknown` 不能落入默认可行**

★ 作为使用者，我不要一个「不知道就算通过」的编译器。

| # | ★ 验收场景 |
|---|---|
| S6-1 | ★ **不可满足核心**要能指认（★ 哪些约束冲突了） |
| S6-2 | ★ **超时** ⇒ `unknown`（★ 不是「可行」） |
| S6-3 | ★★ **多方案要排序**（★ 且给出排序依据） |

### US7（P2）★ 「优雅」是**多指标**，不是「特征最少」

★ 作为工程师，我要的是**改得动**，不是**画得少**。

| # | ★ 验收场景 |
|---|---|
| S7-1 | ★ 指标：★ **修改稳定 · 基准表达 · 意图可读 · 工具风险 · 可制造性** |
| S7-2 | ★★★ **不能仅「最少特征」** |
| S7-3 | ★ 多指标要**可算**（★ 不是形容词） |
