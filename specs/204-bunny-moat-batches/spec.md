# 204 · 用 Bunny 集群做「别人没做甚至做不到」的六件事

**Status**: Planning（2026-10-04 立，待用户确认）

> ★★ **进度看 [`goal-bar.md`](goal-bar.md)** —— 那是**唯一**的目标栏/进度字段。
> 各件的 spec/plan 段里**不写**「已完成 x%」这类会腐坏的话。
> ★ **批量子代理一律用 Bunny**（`opencode-zen` / `space-bunny-free`，provider 与 model **成对写**）；
> **DeepSeek（`deepseek-official` / `deepseek-flash`）只做裁判**，不做产出。

> **定位**：这是**支线规格**（接 `specs/203-bunny-sideline-batches`）。
> 203 做的是「把官方源与仓库读成可核对的表」；204 做的是**只有「已有闸 + 已有集群 + 已抽出语料」三者同时具备才能做**的六件事。
> 支线**只读官方源 / 四家克隆 / 本仓库**，**只写** `docs/recon/`、`specs/204-*/`；
> **不碰** `capabilities.yaml` · `scripts/` · `tests/` · `tools/` · 根 `AGENTS.md` · 门禁 · git。

## 一、为什么这六件事「别人做不到」——三条已实测的依据

| # | 依据 | 实证读数 |
|---|---|---|
| ① | **我们有闸，别人不知道自己在错** | 本轮 Bunny 每一路都**自称「已逐字校验」**，机械回查抓出 **11 / 7360 = 0.15%** 是编造的（含 5 条凭空数字：`1132`/`889`/`1297`/`1981`/`249`，`grep` 零命中）⇒ **没闸的人拿到的就是错的，且不知情** |
| ② | **我们已抽出语料，别人要重做** | 2839 份官方示例 → **3985 个成员名（3887 在官方名单里）** · **2826 份具体前置** · 566 接口 **11557 成员台账** |
| ③ | **我们有既有核验设施，能把活机械化** | `docs/signature-audit.md` · `capabilities.yaml` 的 110 条 level+evidence · 8239+11117 两个官方名单 |

## 三、逐件详规

### C1 · 多路一致率（**先做，它是其它五件的校准器**）

- **输入**：`docs/recon/iview-read-members.md`（461）· `drawingdoc-read-members.md`（274）· `isheet-read-members.md`（53）—— 共 **788** 个成员页，标准答案**已发布**（149/45/267 等）。
- **做法**：把 788 个页分成 **60 箱**（每箱 13–14 页），每箱由 **3 路独立 agent** 各自读同一批页，
  各自输出同一 schema（签名 / 是否废弃 / 是否指针 / 零参三态）。
- **判据**（`SC-20401`–`SC-20404`）：
  - `SC-20401` 三路输出**同 schema**，且都可 `json.loads`。
  - `SC-20402` **逐条一致率**按字段算（签名 / 废弃 / 指针 / 零参），**分母是 788**，可重数。
  - `SC-20403` 分歧条目**逐条列出**，并给「三方谁对 + 依据哪段原文」。
  - `SC-20404` **三路一致率 vs 与已发布标准答案的一致率**两个数**都要报** ——
    前者是「集群自洽性」，后者是「集群正确性」，**不是一回事，不许合并**。
- **产出**：`docs/recon/multiway-agreement.md`
- **为什么值得**：这是把全仓可信度从「Lead 抽查 12 条」升级为**逐条可查数字**的唯一办法。
- **实测校准价值**：本轮已知我有 4 处自己的错误（复核器 `is_file`、样板句误判、ROADMAP 行移位、截断破坏反引号）
  ⇒ **C1 也会测出「Lead 自己的错误率」**，这一半同样要报。

### C2 · 四家工具 × 官方签名对账

- **输入**：`C:\swprojects\{Eduardof0nt,andrewbartels1,SolidworksMCP-TS,Slacker-LLC}\` 的 **335** 个代码文件；
  本仓台账 `docs/recon/interface-ledger.md`（566 接口 / 11557 成员）＋ `C:\swapi\types\` 精确签名。
- **做法**：**前 3 家**（代码 2 / 259 / 59 文件）分箱，每路读一批文件，抽出该文件里所有
  **对官方 API 的调用**（成员名 + 实参个数 + 形参形态），再逐个与官方签名对账。TS 那家（`vespo92`）第 4 批做。
- **判据**（`SC-20411`–`SC-20414`）：
  - `SC-20411` 每个抽出的调用都给**该文件的逐字片段**（我逐字回查，查不到即作废）。
  - `SC-20412` 差异必须是**Mechanical** 的：成员名查不到 / 实参个数 ≠ 官方 arity / `out`·`ref` 参数缺 `VARIANT` 包装。
  - `SC-20413` **按项目分列**，不合成一个总数（各家命名与粒度不同）。
  - `SC-20414` ★ **只报事实，不判"他们错了"** —— 他们可能用的是我们没见过的重载 ⇒ 单列 `unknown_overload`。
- **产出**：`docs/recon/competitor-signature-crosscheck.md`
- **限度**：**我们不跑他们的代码**，不判「能不能跑」；只判「调用的形与官方签名是否一致」。

### C3 · 官方示例前置 × 本仓 evidence 对账

- **输入**：`capabilities.yaml` 110 条（314 条 evidence）＋ C4/B3 抽出的 **2826 份前置**。
- **做法**：每路一个能力条目；先取该条目挂的工具，再经「成员名 → 示例」索引反查相关示例的前置，
  逐个问：**这条前置在 evidence 里被覆盖了吗**。
- **判据**（`SC-20421`–`SC-20423`）：
  - `SC-20421` 三态：`covered` / `not_covered` / `cannot_tell`，**判定依据必须是逐字片段**。
  - `SC-20422` `level=verified` 且**有前置未被覆盖** ⇒ 进「缺口清单」，**但不改 level**。
  - `SC-20423` 前置若来自示例正文却**无对应成员页** ⇒ 单列（那说明该前置是"示例级约定"）。
- **产出**：`docs/recon/precondition-vs-evidence.md`

### C4 · 官方文档内部矛盾（示例 ↔ 成员页 Remarks）

- **输入**：2839 示例 ↔ 11557 成员页。**只比两侧都提到的成员**（约 3887 个）。
- **做法**：每路领一批成员；对每个成员，读它的成员页 `Remarks` 与**用到它的示例**，
  找**不能同时成立**的说法（前置不同 / 返回值形状不同 / 单位不同 / mark 值不同）。
- **判据**（`SC-20431`–`SC-20433`）：
  - `SC-20431` 两侧都给**各自文件**的逐字片段（我逐字回查）。
  - `SC-20432` 分歧**必须点名争的是哪个量**（前置 / 返回形状 / 单位 / mark / 其它）。
  - `SC-20433` ★ 单列一节「**示例比成员页更具体**」的条目 —— 那不是矛盾，但是**只有示例才有的信息**。
- **产出**：`docs/recon/official-internal-conflicts.md`

### C5 · 754 个「缺口」三态澄清

- **输入**：`tools/union-sources.json`（四家操作清单）＋ `docs/union-coverage-matrix.md` ＋ 我们的 340 个工具名。
- **做法**：按域分箱；每路对一批缺口操作，判三态：
  **真缺**（我们确实没有对应工具）/ **换名已有**（我们用了别的名字）/ **判不了**（命名语义不可比）。
- **判据**（`SC-20441`–`SC-20443`）：
  - `SC-20441` 判「换名已有」**必须指明是哪个工具**，且给出**词根对应关系**（不许说"大概有"）。
  - `SC-20442` 每态给计数，**三态之和 = 缺口总数**（可重数）。
  - `SC-20443` ★ 与 `docs/union-coverage-matrix.md` 的 339 对照：**报出矩阵错判了几个**（矩阵按名字对齐，必错判）。
- **产出**：`docs/recon/union-gap-tristate.md`
- **⚠ 依赖**：`tools/union-sources.json` 是主线的文件，**只读**；若它不在盘上，本件**延后**。

### C6 · 事实库去重与唯一家

- **输入**：已有 `claims_norm.json` 的 **6390** 条 claim（6385 过闸）。
- **做法**：机械聚类（同量名校验 + 数值比对），分歧组交给 Bunny 判「同一量 vs 不同量」。
- **判据**（`SC-20451`–`SC-20453`）：
  - `SC-20451` 每个「量」给**唯一家**（保留哪份文档）+ **应删/应改的副本清单**（**只报不改**）。
  - `SC-20452` 区分**矛盾**（两份都声称是现值）与**时序更新**（一份自带轮次/日期）。
  - `SC-20453` 与已发布的 `docs/recon/doc-contradictions.md` **交叉引用**，不重造。
- **产出**：`docs/recon/fact-single-home.md`

## 四、作业方式（沿用 203 实测出来的三条硬约束，不许改）

| 约束 | 实测依据 |
|---|---|
| 子代理一律 **Bunny**，`provider` + `model` **成对写**（`opencode-zen` + `space-bunny-free`） | 只写 `model` ⇒ 整批静默失败（100 路回 `returned: 0`） |
| **一波 ≤ 60 路**；**一份文档一路** | 89 路死 19（21%）；3 份合批的 8 个批次全灭；一份一路 38/38 |
| **先 5 路探针再铺量**；`returned: 0` 当失败查 | 203 全程 6 波零失败 |

## 五、每件都必须过的三道闸

1. **引文逐字回查**（硬闸，不过即剔除）—— 实测挡掉 0.15% 编造。
2. **Lead 独立复核** —— 且**复核器本身也要被验**（203 里我的复核器用 `is_file()` 判目录，误报 7 处）。
3. **计数可重数** —— 每个统计段的数必须能被独立重算一遍（交叉验算式写进产物）。

## ⚠ 明确记下的限度

* ⚠ **C2 不判"他们能不能跑"** —— 只判「调用形 vs 官方签名」。他们可能用重载或私有封装。
* ⚠ **C5 依赖主线的 `union-sources.json`**，只读；不在盘上就延后。
* ⚠ **六件全部是"候选与事实"，不是"结论"** —— 改 `level`、改门禁、改矩阵**都归主线**。
* ⚠ **C1 是自指实验**：它会测出「集群错误率」**也测出「Lead 错误率」**，两个都要如实报，不许只报好看的那个。
* ⚠ 支线**不跑真机**（不碰 SolidWorks / COM）、**不跑 git**、**不改主线的任何文件**。
