## 一、★★★★ 问题与目标（★ 承 `ENGINEERING_P0_SPEC_DRAFT.md` §1）

★★ **项目已有大量工具，缺口不是「有没有 API」，而是**工具请求、实际效果与证据之间不闭合****。
★★★ **一次返回 `true` 不能证明**关系、单位、几何、文档状态符合工程意图。

★ **本特性建立一条可信执行路径**，为后续设计契约（EC01）、方法规划（EC03）和工程验收（EC05）提供基础。
★★ **先堵住**：★ 尺寸错 · ★ 假成功 · ★ 选错对象 · ★ 重复执行 · ★ 证据错版本。
★★★ **不在这里实现整套工程设计平台**（★ 计划 §6.1：「**此时不推进齿轮模型、不运行 CAE、不启动云节点**」）。

## 二、★★★★★ 用户故事与验收场景（★ 逐字承 `ENGINEERING_P0_SPEC_DRAFT.md` §2）

### US1（P1）★ 工程师明确表达单位，系统**只换算一次**

★ 作为工程师，我用明确单位提交尺寸和角度；系统按公开契约处理，**不能猜测单位或重复换算**。

| # | ★ 验收场景 |
|---|---|
| S1-1 | ★ 给定长度 **10 mm**，执行器应在**已确认的米制 API 边界**传入 **0.01 m**，并保留请求与规范化值 |
| S1-2 | ★ 给定同一长度以 **0.01 m** 表达，规范化结果与 10 mm **一致** |
| S1-3 | ★ 给定**只接受长度**的字段却传入**角度** ⇒ ★ **调用 COM 前拒绝** |
| S1-4 | ★ 给定旧调用省略单位 ⇒ ★ **仅在该工具确有已登记历史单位契约时**走兼容路径；★ **未知不得套全局 mm 默认** |

### US2（P1）★ 草图关系必须**真的生效**

★ 作为工程师，我要求两实体相切/相等/重合时，需要看到**实际约束证据**，而不是布尔值。

| # | ★ 验收场景 |
|---|---|
| S2-1 | ★ 给定合法实体与关系，**正式工具路径**执行后**回读关系及相关几何义务**，满足才通过 |
| S2-2 | ★ 给定关系 API **返回 `true` 但关系图没有变化** ⇒ ★ **判定失败**；★ **若不能可信回读则 `unknown`，不得通过** |
| S2-3 | ★ 给定实体类型错误、数量错误或关系名不支持 ⇒ ★ **调用前拒绝** |
| S2-4 | ★ 给定关系**已经存在** ⇒ ★ 只有**前态检查与效果判据均能确认**时才允许返回已满足，**不再盲目添加** |

### US3（P1）★ 只修改**指定**文档与对象

★ 作为工程师，我不能接受工具因活动窗口变化而修改**另一个**模型。

| # | ★ 验收场景 |
|---|---|
| S3-1 | ★ 文档身份、配置、版本与请求一致才执行；★ **活动窗口切换不构成授权** |
| S3-2 | ★ 重建后持久引用失效或命中歧义 ⇒ ★ **停止并提供证据**，★ **不选择"最近的面"** |
| S3-3 | ★ 草图编辑态/选择状态不满足前置条件时 ⇒ ★ 按**已批准计划**进入或拒绝；★ **不能偷偷改计划** |

### US4（P1）★ 超时之后**不重复制造**特征

★ 作为操作者，我需要知道一次超时是否**可能已经修改**模型。

| # | ★ 验收场景 |
|---|---|
| S4-1 | ★ 非幂等操作超时后标记 **`uncertain`**，重新读取效果或进入恢复流程，★ **不能立即重放** |
| S4-2 | ★ 模态框按既有**分级护栏**处理；★ **未知/危险弹窗不自动确认** |
| S4-3 | ★ DSH 与 WorkBuddy 竞争同一 SW 会话时**不能并发修改**；★ EC00 先接现有互斥边界，★ **完整租约/围栏在 EC04 实现** |

### US5（P1）★ 证据绑定**正确版本**且有失败信息

★ 作为验收者，我能从证据看出**请求、实际效果、未知项与最终模型版本**。

| # | ★ 验收场景 |
|---|---|
| S5-1 | ★ **模型改变后，旧的证据不能直接用于放行新模型** |
| S5-2 | ★ 只完成静态/离线测试的工具**不得升级为真机已验证** |
| S5-3 | ★ 失败日志保留错误分类、前后态和恢复建议；★ **不带明文凭据** |

### US6（P2）★ 旧工具能**受控迁移**

★ 作为现有调用者，我需要知道**哪些接口变了，以及旧调用何时退出**。

| # | ★ 验收场景 |
|---|---|
| S6-1 | ★ 每个迁移工具有旧契约、适配规则、弃用策略及回归测试 |
| S6-2 | ★ **已纳入本特性迁移表**的代表工具，不能通过回退旧入口绕过新硬门禁；★ **未纳入迁移范围的旧工具不适用本条**（★ **不泛化为"所有旧入口"**） |
| S6-3 | ★ 不兼容情形**明确拒绝**而非静默改变尺寸 |

- ★ 对代表工具做**深验收**，对其余范围做**静态盘点**；★ **覆盖率分开报告**。
- ★ 证据哈希表明**完整性**，★ **不天然证明真实性**；★ 记录取得方式和验收者。

## 六、★★★ 范围、非目标与依赖

### 6.1 ★ 代表工具集（★ P0 草案 §5.1 逐字）

★ 正式 G1 需冻结公开 ToolSpec 名称，★ **不在草案里编造 API 名**。★ 至少覆盖：

### 6.2 ★★ 第一版刻意**不承诺**（★ 总计划 §3.2 逐字）

- ★ 不承诺所有行业、所有工况、所有国家标准和所有 SolidWorks 版本自动通过。
- ★ 不承诺替代需要资质、实体测试、第三方检验或法定程序的环节。
- ★ **不直接下发 PLC 控制、真实电机运动或安全控制部署**；★ 先交付设计材料与验证说明。
- ★ **不把静力分析当疲劳、冲击、接触、屈曲和热可靠性证明**。
- ★ 不把「单次建模成功」当「参数族可用」。
- ★ **不把拒绝全部任务当安全完成**；★ 要同时测覆盖、成功和错误放行。
