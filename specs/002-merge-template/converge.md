## 三、不符合项与缺口

### ⚠ 1. SC-004 是**时点判据**，字面已不成立（不是缺陷，但必须说明）

**spec 原文**：「**SC-004**: 模板域在本仓库的能力数为 **0**（有据可查）。」

**实际**：矩阵现在显示 `| ⑨ 模具 | 3 | · | · | · | · | **8⚠** | 3 | **3** |` —— **能力面 = 8，不是 0**。

**为什么这不是缺陷**：**它已经并入完了** —— 并入之后该域的能力数**当然不再是 0**。
选择**当时**确实是有据的（`tasks.md` T-005）：
> ✅ 模具：地图缺口 3、本仓库仅 1 个函数（且那 1 个是 `core_only` 误分类）
> ⇒ 满足 US2 的三条件：① 本仓库≈0 ② 有来源 ③ 最小

**⇒ 处置**：**不改 SC-004**（它是历史的真实判据），
但在本节**明确它读的是「选择时点」**，并给出当前的对照值。
⚠ **同族风险提示**：任何「本仓库 = 0」型判据**在并入后都会自然失效** ——
写这类判据时宜写成「**在选定该域的提交上**，本仓库该域能力数为 0（附 `git rev` 或任务 ID）」。

### 🔴 2. **已修**：能力面列的 `⚠` 标记，含义原先只在**生成器的代码注释**里

**现象**：矩阵里几乎每个能力面数字都带 `⚠`（`45⚠` / `24⚠` / `58⚠` / … / `8⚠`），
**而读者拿到的矩阵里没有任何地方说明它是什么意思**。

**它的含义**原先只写在 `tools/build_union_map.py` 里那一行的**代码注释**：
```python
# 能力面列：缺口>0 而我们有 >=5 个函数时标 ⚠（提醒「这不是能力缺口」）
cell_cap += "⚠"
```

**⇒ 这违反「一个事实一个家」**（事实写在代码里，读者在制品里看不到）。
**本项目的原话**：「文档串与代码不符比没有文档更糟」—— 这里是更轻的一档：
**制品用了一个只在其源码里定义的记号。**

**✅ 已修（本轮）**：图例里加了自解释的一条（并把「这是启发式、不是判定」一并写明）：
```
> - 能力面列里的 **`⚠`** = 该域**缺口(MCP) > 0 而我们已有 ≥5 个函数**
>   ⇒ **它多半不是能力缺口，只是没暴露成 MCP 工具**。
>   ⚠ 这是**启发式标记**（阈值 5），不是判定；**要下结论仍须逐域人工核**。
```
**验证**：重跑 `python tools/build_union_map.py` ⇒ 矩阵 L35 出现该图例；
`git diff --stat` = **`10 insertions(+), 0 deletions`**（纯新增，按事实 61 自查）。

### ⚠ 3. **遗留**：T-005 / T-006 的验收命令**只存在于工作区根，不在仓库里**

`tasks.md` T-005 的验收命令写的是：
```
→ 验收: `python tools\capability_gap.py` 的模具行「我们函数 **8**」
⚠ 原文是裸文件名（`capability_gap.py`）—— **轮 53 已改成仓库内路径**；
  且那个数从「1」变成「8」（并入之后自然会变，见 §三.1 的「时点判据」说明）
```

**实测**：
| 找的地方 | `capability_gap.py` 在不在 |
|---|---|
| 代码副本 `tools/` | ✗ |
| 代码副本 `scripts/` | ✗ |
| **工作区根 `D:\AI\SW\`** | **✓（7.3 KB，2026-10-01 05:55）** |

⇒ **命令在**这台**机器上能跑，但**不在仓库里** ⇒ **换台机器（或 CI）跑不了**。
这与本 spec 自己的假设「**必须可重跑**（不然又是一次『报告计数不附枚举命令』的错）」**相冲突**。

**⇒ 处置**：**记为遗留缺口**，留待下一轮——
把该脚本按 `tools/` 的规范（来源块 / 只读 / 不连 SolidWorks）收进仓库，
或**改写 T-005 的验收命令为仓库内的等价命令**（如 `python tools/build_union_map.py` 后查模具行）。
⚠ **本轮不改**：把它搬进仓库要先过来源门禁与文档串规范，属于**独立改动**，不与本 converge 混提。
