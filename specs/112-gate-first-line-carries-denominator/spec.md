# 112 · 门禁明细的**首行**必须自带分母（而我的判据区分不了分母与编号）

**Status**: Implemented（轮 192）

## 一、起因：闭合轮 191 自己写的限度
```
轮 191 的限度：「有些门禁的 pass 分支不打印 `output` ⇒ 明细较薄」。
```

## 二、★★ 第一版度量（只看**首行**）⇒ 报「5 道没有分母」
```
negative_input_selfproof · report_criteria_alignment · report_freshness ·
signature_audit_freshness · spec_acceptance_paths
⚠⚠ **而按**全文**重量 ⇒ **0 道**没有分母** —— 那 5 道的分母**都在第二行**
  （例：`report_criteria_alignment` 的第二行就写着「权威判据 **N** 条」）
⇒ ★ **上一轮那句「明细较薄」是我**首行判据的假阳性**。
```

## 三、★★★ 而那暴露了真问题：**读者只看首行**
```
本轮我就因为只看首行而误判了一次 ⇒ ★ 该改的不是"让门禁写更多"，
而是**让首行承担它该承担的**（分母在手边，只是没提到首行）。
```

## 四、改动（5 处首行 + 1 处汇总）
```
negative_input_selfproof   → 「扫 …/tools（**102** 个 .py）」

```
★ `report_freshness` 与 `signature_audit_freshness` 的改动含**打印位置调整**
（先解析出计数再打印首行）—— ⚠ 顺序仍**在**「文档损坏 / SKIP」分支之前，失败输出可读性不变。

## 五、⚠⚠⚠ 必须记下的**判据极限**
```
我的判据是「首行里有没有 \d」——
★ 而 `union_conventions` 改前的首行 `[PASS] 规则 5 · 出处与许可` **含数字 `5`**
  ⇒ 判据判它"有分母"，而那个 `5` **是规则编号、不是分母**。
⇒ ★★ **`\d` 区分不了「分母」与「编号」** ⇒ 本判据**只能当粗筛**，不能当结论。
★ 如实记（**不假装判据比它实际更强**）—— 否则下一个人会以为「首行有数字」＝「报清了覆盖面」。
```
