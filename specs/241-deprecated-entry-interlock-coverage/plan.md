# plan 241 · 施工计划（三源 · 冲突裁决 · 边界）

## 一、三源（★ 与本仓既有口径一致）

| 源 | 位置 | 本规格怎么用 |
|---|---|---|
| ① 官方 API 文档树 | `C:\swapi\types\**\*.md` | **第 0 步**：判「某成员是否废弃」与「后继是谁」—— 逐字读 `Obsolete. Superseded by [[…]]` 那一行 |
| ② CHM 解包 / 官方示例 | `C:\swapi\examples\**`、`_raw/chm_*` | 只在需要「调用序」时读；本规格**不需要**（只判废弃与否） |
| ③ 反射转储 | `_raw/reflect_sldworks/iface_*.txt` | 只用来核**成员是否存在 / arity**；★ **不判废弃**（转储里没有 `Obsolete` 信息） |

★ 另有**第四源**：本仓自己的 `specs/202-user-coverage-gaps/recon/official-obsolete-index.json`
（`tools/build_obsolete_index.py` 从源①批量生成的索引，**1671 条**）。

## 二、★ 冲突裁决顺序

```
① 官方页 `Obsolete. Superseded by [[X]]` 那一行  >  ② 索引 json  >  ③ 反射转储  >  ④ 本仓既有登记
```

★★ **为什么索引 json 排在官方页之后**：本轮**实测**那份索引**未过滤**，
直接拿它按**成员名**比对会出 **147 处命中**，而绝大多数是**假阳性**
（★ 项目自己早记过三类：① 后继名 == 自己（解析错）· ② 不同 arity 的不同方法 · ③ 跳代伴随签名变化）。
★ 例：`SaveAs3` 在索引里被标成「废弃 → `SaveAs`」（**方向反了**）⇒ ★ 照索引补表会**污染正确的表**。

⇒ ★★ **本规格只新增 1 条**（`AddMate5`），且**逐字核过官方页原文 + 后继页无 `Obsolete` + 后继在仓库里真被调用**。

## 三、★ 边界（做什么 / 不做什么）

### 做

- `sw_com_traps.DEPRECATED_ENTRIES` += `("IAssemblyDoc", "AddMate5"): "CreateMate"`（**只登记**）。
- 扫描器收口：**点式形态** + **`call_assembly_doc`** 载体。
- 登记表改为 **「文件 → 成员名 → 处数」计数棘轮**（不按行号）。
- 新增两条判据：**登记表不许有死条目** · **点式形态不是盲区**（含合成负例 + 边界冻结）。
- 试点文件那条**死登记**改成按名字，并由新判据真的去核。

### **不**做（★ 每条都有理由，别在下一轮"顺手"做掉）

| 不做 | 理由 |
|---|---|
| **不改任何生产调用路由**（`sw_assembly.py:415` · `sw_assembly_doc.py:364` · `sw_connect.py:1167`） | ★ 铁律 2：无真机证据不得升级；★ 硬约束⑥：验不过的回退、不许留在柜台上 |
| **不把索引 json 的 1671 条全灌进靶子表** | ★ 上面 §二：未过滤，**三类假阳性**；★ 每条进来前要**读两边的签名**（那是独立的一件工作） |
| **不按 `mate_type` 直接分流** | ★ 官方三条分流是**按配合种类**分的，一个 `mate_type` 定不下来（spec §三 反例） |
| **不动 `sw_assembly_doc.add_mate` 的记档** | ★ 它的 docstring **已逐字记档保留**（通用包装拿不到 `mate_type` 语义）⇒ **记档不是待办** |
| **不把点式扫描做成"全量报"** | ★ 全仓 **2923** 个点式调用点 / **362** 个成员名 ⇒ 只能**按靶子表筛** |
