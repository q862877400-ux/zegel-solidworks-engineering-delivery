## 二、★★★ 本轮收敛出的定则（比代码值钱）
> **凡是「状态 / 数字」都要生成，凡是「判断 / 原因」才手写。**
> 两者混在同一节里 ⇒ **数字会随判断一起腐坏**，而**读者分不出哪半是旧的**。
```
这正是 §三 的病：它把「84 接口只覆盖 7 个」（数字）与「两个官方源同时失效」（原因）
写在同一个小节里 ⇒ 原因**至今可能仍成立**，而数字**早就过期** ⇒ 引用它的人**必然踩坑**。
⇒ 修法不是重写那一节，而是**把两半分开**：数字进生成物，原因留手写。
```

## 三、★ 而"零新门禁"是有意的
```
objective 明令「不重造已存在的基础设施」。本轮**一个门禁都没新增** ——
`gen_harvest_digest.py` ⇄ `check_digest_freshness.py` 这对**早就存在**，我复用它的逐字节判据。
⇒ ★ 这也解释了为什么它一开始就该放这里：**§4.2「明确不做」已经在同一个生成器里**，
  「仍空缺」与「不做」是同一件事的两半，**本来就该同源**。
```
