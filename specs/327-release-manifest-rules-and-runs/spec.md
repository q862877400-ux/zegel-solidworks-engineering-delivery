## §0 这一份规格要解决什么

| Q | 核心（逐字） |
|---|---|
| **Q12** | 「工具、元数据、方法和规则构成**同一发布清单及摘要，原子切换**；**计划固定摘要，升级不能悄悄重绑旧计划**」 |
| **Q13** | `RuleRequest` / `RuleResult` 两个结构；「**一个公式能运行，不表示它对当前材料、工况和标准版本适用**」；「效力来源**不可只引用检索引擎生成的摘要**」 |
| **Q14** | `output/runs/<run_id>/` 的目录结构；「**以同卷原子重命名发布新的提交清单**」；「**旧版本不覆盖、不删除**」 |

**★ 这三问的共同点**：★ 它们都在解决「**同一件事有几份说法**」——
★ Q12 说「**只有一份元数据**」，★ Q13 说「**公式与依据分开**」，
★ Q14 说「**只有一条提交链是权威**」。

## §2 交付物

### Q12 —— 发布清单

| # | 契约 | 判据 |
|---|---|---|
| **T1** | **同一发布清单** | ★ 四部分（工具 / 元数据 / 方法 / 规则）**各有摘要**，合成一个 `release_digest` |
| **T2** | **原子切换** | ★ 换清单是**整体换**（★ 不是逐件改） |
| **T3** | ★★ **计划固定摘要** | ★ 计划里存 `release_digest`；★ **清单变了 ⇒ 旧计划拒跑**（★ 不悄悄重绑） |
| **T4** | **禁止多份规则各自裁决** | ★ 同一性质**只有一个裁决者** |

### Q13 —— 规则取证服务

| # | 契约 | 判据 |
|---|---|---|
| **T5** | **`RuleRequest`** | `rule_id` · `rule_version` · `inputs`（带单位/来源）· `application_context` · `required_standard_editions` · `evidence_bundle_ref` |
| **T6** | **`RuleResult`** | `verdict` · `outputs` · `checked_preconditions` · `failed_obligations` · `citations` · `authority_status` · `missing_evidence` · **`rule_code_digest`** |
| **T7** | ★★ **公式与依据分开** | ★ 「一个公式能运行」**≠** 「它对当前材料/工况/标准版本适用」 |
| **T8** | ★★ **效力来源不可只引检索摘要** | ★ 必须有**官方状态记录**；★ 只引摘要 ⇒ `INDETERMINATE` |
| **T9** | **30 天新鲜度政策** | ★ 效力记录超 30 天 ⇒ **标 stale** |

### Q14 —— 落点与持久化

| # | 契约 | 判据 |
|---|---|---|
| **T10** | **`output/runs/<run_id>/` 结构** | `plans/` · `interfaces/` · `questions/` · `events/` · `attempts/` · `checkpoints/` · `commits/` |
| **T11** | ★★ **同卷原子重命名发布** | ★ 先写临时名、`os.replace` 到正式名 |
| **T12** | **旧版本不覆盖不删除** | ★ 新 revision 写新文件 |
| **T13** | ★★ **孤立暂存不算完成** | ★ 没有提交记录 ⇒ **不视为完成** |
| **T14** | **四类持久化** | 任务树 / 接口 / 证据 / 未决问题 |
| **T15** | **B 侧薄编排入口** | ★ 复用**同一规划核心**，★ **不另建状态与规则体系** |

## §3 Requirements

- **FR-001**: 系统 MUST 有**同一发布清单**（四部分 + 合成摘要）
- **FR-002**: 清单切换 MUST 是**原子**的
- **FR-003**: ★★ 计划 MUST **固定摘要**；清单变 ⇒ **旧计划拒跑**
- **FR-004**: 同一性质 MUST **只有一个裁决者**
- **FR-005**: 系统 MUST 有 `RuleRequest`（六字段）
- **FR-006**: 系统 MUST 有 `RuleResult`（八字段，含 `rule_code_digest`）
- **FR-007**: ★★ 规则 MUST **把公式与依据分开**
- **FR-008**: ★★ 只引检索摘要 ⇒ MUST **`INDETERMINATE`**
- **FR-009**: 效力记录 MUST 有**新鲜度**（30 天）
- **FR-010**: `output/runs/<run_id>/` MUST 有**七个**子目录
- **FR-011**: 提交清单发布 MUST 用**同卷原子重命名**
- **FR-012**: 旧版本 MUST **不覆盖、不删除**
- **FR-013**: ★★ 孤立暂存 MUST **不算完成**
- **FR-014**: MUST 持久化**四类**（任务树/接口/证据/未决问题）
- **FR-015**: B 侧入口 MUST 是**薄编排**（★ 复用同一核心）

---

## §4 Success Criteria

- **SC-001**: 发布清单**四部分齐**且**有合成摘要**
- **SC-002**: 换清单**是整体换**
- **SC-003**: ★★ **清单变 ⇒ 旧计划拒跑**
- **SC-004**: **一个性质一个裁决者**
- **SC-005**: `RuleRequest` **六字段齐**
- **SC-006**: `RuleResult` **八字段齐**
- **SC-007**: ★★ **公式能跑 ≠ 适用** —— 分开报
- **SC-008**: ★★ **只引摘要 ⇒ `INDETERMINATE`**
- **SC-009**: 效力记录**有日期**且可判 stale
- **SC-010**: 七个目录**都在**
- **SC-011**: 发布**原子**（★ 临时名 → `os.replace`）
- **SC-012**: 旧 revision **仍在盘上**
- **SC-013**: ★★ **孤立暂存不算完成**
- **SC-014**: 四类**都持久化**
- **SC-015**: B 侧入口**不另建**状态/规则体系
