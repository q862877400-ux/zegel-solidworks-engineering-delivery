## §4 ★★ 三个"最容易做假"的判据

★ 这三问都在解决「**同一件事有几份说法**」——
★ 而"只有一份"这种话**最容易只写在文档里**。★ 我的处置：

| 声明 | 判据落在哪 |
|---|---|
| 「计划固定摘要，升级不能悄悄重绑」 | ★ **计划里存 `release_digest`**；★ 跑前**必须核对**；★ 不一致 ⇒ **拒跑** |
| 「一个公式能运行 ≠ 它适用」 | ★★ **`applicability` 与 `verdict` 分开** —— 公式跑通但不适用 ⇒ **`NOT_APPLICABLE`**（★ **不是 PASS**） |
| 「效力来源不可只引摘要」 | ★★ **`source=retrieval_summary` ⇒ `INDETERMINATE`**（★ 结构性地挡） |
| 「不能由不同消费者自行选边」 | ★ **`ARBITER_TABLE`** —— 同性质再登记**不同**裁决者 ⇒ **拒** |
| 「旧版本不覆盖、不删除」 | ★ **目标已存在 ⇒ 拒**（★ 不是"警告一下"） |
| 「孤立暂存不能视作完成」 | ★ **文件在盘上 ≠ 有提交引用它** —— ★ **两者都要** |
| 「不另建第二套规划循环」 | ★ **`NOT_ALLOWED_TO_BUILD`** 清单 ⇒ 命中即拒 |

**★★ 共同点**：★ 每一条**都有一个判据会失败**，★ 不是"写了一段说明"。
