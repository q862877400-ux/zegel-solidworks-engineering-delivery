# Feature Specification: 交付报告的判据编号与 `AGENTS.md §一` 对齐

**Feature Branch**: `006-criteria-alignment`

**Created**: 2026-10-01 · **Status**: Implemented

**Input**: `AGENTS.md §一` 定义 **A1–A10 十条交付判据**；`harvest-report.md §四` 是**逐条自评**。
轮 82 实测：**两者对不上** —— 属于 **A8**（「报告写明并入了什么、仍空缺什么、为什么」）
**自己没做到**的那一半。

---

## 背景：这次为什么不是"改几个字"

实测报告 §四 用的是**另一套编号**（**同名不同事**）：

| 报告 §四 的编号 | 实际说的 | `AGENTS.md §一` 的真含义 |
|---|---|---|
| A3 | COM 签名对齐 | 五统一门禁 |
| A4 | 目录结构与上游一致 | `level` 五级枚举 |
| A5 | 许可无越界 | **COM 签名对齐** |
| A6 | 禁词 0 命中 | 许可无越界 |
| A7 | 报告写明补齐/空缺 | 禁词 0 命中 |
| A8 | fork 已创建 | **报告写明补齐/空缺/原因** |

⇒ 还**混入**「官方 API 覆盖」「目录结构与上游一致」两条**非 A 判据**的行，
并**缺 A1 / A9 / A10**。

★ 同类问题**此前已犯过一次**（旧 §一 的「A1」指的是官方 API 覆盖）
⇒ **靠人记必然再漂** ⇒ 必须变成机器判据。

---

## 一、验收判据

| ID | 判据 | 怎么验 |
|---|---|---|
| **SC-201** | 报告 §四 的编号集合 **==** `AGENTS.md §一` 的 A 编号集合（10 条，不多不少）| `python scripts/check_report_criteria_alignment.py`（退出码 0）|
| **SC-202** | 自评表里**不许**出现非 `A\d+` 的编号行 | 同上（它把那些行名单独列出）|
| **SC-203** | 新门禁**接进** `release_check`（不是"存在但没人跑"）| `python scripts/check_gate_wiring.py`（14 个门禁全接线）|
| **SC-204** | 新门禁的结果**进返回体汇总**（「跳过了」不许隐形）| 同上（汇总完整性段）|
| **SC-205** | 新门禁**有牙齿**：拿**写坏的报告**当输入必须红 | 见 [converge.md](converge.md) §2.2 的负例实测 |
| **SC-206** | 新门禁**便携**：`AGENTS.md` 拿不到时 **SKIP 且 exit 0** | 同 SC-205 的负例 |

---

## 二、**顺带修掉的一个假绿**（本轮实测撞见）

⚠ 修 §四 时我用一个（变量为空的）批量脚本把报告那行写成了 `> 偏离上游： · 工作区 clean`
—— **数字整段被抹掉** —— 而 `check_report_freshness.py` 打印
「**SKIP** —— 报告里找不到「偏离上游：…」那行」并 **exit 0** ⇒
`release_check` **全绿**、`test_report_freshness_gate` **也绿**。

★ 那正是本项目记录过的**第 4 种面孔**：**失败伪装成 skipped**。
⇒ 本特性**一并加固**：**区分两件事** ——
① **数据源不可用**（报告不存在）⇒ SKIP（便携性）；
② **报告在、但那行读不出来** ⇒ **红**（报告坏了就是坏了）。
判据见 **SC-207**（负例实测见 converge）。

---

## 三、明确**不做**的

* **不删**报告里原有的任何一节内容（只替换 §四 那一节的表）；
* **不改** `AGENTS.md`（判据定义是权威，报告向它对齐，不是反过来）；
* **不引入**新依赖。
