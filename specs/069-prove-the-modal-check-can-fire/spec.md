# 069 · 造一个**真模态框**，证明判据**能响**

**Status**: Implemented（轮 150）

## 一、起因：上轮缺的那一步
`068`（轮 149）把 21 份复制全量迁移，端到端输出变成「**扫了 49 个窗口 · 无模态框**」——
⇒ ★ 但那**只证明了判据「在扫」**（窗口数 1 → 49），
**没有**证明它**真能抓到一个模态框**。
⇒ 本轮补这一步。

## 二、★ 靶子：一个**真的 `#32770`**
`tools/fake_modal_dialog.py`（**不连 COM**、只在被测进程里建一个窗口）：
```python
DIALOG_CLASS = "#32770"          #: Win32 预定义对话框类（官方常量 WC_DIALOG）
STYLE = WS_POPUP                 #: ★ **故意不置 WS_VISIBLE**
```
⇒ 它打印自己的 PID 后停住，等测试来抓、来杀。

## 三、★★★ 证明（2 passed）
```
① test_the_check_can_actually_find_a_real_dialog
     ⇒ 新口径（不过滤可见性）**抓得到**那个 `#32770` ✓
② test_the_old_visibility_filter_would_miss_it
     ⇒ 旧口径（only_visible=True）**确实漏掉**它 ✓
```
⇒ ★★★ **「漏检 48/49」从一个说法变成了可复现的演示**（事实 62 的**正向**落点）。

## 四、⚠ 本轮踩的两个坑（都记下）
```
① **`0x10000000` 就是 `WS_VISIBLE`** —— 我把它当成了 `WS_OVERLAPPED`
   （后者的值是 `0x00000000`）⇒ 第一版靶子窗口**是可见的**（实测 visible=1）
   ⇒ **对照不成立**（旧口径也能抓到）⇒ 去掉即修。
   ⚠ 若没核对 `visible=?`，这个对照会**静默失效**（旧口径"也抓到"会被当成判据好）。
② ★ **`Stop-Process -Name python` 会杀掉所有 python 进程** ——
   我用它清理靶子 ⇒ **险些误伤环境**。
   ⇒ **必须按具体 PID 杀**。已确认本次没弄坏（SolidWorks 仍连得上、COM 正常）。
```

## ⚠ 明确记下的限度
* ⚠ 靶子是**我们自己造的** `#32770`，**不是** SolidWorks 真实弹出的模态框
  ⇒ 证的是「**判据能抓到这一类窗口**」，**不是**「SolidWorks 的某种具体弹窗能被抓到」；
* ⚠ 靶子窗口**不可见** ⇒ 它复现的是**旧判据的失效模式**，不代表真实模态框总是不可见；
* ⚠ 「窗口 vs 绘图区」**仍未查明**。
