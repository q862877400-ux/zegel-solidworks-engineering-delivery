# 侦察 · 「要求调用方先选」工具族（batch26 – batch50）

> 扫描范围：`mcp-server/tool_specs_batch26.py` … `tool_specs_batch50.py`（共 **25 个文件 / 108 个 ToolSpec**）。
> 机制前提 = **事实 503**：`tool_registry.py` 的 `make_tool_function._impl` 顺序是 `kwargs[inject] = resolver(params)`（★ `RESOLVERS["model"] → connect_solidworks` **会清空选区**，见 `docs/known-facts.md` 事实 503 的单变量隔离 `output/selection-lifetime-evidence.json`）→ `spec.pre_call(params)` → `derived_args` → 调目标函数 ⇒ ★★ **凡「要求调用方先选」又没有 `pre_call` 的，经工具层必然拿不到那个选区**。
> 方法：不 import，各 spec 文件用 `ast` 解析出 `ToolSpec(...)`（含 `_spec(...)` 这类「返回 ToolSpec 的助手」的展开）；再按 `spec.module` / `spec.function` 到 `scripts/` 里取该函数**及其同模块被调助手**的源码，搜 `GetSelectedObjectCount2` / `SelectionManager` / `resolve_selection` / `GetSelectionPoint` / `selection_count`；并逐条读 docstring 判断**「要求调用方先选」**（前置）还是**「回读选区信息」**（返回方向）。

## 真危险那批：按「最可能拿到选区的方式」排序

排序口径 = 补一个 `pre_call`（或连同参数）**能不能把选区真的拿到**，从易到难。

### 第 1 档 · 对外**已经有**声明式字段，只差把线接上（2 条）

| 工具 | 缺什么 | 依据 |
|---|---|---|
| `solidworks_surface_fill` | `selection` 参数已存在（默认 `""`）⇒ 只需给它挂 `pre_call=_select_edges(mark=1)`；⚠ 注意能力层轮 435 已**故意不再重选**（`Select4` 没有 mark 参数，选完 mark 变 0 ⇒ 填充不成）⇒ pre_call 必须**带 mark 选中** | `scripts/sw_surface_features.py::insert_fill_surface_report`：「**尊重调用方已选好的选区（含它的 mark）**」/ 「请先选上该填的那一圈边，**且用 mark = 1**」 |

## 拿不准 / 需要人来判的地方

1. **`solidworks_surface_fill` 分档**：只有 `selection` **非空**（声明式分支）才要求活选区；`selection=""` 走「自动取最高一圈」的旧路仍能成。我按保守口径算 **真危险**；若按「默认路径可用」口径，它可降为「无关 + 条件触发」。
2. **`solidworks_weldment_create_profile_center_mate`** 除了选区问题，还有一个**独立**的类型错：`entities` 是 `str` 而 `EntitiesToMate` 期望 COM 数组 ⇒ 我只按「前置选区」判它，**类型错未计入**。
3. **软依赖四条**（官方/能力层提到选区，但代码不读、或自解析、或有回退、或能降级 ⇒ 判 **无关**，只在此备注）：`solidworks_gtol_insert`（无选区也能建，只少引线）· `solidworks_part_shell`（`faces_to_remove` 未暴露、函数体不读选区）· `solidworks_surface_knit` / `solidworks_surface_extend`（`_select_all_surface_faces` 自己选全部面）· `solidworks_weldment_create_weldment_profile`（`_ensure_sketch_selected` 有按名字的回退链）。
