  `"★ The criterion is that the sketch entity count changes."`

### 6 · `solidworks_simulation_set_study_option` / `…_set_study_options`（batch37 → `sw_simulation_study_options`）
**判定：成立** —— doc 承诺未知族名/选项名「raises」，而包装层把异常吃掉改回 `ok: False`。

- **仓内那一段**（`mcp-server/tool_specs_batch37.py`，两条工具 doc 同句）：

## 存疑

### 7 · `solidworks_simulation_list_setter_summary`（batch36 → `sw_simulation_study_options.list_setter_summary`）
**判定：存疑** —— doc 括注了 `(family / name / type)`，但登记表里明明存了 type，函数却把它丢了。

- **仓内那一段**（`mcp-server/tool_specs_batch36.py` · 工具 doc）：
  `doc="Return the catalogue of simulation study-option setters (family / name / type) as a "`
- **目标那一段**（`scripts/sw_simulation_study_options.py`）：
  docstring：`"""返回各族 setter 数量与布尔型清单（供文档生成 / 自检使用）。"""`
  登记表类型标注：`STUDY_OPTION_SETTERS: dict[str, dict[str, str]] = {`
  函数体：`        family: {` / `            "total": len(items),` / `            "boolean": len(BOOLEAN_SETTERS.get(family, ())),` / `            "names": sorted(items),`

**一句话依据**：`STUDY_OPTION_SETTERS` 的值类型是 `str`（签名/type 串），但 `list_setter_summary` 只回 `total` / `boolean` / `names`，**按 doc 去取每个 setter 的 type 取不到**；判为存疑是因为 `boolean` 计数可被读成「部分类型信息」，且 doc 那句是括注。
