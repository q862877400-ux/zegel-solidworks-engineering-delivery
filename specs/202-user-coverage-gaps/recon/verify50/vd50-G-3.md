# vd50-G-3 · 导出工具的收尾检查（产物存在且非空）—— PDF 与 BOM / 切割清单

**本片范围**：`scripts/sw_review.py` · `scripts/sw_drawing*.py` · `scripts/sw_weldment.py` 里的 **PDF 导出** 与 **BOM / 切割清单导出**入口。
**判据来源**：本仓事实 250 —— 「**导出只回 `SaveAs` 的 bool 是不够的，要加『产物存在且非空』的收尾检查**」，判据抄自 `Cai-aa/CAD-Agent-Hub`（MIT）。

---

## 〇、判据原文（下面每条结论都拿它当尺子，只引一次）

### 〇-1 「官方/目标那一段」—— 判据本体（目标项目 `Cai-aa/CAD-Agent-Hub`，MIT）

`C:\swprojects\Cai-aa__CAD-Agent-Hub\MCP\Solidworks\docs\compatibility-and-lessons.md` 的 `## Save routing` 段：

```
- STEP, IGES, STL, PDF, DXF, and DWG exports use
  `IModelDocExtension.SaveAs`. They never pass through `SaveAs3`.
- Both paths verify that the target exists and is non-empty before reporting
  success.
```

★ **PDF 被这条判据点名了**（在 `Extension.SaveAs` 那一条里）⇒ PDF 落在判据射程内，不是射程外。

目标侧的实际实现（同仓 `MCP\Solidworks\src\solidworks_mcp\executor.py`）：

```
if not target.exists() or target.stat().st_size <= 0:
    raise RuntimeError(f"SolidWorks reported success but output is missing: {target}")
```

⇒ 判据的形状是**「存在」+「非空」两条都要**，且判据**落在产物上**，不是落在 COM 的 bool 上。

### 〇-2 官方那一段 —— 官方只承认 bool，所以这条判据是我们**加**的（对照说明）

`C:\swapi\types\IModelDocExtension\SaveAs3.md`：

```
## Returns
True if the save is successful, false if not
```

```
If the file is saved successfully, then the returned value is true and Errors is 0.
```

⇒ ★ **官方没有要求核对产物**（官方只说「返回 true 且 Errors 为 0」）⇒ 事实 250 的判据不是官方要求，而是从 CAD-Agent-Hub 抄来的**加固要求**。这不影响判据成立，只说明它的出处。

### 〇-3 「仓内那一段」—— 本仓落实了这套判据的那一处（作对照基准）

`scripts/sw_export.py::_export_generic` 的收尾段（事实 250 说「落地过一处」就是这里）：

```
    #: ★★★ 收尾检查：**产物要存在且非空**（★ 复用本文件既有的 `_file_signature`）
    signature = _file_signature(output_path)
    artifact_size = signature[0] if signature else None
    artifact_ok = signature is not None and signature[0] > 0
```

```
    #: ★ 判据取**两者的与**：★ 调用不报错 **且** 产物真的写出来了
    return bool(success) and artifact_ok
```

其来源块把出处写死在这里：

```
# 定位:   抄的是它 `docs/compatibility-and-lessons.md` 的判据：
#         「保存路由两条（原生 `SaveAs3` / 导出 `Extension.SaveAs`），★ **两条都
#          「验证目标存在且非空」才报成功**」。
```

⇒ ★ 基准形态 = **`bool(success) and artifact_ok`**，其中 `artifact_ok` 必须含 **`size > 0`** 那一项。**本片下面每条都按这一形状判**。

## 二、逐条详情

### G3-1 · `export_to_pdf` —— **不成立**

**仓内那一段**（`scripts/sw_export.py`，函数尾）：

```
    success = model.Extension.SaveAs(str(output_path), 0, 1, pdf_data, errors, warnings)

    _print_result("PDF", output_path, success, errors, warnings)
    return success
```

`scripts/sw_export.py::_print_result` 的全段（确认它只打印、不核对）：

```
def _print_result(format_name, path, success, errors, warnings):
    """打印导出结果"""
    if success:
        print(f"{format_name} 导出成功: {path}")
    else:
        print(f"{format_name} 导出失败, 错误码: {errors.value}, 警告码: {warnings.value}")
```

**官方/目标那一段**：`C:\swprojects\Cai-aa__CAD-Agent-Hub\MCP\Solidworks\docs\compatibility-and-lessons.md`

```
- STEP, IGES, STL, PDF, DXF, and DWG exports use
  `IModelDocExtension.SaveAs`. They never pass through `SaveAs3`.
- Both paths verify that the target exists and is non-empty before reporting
  success.
```

**判定：不成立。**
**一句话依据**：PDF 被目标判据点名要核产物，而这里 `return success` 把 COM 的 bool 原样透出，通篇没有任何 `st_size` / `is_file()`。

⚠ ★ 顺带一处**同函数的兄弟分支**（也是 PDF 面的事实，不另立条）：`batch_export_formats` 把 `.pdf` 交给它时，外面那层**补了**产物判定（见 G3-5）⇒ 单走 `export_to_pdf` 这条路时缺口是裸的。

### G3-3 · `export_assembly_bom_csv` —— **部分成立**（只缺「非空」半边）

**仓内那一段**（`scripts/sw_delivery.py`）：

```
    after = _file_signature(target)
    produced = after is not None and after != before
    return {
        "success": produced,
```

它复用的签名函数（同文件）：

```
def _file_signature(path: Path):
    if not path.is_file():
        return None
    stat = path.stat()
    return stat.st_size, stat.st_mtime_ns
```

**官方/目标那一段**：`C:\swprojects\Cai-aa__CAD-Agent-Hub\MCP\Solidworks\src\solidworks_mcp\executor.py`

```
if not target.exists() or target.stat().st_size <= 0:
    raise RuntimeError(f"SolidWorks reported success but output is missing: {target}")
```

（对应文档句：`Both paths verify that the target exists and is non-empty before reporting success.`）

**判定：部分成立（缺「非空」半边）。**
**一句话依据**：判据要求「存在」**且**「非空」两个条件，而这里的 `produced` 只由 `after is not None`（存在）与 `after != before`（本轮被改写）两项构成 —— 全程**没有一处拿 `st_size` 跟 0 比**，首次运行时 `before is None` ⇒ 一个 0 字节文件同样让 `produced` 为真、`"success"` 为真。

## 四、查不到的 / 不在射程的（如实写，不顶替）

1. ★ **`scripts/sw_review.py` 里没有 PDF / BOM / 切割清单导出函数** —— 按铁律 5 如实记「查不到」。
   该文件里与 PDF 相关的只有**只读**的解析入口，全段开头是：
   ```
   if source.suffix.lower() != ".pdf" or not source.is_file() or not 0 < source.stat().st_size <= 256 * 1024 * 1024:
   ```
   （`inspect_pdf_text_layout`）。它唯一带收尾检查的写出函数是 BMP 预览 `save_preview`，**不属于本片（PDF/BOM/切割清单）**：
   ```
   ok = model.SaveBMP(str(output_path), int(width), int(height))
   if not ok or not output_path.exists():
       raise RuntimeError(f"预览图导出失败: {output_path}")
   ```
   （★ 顺带可见：它也只有「存在」，没有「非空」。）

2. ★ **`scripts/sw_drawing_review.py` 本身不含任何导出函数** —— 它和 `sw_drawing.py` 同形，是一个兼容桥接文件，全段是：
   ```
   """工程图子技能审视器的兼容入口。"""
   ...
   _IMPLEMENTATION = (
       Path(__file__).resolve().parents[1]
       / "subskills"
       / "solidworks-engineering-drawing"
       / "scripts"
       / "drawing_review.py"
   )
   ```
   ⇒ 该文件在 PDF / BOM 出口上没有可核的函数。

3. ★ **BOM 的口径说明**（避免与切割清单混淆）：`scripts/sw_delivery.py::export_assembly_bom_csv` 自己在返回值里写了限制：
   ```
   "limitations": ["CSV 为装配组件属性清单，必须与 SolidWorks 原生 BOM 和工程图人工核对"],
   ```
   ⇒ 它不是 SolidWorks 原生 BOM 导出器，而是**属性汇总 CSV**；本条按「仓内唯一的 BOM 导出入口」核。
