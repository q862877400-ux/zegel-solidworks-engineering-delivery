# vd50-G-2 · 导出工具的收尾检查（产物存在且非空）—— DXF / BMP / 图片

**范围**：`D:/AI/SW/scripts/sw_export.py` 里 DXF、BMP、图片（PNG/JPG）三条路的导出函数。
**判据来源**：本仓事实 250（「导出只回 `SaveAs` 的 bool 是不够的，要加『产物存在且非空』的收尾检查」，判据抄自 CAD-Agent-Hub · MIT）。

---

## 〇、判据的「目标那一段」（三条结论共用同一段原文，只引一次）

**官方/目标原文**（`C:\swprojects\Cai-aa__CAD-Agent-Hub\MCP\Solidworks\docs\compatibility-and-lessons.md`，`## Save routing` 段）：

```
- STEP, IGES, STL, PDF, DXF, and DWG exports use
  `IModelDocExtension.SaveAs`. They never pass through `SaveAs3`.
- Both paths verify that the target exists and is non-empty before reporting
  success.
```

**目标侧的实际实现**（同仓 `MCP\Solidworks\src\solidworks_mcp\executor.py`，原生保存路）：

```
if not target.exists() or target.stat().st_size <= 0:
    raise RuntimeError(f"SolidWorks reported success but output is missing: {target}")
```

⇒ ★ 判据的形状是**「存在」+「非空」两条都要**，且它**落在产物上**，不是落在 COM 的 bool 上。

## G-1 · `export_to_dxf` —— **不成立**（分支不一致）

**仓内那一段**（`scripts/sw_export.py`，函数体全段）：

```python
    doc_type = get_com_member(model, "GetType")
    if doc_type == 3:  # 工程图
        return _export_generic(model, output_path)
    else:
        # 零件默认按“展开几何 + 折弯线”导出；其余选项由位掩码控制。
        return export_flat_pattern_dxf(model, output_path)
```

**官方/目标那一段**：同 §〇 的 `Both paths verify that the target exists and is non-empty before reporting success.` —— 且这条明确点名 DXF/DWG：`STEP, IGES, STL, PDF, DXF, and DWG exports use IModelDocExtension.SaveAs`。

**一句话依据**：工程图分支落到 `_export_generic`（那段有检查），**零件分支落到 `export_flat_pattern_dxf`（那段没有）** ⇒ 同一个 `export_to_dxf` 名字下，两条分支的判据强度不一样。

⚠ **同一缺陷链**：G-1 与 G-2 是**同一条链的两端**（分发者与被分发者），**不是两个独立缺陷** —— 修 G-2 即同时修掉 G-1 的零件分支。

## G-3 · `export_to_bmp` —— **不成立**（只看官方 bool，成功时无条件回 Path）

**仓内那一段**（`scripts/sw_export.py`，函数末尾）：

```python
    ok = get_com_member(model, "SaveBMP", str(p), int(width), int(height))
```

**官方/目标那一段**（目标项目对**同一个** `SaveBMP` 的做法，`MCP\Solidworks\src\solidworks_mcp\inspection.py`）：

**一句话依据**：目标项目在**官方那个 bool 之外还加了「存在 + 非空」**（官方 `C:\swapi\types\IModelDoc2\SaveBMP.md` 的 Returns 原文是 `True if file is created successfully, false if not`），而我们这里 `ok` 一真就 `return p`，**产物校验整段不存在**。

## 二、★ 如实记：这 3 处缺口**在工具层被盖住了**（不夸大）

- 三个 MCP 工具走的都是 `*_report`，不是裸函数：`solidworks_export_dxf` → `function="export_dxf_report"`；`solidworks_export_bmp` → `function="export_bmp_report"`；`solidworks_export_image` → `function="export_image_report"`。
- 批量路自带检查：`batch_export_formats` 里 `produced = api_success and after is not None and after != before`，且 `.dxf` / `.dwg` 也走这条 ⇒ 批量导出 DXF 时是有产物回读的。
- `export_flat_pattern_dxf` **没有**注册成 MCP 工具（`mcp-server/tool_specs_batch59.py` 的来源块里明写「★★ `export_flat_pattern_dxf` 本批不注册」）。

⇒ ★★ **所以缺口只在「直接调 `scripts/sw_export.py` 的裸函数」时暴露**（脚本、探针、其它仓内代码），**从 MCP 工具调用看不到**。这一条必须写明，否则会把缺口读得比实际大。
