### 1 · `solidworks_sketch_spline`（batch76 → `sw_part.sketch_spline`）—— doc 把「必须先有活动草图」归因成**官方 Remarks**，官方逐字写的恰是反面

**判定：成立** —— 工具 doc 与目标函数 docstring/报错文案都把这条写成「官方 Requirements」，而官方页原文说**没有活动草图时会新建一个**。

- **仓内那一段**（`mcp-server/tool_specs_batch76.py` · 工具 doc 末句）：
  `"★ 前置（官方 Remarks）：**必须先有活动草图**。"`
- **目标那一段**（`scripts/sw_part.py` · `sketch_spline` 抛错文案）：
  `"② 是否**已有活动草图**（官方 Remarks 要求）。"`
- **官方那一段**（`C:\swapi\types\ISketchManager\CreateSpline2.md` · `## Remarks`）：
  `This method creates a spline in the active 2D sketch. If a sketch is not active, then a new sketch is created. Use [[ISketchManager::ActiveSketch]] to check if the sketch active.`

**一句话依据**：官方逐字是「**若没有活动草图，则新建一个草图**」，即活动草图**不是**前置；而 doc 与目标函数的报错文案都把它写成「官方 Remarks 要求」。
★ 补一句来源对照：本仓把「必须先有活动草图（否则不建、回 `None`）」这句**真正属于官方**的话挂在 `CreateLine2` 上（`capabilities.yaml` 的 `sketch_line2` 条逐字引官方 `"If a sketch is **not active**, then the line is **not created and NULL is returned"`）⇒ ★ 这里像是**把 `CreateLine2` 的前置搬到了 `CreateSpline2` 上**。

### 2 · `solidworks_feature_cosmetic_thread`（batch76 → `sw_feature_entry_ops.insert_cosmetic_thread`）—— doc/模块注释称枚举值「**逐字取自 `InsertCosmeticThread3.md` 的 Parameters 段**」，该段里没有这两个数值

**判定：成立** —— 数值本身对，**出处标错**（官方方法页的 Parameters 段只指向枚举，不含数值）。

- **仓内那一段**（`scripts/sw_feature_entry_ops.py` · 常量区注释）：
  `#: ★ 官方枚举值（逐字取自 `InsertCosmeticThread3.md` 的 Parameters 段）`
  下面两行即 `STD_ANSI_METRIC = 1  #: `Standard`：1 = ANSI Metric` 与 `END_TYPE_THROUGH = 2  #: `EndType`：2 = Through`；
  工具 doc 的 `Param` 描述同样标注出处：`Param("standard", int, description="螺纹标准：**1 = ANSI Metric**（官方 `Standard`，逐字）。")` 与 `Param("end_type", int, description="末端条件（官方 `EndType`）：**0 = Blind**（此时 `depth_mm` 有效）· **2 = Through**。")`
- **官方那一段**（`C:\swapi\types\IFeatureManager\InsertCosmeticThread3.md` · `## Parameters` 逐字）：
  `- **Standard**: Thread standard as defined by [[swCosmeticStandardType_e]]`
  `- **EndType**: End condition as defined by [[swCosmeticEndConditions_e]]`
  （数值实际在 `C:\swapi\enums\swCosmeticStandardType_e.md` 的 `swStandardType_StandardAnsiMetric | 1` 与 `C:\swapi\enums\swCosmeticEndConditions_e.md` 的 `swEndConditionBlind | 0` / `swEndConditionThrough | 2`）

**一句话依据**：doc 与模块注释都把这句「1 = ANSI Metric」「2 = Through」标成官方方法页 Parameters 段的逐字，而那一段逐字只是**指向两个枚举**，照着它 grep 找不到这两个数 ⇒ ★ 值对、出处不实（按铁律 5，两处原文都给出，不裁定哪个意图）。

## 存疑

### 3 · 三条工具 doc 的「判据」写成 **特征树新增 `+` 返回对象 `GetTypeName2`**，目标函数里的 `ok` 是 **`or`**

**判定：存疑** —— 两个证据量**都回读并都写进返回值**了，所以「两条都报」成立；但 doc 用「+」承诺的**合取**判据，代码写的是**析取**（任一为真即 `ok=True`）。

- **仓内那一段**（`mcp-server/tool_specs_batch76.py`，三处同句式）：
  `"★ **判据**：特征树**新增** + 返回对象 `GetTypeName2`（★ 真机建成时是 **`CosmeticThread`**、名 `装饰螺纹线1`）。"`
  `"★ **判据**：特征树**新增** + 返回对象 `GetTypeName2`（★ 真机建成时是 **`FlattenSurface`**、名 `曲面-展平1`）。"`
  `"★ **判据**：特征树**新增** + 返回对象 `GetTypeName2`（★ 两条都报）。"`
- **目标那一段**（`scripts/sw_feature_entry_ops.py` · 三个函数末行同句式）：
  `out["ok"] = bool(out.get("ret_type") == "CosmeticThread" or out.get("new_features"))`
  `out["ok"] = bool(out.get("ret_type") == "FlattenSurface" or out.get("new_features"))`
  `out["ok"] = bool(out.get("new_features") or out.get("ret_type"))`
- 同模块自述（加重这一条）：
  `★ 那说明"**树增量**"这条判据在本模块里**是假的**（★ 本格的 `ok` 是靠 `ret_type` 成立的，不是靠树）。`（`_feature_names` 的 docstring）

**一句话依据**：`ok` 是 `or` ⇒ **类型名不对但树动了**也会判成功，与 doc 写的「+」不一致；判为**存疑**是因为 doc 也可能只是在说「两项都回读当证据」（三项都确实都回读了），且 `thicken` 那条自己括注了「★ 两条都报」。
