  names = getattr(params, "profile_sketches", None) or []

## F2-4 `mark` 落在 `SelectByID2` 的**第 7 位**（= 官方那一档，没被挪到别的槽）｜ **成立**

这一条是「**我们传几**」的落地校验：光看字面 `int(mark)` 不够，要确认它进了 `Mark` 形参。

- 仓内（`mcp-server/tool_specs_batch4.py` · `_select_sketch_by_name`）：
  ```python
  return bool(get_com_member(
      get_com_member(model, "Extension"), "SelectByID2",
      str(name), "SKETCH", 0.0, 0.0, 0.0,
      bool(append), int(mark), create_empty_dispatch_variant(), 0))
  ```
- 官方（`C:\swapi\types\IModelDocExtension\SelectByID2.md` · **Signature**）：
  > `System.bool SelectByID2( System.string Name, System.string Type, System.double X, System.double Y, System.double Z, System.bool Append, System.int Mark, Callout Callout, System.int SelectOption )`
  > - **Mark**: Value that you want to use as a mark; this value is used by other functions that require ordered selection

- 依据：9 个位置**逐位对上**（Name / Type / X / Y / Z / Append / **Mark** / Callout / SelectOption）⇒ 传入的 `int(mark)` 确实落到官方 `Mark` 形参，SOLDWORKS 收到的那一档就是 F2-1…F2-3 里对过的那一档。
  ★ 回读方向同样对得上（`C:\swapi\types\ISelectionMgr\GetSelectedObjectCount2.md` · **Signature** `System.int GetSelectedObjectCount2( System.int Mark )` · **Mark**: `Any other value = Value that was used to mark and select an object`）⇒ 仓内 `_mark_count(model, mark)` 读的就是同一档，不是「全部选中」（那要用 `-1`）。

## F2-5 选的**形态 + Append 序**与官方例子逐位一致（mark 对上的前提）｜ **成立**

- 仓内（`mcp-server/tool_specs_batch4.py` · `_select_sketches_in_order`）：
  ```python
  for i, nm in enumerate([n for n in (names or []) if str(n).strip()]):
      _select_sketch_by_name(model, nm, mark, append=(i > 0))
  ```
  ⇒ 扫描：轮廓 `append=False`（`i==0`）→ 路径 `_select_sketch_by_name(model, path, 4, True)`；放样：第一个轮廓 `False`、其余 `True`。
- 官方（两例逐字，扫描例见 F2-2、放样例见 F2-3）：两条都是 **`False` 打头、`True` 跟上**，且**按草图名 + `"SKETCH"` 选**（不是按点、不是按面/边）。
- 依据：仓内既选了**同样的实体形态**（草图本身），**又给了同样的 Append 序** ⇒ mark 1 / 4 落在与官方例子同构的选区上；否则「数字对、形态错」也会建不出特征。
