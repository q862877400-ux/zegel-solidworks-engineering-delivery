## F-5 · `part_wrap` · 官方 mark 在 MCP 工具面上**无处施加** —— 判定：**成立**

- **官方原文（在）** — `C:\swapi\types\IFeatureManager\InsertWrapFeature2.md` 的 `## Remarks` 逐字：
  `To select...`
  `Use [[IModelDocExtension::SelectByID2]] or [[IModelDocExtension::SelectByRay]] and specify a Mark of...`
  随后三档取值 `1`（面）/ `2`（拔模方向）/ `4`（2D 草图）——
  ⇒ ★ 官方把「用哪两个 API、按哪几档 mark 选」写成**调用前的硬前置**。
- **我们的原文（在）** — `mcp-server/tool_specs_batch4.py` 里逐字：
  `「显式拒」那一族（part_sweep / part_loft / part_axis / part_wrap）**都要**在 pre_call 里按官方 mark 把**草图**选上`
  `mcp-server/tool_specs_batch48.py` 里逐字（同一病灶在 sweep 上的原话与修法）：
  `★ 而**原先这条 spec 既没有 selection 类参数、也没有 pre_call** ⇒ ★★ **调用方无从提供选区** ⇒ **经工具层必然失败**`
  ★ 而 `mcp-server/tool_specs_batch50.py` 里 `solidworks_part_wrap` 的 `ToolSpec` **只有三个 Param**（逐字
  `Param("wrap_type", str, default="emboss",` · `Param("thickness_mm", float, default=1.0,` ·
  `Param("reverse", bool, default=False,`），
  **没有 `pre_call=`、没有 `param_alias`、没有任何 selection 入参**；它的 `doc` 逐字写的是
  `★ **对已选中的「草图（mark=4）+ 面（mark=1）」建包覆特征**`
  ⇒ ★ 而 `scripts/sw_wrap.py::create_wrap_report` 逐字 `if sel.get("sketch", 0) < 1 or sel.get("face", 0) < 1:`
  会在选区为空时逐字返回 `"error": "包覆要选 **草图（mark=4，★ 必须是 2D 草图）** 与 **面（mark=1）**"`。
- **依据**：同族四条里 `part_sweep` 已按 batch48 的修法补上 `pre_call=_pre_sweep_sketches`、
  `part_loft` 在 batch47 补上 `pre_call=_pre_loft_profiles`；唯独 `part_wrap` 的 `ToolSpec` 至今没有任何入口
  能把官方要求的 **mark 4（草图）** 与 **mark 1（面）** 打上去 ⇒ 经 MCP 工具面调用时，官方 mark 无处施加，
  必然落到 `create_wrap_report` 的选区拒绝分支。
  ★ **旁证（说明为什么真机曾跑通）**：`docs/known-facts.md` 事实 254 逐字
  `**InsertWrapFeature2` 在"选择正确"时仍**静默不建**（不抛异常、特征树不变）** —— 2026-10-01（轮 329）`
  ⇒ 那次真机 PASS 的前提是「选择已经是对的」（直接调 wrapper、选区已在），**不是经工具层打上的 mark**。
  ★ 该项仓内已有记录（`specs/202-user-coverage-gaps/recon/preselect-family-b.md` 逐字
  「mcp-server/tool_specs_batch50.py 的 spec **没有 pre_call**、也没有 selection 参数」）—— 本条是**复核确认**，不是新发现。
