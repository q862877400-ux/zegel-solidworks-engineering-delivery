# 109 · 用**类型库方向信息**复核既有 byref 规则 ⇒ **负结果：规则无害**（但机制性反例存在）

**Status**: Implemented（轮 189）· ⚠ **负结果**（假设成立、但在调用面上不命中）

## 一、起因：一个**有机制**的假设
```
`scripts/audit_byref_args.py` 的口径：
  > `Int32&` **算**一个（必须传），`Object&` / `Variant&` / `Dispatch&` **不算**（纯出参，不用传）
★ 这条**来自反射文本**，而反射的 `&` **只说明「按引用」、不区分方向**
  ⇒ 「`Object&` 是否真的『纯出参』」原本是**假设**。
★★ 而轮 188 用**类型库方法表**（第 4 套源）发现它**给方向**，且
  `ISafeArrayUtility.PutDouble(VariantArray = **in,out**)` 是一个**必须传**的数组形参
  ⇒ ★★ 机制上成立：**那条口径会漏掉 `in,out` 的数组形参**。
```

## 二、★★★ 实测（`tools/audit_inout_array_params.py`，纯静态）
```
扫了 **507** 个接口
含 `in,out` 数组类形参（VARIANT / LP_tagVARIANT / POINTER(IDispatch) / POINTER(IUnknown)）
  的成员 = **62** 条记录 ⇒ 去重 = **29** 对 (成员, 接口)
  例：IBody2.GetMiddleSurface · IFeature.GetBox ·
      ICustomPropertyManager.GetAll / GetAll2 / GetAll3 · IBomFeature.GetConfigurations …
★★ 而**本仓库生产代码按字面量调用过的 = 0**
   （唯一命中的 2 个 `PackVariant` / `PutDouble` **只出现在探针**里）
★ 把检查面**扩大**到「全仓库 · 排除探针/登记表/测试/生成物 · **连点调用也算**」⇒ **仍然 0 命中**
⇒ ★★★ **那条口径在实践中目前无害** —— 不是因为它对，而是因为**我们还没碰那 29 对成员**。
```

## 三、★★★ 顺手抓到一处**源间方向分歧**（铁律 4 的具体实例）
```
同一个 `PutDouble` 的 VariantArray：
  · swapi md    : `out`        （"void PutDouble( out System.object VariantArray, …)"）
  · 反射文本    : `Object&`    （只说明按引用，**无方向**）
  · 类型库      : **`in,out`** （comtypes flag=3）
                  ★ 同表里 `GetInfo` 的 Count/Type 是 **flag=10 = out** ⇒ 它**确实在区分**，不是默认值
  · 实测（轮 188）: 传**全新** `VARIANT()` ⇒ **没回写** ⇒ 与 **`in,out`** 一致
                    （`PutDouble` 是**往已有数组里追加** ⇒ 需要**已有的**数组）
⇒ ★ 按**铁律 4**（冲突以**出厂类型库**为准）⇒ **类型库赢**，md 的 `out` 是**简化措辞**。
```
