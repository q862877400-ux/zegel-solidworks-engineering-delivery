## 定则

**动手碰任何一个 API 成员之前，先把那个成员的官方页读完** —— ★ 三样缺一不可：

| # | 读什么 | 在哪 |
|---|---|---|
① | 签名 + `## Parameters` | `C:\swapi\types\<接口>\<成员>.md` |
② | **`## Remarks`** | 同上（★ **前置与语义几乎都写在这里**） |
③ | **那一页顶上的 `Example` / `See Also` 链接** | `D:\AI\SW\AI Solidworks\官方文档\`（CHM 解包） |

★ **为什么第 ③ 样最容易被漏、而它信息量最大**：★ **例子给的是"调用序"，签名与 Remarks 都给不了。**
★ 而 `See Also` 会**列出同族的邻居方法** —— ★ 本仓正是从那里挖到过**从没查过的专用方法**。

⇒ ★★ **"试参数"是最后手段，不是主要手段**：
★ 先把上面三样读完；★ **读完仍不成，才允许开探针**，★ 而探针的 `来源块` 里要**写明读的是哪一页**。
★ **查过而查不到** ⇒ 按**铁律 5** 写「查不到」并换思路，**不要用相似名字蒙混**。

## 定则 ② · 示例的 `Preconditions` **不得默认升级为 API 契约**

★ **官方示例里的 `Preconditions` 默认解释为「该示例可复现时所需的环境 / 前置条件」** ——
★ **除非** API Reference 的 `## Remarks` / `## Parameters` / Requirements **或真机行为**明确证明
它是 API 的**强制前置**，★ **否则不得直接升级为能力契约** ✓

★ **实证（规格 209 · B2-2 · idx 34 `balloon`）**：官方示例 `Add_Autoballoon_to_Face_Example_VB.md`
的 `Preconditions` 逐字要求「Open a drawing **with a bill of materials (BOM) table**」——
★ 而**真机两格独立对照**：★ **没有 BOM 表那格照样插进去了**（`GetNoteCount` **0 → 1**、返回数组长度 1）⇒
★ 「**示例里存在 BOM**」推不出「**API 必须有 BOM**」✓（★ 本条是先按示例推断、**被真机否证**才记下的）

★ **同理**：示例里的 **mark / 参数 / 调用顺序**也要分「**示例复现条件**」与「**API 强制要求**」——
★ 例：`InsertSheetMetalUnfold` 的 **`mark 4` 不是必需的**（只给固定面 mark 1 也建得出 `展开1`，规格 209 §五 第 11 条）✓

★ **可复用的分类法**（用于 `docs/recon-206/pre-code-conflict-lookup.md` 的 `precondition_diff` 那批）：
★ **不逐条重验**，先分四类 —— **A 纯示例环境** · **B 官方明确写成 API requirement** ·
**C 官方未说明、代码曾自行推断** · **D 已有真机证据** ⇒ ★ **优先处理 C**
（★ 那是唯一"我们当年自己猜的"一类，也是最可能已经错了的一类）✓
