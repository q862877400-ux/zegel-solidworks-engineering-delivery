## 〇、为什么是"判据优先"（★ 这一轮的主题是上一轮**用五次事故换来的**）

```

   ⑤ 轮 417–419 判据**在这条路上间歇性不稳**  ⇒ B 组两条连接件**拿不到正例**
⇒ ★★ **命题**：★ **判据本身也是被测对象** —— 它必须**先被验过**，才能拿去判别人。
   ★ 而这件事**现在只写在事实里（320/323/329/330/332/333/334）**，★ **没有工具、没有门禁**。
⇒ ★★★ 本轮的**核心交付**就是把它**从"我下次记得"变成"机器每次都做"**（与 §三「把验证责任转移到静态比对」同一族）。
```

## 三、硬约束（★ 沿用 v2，一条不改）

```
① 完成判据必须是一条**能跑出绿的命令**
② **数字只从生成物来**（不手写）
③ 每件「声称完成」必须有 `output/*-evidence.json` 的 `verdict: pass`，否则标注「未真机验证」
④ **核功能不核名字**
⑤ **不把"成员没碰过"当待办**
⑥ **验不过的回退、不许留在柜台上**
⑦ **不碰高风险写操作**（保存 / 另存 / 删除）
⑧ 只做**已核实的真缺口**
⑨ 新增文件必须带**标准来源块**（六字段 + 覆盖声明）
⑩ 改了运行时文件必须重跑 `sync_bundled_skill.py`
★ ⑪ **判「未建成」之前，先穷举「调用前提」这一维**（★ 本轮新增 —— 上一轮五次事故的定则）
★ ⑫ **换判据之前先验判据**（★ 本轮新增 —— 在已知成功的场景上看它能不能复现 `0→1`）
```
