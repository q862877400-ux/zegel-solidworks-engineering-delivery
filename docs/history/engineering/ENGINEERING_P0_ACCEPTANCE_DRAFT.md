## 2. 验收证据规则

每条记录必须含：正式feature编号、FR/SC、任务、测试身份、执行版本、环境、输入、期望、实际、容差/规则、工件与哈希、错误/未知、阶段等级、结论和责任人。

- 不共享被测实现计算出来的期望值。
- 不用截图或返回true代替机器可读效果回读；截图可作为辅助。
- 正例与负例都必须保留，不能只交漂亮结果。
- 失败样例不能在验收时删除；范围变化先走spec变更。
- 工件修改/重建/配置变更后，证据是否仍有效按版本和影响范围检查。
- 测试桩结果只证明离线契约，不能升级为COM实际验证。
- 因环境阻塞的任务写blocked/not_run，不写pass或not_applicable。

- [ ] spec/plan/tasks/contracts/acceptance没有相互矛盾的结果语义。

- [ ] 旧状态/来源/负面事实不被新任务自动清空。

- [ ] 无可靠版本/回读时承诺降级并阻断相应放行。

- [ ] 依赖无环，公共文件单责任人，真机串行。
