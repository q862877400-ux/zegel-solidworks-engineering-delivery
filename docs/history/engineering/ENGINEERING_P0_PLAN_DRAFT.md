## 3. 数据流与责任边界

```text
公开工具请求
  → 查唯一ToolSpec/风险/旧契约适配
  → schema/量纲/参数域校验
  → 规范化值与请求记录
  → 核验文档/配置/模型版本/引用/编辑态
  → 进入现有单会话互斥与弹窗护栏
  → 调用已确认的COM边界
  → 即时效果回读/必要重建后回读
  → pass/fail/unknown与恢复状态
  → 绑定最终版本的证据
  → 原工具结果兼容适配
```

Agent只提交请求与解释；不能通过自然语言解除门禁。执行器负责调用与异常；验证器用只读回读/确定性几何判据，不复述执行器布尔值。证据记录器不自行签发工程审签。

## 5. 核心算法与失败处理

### 5.1 单位

1. 查ToolSpec字段的物理量、公开单位、规范化单位、COM边界单位及历史默认。
2. 拒绝未知单位、错误量纲、非有限值及不符合域约束的值。
3. 用受测映射 `normalized = supplied × scale`；偏置单位如温度独立定义，不混用乘法。
4. 规范化结果用不同结构包装，避免作为原始输入再次进入转换。不能只靠字段名以 `_mm` 结尾推断。
5. 到官方确认的COM接口边界转换一次，记录目标单位和实际参数。
6. 输出必须标单位；尺寸回读按同样规则规范化后比较。

同单位对照不只测10 mm，还要测小值、大值、允许零值/负值、重复规范化、旧接口混合调用。长度负值是否允许由字段语义决定，不能全局禁止或允许。

### 5.2 文档身份与版本

- 模型身份至少区分会话内文档、配置、保存身份；未保存文档不能把空路径当全局唯一ID。
- 请求记录预期模型版本。执行前检查，不一致则拒绝或重新计划；不能执行后补写版本来合理化。
- 文件哈希只能描述保存字节，不能代表尚未保存的内存模型。现有内存指纹能否检测尺寸/特征/配置变化需先研究。
- 若无可靠内存变更检测，采用保守策略：受控节点、禁止未确认外部编辑、明确保存检查点；无法确认时unknown，不声称强一致。
- 完整作业租约/围栏与全链批准版本绑定由EC04实现；EC00只定义兼容字段和本地边界。

### 5.3 引用解析

```text
持久引用恢复
  → 类型/所属文档/配置检查
  → 语义锚点核验
  → 几何签名与容差比对
  → 唯一候选才返回
  → 0候选/多候选：拒绝并记录
```

重建/特征替换可能改变拓扑。持久引用字节相同不等于一切语义稳定；几何接近也不能自动确认是原对象。只记录定位证据，不猜测API返回包装。

### 5.4 关系效果

- 前态记录实体类型/身份、已有关系、关键坐标或曲率度量、预期自由度。
- 按已核验官方签名和调用序提交关系。
- 后态回读关系与义务。关系存在但几何不满足、或几何巧合满足但未建立应持久的关系，均不能当作完整成功。
- 数值判据使用 `abs(error) ≤ abs_tol + rel_tol × scale`，容差与尺度定义随关系类型冻结；不能任意放宽到刚好通过。
- 相切要核验相关方向/接触位置的语义；重合与相等也要区分对象类型，不能统一比较一个坐标。
- 欠约束不天然失败，过约束不天然由加更多关系解决。预期自由度必须明确。
- 无可信关系回读时返回unknown；安排限定探针，不将“看截图像对”升级成机器通过。

### 5.5 效果状态机

```text
validated → context_checked → executing
  ├─ known no execution → rejected/failed
  ├─ returned → inspecting → pass/fail/unknown
  └─ timeout/ambiguous COM error → uncertain
                                  └─ inspect/recover，不能直接retry
```

“没有完成返回”不等于“没有修改”。异步护栏退出、COM服务错误和读取失败都可能产生不确定状态。只有操作可证实未执行、已满足或可受控补偿时，才能选择下一步。

### 5.6 恢复与写入保护

- 不对所有动作提供通用rollback；COM操作不是数据库事务。
- 使用批准的自有检查点、前向补偿或停止人工处理；逐类定义。
- 保存重开只操作自有样例，用户未保存文档不在自动关闭/重启范围。
- 特征创建超时：先检查是否存在预期效果及多余实体；无法判断则停止。
- 旧入口兼容时不改变恢复语义，更不能把unknown压回true。

## 7. 测试分层

### L0 静态契约

注册与参数/来源/单位/风险/效果/旧映射一致；发现缺字段按unknown/阻塞登记。静态解析不能导入有连接COM副作用的模块。

### L1 纯离线单元/状态测试

单位等价、错误量纲、非法数值、重复转换、上下文冲突、引用歧义、true无效果、证据过期、超时非幂等、脱敏。

### L2 公开路由集成桩

从真实ToolSpec构造调用，检查注入和参数包装、互斥和前后置；内部函数绿但公开路由错必须被抓到。桩测试不能称为COM验证。

### L3 受控真机

官方依据核完、依赖/权限就绪后运行：关系正负例、几何尺寸回读、重建、保存重开、错文档保护和安全竞争。会挂或无可靠回读时保留unknown和负面事实。

### L4 收口

聚焦测试、适用的仓库门禁、证据映射和台账；全量按既有规则。文字编写不运行真机门禁。

## 8. 实施次序

1. G0权属和基线→G1范围冻结。
2. 官方与死路限定研究→单位/结果/版本契约→G2。
3. 先负例测试，再边界实现；跨文档一致性→G3。

## 9. 迁移与退出

- 旧入口保持原公开契约或返回明确弃用错误；禁止静默将历史单位改为新单位。
- 适配层记录调用路径与默认依据，纳入同一门禁。
- 真机未通过时不开生产新路径；离线成果可合并到受控开发路径，但标明等级。
- 验收失败不能修改参考值迎合输出；需要需求变更时保留前后版本和原因。
- EC00退出后输出范围清单、可信代表工具、未关闭欠账和后续EC01/EC04接口；没有全域"工具全部可信"宣言。

## 10. 冻结准备决策（旧表面保持 · 新工程入口）

以下为本轮**明确冻结**的兼容决策，后续实现不得单方面推翻；依据 `output/ENGINEERING_PARALLEL_PREFLIGHT.md` §3.3 的 C01–C16 与 `mcp-server/tool_registry.py` 实际代码。
