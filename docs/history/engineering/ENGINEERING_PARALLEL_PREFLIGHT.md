## 4. 原交接的纠错决定

1. “旧DSH配置查不到模型”不能推出模型不存在；本次WorkBuddy两个自定义类型有回报。
2. 原model_ref按职责映射到glm/gemini，违反20＋20目标。新名册按DS/HY侧绑定，不回退默认模型。
3. “只读6路”是旧建议，不是本次上限；删掉人为上限，保留40目标，不保证每时刻40个都运行。
4. 原 `allowed_now = gate == A` 忽略依赖：11个A级槽位仍依赖产物。新名册分独立源码初审与依赖产物复核；未齐的复核不判就绪。
5. 原草案开头“11/9/20”和实际“22/12/6”统计矛盾；以实际解析条目为准。
6. output被gitignore不提供隔离；独立目录、writeScopes、提示词都不是OS文件锁。
7. 同文件不同函数仍可能冲突；公共文件单点合并，40人不直接共享工作树写代码。
8. `_COM_LOCK`存在性检查不证明原子锁或异常恢复；当前COM禁止，未来单执行责任人串行队列，另行验证跨进程互斥。
9. class=S不是COM授权；“用完必须关SolidWorks”不安全。不得关闭不属于本次的文档/会话。
10. round_chain当前确有 `git add -A` 和 `reclaim_solidworks.py --close`；不作为各路纯验证命令，先由唯一责任人提出副作用拆分。
11. fixed=False不足以装配验收；还要按任务核配合语义、自由度、干涉、传动关系、保存持久性。
12. COM侧单位不能全局断言；按成员级官方签名/Remarks/示例及本仓冲突索引裁决。

## 6. 隔离与合并

- 当前只读准备无需创建40个worktree或全仓副本。
- 正式编码首选：唯一基线责任人制作“HEAD＋明确归属的未提交文件覆盖层”，再建独立候选区。裸HEAD会漏掉sw_part修复和新关系文件，不能直接用。
- 候选区业务写授权与共享主检出分开；后者仅唯一合并人写。未验证路径权限只能称流程隔离，不能称硬隔离。
- 无独立写区则只交补丁文本/提案；不得先改共享源码再用git diff假装隔离。
- 候选补丁含源文件哈希、路径、来源许可、契约影响、测试命令与结果。应用前核基线和路径；漂移/未知权属停止，不自动重放。
- Windows路径核大小写、斜杠、相对路径、重解析点；不同字符串不保证不同文件。
- 唯一合并人是执行角色，主代理是审计角色，问题退回责任人。
- 无自动暂存、commit/push；不改gitignore。准备文档先output交付，正式版本落点在Spec中确定。
