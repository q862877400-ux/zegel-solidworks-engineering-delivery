# EC00 Spec 草案——可信工具底座

- 日期：2026-10-08；状态：DRAFT／待评审。
- 工作包代号：EC00，尚未分配本仓正式特性编号。
- 总计划：[ENGINEERING_CONSTRUCTION_PLAN.md](ENGINEERING_CONSTRUCTION_PLAN.md)。
- 本文只规定需求，不证明任何实现或真机验收已完成。
- 正式立项后按本仓 spec-template 整理；不修改已有规格及 `.specify/feature.json`。

## 1. 问题与目标

项目已有大量工具，缺口不是“有没有API”，而是工具请求、实际效果与证据之间不闭合。一次返回true不能证明关系、单位、几何、文档状态符合工程意图。

本特性建立一条可信执行路径，为后续设计契约、方法规划和工程验收提供基础。先堵住尺寸错、假成功、选错对象、重复执行和证据错版本；不在这里实现整套工程设计平台。

## 2. 用户故事与验收场景

### US1：工程师明确表达单位，系统只换算一次（P1）

作为工程师，我用明确单位提交尺寸和角度；系统按公开契约处理，不能猜测单位或重复换算。

- 给定长度10 mm，执行器应在已确认的米制API边界传入0.01 m，并保留请求与规范化值。
- 给定同一长度以0.01 m表达，规范化结果与10 mm一致。
- 给定只接受长度的字段却传入角度，调用COM前拒绝。
- 给定旧调用省略单位，仅在该工具确有已登记历史单位契约时走兼容路径；未知不得套全局mm默认。

### US2：草图关系必须真的生效（P1）

作为工程师，我要求两实体相切/相等/重合时，需要看到实际约束证据，而不是布尔值。

- 给定合法实体与关系，正式工具路径执行后回读关系及相关几何义务，满足才通过。
- 给定关系API返回true但关系图没有变化，判定失败；若不能可信回读则unknown，不得通过。
- 给定实体类型错误、数量错误或关系名不支持，调用前拒绝。
- 给定关系已经存在，只有前态检查与效果判据均能确认时才允许返回已满足，不再盲目添加。

### US3：只修改指定文档与对象（P1）

作为工程师，我不能接受工具因活动窗口变化而修改另一个模型。

- 文档身份、配置、版本与请求一致才执行；活动窗口切换不构成授权。
- 重建后持久引用失效或命中歧义，停止并提供证据，不选择“最近的面”。
- 草图编辑态/选择状态不满足前置条件时，按已批准计划进入或拒绝；不能偷偷改计划。

### US4：超时之后不重复制造特征（P1）

作为操作者，我需要知道一次超时是否可能已经修改模型。

- 非幂等操作超时后标记uncertain，重新读取效果或进入恢复流程，不能立即重放。
- 模态框按既有分级护栏处理；未知/危险弹窗不自动确认。
- DSH与WorkBuddy竞争同一SW会话时不能并发修改；EC00先接现有互斥边界，完整租约/围栏在EC04实现。

### US5：证据绑定正确版本且有失败信息（P1）

作为验收者，我能从证据看出请求、实际效果、未知项与最终模型版本。

- 模型改变后，旧的证据不能直接用于放行新模型。
- 只完成静态/离线测试的工具不得升级为真机已验证。
- 失败日志保留错误分类、前后态和恢复建议；不带明文凭据。

### US6：旧工具能受控迁移（P2）

作为现有调用者，我需要知道哪些接口变了，以及旧调用何时退出。

- 每个迁移工具有旧契约、适配规则、弃用策略及回归测试。
- 已纳入本特性迁移表的代表工具，不能通过回退旧入口绕过该工程路径的新硬门禁；未纳入迁移范围的旧工具不适用本条。不兼容情形明确拒绝而非静默改变尺寸。
- 此特性以有限代表工具验收，不假装全部API已逐一真机复验。

## 4. 非功能与约束

- 不依赖模型自述正确性；离线校验和效果判据由确定性代码执行。
- 正式工具路径必须是验收对象，内部函数探针不能代替。
- 默认不改变用户数据；真机样例只使用批准的自有测试文档。
- 本仓来源块、许可、命名、官方签名及门禁纪律继续适用。
- 对代表工具进行深验收，对其余范围做静态盘点；覆盖率分开报告。
- 证据哈希表明完整性，不天然证明真实性；记录取得方式和验收者。

## 5. 范围、非目标与依赖

### 5.1 代表工具集

正式G1需冻结公开ToolSpec名称，不在草案里编造API名。至少覆盖：

1. 一种草图长度/角度输入；
2. 一种实体生成或特征修改；
3. 草图关系正式路径；
4. 文档身份/重建/保存重开路径；
5. 一种对象引用和效果回读路径。

精确名称、版本、已知限制和旧调用测试在baseline与contract迁移表填实。若范围缩减必须走需求变更，不在验收时偷偷删失败工具。

### 5.2 非目标

不实现工程规划器、全域几何证明、全部API单位逐项真机认证、完整云服务、完整租约协议、整机国标合规、PLC实机控制及制造级齿轮设计。

### 5.3 前置与外部依赖

离线任务需要源码与可控测试环境。真机任务另需授权的Windows/SW/许可/插件、可运行COM依赖、正式调用入口、护栏和自有测试目录；这些目前不能视为已就绪。
