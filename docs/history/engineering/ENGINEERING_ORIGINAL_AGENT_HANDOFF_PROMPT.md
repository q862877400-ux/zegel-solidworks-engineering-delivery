# 发给原开发 Agent 的交接提示词

## 使用方法

把下面“提示词正文”整段复制给原来在 DeepSeek Harness 中开发本项目的 Agent。

它完成后，把三份交付文件的完整路径或文件本身发给 WorkBuddy。优先传文件，不需要复制整份代码仓库，也不要复制密钥或聊天历史。若两边能读同一块磁盘，直接给文件绝对路径。

三份材料齐全后，接手方只做兼容与开工准备审计。**是否开工仍需另行明确授权。**

## 提示词正文（从这里复制）

你是此前在 DeepSeek Harness 中开发 `D:\AI\SW` 项目的原开发 Agent。现在另一位 Agent 在 WorkBuddy 中接手，准备将工程能力升级拆成多路 AI 并行施工。

**这次只整理交接与施工前准备。不要开工，不改业务代码、测试源码、现有配置、角色表、已完成规格、分支或施工游标。不要启动 SolidWorks、COM、CAE、云服务，不安装依赖、不提交、不全仓暂存，也不要批量启动子代理。**

接手方只负责调度、审计与监督，不亲自写业务代码。未来希望至少20路 DeepSeek V4.1 Flash和20路HY4，但必须先确认真实路由、现有契约和写入隔离。当前只需提供事实和可执行准备方案。

请优先使用你已有的项目上下文与直接相关文件，不重新扫描全仓、不阅读无关材料。找不到就写“未确认/查不到”，不要猜接口、模型ID或启动命令。

### 一、先确定项目到底是什么

区分并解释：

1. 现有Python能力内核/标准stdio MCP服务。
2. MCPB清单与发行包。
3. DSH角色/工具路由/技能配置。
4. 是否确有DSH原生Cordis插件代码，其入口、`apply(ctx)`、`inject`、生命周期/effect/dispose、配置与打包规范在哪里。

不能因为“它供DSH使用”就假设全部代码是原生Cordis插件，更不能建议整仓重写成TypeScript。给出真实入口、启动方式、依赖与规范文件路径；历史记忆与当前源码不同要标出。

### 二、把现有代码契约讲清楚

以源码和现有测试为权威，不能把新架构草案当现行契约。请整理：

- ToolSpec/Param的字段、默认值、必填、注入与实际resolvers、别名、派生参数、pre_call、extra_op及互斥条件。
- 模块导入路径、公开MCP名→批次注册→目标函数→宿主对象的调用链。
- 长度/角度/其他量值的公开单位、内部单位、COM边界单位、实际转换位置；指出已转换或可能重复转换的路径。
- 公开输入、response_format、JSON/Markdown返回、错误载荷/异常语义；哪些客户端依赖这些形状。
- writes/read_only/idempotent/destructive的三态和优先级，预检开关、异常/unchecked/不适用的实际处理。
- 现有互斥/弹窗护栏/超时/恢复、选择语法、持久引用和模型状态指纹，以及它们不能保证的事。
- 生成文件、权威状态源、注册接线门禁、验收等级、来源/许可、完成规格不可变等施工规矩。
- 现有聚焦测试：真实文件/函数、需要的依赖、有无COM/导入副作用；不能写不存在的测试名。

每项给具体`路径:行号`、对应测试和已知限制。列“必须兼容”“允许受控扩展”“需要版本迁移/业主决定”三类，不要泛泛说兼容旧代码。

### 三、把当前状态和不能覆盖的改动交代清楚

仅做必要的只读版本/工作树核对，允许诊断命令但不得修改：

- 仓库、当前HEAD、分支、正式规格编号/重复编号、`.specify/feature.json`与ROADMAP指向及是否冲突。
- 当前未完成工作与最近一次可定位证据；旧的“下一步”与最新决定不一致时明确说明。
- 未提交/未跟踪改动及已知权属。无法确认所有者就标“未知，禁止覆盖”，不要将全部改动认成你自己的。
- 当前单位、草图关系注册/参数包装/效果回读、关窗/计数、超时重试与收尾链副作用的真实状态。
- 上次已完成架构和P0草案中，哪些还没达到本仓正式spec的来源/许可/可运行验收要求。

若已有架构或草案在`output/ENGINEERING_*.md`，只引用，不修改它们或把32项任务勾成完成。接手方需要事实基线，不是另写一份大架构。

### 四、把指定模型的实际调度方式交清楚

未来目标为20路DeepSeek V4.1 Flash和20路HY4，**本轮不要批量启动**。

从实际配置的脱敏视图/公开模型列表/已有运行记录整理：

- 每个模型的显示名称、准确Provider ID、准确provider-owned Model ID、实际使用的DSH profile和子代理provider。
- 哪条子代理路径允许按模型覆盖；角色表当前模型是否会覆盖请求；哪些后端会拒绝agentOptions。
- 完全按已有文档和实现提供启动/继续/停止/查询方式，不编造`--model`或`--provider`参数。
- 调度结果在哪里能看到真实provider/model、子会话ID、状态、有效响应和失败原因；不能用Agent自称证明模型身份。
- 已知并发上限/配额/宿主限制及证据；不清楚就写未知。不要把有40个任务等同40路同时运行。
- 如果模型未配置或不可用，列出缺什么以及在哪个界面确认；不要自己改配置。

**安全要求：不读取或输出明文API密钥，不复制credentials.yaml、Authorization头、完整配置、敏感环境变量、私人聊天或日志。只提取白名单字段（provider/model/profile/子代理类型/已知能力/非敏感记录位置），敏感路径和凭据引用必要时脱敏。不要把私有源码或数据上传外部。**

### 五、给出40路并行的准备方案，而不是抢跑实现

按已有代码可独立拆分的边界，提供20个DS槽位和20个HY槽位。每个槽位写：

- 职责、对应需求/现有任务、必要输入文件、预期交付、上游依赖。
- 拟定读范围与候选写范围；本轮实际写权限为空。
- 哪些先做只读研究/契约提案，哪些必须等共享契约冻结，哪些只能最后集成。
- 既有公共文件的唯一合并责任人；同文件不同函数不默认允许无锁并发修改。
- 独立快照/worktree/补丁区在现有宿主是否可用；writeScopes是否只是提示，不要误称硬锁。
- 如何固定基线、处理他人改动、记录patch、拒绝基线漂移、审计后再合并；无自动全仓暂存/提交。
- 每路可做的静态/离线检查与被禁止操作，尤其现有coder角色的限制。
- 开工前必须满足的门和需要业主确认的决定。

如果现有EC00不足以提供40个安全独立实现单元，明确指出哪些槽位只能准备/测试/审核或等待。不能为了凑40路强拆同一个文件，也不能让40路抢同一COM会话。

### 六、只产出这三份文件

在确认父目录有效后，保存到本仓已有`D:\AI\SW\output`，不另建业务目录：

1. `DSH_PARALLEL_HANDOFF.md`
   - 项目形态、规范路径、现状、权属、兼容要求、模型路由、阻塞和下一步。
   - 开头用一页摘要说明“已确认/未确认/不得操作”。正文只保留关键证据和引用，建议不超过300行。
2. `DSH_EXISTING_CONTRACTS.json`
   - 可被程序读取的现有契约索引；字段含id、来源路径/行号、公开接口、输入/默认/单位/注入/返回/错误/效果语义、对应测试、限制、兼容策略。
   - 模型路由只填脱敏provider/model/profile等事实；不能确认填null加reason，不用占位值冒充真实配置。
3. `DSH_PARALLEL_ROSTER_DRAFT.md`
   - 40槽位预分工、公共文件责任、依赖/隔离、只读模型烟雾测试规约和开工门。
   - 所有槽位标“未启动/不允许施工”；当前业务写入范围为空。

每份文件标日期、事实核对版本/取得方式和unknown。保留来源/许可。本轮只允许写这三份新交接文档，不修改既有文件；如同名文件已存在，先读并说明如何保留旧版本，不盲目覆盖。

### 七、最后回复我什么

只回复：三份文件的完整路径、最关键的3～5条兼容/调度结论、仍需我确认的事项。

不要说“40路已启动”“已开工”“兼容已验证”“真机通过”，除非存在本轮授权和真实证据；本轮没有这些授权。
