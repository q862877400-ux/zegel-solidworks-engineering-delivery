# 机械与自动化工程能力系统——详细施工总计划

- 日期：2026-10-08
- 状态：DRAFT／待评审；本文是施工安排，不是实现或验收证明。
- 目标仓库：`D:\AI\SW`。
- 架构依据：[ENGINEERING_MODELING_ARCHITECTURE.md](ENGINEERING_MODELING_ARCHITECTURE.md)。
- 本轮边界：只编写计划与配套草案；不改业务代码、旧规格、当前特性游标、分支和工具注册，不操作 SolidWorks，不安装或上线。
- 编号约定：下文 `EC00～EC12` 是本计划的工作包代号，**不是已经分配的 Spec Kit 特性编号**。正式施工前重新检查本仓编号及冲突，由创建流程分配。不得照搬 zcode 的 `003`。

## 0. 先说结论

不要把这个工程做成“再加一层提示词和几个专家角色”。应做成一个有明确适用范围、可编译、可验证、可追责的工程能力产品。

施工采用两条纵向主线：

1. **可信执行主线**：接口契约、单位、选择、状态、COM、效果回读、保存重开、证据和发布门禁。
2. **工程能力主线**：功能/载荷/制造需求、规则计算、成熟方法、规划编译、设计变更、工程图、机构/自动化、CAE、合规和交付。

两条主线必须在同一个小型工程交付物上汇合。不能先堆上百个方法，最后才发现工具执行和验证不可靠；也不能只修底层，长期没有可使用的工程闭环。

首个闭环选择：**参数化安装板／支架 + 孔组与配合关系 + 尺寸链 + 工程图 + 参数修改 + 保存重开 + 证据包**。它比单独的齿轮更能同时检验设计意图、几何、制造、制图和可修改性。轴系作为第二个方法族；机构与自动化作为第二条产品纵切片。齿轮、复杂曲面与拓扑作为挑战集，不作为所有工作开工的先决条件。

### EC00——可信工具底座与旧欠账收口

**目标**：确定“请求了什么、改了什么、如何证明”，堵住单位、状态、假成功和不确定执行。

**复用**：ToolSpec、注册、sw_part、sketch_relations、tool_caller、sw_guard、release_check、212/210既有工作。

**施工顺序**：

1. 为旧规格→新任务建立映射；保留原状态和证据，不重开/重关旧任务。
2. 建立纯静态基线清单：工具注入/参数/单位/返回/风险/效果/对应测试。
3. 整理 mm/m、deg/rad、力/应力/转速转换边界；面向用户单位不等于 COM 单位。
4. 在单一边界转换，禁止重复换算、禁止静默猜单位；无单位旧工具走显式兼容策略。
5. 完成草图关系正式路由、API签名依据、正负例及关系回读；参数包装问题未解决不得标通过。
6. 统一语义选择、文档身份/版本、重建与保存重开判据。
7. 处理超时/COM异常后状态：先回读，不能自动重试非幂等操作。
8. 证据加入请求、计划、模型版本、执行节点、结果度量、判定来源和未知项。
9. 聚焦测试/既有门禁/受控真机验收；未接通环境停留离线完成，不伪造真机成绩。

**建议新增**：`schemas/engineering/tool-execution.schema.json`、`tests/test_engineering_tool_contract.py`；若本仓已有等价schema则扩展并建立迁移，不重复。

**退出**：EC00配套草案中的 FR/SC 全映射；必须至少有一组对照测试证明曾经的假成功会被拒绝。详见同目录五份 P0 草案。

### EC01——工程设计契约与对象模型

**目标**：把“做一个支架”变成能计算、规划、验收的工程需求。

**建议落点**：扩展现有 design_plan schema 和编排入口；增加单一权威 EngineeringContract 定义，必要时在 `schemas/engineering/` 建schema与迁移工具。

**任务序列**：

- EC01-T01：定义用户故事和非目标；划分已知、假设、待确认、必需缺失四类信息。
- EC01-T02：定义 Quantity、CoordinateFrame、Datum、LoadCase、MaterialRef、ProcessIntent、Fit/DimensionChain、ParameterDomain。
- EC01-T03：定义 FunctionRequirement、VerificationObligation、Assumption、ApplicabilityDecision、ApprovalRef；安全等级/工况缺失不能默认“普通”。
- EC01-T04：设计状态机 `draft→needs_clarification→frozen→superseded`，契约冻结和内容哈希。
- EC01-T05：实现schema校验及旧设计计划→新契约适配；旧信息不足保留unknown。
- EC01-T06：加入局部坐标/单位/材料版本/配置身份检查。
- EC01-T07：把澄清问题限定成影响决策的最小问题集；可保守假设项与禁止假设项分开。
- EC01-T08：构造板、轴、机构、气动四类契约及缺参数/冲突/错误单位负例。

**验收**：非法量纲和缺关键工况在COM前阻断；两个不同表述的同意图归一到同语义；新版本不能借用旧批准；工程基准不能简单等同任一CAD基准面。

### EC02——领域规则、计算与国家标准适用性基础

**目标**：用审计过的算法和规则回答“这样设计行不行”，不让检索片段直接当规则执行。

**建议落点**：复用 `dfm_review.py`、`sw_applicability.py`、知识检索；职责独立的确定性计算模块可放 `scripts/engineering/`。

**任务序列**：

- EC02-T01：定义 rule/calculation 标准接口：输入单位、适用域、来源、版本、阈值、输出和unknown。
- EC02-T02：建立标准登记模型：标准号、版本、实施/废止状态查证日期、许可、适用设备、条款索引、证据类型。
- EC02-T03：分开强制义务、合同要求、推荐标准、企业规范和经验规则，不用 GB/T 标签替代法律适用判断。
- EC02-T04：第一批算法做尺寸链极限法、明确统计假设的RSS、孔边距/工具可达性、基本轴强度、传动功率/效率边界。
- EC02-T05：建立计算手册算例/独立复算/边界值/量纲/单调性/区间检查。
- EC02-T06：规则决策保留依据与反例；矛盾规则按优先级和适用性处理，不能多数投票。
- EC02-T07：标准版本变化形成影响清单，证据自动标过期；不能只改数据库版本号。
- EC02-T08：建立首个限定设备类别的适用性矩阵；未知类别返回待澄清，不能“无标准适用”。

**验收**：每条硬规则可查出处与适用域；算法有不共享实现的参考值；过期、缺源、域外、统计假设缺失均不能返回通过。

### EC03——方法库、工程IR与受约束规划编译

**目标**：模型选择成熟方法与解释，不直接拼底层API。

**复用**：golden-workflows、vibecad计划、工程DAG、既有效应声明。

**任务序列**：

- EC03-T01：定义 MethodSpec：目标、适用域、前后置、步骤、禁止条件、复杂度、修改域、验证义务和失败域。
- EC03-T02：建立板/孔组/阶梯轴/安装支架四个受控方法，记录选法原因和替代方案。
- EC03-T03：定义 SketchIR、FeatureIR、AssemblyIR、DrawingIR 及设计语义引用；版本化并接适配器。
- EC03-T04：实现任务分解与确定性规则检查；参数可行性使用域适合的约束算法，不把连续几何全部塞进SMT。
- EC03-T05：定义不可满足核心/未知/超时/多方案排序；unknown不能落入默认可行。
- EC03-T06：编译为带前后置与验证步骤的工具DAG；非法路由在编译期失败。
- EC03-T07：明确优雅的多指标：修改稳定、基准表达、意图可读、工具风险、可制造性；不能仅最少特征。
- EC03-T08：建沙箱探索通道；探索产物不得直接进入生产方法库，需审查来源/域/正负例。

**验收**：两模型生成的合法意图都通过同一编译器；编译器能拒绝越权/欠约束/循环依赖；不需要COM即可检验计划正确性；冻结计划不能被执行器静默改写。

### EC04——安全作业、恢复、版本与证据链

**目标**：执行不抢同一个COM；失败可恢复；验收绑定正确版本。

**复用**：queue_worker、reviewer_gate、工程编排、sw_guard。

**任务序列**：

- EC04-T01：定义 Job状态与节点租约：queued/planned/approved/running/uncertain/validating/blocked/completed/failed。
- EC04-T02：单SW会话互斥、租约续期、围栏令牌；过期worker不能继续修改。
- EC04-T03：比较并交换模型版本；批准绑定contract/plan/model版本，跨版本立即失效。
- EC04-T04：幂等键和操作效果回读；创建类动作超时不能盲重试。
- EC04-T05：阶段检查点与前向补偿；不宣称COM有数据库式全局事务。
- EC04-T06：独立验收器只读最终模型；不把同一Agent自评当放行者。
- EC04-T07：Artifact/EvidenceManifest 哈希、相对路径、敏感信息过滤和保留策略。
- EC04-T08：注入worker退出、审批过期、模型被外部修改、模态框与读写失败。

**验收**：双客户端争抢只能一个得到执行权；超时未回读不重试；旧证据不能放行新模型；失败不丢用户文件；没有许可/权限的动作停在设计建议。

### EC05——首个通用零件工程闭环

**目标**：把上述基础在真实工程交付物上接起来。

**纵切片**：一块安装板或支架，有安装孔、功能基准、配合/公差、材料及加工意图；关键参数在预先批准的修改域内变化。

**任务序列**：

- EC05-T01：冻结工况与包络、安装对象、孔组、材料、工艺、公差和交付要求；缺载荷不能给强度结论。
- EC05-T02：建立独立参考几何、质量/体积、公差和孔坐标验收值。
- EC05-T03：草图先设计自由度/关系/尺寸图，再执行；有意保留自由度必须标注，不机械要求全锁死。
- EC05-T04：构建基准与主特征；辅助倒角/圆角后置，避免早期拓扑依赖污染。
- EC05-T05：独立回读孔径/位置/轮廓/体数/材料；检查制造工具可达性与装夹。
- EC05-T06：测试参数域的角点、边界及关键关系扰动；从修改行为检验设计意图。
- EC05-T07：保存重开/配置切换/导出比较；工程图通过EC08基础路径同步更新。
- EC05-T08：组装工程交付包和残余风险；完全走正式工具层，不以内部脚本演示替代。

**验收**：原尺寸与至少三组不同类型参数扰动均有测试；保存重开和工程图无悬空；所有通过项都绑定同一模型版本。具体扰动集合由spec冻结，不在验收时删掉失败点。

### EC06——装配、机构、尺寸链与维护

**目标**：不仅“把零件摆在一起”，还懂运动、配合、公差和装配次序。

**任务序列**：

- EC06-T01：建立装配层级、地件、目标自由度、运动范围和禁用位姿。
- EC06-T02：实现配合约束图检查，区分欠约束、冗余、过约束和预期运动自由度。
- EC06-T03：基准与配合链映射到公差链；极限法与统计法各自声明假设。
- EC06-T04：位置扫描+自适应局部加密检查干涉；有限采样不能冒充连续全域证明。
- EC06-T05：验证紧固件可达、装拆次序、轴承安装、润滑、传感器调整和维护空间。
- EC06-T06：建立简单双导杆滑台/轴承支撑轴系两类案例；齿轮列为附加挑战。
- EC06-T07：检查组件配置、BOM、持久引用、替换件和参数修改后的配合稳定性。
- EC06-T08：交付运动包络、关键间隙、公差链、装配和维护说明。

**验收**：目标自由度与实际一致；边界位姿无未解释干涉；错误配合/错轴向位置必被检测；无法证明全域的部分以coverage/unknown记录。

### EC07——机械与自动化设计纵切片

**目标**：让机械、传动、传感器与控制逻辑使用同一份工程需求。

**首域**：限定行程/载荷/节拍的直线搬运单元；只设计和验证，不直接驱动实机。

**任务序列**：

- EC07-T01：冻结节拍、负载、行程、精度、环境、人员接近、失电/失气工况。
- EC07-T02：MotionIR包含运动曲线、峰值/均方根负荷、惯量、效率、制动、热边界；选择电机/减速/丝杠或气动方案。
- EC07-T03：AutomationIR定义IO、传感器、状态机、互锁、超时和故障恢复；接口型号数据须有可用来源和版本。
- EC07-T04：SafetyFunctionIR分开普通互锁和安全功能；风险/安全等级的确定需要适用方法与审核责任。
- EC07-T05：极限/原点/夹紧/开门/失电/失气/传感器冲突形成有限状态可达性测试。
- EC07-T06：机械行程止挡、制动/保持、能量释放、维护模式与控制需求交叉检查。
- EC07-T07：输出选型计算、IO表、功能状态图、联锁矩阵、故障清单与安全验证计划。
- EC07-T08：软硬件联调接口做仿真桩；真实设备连接另立安全审批，不随安装默认打开。

**验收**：至少一个正常循环和具名故障矩阵可重复验证；安全功能unknown不能被普通互锁测试替代；设计产物标清“未经实机调试/安全确认”。

### EC08——工程图与多工艺建模方法

**目标**：制图表达工程意图；方法覆盖不同工艺，不只会实体拉伸。

**分四个子域逐一放行，不合并成一个大任务**：

- EC08A 工程图基础：视图/剖视/局部放大、功能尺寸/基准/配合、公差、材料、技术要求、BOM和版本。
- EC08B 钣金：厚度/折弯半径/工艺参数、展开一致性、折弯干涉、加工和装配空间。
- EC08C 焊件：型材、连接、切割清单、焊接可达性、变形与后加工假设。
- EC08D 曲面：连续性、边界/拼接、偏差、厚化和工艺要求；“看起来顺”不能当曲率通过。

**每子域共同任务**：需求冻结→官方调用与死路审查→MethodSpec→IR适配→独立几何/工艺验收→修改域→保存重开→交付样例。

**工程图验收**：尺寸值、基准、公差、模型配置版本都能回读比对；悬空标注检测；版面/遮挡/线型与可读性另设检查。制图标准符合不代表整机安全合规。

### EC09——CAE和拓扑优化可信纵切片

**目标**：把物理问题定义、离散验证和工程解释放在求解器前后。

**任务序列**：

- EC09-T01：建立简单梁/板静力基准，固定理论或可信独立参考解。
- EC09-T02：AnalysisIR定义几何简化、材料、本构、载荷、边界、接触、目标量和适用域。
- EC09-T03：几何/单位/刚体模态/约束与载荷平衡检查；缺失条件不能以默认值求解后“通过”。
- EC09-T04：至少三档有策略的网格与关注量收敛；奇异峰值不能单纯细化网格追峰。
- EC09-T05：分开计算verification、物理validation和不确定性；无实体/可信实验时只写验证范围。
- EC09-T06：设计敏感性和保守边界；优化输入/不可改域/制造约束冻结。
- EC09-T07：拓扑结果重构为可制造设计后重新分析，不把云图直接交制造。
- EC09-T08：未支持物理领域拒绝或升级；疲劳/冲击/接触非线性另立spec。

**验收**：参考解、反力平衡、网格关注量、材料/载荷版本闭合；优化后复分析；求解成功不是工程通过；没有validation证据不写“真实工况已验证”。

### EC10——安装、跨宿主适配与线上执行节点

**目标**：安装即有工作方式和诊断，不是安装即赋予无限工程权限。

**任务序列**：

- EC10-T01：定义能力包内容：版本清单、兼容矩阵、方法/规则/schema、诊断、测试和操作指南；不带密钥。
- EC10-T02：DSH/WorkBuddy适配只做宿主差异层；共享同一工程内核与标准MCP边界。
- EC10-T03：诊断 Python/COM/MCP、SW版本/许可/插件、模板、写入目录与单节点占用；诊断不自动启动真实修改。
- EC10-T04：可复现依赖、最小权限、升级/回滚和配置迁移；不污染用户全局环境。
- EC10-T05：云编排+受管Windows节点；COM不直接暴露公网；节点鉴权、任务签名/租约、作业隔离。
- EC10-T06：用户/项目访问控制、数据保留、日志脱敏、文件下载授权和外发确认。
- EC10-T07：新环境安装→诊断→受控案例→证据交付→卸载/回滚全流程。
- EC10-T08：多客户端队列与断连/过期审批测试；部署独立审批，本轮不创建云服务。

**验收**：安装失败有明确原因；DSH和WorkBuddy不能同时控制同一会话；无凭据入包；未授权用户不能读另一项目产物；升级失败可回到已知良好版本。

### EC11——合规、发布与工程交付包

**目标**：标准责任落到具名义务和证据，不能靠“符合国标”一句话。

**任务序列**：

- EC11-T01：针对一个限定设备类别冻结规范配置及其来源；机械、电气、安全控制、气动/液压等按适用范围选。
- EC11-T02：要求→条款→模型/计算/测试/审查义务→证据→结论映射。
- EC11-T03：规定pass/fail/unknown/not_applicable/expired的依据；不适用必须有原因。
- EC11-T04：关键义务未知或失败时阻断工程合规发布；允许输出有水印/边界的设计草案。
- EC11-T05：交付包包含CAD/图纸/BOM、计算书、装配维护、自动化设计材料、适用性矩阵、残余风险、版本manifest。
- EC11-T06：区分软件包发布、CAD工件完成、设计审签、整机符合性，不共用一个approve字段。
- EC11-T07：标准更替、材料/工况/参数变更导致证据失效与补验计划。
- EC11-T08：留足实体检验/第三方/法定程序接口，不宣称软件自动代办。

**验收**：随机抽取义务可回溯到真实证据；删除关键证据或更改工况后合规放行失效；推荐标准不能自动成为强制法律结论。

### EC12——可复用能力包与弱模型评测

**目标**：证明安装后系统能力提高，并保证新方法不会带回旧失败。

**任务序列**：

- EC12-T01：案例分训练/开发/留出，按零件族/参数域/故障划分，避免近似复制污染。
- EC12-T02：建立原模型+工具、模型+提示词、模型+工程系统三组对照；强模型只是参考，不是解法。
- EC12-T03：盲评设计正确性、可修改性、制造装配、制图、合规、拒绝合理性和错误放行。
- EC12-T04：记录成本/耗时/人工介入/重试/拒绝/成功，不能只挑成功案例。
- EC12-T05：冻结数据、模型版本、温度、预算、允许工具和运行环境；重复试验与置信区间。
- EC12-T06：单方法准入：来源许可/适用域/正负例/参考oracle/修改域/保存重开/失败说明齐全。
- EC12-T07：方法和规则版本升级影响分析，旧项目固定版本或显式迁移。
- EC12-T08：未见任务进入沙箱；实验通过后仍需独立审核才变成生产方法。

**验收**：留出集可重复；系统增益不是增加无限重试得到；错误放行与拒绝率联合考核；零事故样本不等于零风险；各领域发布分别过门。

## 6. 第一轮怎么开工：不含隐性副作用

### 6.1 第一批只做 EC00 的离线施工

1. 评审本计划及五份P0草案。
2. G0 核对编号、feature游标、分支、未提交改动、现有约束；明确本轮允许写哪些文件。
3. 批准后创建**一个**正式特性，先做 spec/plan/contracts/tasks 一致性，不先创建全部领域目录。
4. 离线提取ToolSpec与单位清单，核实对应旧任务；禁止导入会连接COM的模块来做“静态检查”。
5. 先写单位/错误/假成功/非幂等重试负例，再修改接口。
6. 实现边界换算和效果验证路径，做聚焦测试。
7. **此时不推进齿轮模型、不运行CAE、不启动云节点。**
8. 环境和执行授权就绪后，按官方签名/Remarks/Example与护栏开展EC00真机任务。
9. 验收写清offline/runtime/product三个结论；欠证据则只完成离线任务。

### 6.2 命令纪律

本文不运行任何命令。下列是正式施工的约束，不是本轮已执行结果。

- 真机命令只能从既有护栏入口进入，使用明确的解释器、工具层契约、超时和自有测试文档。
- 先前源码核对已发现 `round_chain.ps1` 收尾包含全量暂存与关闭SW等风险动作。正式施工前必须拆分“生成与验证”和“提交与资源处置”，采用显式文件白名单、工件权属及授权；在该拆分完成前，不直接运行整条链。它不是纯只读收尾。
- 聚焦测试按改动面执行；不重复跑已有通过的同一门；全量测试仅按本仓规定情形。
- 生成文档由生成器维护，禁止手改 `docs/dead-ends.md` 等生成索引。
- 当前未完成正式接入时，离线工作不需要假装MCP已经连接。
- 原提交辅助脚本是历史机制参考，不能不看权属就全仓暂存；提交/推送另行授权，保留其他会话改动。

## 7. 分工与并行规则

| 角色 | 可负责 | 不能代替 |
|---|---|---|
| 工程需求负责人 | 功能/工况/制造/验收决定 | 不能用模型推测代替缺失载荷 |
| 领域算法负责人 | 计算、方法、适用域与参考例 | 不能自审自己写的oracle后宣布独立验证 |
| CAD适配负责人 | ToolSpec、COM、选择、调用序、回读 | 不能改变冻结工程需求来绕过失败 |
| 验证负责人 | 独立读取、正负例、变形测试、证据 | 不能只复制执行器的success |
| 标准/安全负责人 | 标准适用、义务、外部验证责任 | 不能凭检索摘要代替条款核验 |
| 发布/运维负责人 | 包、权限、节点、升级与回滚 | 不能把安装成功视作工程合规 |

可以由一人承担多个角色，但审核记录必须区分职责；安全关键结论不能仅由生成者自签。

任务标 `[P]` 需要同时满足：输入已冻结、不同文件/数据写入、没有运行时共享状态、可以独立测试。不同文件但争抢COM不算可并行。

双会话施工前登记 write-scope；更改公共schema、注册器、capabilities与门禁由一个责任人合并。独立验收样例和期望值不能由实现代理随意“更新为实际输出”。

## 8. 证据、台账与状态规范

### 8.1 验收记录的最小形状

```json
{
  "feature_key": "EC00",
  "task_id": "T018",
  "requirement_ids": ["FR-004"],
  "verification_level": "runtime",
  "result": "unknown",
  "artifact_version": "sha256:<actual-content-hash>",
  "environment_ref": "<actual-environment-record>",
  "evidence_refs": [],
  "reason": "缺少关系生效回读，禁止放行"
}
```

这是格式说明，尖括号字段不能进入真实证据。真实执行必须填真实值；未运行不生成“通过”manifest。

### 8.2 每个任务怎么勾完成

任务行必须写：编号、用户故事、文件/模块、依赖、输出、测试/证据、完成判据。

- `[ ]`：未完成，包含被阻塞的任务。
- `[x]`：其交付和规定证据均完成。
- 阻塞原因另列：环境、契约、官方语义、依赖、用户决定、外部实验。
- 文档写完只能勾“文档任务”，不能勾对应实现和真机任务。
- 离线完成与真机完成拆任务，避免一个大勾遮住半完成。

### 8.3 每轮收口要留下什么

1. 本轮写入范围及实际改动。
2. FR/任务/测试/证据新增映射。
3. 聚焦测试和阶段适用的门禁结论；未运行写未运行。
4. 原capabilities和ROADMAP的对应更新，保留来源与负面结论。
5. 下一轮第一动作和阻塞，不让接手者重新探索全仓。
6. 提交范围与权属记录；没有提交也要如实写。

## 9. 风险清单与治理动作

| 风险 | 触发信号 | 必须采取的动作 |
|---|---|---|
| 继续用工具覆盖代替设计能力 | API数增加，工程验收无变化 | 停扩工具数，做EC05纵切片 |
| 规划失控/弱模型乱编 | 非法IR、缺字段、越权动作 | schema/编译阻断，有限澄清/重新计划 |
| 单位隐患 | 1000倍/弧度角度错、重复换算 | 单边界转换、量纲校验、对照与变形测试 |
| 假成功 | API true但几何/关系不变 | 效果回读，unknown不放行 |
| 引用漂移 | 重建后命中别的面/边 | 语义签名复核，歧义停止，不自动挑近邻 |
| 非幂等重复 | 超时后多实体、多特征 | uncertain+回读；禁止直接重放 |
| 跨宿主竞争 | DSH/WorkBuddy同时发真机任务 | 单节点租约/围栏，串行执行 |
| 标准过期/域外 | 版本变更、工况类别未确认 | 适用性重算、证据失效、具名待办 |
| 验收同源 | 执行函数输出被当期望值 | 独立oracle、只读验收、固定参考数据 |
| 方法僵化 | 不支持的新任务仍强套模板 | 明确拒绝或沙箱探索，禁止偷偷降级 |
| 软件“通过”但工程不成立 | 只检查体积，不查载荷/工艺 | 分级放行，缺物理证据不承诺工程通过 |
| 用户数据/商业设计泄漏 | 日志/包有密钥、跨项目文件 | 脱敏、最小权限、外发授权、隔离测试 |
| 把美观当优雅 | 少特征但修改易崩 | 参数域/依赖/基准稳定作为首要评价 |
| 计划过大无法施工 | 一个任务横跨多个领域且无退出条件 | 缩成一个方法/一组接口/一个独立验收单位 |

## 10. 变更与回滚策略

- 需求变化：先改决定记录和spec，再同步plan/contracts/tasks及验收；不先改代码掩盖。
- schema变化：版本化、兼容适配与迁移测试；失去信息的迁移必须报告unknown。
- 规则变化：冻结旧项目版本，计算受影响义务，不让旧证据自动跟随新规则。
- CAD执行失败：保留自有检查点与证据，在自有目录恢复；不要覆盖用户原件，不默认撤销全部历史。
- 注册切换：受控启用新路径，保留兼容入口到迁移完成；旧路径不能绕过硬门禁。
- 发布失败：回到已知良好能力包和规则/方法组合，节点停止接新任务；不修改失败证据。
- 官方签名/示例冲突：查本仓冲突索引，记录版本/调用序，限定探针；连续修补无新证据就暂停换路线。
