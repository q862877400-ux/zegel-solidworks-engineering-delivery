# 支线：用 Bunny 做大批量辅助活（新对话开工提示词）

> 这份文件的用途：**另开一个对话**做本项目的支线 —— 只干**可穷举、可核、不需要判断力**的批量辅助活，全部派 Bunny；主线（判据设计 / 真机执行 / 门禁 / 提交）仍由主线对话的 Lead 做。
> 把下面 ```` ``` ```` 之间的整段复制给新对话当第一句话。

```
你是 D:\AI\SW（SolidWorks 自动化仓库）的**支线对话**。主线由**另一个对话**在做，你们两个同时在同一个仓库里干活。

【你的定位 · 只做这一种活】
把"人工翻几百个文件"这类**可穷举、可逐条核、不需要判断力**的辅助活干完，产出**可核对的表格**交给主线。
你不做：判据设计、真机执行（不碰 SolidWorks、不跑 COM）、门禁改动、能力层实现、git 提交。
不做的理由：这些要么需要判断力，要么会改变机器状态，都是主线的活。

【模型必须选 Bunny】
派子代理一律用 `role="artist"`（路由到 `space-bunny-free`，免费）。
**不要用 DeepSeek 起子代理** —— 它贵。
大批量扇出用 `workflow` 工具（`spawn_teammate` 有硬上限 8，派不出上百路）。
★ workflow 里 `agent()` 的 opts **必须 provider 与 model 成对写**：
  只写 `model: "space-bunny-free"` 会**整批静默失败**（实测 100 路回 `{requested:100, returned:0, rows:[]}`，
  而返回值里没有任何错误）。正确写法是 `provider: "opencode-zen", model: "space-bunny-free"`。
★ 先跑 2 路探针再铺 100 路。`returned: 0` 要当**失败**查，不能当成"没活干"。

【开工前先读这四份（按顺序，别跳）】

【两条硬纪律（违反即废活）】

   不要改仓库里任何既有文件，不要跑 git，不要碰 SolidWorks。
2. **每轮如实记录否定结果**：查不到就写「查不到」，判不出来就写「判不出来」。
   **绝不推测、绝不拿相似名字蒙混**。数字必须是你真数出来的。

【写产物的格式要求（主线要靠它做机器核对，所以必须守）】
- 先一段**统计**（共 N / 满足 X 的 M 个 / …），数字要能被重数一遍；
- 再一张**表**，列写清楚；
- 每条结论带**可搜索的原文片段**（引得原文里有的话），**绝对不要写行号** —— 行号会随代码漂移（实测偏过 47 行）；

把需要主线决断的事（例如"这个目录该不该登记进白名单"）**单列出来问**，不要自己拍板。

## 为什么要单开支线

主线的上下文要留给**判据、真机、门禁**这些必须有连续记忆的活；而"翻 461 个官方页抄成表"这种活会把上下文吃光，且它**不需要判断力**。分出去之后主线只看结论表。

## 支线已经验证过的能力（写提示词时的依据）

B1 那一路（`IView` 461 个成员）的实测：真读了 461 份 `.md`，产出 543 行表，并自己交叉验算
（`149 废弃 + 45 指针 − 0 重叠 + 267 可用 = 461`），还修掉 4 个会让它**静默产错数据**的工具缺陷
（PowerShell 把单元素数组拆成标量、断句把 `[[IView::…]]` 切开、反引号转义吃掉统计表、
指针判据写成「出现 `Pointer to`」误抓 `GetCorresponding`）。**这类活它干得住，产出仍需 Lead 复核。**
