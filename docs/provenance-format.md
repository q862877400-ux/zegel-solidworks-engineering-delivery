# 来源标注制（每个移植函数都要有）

每个移植函数必须带来源头注释，并入 `capabilities.yaml` 的条目另带结构化 `provenance` 字段；许可必须与来源表一致（见 [sources.md](sources.md)）。

头注释模板：

```python
# ── 来源 ─────────────────────────────────────────────────────────
# 仓库: xarial/codestack  (MIT License)
# 文件: solidworks-api/document/drawing/create-third-angle-views.md
# 定位: Create3rdAngleViews2 正确入口
# 官方签名依据: C:\swapi\types\IDrawingDoc\Create3rdAngleViews2.md
#              + D:\AI\SW\AI Solidworks\官方文档\SWhelp\sldworksapi\
# 本函数为静态移植，未在本机实测（见 AGENTS.md 铁律 2）
# ────────────────────────────────────────────────────────────────
```

最后那行「未实测」标注不许删：静态移植与实测是两种状态，删掉它等于把 `source_verified` 说成 `verified`。

`capabilities.yaml` 条目的结构化出处：

```yaml
provenance:
  - {repo: Slacker-LLC/solidworks-mcp, license: Apache-2.0, files: ["sw_feature.py"], upstream_verified: "SW 2026 SP3.2"}
    # repo 要写 owner/repo 全名，不只写目录名；upstream_verified 填来源自己声明的验证环境，没有就留空
```

`repo` 写 `owner/repo` 全名，`license` 在白名单内，`files` 列出实际移植的文件；来源清单与许可判定表见 [sources.md](sources.md)。

## 覆盖范围 —— **门禁真正在判的东西**

来源块是注释，门禁判的是「**这一行代码在不在某个来源块的覆盖范围内**」。
默认覆盖范围**只到紧随其后的那一个定义单元**（一个函数的整个函数体，或一个常量字典的闭合括号）。

要覆盖更多，必须在块里写**那一行标记**（`scripts/check_provenance.py` 的正则：

```python
WHOLE_FILE_MARK = r"覆盖\s*[:：]\s*全文件|scope\s*[:：]\s*whole-file"
GROUP_MARK      = r"覆盖\s*[:：]\s*后续同级定义|scope\s*[:：]\s*following-siblings"
```

| 标记 | 覆盖到哪 |
|---|---|
| （不写） | **只到紧随其后的第一个定义** |
| `# 覆盖: 后续同级定义` | 到**下一个来源块**为止的全部同级定义 |
| `# 覆盖: 全文件` | 文件末尾 |

⚠ 标记行**不要**加 markdown 粗体 —— 正则匹配不到 `**`。

### ⚠⚠ 两条已经踩过的坑（**每一条都真的发生过，且各踩过两次**）

#### 坑 1 · **新代码插在了来源块的「上方」**

`# 覆盖: 后续同级定义` 的**真实语义**（2026-10-01 轮 126 用负例测试量准）：
它覆盖到**下一个来源块的起始行之前**，而下一个来源块**接着往下覆盖** —— **两者接得上**。
所以它**不会**被下一个块"截断"。

```
量到的四种形态（tests/test_provenance_coverage_semantics.py 钉住）：
  无标记 + 2 个 def                ⇒ 第一个**覆盖**、第二个**未覆盖**
  后续同级 + 2 个 def（同一块下）    ⇒ **都覆盖**
  后续同级 + 另起一块 + def c       ⇒ **都覆盖**（接得上）
  ★ def 插在来源块**之前**          ⇒ **未覆盖**   ← **这才是真因**
```

⚠⚠ **2026-10-01 轮 125 我在这里得出了错误的结论**：当时门禁报了 3 行未覆盖，
我判成「`后续同级定义` 会被下一个来源块截断」，并把这句话**写进了 ROADMAP**。
轮 126 写负例测试时**当场被推翻** —— 真因是
`t.index("\n\n# ── 来源")` 命中了**更靠前**的那个块 ⇒ 新函数被插到了它的**上面**。

⇒ **做法**：新函数要贴在**某个来源块的下方**（而不是上方）；
不确定时就用 `# 覆盖: 全文件`，并**在块里写明为什么**。
★ 这也解释了为什么值得**把行为写成负例测试** ——
**是测试推翻了我的解释，不是我的记忆。**

#### 坑 2 · **判据查「整段实现」会被自己的文档串误伤**

文档串里**必须**提到那个"不该用的名字"（才能解释为什么不用它），
于是 `assert "X" not in 整段` 会被**自己的说明文字误伤**。
⇒ **做法**：查**调用形态**（带引号的成员名）或**构造那一行**。
⚠ 同一个坑**踩了两次**（轮 119 与轮 124）。

### ⚑ 为什么这节必须写在文档里，而不只写在门禁源码里

门禁源码里的注释**只有读门禁的人看得到**；而这里的三条坑是**写代码的人**踩的。
⚠ **2026-10-01（轮 126）实测**：本节写之前，`provenance-format.md` **只有 28 行、一个字都没讲覆盖范围** ——
规矩只活在 `check_provenance.py` 的源码注释里，而踩坑的人**不读那个文件**。
