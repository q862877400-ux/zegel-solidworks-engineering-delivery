## 一、路线（一句话）

> **DeepSeek 提出结构化设计需求和方法候选；确定性程序检查需求、计算参数、编译方法；
> 单一执行器操作 SolidWorks；独立检查器从真实模型和图纸回读 E1–E7；工程师批准交付。
> 先完成一个限定参数域的板件与简单装配，再按同一验收方法扩展。**

真正要补的不是模型、不是 CAD 内核、不是又一批工具，而是：
**每条工程要求必须落实为建模动作，和一条不能被生成者绕过的验收义务。**

## 二、四个选择与不选的路

| 维度 | 选择 | 为什么 |
|---|---|---|
| **表示** | 结构化工程需求 + 参数/约束/特征依赖 | 自由 Python、网格、工具名列表都无法承载「要求 → 动作 → 验收」的对应 |
| **生成** | 经验证的方法展开为主，DeepSeek 负责理解、补问、有界组合 | 不承诺开放世界机械设计；靠增加方法扩展覆盖，不靠增加整件模板 |
| **执行** | 现有 Python/MCP/COM 路线继续用，单一 CAD 写入者 | 已有工具池足够大；当前瓶颈是注册阻断、需求遗漏、验收失真 |
| **验收** | 真实回读 + 独立复算 + 参数修改 + 原生重开 + 负例 | 「能编译 / API 成功 / 图纸有尺寸 / 测试绿灯」任一项单独都不等于工程合格 |

不选的路与原因：

| 路线 | 取舍 | 原因 |
|---|---|---|
| 继续扩工具数量 | 停止作为主线，只补首件必要动作与回读 | 声明 **501** 条已远超当前能验收的面积（出处：`state/facts/R-engineering-path.md` R-01） |
| LLM 自由写 COM 脚本再凭报错修复 | 只留隔离研究通道 | 它既能改实现也能改目标和检查条件，「删要求换成功」无法可靠阻止 |
| 网格生成后导入 CAD | 不作工程主路 | 几何外观不是草图约束、驱动尺寸、配合和原生编辑历史 |
| 换其他代码式 CAD 后端 | 不选 | 与原生交付目标不匹配，还要重新承担特征历史、图样、版本兼容 |
| 训练/微调 CAD 专模 | 暂缓 | 缺工程师冻结的任务真值、稳定执行链和可靠验收器 |
| 只做标准检索与提示词 | 不足 | 检索到条文不等于适用性已判定，更不等于规则进入生成与放行 |
| 多智能体投票决定合格 | 不选 | 可以分工审查，但投票不能替代尺寸、约束状态和条款证据 |
| 模板 + 规则 + 受控执行 + 独立验收 | **主路** | 直接对准 E1–E7，能复用既有资产，可通过限定范围逐步扩展 |

## 三、目标结构：一份需求，三类资产，一个裁决

### 3.1 生产数据流

```text
用户中文需求 + 项目输入
  → DeepSeek 提议：需求 / 缺项 / 候选方法，不生成任意 COM 代码
  → 工程需求确认：参数、来源、功能、基准、材料、工艺、交付范围
  → 规则计算与适用性检查 + 方法选择
  → 编译：约束/特征/配合/图样计划 + 每条要求的验证义务
  → 计划内容冻结 + 写入授权
  → 唯一 CAD 执行器逐阶段运行
  → 从原生文件回读 + 独立规则计算 + 参数修改/重开试验
  → E1–E7 报告
  → 待工程审核 → 人工批准指定版本 → 正式交付
```

失败回路只返回：失败要求 ID、原始观测、涉及对象、可修改域、允许的恢复动作。
DeepSeek 可提出局部修订；执行器不得接受它改验收阈值、删除要求、填 PASS 或自行签署批准。

### 3.2 三类资产，职责不混

| 资产 | 回答什么 | 最小内容 |
|---|---|---|
| **规则包** | 这个设计在这些条件下应满足什么 | 适用对象/工艺/参数域，输入量纲与来源，版本化算法或检查，原文定位或独立依据，边界与正负例，审批记录 |
| **方法包** | 怎样把已确认设计做成可编辑 CAD | 输入、设计基准、主参数、约束与特征依赖、调用适配、失败恢复、验证义务、支持参数域与环境 |
| **验收包** | 实际产物是否满足要求 | 观测采集器、独立判定器、坏样件、变更与重开试验、覆盖范围、证据版本绑定 |

「有规则数据表 / 有函数 / 有单元测试 / 走过真机 / 限定域可交付」**分开记录**。
不另造覆盖既有 `level` 的成熟度枚举；在既有能力项旁关联交付族、E1–E7 结果和证据清单。

### 3.3 结构化需求不退回关键词

`scripts/engineering_contract.py` 是已确认工程需求的候选权威定义，
`scripts/engineering/design_ir.py` 保留为自然语言提议层。
正式施工先做字段归属与调用方对照，避免二者各自决定缺项、单位和批准状态。

每项关键值记录 `requirement_id / value / unit / source / confirmation / allowed_domain`。
尺寸缺失就问；材料、功能孔型、配合、制造约束、影响承载的工况**不得偷偷填默认值**。
图纸技术要求同样从这份需求生成。

关键对象至少贯通：要求 ID → 功能/接口 → 参数/基准 → 草图/特征/配合 → 图样标注 → 验收条目。
引用用语义角色和版本归属，跨重建不依赖当前选区或数组下标。
解析结果为多个或缺失时**停止**，不选最近的一个。

### 3.4 方法编译补什么，而不是再造编译器

- `scripts/engineering/compiler.py` 保留方法定义与前置检查；`registry.py` 保留工具名/实参绑定；
  `expand.py` 保留子方法展开。让它们最后产出**同一种执行计划**。
- 当前 `CompiledPlan`（哈希侧）与 `ExecutablePlan`（参数执行侧）分离。
  增加显式适配和完整内容校验，使需求版本、全部实参/表达式、语义引用、工具/规则/方法版本
  和验证义务进入**同一批准指纹**。
- 前后置与验证义务不能只是一句散文。散文解释保留，但执行引用必须解析到真实检查函数；
  解析不到即不可发布。
- 编译前检查硬要求覆盖：孔数/孔型/位置、材料、图样、配合等各有承担节点。
  不能满足全部硬要求的「只出板」是**未完成方案**，不是等价候选。
- 不强制凑候选数量。允许只找到一个合法方案；质量排序在硬要求全满足以后发生。
- 不全盘沿用「圆角必须在孔前/孔后」「孔组一律圆周阵列」这类全局口号。
  按几何、特征角色、工艺和后端失败域选择，并用参数修改试验验证。

### 3.5 运行位置与资源

DeepSeek 的对话、补问和候选生成留在现有宿主；持久作业状态、权限、证据与最终判定由本地工程服务掌管。
MCP 是调用入口，不应只是让模型任意组合全部底层工具；也不需要为了任务持久化先重造桌面 Agent。

复用 `scripts/engineering/jobs.py`、`executor.py`、`recovery.py`、`authorization.py`。
正式入口必须串起：会话独占、文档所有权、版本检查、授权、工具派发、观测、检查点。
兼容工具入口不能绕过相同写入控制。

首期保持本机执行。网络不可用时不新编语义方案；已批准且输入/规则版本齐全的任务能否继续，
按本地策略显式决定。不部署第二套本地规划模型。

## 四、E1–E7 的采集器与判定器

每个检查拆两段：**采集器从实际产物取数，判定器对冻结要求判断**。
规划器不能提交「我已经检查过」代替观测。

统一结果包含：检查 ID、要求 ID、对象/配置、观测是否完整、原始值与单位、期望值/依据、状态、
原因、证据引用、产物版本、检查器版本。顶层用 `pass / fail / unknown / not_applicable`，
运行失败另带错误码。既有多套 verdict 显式映射，禁止把其他非空字符串当 true。

| 判据 | 必须读什么、怎么判 | 必须能拒绝的负例 | 不能当替代品 |
|---|---|---|---|
| **E1 草图全约束** | 枚举全部适用草图；读取实际求解状态、欠约束实体、关系对象和驱动尺寸；位置/形状/大小均由约束表达。无异常、无欠约束；全固定还须检查设计意图 | 删定位关系、删尺寸、重复关系、全部固定却无驱动参数、采集失败 | 数关系、预填 expected_status、截图颜色、把未知 DOF 写 0 |
| **E2 参数化可重建** | 在已交付原生模型副本中改既有主参数，重建并核关键尺寸/关系及下游；再保存重开复核 | 只改属性没改模型、孔未随板宽变化、旧图纸、重建失败 | 新建另一份相同外形模型、文件哈希变了 |
| **E3 特征树可编辑** | 回读特征类型、错误/警告、引用与父子依赖；实际编辑前序草图或参数并验证后续 | 导入死实体冒充原生特征、悬空引用、错误配置、目标对象漂移 | 特征数大于零、STEP 可打开 |
| **E4 装配自由度闭合** | 对目标组件回读实际配合对象/状态与剩余运动；核目标 DOF、干涉、关键间隙、配置。静态首件不承担运动全域承诺 | 重复同一配合、全固定冒充配合、错轴/错向、漏配合、实体干涉、无间隙依据 | 配合数扣常数、模型摆在正确坐标、只验一个 bbox |
| **E5 图样合规** | 先由功能/制造/检验要求生成必要标注清单；逐项绑定实际尺寸/基准/公差/技术要求及所指几何；核模型配置、尺寸值、悬空、重复矛盾和版面 | 注释数量没变但孔位标错、少关键定位尺寸、错误基准、旧模型视图、默认材料、公差无依据 | 注释数量达标、文件非空、模板名带 GB |
| **E6 工艺可行** | 首件只选已确认机加工路线；从实际几何和工艺输入检查刀具可达、孔深/刀具、壁厚/余量、装夹与装配空间等适用项 | 刀具进不去、无有效加工基准、越过已验证工艺范围、删除必需检查 | 通用 DFM 分数、固定经验阈值、仅声明「机加工」 |
| **E7 结论可溯源** | 每条工程判断解析到有效证据或可复算依据；核原文/算法、适用性、版本、来源完整性、输入与产物绑定 | 假引用、摘要冒原文、旧版本证据、随意填来源标签、空 citations、缺文件 | 标准号字符串、台账 verified、生成者的结论文本 |

**范围原则**：E1 针对本交付范围中需要全约束的草图；机构运动属于 E4，
不借「有意自由度」放宽刚性零件草图要求。具体 API 是否支持数值 DOF、仅支持状态枚举
或需要组合诊断，在首个真机技术验证中确认；本文件不杜撰成员名。
若只能取得可靠的「完全定义」状态，记录原始状态并在验收规范明确其与 E1 的关系，
不能伪造一个测量值 0。

**不适用不是失败兜底**：单件可将装配项记录为有理由的不适用，
但整个首件交付包必须含简单装配，真实覆盖 E4；E6 必须有真正适用且通过的工艺项。
缺规则/缺采集能力是 `unknown`，不是不适用。

**人工审核不是改色按钮**：可审批需求、适用性和只能人工完成的工程判断，
但不能把失败的机器判据改为通过。视觉检查补充图样可读性，不能代替尺寸、公差与约束证据。

## 五、首件交付范围

**机加工安装板 + 简单定位装配**，连同零件图、装配图、BOM、工艺检查与验收包。
具体标准件、材料、接口、公差和制造条件在需求冻结时确认；不预选标准等级、不替用户决定载荷。

选它的理由：这个对象已经能暴露草图约束、孔位联动、原生编辑、配合、尺寸链、图样和工艺
的大部分共性问题，且能直接利用既有实现。它是完整工程交付链的最小样板，不是最终产品边界。

首件必须交付：

- 原生参数化零件与装配，主参数、设计基准和功能关系可理解；不能靠固定所有对象蒙混。
- 与同一模型修订绑定的原生图纸、PDF、BOM；关键标注有语义映射。
- 规则/标准配置及适用项清单、独立计算、工艺与检验要求、未覆盖事项。
- E1–E7 报告、原始观测、命令/环境、文件清单和哈希、人工批准记录。
- 一次真实的「打开已交付件 → 改主参数 → 重建 → 重新检查与出图」演示及证据。

有承载功能而缺载荷时，不可当作低风险练习直接放行；先补输入或明确仅交几何设计草案。
软件测试样件可采用合成需求，但要明确不是实际设备制造放行。

## 六、施工顺序 S0–S6

顺序固定：`S0 → S1 → S2 → S3 → S4 → S5 → S6`。
S0 的限定维修与 S1 的判据设计可在职责分离下并行；**所有真机工作串行**。
始终只展开一个交付族，不同时铺开所有旧工作包。

### S0｜恢复首件所需的正式通路，冻结可复现基线

1. 记录版本、解释器、模板、配置与文件权属；按「已有实现 / 能导入 / 能注册 / 有测试 /
   有当前真机证据」建立首件依赖清单。
2. 定位并修复当前注册阻断、`MethodSpec.allows` 缺失等首件链必经问题。
   重名先比较语义与调用者，单位问题核完整调用链，不能为消除门禁简单改名或加豁免。
3. 把首件会用到的声明式和装饰器工具纳入同一可调用目录与准入检查，做工具层实参/回读测试。
4. 审计收尾命令。`tools/round_chain.ps1` 当前仍有 `git add -A`、生成器和关闭 SolidWorks 动作；
   先使验证结果可靠传播、写入范围及资源所有权显式化，不把它当只读检查运行。
5. 非首件缺陷登记到队列；涉及共享安全、数据损失、误放行或共同注册入口的缺陷必须先修。

**完成标准**：首件依赖能经正式入口解析/注册；相关测试收集和执行通过；无忽略文件、
放宽断言换绿；已有的两类注册来源都得到行为验证；非本任务文件和用户会话不变。
全量旧失败逐条归类，不宣称全仓绿。

**停线条件**：正式入口仍阻断，或不能确定会修改/关闭谁的文档。
此时可继续离线判据工作，不做真机写入。

### S1｜先做 E1–E7 的验收规范与坏样件，再谈新能力

1. 按第四节为每条 E 定义输入、取数来源、判定、unknown、不适用理由和版本绑定。
2. 优先用既有结果/证据类型扩展，建立唯一映射，不复制一套 verdict。
3. 写最小正例、负例与缺证据例；先用合成观测验判定逻辑，再用真实坏样件验采集链。
4. 把现有估算器明确限制为预检用途；图纸 `covered` 布尔、调用者传来的 `formula_ok`、
   规则来源标签都不能直接授权交付。
5. 建立一份「要求 → 检查 → 原始证据」的覆盖表。代码规范门禁和工程产物验收**分别**报结果。

**完成标准**：每条 E 都有「好输入通过、已知坏输入拒绝、缺证据 unknown」；
任一检查未运行、上游失败或对象未覆盖，报告不绿。
此时只叫**离线判据成立**，不叫 E1–E7 真机通过。

**停线条件**：某项没有可验证的采集方式。必须列为技术风险，不能先把返回值填上。

### S2｜冻结首件需求和最小规则包，把知识变成执行义务

1. 与工程负责人冻结首件功能、接口、主参数及可修改域、材料、工艺、必要图样和交付目的。
2. 从这些要求倒推最小规范/规则集合，不先批量搬整个标准库。
3. 对标准相关规则，实现时通过知识库取原文、核版本与适用范围；
   依本项目授权处理缺源。供应商工艺/经验规则单列来源和适用边界，不冒充标准条文。
4. 编写规则登记 → 参数输入 → 计算/检查 → 引用 → 验收结果的闭环。
   规则代码摘要绑定实际执行算法及依赖数据，而不是仅对聚合函数算哈希。
5. 引用或知识库暂不可用时保留 `unknown`；开发可用合成夹具测试机制，
   但制造放行不可用夹具代替原文。
6. 完成结构化需求到方法计划的单一映射，去掉关键参数的静默默认值和凑候选的需求删减。

**完成标准**：首件每条硬要求有执行承担者和验收者；每项关键规则有原始依据、适用性、
输入、独立参考例；换材料/工艺/规则版本、移除引用或未确认参数均不能继续旧批准。

**停线条件**：必要规则无法取证或工程负责人未确认关键输入。不得为了让后续成事而默认一个等级。

### S3｜做成原生可编辑的板件参数族，真过 E1–E3

1. 用已有板/孔组路径改成尺寸与关系驱动的方法：位置、方向、大小完整约束；
   不得全固定，不得仅用初始坐标画对。
2. 为主尺寸、基准、孔位和特征建立稳定语义引用；孔型/孔位逐项回读，不只比较总切除体积。
3. 先核官方签名、Remarks、示例和死路限制，再做限定真机试验。
   先验证检查器能看见真实坏样件，再验证生成方法。
4. 在同一个交付件副本上改已有主参数，检查下游联动、特征错误和引用；
   保存重开、配置切换后复查。
5. 将 E5 最难的一个必需尺寸/基准标注同步做小验证，
   避免等装配完成后才发现图样 API 到不了。

**完成标准**：名义样件和冻结的边界/扰动样件都真过 E1–E3；
单位错、缺关系、错误孔位、引用漂移必被检出；原生编辑成功不以新建文档替代。
记录观察精度与范围，不将有限样本称为整个连续参数域的数学证明。

**停线条件**：约束状态取不到、主参数改动不联动、只能导入实体而无编辑历史、
必需图样绑定不可实现。

### S4｜把装配、图样与工艺接上，完成首个 E1–E7 交付包

1. 装配有地件、有功能配合；回读配合目标与实际剩余运动，检查干涉和关键间隙。
   先做静态定位装配，不把连续运动全域验证塞进首件。
2. 从功能/制造/检验要求生成必要尺寸清单；逐项创建或绑定真实图纸对象，
   验证其数值、基准、所指几何和版本。模型已有尺寸导入只是手段，不是全部标注义务。
3. 用冻结工艺检查实际几何；对加工和装配路线不能机器判的部分明确列人工义务及签核。
4. 移除生成图样时固定追加的材料/公差文字，改为取批准需求；读取不完整返回 `unknown`。
5. 原生重开全套文件，核关联、BOM、标注和实际 PDF 版面；形成一致版本的证据包。

**完成标准**：同一首件的 E1–E7 全部适用义务有实证，整个交付族不靠把 E4/E6 列不适用通过；
少一条关键定位尺寸、换一份旧图、重复配合、缺工艺依据都使放行失效。
自动状态只能到「待工程审核」，正式交付另需具名批准。

**停线条件**：图纸只能导出但不能核语义、工艺无法说明、引用原文缺失。

### S5｜真实 DeepSeek 端到端、修改与中断试验

1. 把同一工程服务接入当前宿主；真实 DeepSeek 接收自然语言需求、补问并产出结构化提议，
   不由测试脚本偷偷代填工具序列。
2. 采用受控高层入口：提议/校验需求、列方法、编译计划、执行已批准版本、查询状态与证据。
3. 先用少量同义表达、歧义表达、缺项和域外任务验证理解；
   再以同一冻结任务集比较「模型直接用工具」和「模型用工程系统」。
4. 在计划冻结后改参数、改文件、换配置、取消、断网、超时、保存失败等情况下试验。
   超时后进入结果未知，先观察/恢复，不能自动重放非幂等写入。
5. 人工接管单独记录，不能藏在成功率里。缺参数的澄清与中途代操分开计数。

**完成标准**：一个真实自然语言任务通过完整链并交付首件；改主参数后图纸和验收更新；
过期批准、缺证据、需求被删、未知执行均被挡住；非法任务不写 CAD；
合法任务不能靠全拒绝通过安全测试。

**停线条件**：仍靠关键词把陌生需求落到「板」、真实模型未调用、执行入口能绕过检查，
或恢复不能确定工件归属。

### S6｜限定发布、重复验证，再扩展交付族

1. 发布一个明确支持参数域、工艺、SW 版本/配置、规则包版本、人工审核条件的能力包；
   不写「机械设计全覆盖」。
2. 从已有语料中筛选并补齐首件集，由工程负责人确认真值，区分开发集与留出集；
   不能用 AI 自动标签直接作为最终验收真值。
3. 固定模型版本、预算、重试上限、工具集合和环境，记录全部尝试，
   而不是只汇总成功产物。
4. 在受控新环境或干净配置副本上做安装/恢复/交付复现。
   源文件和自动复算入口入库；大工件与原文留在受控证据位置，
   仓内清单保存版本/哈希/取得方式。
5. 通过以后，按「轴/孔与配合 → 支撑轴系/定位夹具 → 有限运动机构 → 钣金/焊件 →
   CAE/拓扑等独立域」扩展；具体先后由真实需求调整，每一域重新跑相同准入流程。

**首发试验目标（需在 S1/S2 冻结，不是当前成绩）**：首件交付族的合法参数/接口组合数与非法输入例数，按 S1 冻结时确定的规模设定；另覆盖单位、引用、保存、中断、版本、证据缺失等故障。合格率、证据完整率与错误放行率三项目标同样在 S1/S2 冻结时确定（目标值待批准，非实测读数；落点 `specs/` 的 S1/S2 判据文件）。报告实际分子/分母和失败分布；有限样本零错误不等于零风险。

**停线条件**：本机能演示但他人不能复现、盲集未经确认、缺证据还给合格、升级后旧报告继续放行。

## 七、工程知识怎么扩展

每次扩展一个方法，按序：

1. 明确用户需求与支持域，并列出会失败的输入。
2. 确认已有代码/规则/官方示例和来源许可；优先沿用本仓模式。
3. 将规范拆成「可自动检查 / 需人工判断 / 需实物检验 / 不适用且有理由 / 尚未覆盖」几类义务。
4. 对能编码部分，编写确定性计算、量纲与适用性检查；独立复算和边界反例先于生产放行。
5. 方法编译消费这些义务，CAD 回读供给实际数据；规则升级使相关证据失效。
6. 用新参数组合和变更任务检验迁移性，再登记为受支持范围。

第一阶段只支持已经能验收的基本构造。
第二阶段把「板、孔组、定位、连接、旋转轴、图样」作为可组合方法，明确各自接口/效应/依赖；
有限枚举或受限任务分解足够时，不引入通用规划器。

自由曲面、图纸逆向和新颖机构保留探索通道。探索产物始终是草案；
经来源、参数域、真实回读、变更测试和工程复核后才加入生产方法包。

## 九、责任与投入

三项必须有人承担的责任：

- **工程负责人**：确认功能、接口、工艺、标准适用与最终审签。这是不能由更大模型消掉的工作。
- **CAD/执行负责人**：把已确认需求可靠写进原生模型，管理 COM、引用、保存与恢复。
- **验证负责人**：定义独立期望、坏样件和放行规则；不能将实际输出直接抄成期望值。

可以一人兼任，但记录中区分生成与审核责任。
多代理适合只读调查、独立算例、代码与测试分工，**不并发控制同一 SolidWorks 会话**。

有效工程人日粗估（复用现有代码、首件范围不扩张、无重大接口障碍的假设下）：

| 步骤 | 粗估 | 主要不确定性 |
|---|---:|---|
| S0 | 2–4 | 共同入口阻断、收尾副作用、旧测试漂移 |
| S1 | 3–5 | 真实状态采集与独立判据设计 |
| S2 | 4–8 | 必需原文取得、工程输入确认、规则参考算例 |
| S3 | 5–9 | 驱动尺寸、约束回读、稳定引用与原件修改 |
| S4 | 6–12 | 图纸语义绑定、装配验证、工艺数据与人工复核 |
| S5 | 3–6 | 宿主实际连通、真实模型理解、中断恢复 |
| S6 | 3–5 | 留出样本、干净环境复现和发布收口 |
| **合计** | **26–49** | 不含等待授权、标准材料、现场试验和重大进程内桥开发 |

代理并行不会把真机单通道和工程师确认时间按代理数等比分摊。
S0/S1 后按实际阻断重新估算，S3 后才给首发日历承诺。

## 十、防止回到「工具与门禁越来越多，交付不动」

1. 每个任务必须回答：服务哪个首件要求、改善哪条 E、增加哪个可重复试验。没有答案不进当前迭代。
2. 共享基础设施修复限定在阻断、安全和首件依赖；不把全仓整理作为获得第一个合格样件的前置。
3. 每步结束给出同一首件 E1–E7 状态表及证据变化，而不是代码行数、工具数或规格勾数。
4. 每条新检查器必须能拒绝一个真实坏样件，不能只新增「字段存在」的门禁。
5. 需求、阈值和盲集冻结后，失败只能修实现或走批准的需求变更；
   不能换样本、删标注义务、改为人工通过来完成阶段。

**全方案的完成定义**：一个限定交付族，真实 DeepSeek 从自然语言开始，
在冻结范围内反复产出可编辑、可重建、可装配、可出图、工艺有据且证据完整的 SolidWorks 交付包；
已知坏输入和坏产物被拒绝，人工批准绑定正确版本。做到这一点之后，扩展才是在积累可靠工程能力。
