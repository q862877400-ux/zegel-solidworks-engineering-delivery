# 答复你反问的四项（含两处我顺手验证的结果）

## 一、那 10 个文件是谁写的

**是 SolidWorks 自己的求解器写的。** 我们的拓扑优化模块是 cosworks 原生接口的薄封装：
建研究、建网格、跑分析、取结果——求解本身在 SolidWorks 里做，我们只驱动它。

★ 所以你那条"结果文件夹"的方向是对的，但两处限制：
一是**我们本地的 API 文档里没有 cosworks（`ICW*`）的类型页**，所以我**查不到**那个设置，**不能当事实用**；
二是我们代码里搜"结果文件夹 / ResultsFolder"**0 处** —— 也就是说**我们从来没设过它**。
要确认它存在，得去查本机 SolidWorks 的类型库反射；我能做，但这一步不属于"立刻可动手"。

## 二、运行时用户会不会同时开着自己的模型

**这题我答不了，是用户的事。** 但给你两条我方的证据：
我们的回收脚本里写死了一条安全判定 —— **只要 SolidWorks 里有一个不是我们打开的文档，就拒绝重启**；
说明代码本身就假定这种情况会发生。加上单实例约束：如果用户开着文档，我们的工具就是**在他的会话里**操作。

## 顺手验证：你担心的那个取舍（Pack and Go 要不要先开原件）

★ 我查了本地的官方文档：`GetPackAndGo()` 挂在**文档扩展接口**上 ⇒ **必须先有打开的文档**
（官方示例的前置也写着"指定装配体存在"，即先打开它）。
⇒ **所以"拿原件直接 Pack and Go"与"从不开原件"确实冲突**——你的担心成立。

★★ 但有一条折中可以同时满足两者：**先纯文件复制整棵树 → 然后只打开副本 → 在副本上跑 Pack and Go**
让它把引用更新到沙盒内。这样**原件从头到尾没被打开**，而"打包会更新引用"这个好处仍然拿到。
★ 我的倾向是走这条，★ 但它**没有实测过**——我会用合成件做你说的金丝雀实验来判别，不用用户件。
