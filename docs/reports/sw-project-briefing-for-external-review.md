# SolidWorks 自动化项目 · 三件我们真正卡住的事

你看不到我们的文件，本文不引用文件名与路径。这一份不问流程细节，只问**我们真的过不去的三个坎**。

## 背景（够你判断用）

一个自建的 SolidWorks 自动化仓库：把官方 API 封成 **448 个可被 AI 调用的工具**，能力层 176 个模块，真机验证脚本 590 个，工作项 157 个，自动门禁 33 道。人手是**一个人 + AI**。

两条已经做成的事（作为下面的前提）：一是**工具目录已经能低成本加载**——不必把 448 个工具全塞进上下文，而是按"预设"决定呈现哪些，这件事已经装好并在运行；二是我们有一套自己的验证纪律——**判据一律用回读**（调完再读一遍状态），不看被调成员返回什么。

---

## 坎一：448 个工具怎么验证——一个一个真机跑不现实

**现状**：每条能力的真机验证都是**人手设计的一次性脚本**，各自要配夹具、设计判据。真机跑要**独占一台机器**；而相当多的工具**需要前置**（先选中一个面、处于草图或编辑态、有活动文档）才能调。所以"全量跑一遍"在我们的规模上是**几小时到十几小时**的量级，而且会随工具数线性增长。

**我们想到的都不够**：抽样、按优先级排序。★ 抽样有个致命问题——**它抽不出"哪些工具会互相破坏"**（组合效应），而这类问题恰恰最难在生产里发现。

**我们猜过几个方向，但不知道哪个真的成立**：
一是**从工具自己的声明自动合成调用**，只看"调用路径通不通"，不看"做得对不对"；
二是**变异测试**——故意破坏底层某一处，看哪些工具会红，用它反推覆盖面与脆弱点；
三是**正交/组合覆盖**，用少数几个探针覆盖一大批工具；
四是**录放**——录下一次真实使用的调用序列，用来做回归。

**请你判**：在"真机昂贵、夹具昂贵"的约束下，**这四条哪条真能省时间、哪条只是听着好**？有没有我们没想到的做法？★ 尤其：**"做对了没有"与"路径通不通"这两件事，值不值得分开验证**（我们倾向分开，因为前者贵得多）。

---

## 坎二：第一次选错工具了怎么办——我们只有"让它选对"，没有"选错之后"

**现状**：工具目录能低成本加载（见背景）。工具选择的精确度，据业主是 **80% 左右**——★ 这个数字我在仓库里**没有找到对应记录**，它是业主给的，请你按"未在我方留证"对待。

**卡在哪**：我们把全部力气花在"**让它第一次就选对**"（工具命名、描述、目录分区、呈现方式），★ **完全没有设计"选错之后怎么办"**。而 80% 意味着**每五次就有一次选错**，这个失败率在真实使用里是不能接受的。

**我们猜的方向**：一是执行**之前**先做一次可逆性判断（这个操作能不能撤）；二是把失败**分类**（参数错 / 前置不满足 / 选错了工具 / 需求本身理解错），只在最后一类才回退重选；三是让每个工具**自己声明"我这里不适用"**，而不是硬失败；四是**试探性执行 + 回读判据 + 回滚**。

**请你判两件**：
一、**兜底的责任该放在哪一层**——工具层、编排层，还是模型侧的提示里？★ 我们的直觉是"工具层负责声明自己不适用、编排层负责分类与回退"，但不确定这是不是会变成一个新的复杂性来源。
二、**回退的代价怎么控制**。在我们的场景里回退很贵：真机上"退回去"意味着把已经改过的模型**改回原样**（或者干脆丢弃重来）。★ 有没有比"丢弃重来"更省的做法？

---

## 坎三：建模的"思路"从哪来——先画什么、再画什么

★ 这是我们三条里最深的一条，也可能是我最需要你回答的一条。

**现状**：448 个工具全部是**操作级**的——拉伸、切除、圆角、阵列、抽壳、装配、出图。但"**给我建一个什么东西**"需要的是**策略级**的知识：**先做哪个特征、再做哪个特征**、基准怎么选、什么时候该用草图驱动什么时候该用特征、公差与可制造性怎么落进模型里。

**卡在哪**：**这套知识既不在预训练里，也不在官方 API 文档里。** API 文档只告诉你"这个成员怎么调"，从不告诉你"这个零件该怎么建"。我们已经实测到一次具体现象：an agent 能**把 API 调对**（读出正确的特征、正确的参数），但**建出来的东西是不是"该这么建"，我们没有任何判据**。

**我们手里的替代品、以及它的不足**：我们有一份机械设计的知识资产（设计规范、选型计算、可制造性检查、失效分析）。★ 但"给一句话就建出**正确且高效**的模型"这条路，**我们从来没有验证过**——它到底够不够，我们不知道。

**请你回答三件**：

一、**"建模策略"能不能外置成可检索的知识**（规范、案例库、从已有模型反推特征树），还是这件事**必须靠模型自身的能力**？★ 如果能外置，最有效的载体是什么形式——自然语言的规范、还是结构化的"零件类型 → 特征序列"模板？

二、★ **怎么让它知道"顺序"**：同一个零件往往有多种建模顺序都能建出来，**哪一个更好、凭什么**？我们缺的正是这个判据——是"几何更稳"、"后续更好改"、"重建更快"，还是别的？★ 你有没有一个可操作的**优劣判据**，能让我拿它去评判两个建模流程？

三、★ **怎么验证"建得对"**：几何对不对我们可以回读（体积、包围盒、面数），但"**该不该这么建**"（特征顺序、基准选择、是否利于后续修改、是否符合工艺）我们**判不了**。★ 请你给一个可操作的验收定义——哪怕是"先用人工判一批、再提炼成规则"这种渐进方案也行。
