## §1 背景：为什么"给 SolidWorks 做个 AI 接口"是件难事

★ 冷读者最容易误判的地方在这里 —— 这不是"包一层 REST API"那种活。四个真实约束：

**1. 官方 API 是 COM + 迟绑定，很多成员"看着在、其实调不到"。**
官方类型库里有一族接口**标记为"仅进程内非托管 C++"**。★ 本项目实测：某个钣金特征数据接口上的
`AccessSelections` 与 `SetFixedFace`，**20 多种参数形态全部失败**（多数报"类型不匹配"；
其中一种报 `0x80010105`，即 **RPC 服务端故障**）⇒ 我们把它记成**架构性限制**并停下。
★★ **但这个结论现在受到质疑**（理由见 §13 —— 那个错误码说明调用**其实已经封送过去了**）
⇒ ★ 我把这一条从"真墙"降为"**待验证的墙**"，见 §9。

**2. 模态弹窗会永久冻住调用。**
SolidWorks 一旦弹出模态对话框，那个 COM 调用**永远不会返回** —— 这是本项目**无人值守挂起的头号原因**。
★ 我们的处置不是"小心点"，而是自建了一个**弹窗护栏**：硬超时 + 子进程隔离 + 执行中每 0.5 秒扫一次窗口 +
**把弹窗分三级**（语义唯一明确的自动点；多义或进度窗**不点**、立刻杀掉那个被冻住的调用并把证据交回人；
含危险词的禁止点）。★ 所有真机命令**一律**走它。

**3. 返回值不可信 —— 这是本项目反复吃亏换来的一条铁律。**
★ 实测例：`SelectByID2` 返回 `false` 而选区计数其实是 1；`RecordLine` **在"录制根本没开"时也返回 `True`**；
`SetSelectedObjectMark` 参数传错时**返回 false、不报错、标记静默未设**。
⇒ ★★ 于是本项目规定：**判据必须是"回读"**（调完之后**再读一遍状态**，看它到底变没变）。

**4. SolidWorks 是单实例 COM，多进程抢同一连接会死锁。**
★★ **这条约束的因果要说准**（上一版没说清，评审也指出来了）：因为它**只能有一个进程连着**，
所以**必须从中挑一个实现来跑** —— 而"挑哪个"的标准是**许可证**：挑许可证最宽松的那份（可以在其上自由修改与分发），
至于那份**传染性许可证**（AGPL 类）的实现，**只读它的思路、不抄它的代码**。
⇒ ★ 所以不是"单实例决定了许可证选型"，而是"**单实例 ⇒ 必须二选一；许可证 ⇒ 选哪一个**"。

## §3 本项目的核心方法论：**怎么判断"真的做成了"**

**判据一律用回读。** 看的不是"调用没报错"，而是**调用之后再去读一遍状态**：

| 例子 | 不信什么 | 信什么 |
|---|---|---|
| 选中一条边 | `Select4` 的返回值 | 选区计数接口的**读数** |
| 相交特征建成了 | `PostIntersect` 回的对象 | **特征树增量** + 交线数量接口 |
| 插了 BOM 气泡 | 批量插气泡接口回的数组 | **视图里"注记数量"接口的前后增量** |
| 草图被隐藏了 | 那个调用的返回值 | 特征可见性属性的**前后读数** |

**"选不上"与"选了也没用"必须分开记。** ★ 选区读数为 0 ⇒ 那是**前置没备成**，**不构成"能力无效"的证据**；
★ 只有**确实选中了**、调完**结果仍未变**，才是"这个能力不行"。

**官方文档与真机不一致时以读数为准，并逐条记账。** ★ 分歧账本现有 **12 条**（例：官方页多处写长度单位是"米"
而真机是**文档单位（毫米）**；官方示例让某个选择标记看起来必需、真机证明**不必需**）。

**验证等级五级**：`verified`（我们自己真机跑过）/ `source_verified`（来源声明跑过、我们未复现）/
`stitched`（并进来了、从未运行）/ `indexed` / `not_implemented`。
★ **禁止**把别人的声明写成 `verified`。

## §6 ★ lean 模式（工具数太多的问题）—— **已实装并在运行**

★ 这段按用户指示重写。**上一版说"待部署"是错的。**

**问题**：本项目对外有 **448 个工具**。工具一多，宿主（AI 客户端）面对的工具目录就臃肿 ——
既占上下文，又让模型选错。

**状态**：★ **已实装**。★★ 而且**你现在读到的这份简报，其作者（我）与上一轮评审的交互本身，
就是运行在 lean 模式下**（用户确认）。

**机制**（关键理解点）：

```
工具注册表本身**搬不进 preset**（消费方全在宿主平面）
        ↓
preset 能拥有的是这份注册表的**呈现方式**
        ↓
宿主本来就提供按**作用域**设置呈现方式的机制，可选模式含 native / ptc / both，**我们新增了 lean**
```

⇒ ★ **"按 preset 分别选工具呈现方式"是宿主本来就有的功能** —— 项目前两轮曾判断"做不到 / 要塞进 preset"，
**都是错的**，已记账更正。

**为它补的三个缺口**：① 该机制的 `mode` 可选值原先只有 `native|ptc|both` ⇒ **新增 `lean`**；
② 非 native 模式一律等待某运行期注入 ⇒ **lean 走立即路径**（否则永久 pending）；
③ ★ 另修一处真 bug：设置呈现方式时**漏注册目录段** ⇒ 默认部署下 lean preset 拿不到目录段（**项目自己的新测试抓到的**）。

★★ **但评审有一条批评成立，我接受**：**"机制能跑"不等于"效果成立"**。
现有的 **9/9 通过**与 **447 项测试**只证明**机制能运行**；★ **没有任何证据**表明
"上下文真的变小了""模型选错真的变少了"。★ 那需要**任务级**的端到端对照（native vs lean），
而这正是 §14 里我列为**最想做但最贵**的那件事。

## §9 技术难点（真墙 / 待验证的墙 / 看起来像墙）

### 9.1 ★ 待验证的墙（评审质疑后**从"真墙"降级**）

**某一个钣金特征数据接口上的 `AccessSelections` 与 `SetFixedFace` 调不通。**

- 我们原先的结论：**架构性限制**（"官方标记仅进程内 C++，封送不过去"），**要过只能换绑定后端**。
- ★★ **评审的质疑（我复核后认为成立）**：我们记录的错误里有一个是 `0x80010105`（**RPC 服务端故障**），
  它意味着**调用已经封送过去了、是 SolidWorks 端抛了异常**；★ 如果真是"仅进程内、无法封送"，
  预期应是 `E_NOINTERFACE` 或类型不匹配，**而不是服务端故障**。★ 这更像**状态或调用顺序**问题。
- ★★ **而且实测我们确实没做的两件事**（我查证过）：
  ① **从没试过 `comtypes`**（换一个绑定后端）—— 全仓只有一处提到它，还是"分类说明"，不是实验；
  ② 记录里**只有两个成员被孤立调用**，**没有证据**说明是否走过完整的
  "取定义 → 取得访问权 → 修改 → 写回定义 → 释放访问权"序列。
- ⇒ ★ 我把这条**降级为"待验证的墙"**。★ 它已经影响了 **3 条能力**的结论（一条折弯 / 边线法兰 / 角撑板）。
- ⇒ ★ **判据（若做这个实验）**：**换一个绑定后端能过 ⇒ 墙在绑定层；同样失败 ⇒ 墙在 SolidWorks 本身**。
- ★★ **我又查了三件事，全都让这条结论更弱**（都是本次实测）：

| 查什么 | 结果 |
|---|---|
| 官方类型库里有多少接口带这个"取得选择访问权"成员 | ★ **117 个**（★ 评审猜"同族有成对的调用"—— **猜对了**，且规模远超预期）⇒ ★ **正控制随手可得**：随便挑一个兄弟接口试一次即可 |
| 我们**有没有成功用过它**（任何接口、任何地方） | ★ **一次都没有** —— 全仓只有门禁与注释在谈论它，没有任何一处**成功的调用** |
| 我们的后端清单里对**替代后端**是怎么写的 | ★★ 清单里**同时**断言"**comtypes 不是原生指针接口的替代品**"与"C# PIA **同样不能**调用" —— ★★ 而这两条的验证状态字段**都是空的**，**没有任何实测证据** |

⇒ ★★ **这是我自己的一处"结论强度超标"**：从**一个接口**的失败，推广成了**整族不可达 + 两种替代后端都不行**，
而三条推广**都没有证据**。★ 本项目自己的纪律（"查不到就写查不到""不许把未验证的写成结论"）本该拦住它。
★ 评审的"正控制"是**最便宜且最有判别力**的一步 —— ★ 我把它排进 §15 的行动顺序。

★★ 评审还给了**把"该停"变成可操作规则**的三条（我全部接受，见 §15 的 C 部分）：
看**错误签名**而不看尝试次数；变化要**覆盖不同轴**（参数编码 / 调用顺序 / 对象状态 / 绑定后端，至少 3 根且必含后两者之一）；
以及**加正控制**。

### 9.2 真墙（架构性，换参数解决不了）

| 墙 | 实测 | 现状 |
|---|---|---|
| **曲面创建接口的返回值跨次变化** | 同一个调用**有时成功有时回 `None`**（四轮探针，已排除调用顺序与单例状态）；换用后继版本**仍然** `None` | ★ 不修返回值，改**让失败可见**（对 `None` 抛带原因的异常）★ **评审补充**：还应**逐比特记下四轮的完整入参**、对比成功与失败组（可能是我给了无效几何、而它静默返回 `None`）⇒ **我接受，列入待办** |
| **实体（边/面）没有可用名字** | 按名字选择边与面，**计数都是 0** | ★ 可行路径是**按对象选**，或**按面上的点**选 |
| **模态弹窗永久冻住调用** | 无人值守挂起的头号原因 | ★ 弹窗护栏 |
| **单实例 COM** | 多进程抢同一连接会死锁 | ★ 运行期只跑一个服务 |

### 9.3 看起来像墙、其实是"我自己调错了"

- **空的 COM 接口参数不能传 Python 的 `None`** ⇒ 报"类型不匹配"，★ 而那个错误**看不出是这个参数的问题**。
  ★ 我因此一度差点得出"选择不可能"的错误结论。
- **同名接口分属不同族** ⇒ 用错接口时"连**读**都读不到"，★ 看起来像"属性只读"，实际是"接口不对"。
- **探测脚本没按工具层的契约调** ⇒ 同一个错犯过三次，每次"失败"都像能力坏了、实际是调用方传错了对象。

### 9.4 三个"空白域"

★ 我们说的"空白"判据是：**官方 API 里有这个能力，而别人没做** —— ★ 不是"全网搜索无结果"
（★ 评审说得对：**否定性断言无法靠检索证明**）。★ 并且我接受评审的另一半：
**"有没有人做过"与"有没有人需要"是两件事** —— 后者是产品判断，我们目前**没有证据**。

拓扑优化已做出可跑的闭环；动画导出（AVI）与成本估算仍是缺口。

### 15.1 A（测试红 → 工具真机失败的"桥"）：**拆成两半，不要通用映射表**

**第一半 · 大部分红根本走不到用户，不需要桥。**
A 类（守卫钉数）、B 类（测试污染）、D 类（措辞 / 门禁自检 / 负例自证）**都没有用户调用路径经过它们**。
★ 真正在代码路径上的只有 C 类里的两条（**出参未包装**、**调用与导入不一致**），也许再加分类表那条。
做法（评审估一两小时）：
1. 沿**导入关系与工具声明批次反查**：这段代码会被哪些对外工具走到。★ **用的时候现算，不要长期维护一张会腐坏的追踪表**；
2. 对这几个工具，**经护栏在真机上各调一次**，参数由声明合成；
3. ★★ **只看"错误的性质"，不看对不对**，分四类：**前置未备成**（选区 0 / 无文档）· **接线错误**
   （`NameError` / `ImportError` / 出参类型不匹配）· **SolidWorks 端报错** · **被护栏杀掉**。
   ★ 只有**接线错误**才是这两条红所预示的**用户可见失败**。

**第二半 · 通用版值得建，但只建"存活"，不建"正确性"。**
夜里用我们已有的**后台串行跑法**，把 **448 个工具各调一次**，同样分四类；参数从声明合成；
★ 判据只有"**调用路径走通没有**" ⇒ **不需要给每个工具写端到端测试**，成本是**一晚上机器时间**。

★★ **这会得到一条与"能力等级"正交的轴**：能力等级回答"**做对了没**"，存活状态回答"**这条路径能不能走通**"。
- "单测绿 ≠ 工具可用"这层断层由**存活跑**补上；★ "工具可用 ≠ 真机建成"仍由**探针 + 回读**负责，**别指望存活跑去填**；
- ★ **顺便解决我的问题 5**：那 197 个无能力条目的工具**不必建 197 条能力**，只给它们**存活状态**，
  诚实标成"**只知道能调通**"；★ 再加一个**棘轮**：新增工具要么挂能力条目，要么**显式标"底层原语"并写理由**。

★ **我采纳，并补一条要求**：★ "参数由声明合成"很可能让**"前置未备成"那一类占绝大多数**
⇒ ★ 我要求把**这一类的比例本身当作一等读数报出来**（★ 若 80% 落在这类，那说明"工具对调用者前置的依赖过重"，
那本身就是一条重要的架构读数，而不是"没测出来"）。

### 15.2 B（端到端任务集的夹具与判据）：

**夹具：脚本生成可以，而且比手搓好**（参数化零件的期望值是**构造出来的**：体积 / 包围盒 / 孔数 —— 这是便宜地拿到真值的唯一办法）。
两个风险要防：**① 循环** —— 夹具必须用**独立于被测工具**的路径生成一次、**冻结成文件**，别每次重生成；
**② 选择偏差** —— 掺 **3–5 个留出的"野外"文件**（真实零件或装配体，带压缩特征 / 外部引用 / 多配置），这些才暴露盲区。

**成本：拆成两半，大半不需要 SolidWorks。**
- **目录体积（native vs lean）**：token 数是**确定性**的，**零成本，今天就能量**；
- **工具选择准确率**：给智能体同一任务和各自的目录，**只记首选工具与序列、不执行**，与参考序列比 ——
  ★ 这一步**可几百条并行**，不占机器；★ lean 的两个主张（**上下文小、选错少**）正好都落在这一半；
- **真机执行只做试点**：**3–5 个任务 × 2 种模式 × 每格 3 次 ≈ 30 次**，夜里串行。
  ★ 模型输出有随机性，**单次没有意义** ⇒ **先看方差，再决定要不要扩**。

**判据：按成本分层，自动的优先。**
① 产物存在 / 非空 / 能被读回（导出文件能解析、实体数合理）；
② **几何回读对比构造期望值**（体积 / 包围盒 / 面数 / 特征数，带容差）；
③ 只有**没有真值**的项（如工程图版面）才用 LLM 判分，★ **当旁证、不当闸门**，并抽几个人工校准。
★ "审美"不用判 —— **把工程合理性翻成约束**（孔径范围、圆角存在）。

★ **主指标别只看通过率**（n=30 太粗）⇒ 看**同任务下的配对差**：调用次数 / 错工具次数 / 恢复次数 / token。

★ **我采纳**。★ 我的补充：**"必须用独立路径生成夹具"这一条我们其实踩过同类坑**（用被测工具造夹具 ⇒ 循环论证），
所以我会把它写成夹具的一条硬前置。

### 15.3 C（怎么区分"该停"与"过早停"）：**看错误签名，不看尝试次数**

1. **看签名**：每次记 (错误码, 是**客户端封送时抛**还是**服务端抛**, 消息)。★ **输入一变签名就变 ⇒ 还在学习**；
   跨**本质不同**的变化签名都不变，才算收敛。★★ 评审指出：**我们的案例里签名其实变过**
   （"类型不匹配" vs "服务端故障"）⇒ ★ **那是该追的线头，不是该停的理由**。
2. **变化要覆盖不同的轴**：轴 = 参数编码 / **调用顺序** / **对象或文档状态**（如是否处于特征编辑态）/ **绑定后端**。
   ★ **20 多种参数形态只算一根轴** ⇒ 评审的门槛：**定性为墙之前至少覆盖 3 根轴，且必须含"顺序"或"后端"之一**。
3. ★★ **加一个正控制**：同一套调用方式，在**同族、已知能用**的接口上能过吗？
   ★ **能过而这里不能 ⇒ 才可能是这个接口特有的真墙；同族也过不了 ⇒ 是我们的调用方式有问题。**
   ★ 这是**最便宜也最有判别力**的一步 —— ★★ 而我已经查到：**同族有 117 个接口**（§9.1）。

★ **操作上把两件事分开**（我采纳）："同一启发式修补 ≥3 次就停"**只限定在"修补启发式"这个动作上**；
★ **"把某物定性为墙"是另一个动作**，要过上面这张清单。
★ 死路记录**分三档**：**已证实的墙** / **未证实（列出没覆盖的轴与重开条件）** / **我们的缺陷**
⇒ ★ **只有第一档能写"架构性限制"**；★ 那条 `AccessSelections` **现在应该在第二档**（我已据此改过文档）。

### 15.4 D（结构化证据先改什么）：**先只做新条目，存量不动**

两个设计避免半途而废：
1. ★★ **把结构放在"咽喉点"，不改 590 个探针**：既然**所有真机命令一律走弹窗护栏**，
   就让**护栏**要求探针最后输出一行 JSON（`方法 / 前值 / 后值`）并由护栏校验；
   ★ 再提供一个小 helper（形如"读 → 动作 → 读"）。**新探针用它，旧探针不动，标"遗留"。**
2. **门禁先只警告，再升级**：第 0 步用 **3–5 个有代表性的现有探针做一天的 spike**，实测真实迁移成本；
   第 1 步 helper + 护栏校验，门禁**只警告**，连续两轮收尾链干净；
   第 2 步对**新增或修改**的条目变红；第 3 步存量只在 Q1 高风险清单要重探时**顺带迁**。

★ 评审强调的关键性质：**任何一步停下，系统都是一致的**（旧的是遗留、新的是结构化）；
**回退只需把门禁从"失败"改回"警告"** ⇒ ★ **半途状态本身合法**。

★ **我采纳**，并认为这条最值钱的地方是：★ 它把我原来"静态几乎判不了回读"的死结，换成了
"**护栏校验产物的形状**" —— ★ **不需要判语义**。
