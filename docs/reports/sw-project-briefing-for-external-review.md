## §1 背景：为什么"给 SolidWorks 做个 AI 接口"是件难事

★ 冷读者最容易误判的地方在这里 —— 这不是"包一层 REST API"那种活。四个真实约束：

**1. 官方 API 是 COM + 迟绑定，很多成员"看着在、其实调不到"。**
官方类型库里有一族接口**标记为"仅进程内非托管 C++"**。★ 本项目实测：某个钣金特征数据接口上的
`AccessSelections` 与 `SetFixedFace`，**20 多种参数形态全部失败**（报"类型不匹配"，或报
`服务器出现意外情况 0x80010105`）⇒ 我们把它**当作架构性限制停下来**，不再换参数试。

**2. 模态弹窗会永久冻住调用。**
SolidWorks 一旦弹出模态对话框，那个 COM 调用**永远不会返回** —— 这是本项目**无人值守挂起的头号原因**。
★ 我们的处置不是"小心点"，而是自建了一个**弹窗护栏**：硬超时 + 子进程隔离 + 执行中每 0.5 秒扫一次窗口 +
**把弹窗分三级**（语义唯一明确的自动点；多义或进度窗**不点**、立刻杀掉那个被冻住的调用并把证据交回人；
含危险词的禁止点）。★ 所有真机命令**一律**走它。

**3. 返回值不可信 —— 这是本项目反复吃亏换来的一条铁律。**
★ 实测例：`SelectByID2` 返回 `false` 而选区计数其实是 1；`RecordLine` **在"录制根本没开"时也返回 `True`**；
`SetSelectedObjectMark` 参数传错时**返回 false、不报错、标记静默未设**。
⇒ ★★ 于是本项目规定：**判据必须是"回读"**（调完之后**再读一遍状态**，看它到底变没变），
**不是**看被调成员返回什么（§3）。

**4. SolidWorks 是单实例 COM，多进程抢同一连接会死锁。**
★ 所以运行期**只能有一个**服务在跑 —— 这也决定了选型：只在宽松许可的那份实现上跑，传染性许可的只读思想。

## §3 本项目的核心方法论：**怎么判断"真的做成了"**

★ 这是最该让外部审阅者看懂的一段，也是**刚刚被用户撤掉一部分**的地方（§8 说明为什么撤）。

**判据一律用回读。** 一个能力算不算"验证过"，看的不是"调用没报错"，而是**调用之后再去读一遍状态**：

| 例子 | 不信什么 | 信什么 |
|---|---|---|
| 选中一条边 | `Select4` 的返回值 | 选区计数接口的**读数** |
| 相交特征建成了 | `PostIntersect` 回的对象 | **特征树增量** + 交线数量接口 |
| 插了 BOM 气泡 | 批量插气泡接口回的数组 | **视图里"注记数量"接口的前后增量** |
| 草图被隐藏了 | 那个调用的返回值 | 特征可见性属性的**前后读数** |

**"选不上"与"选了也没用"必须分开记。** ★ 选区读数为 0 ⇒ 那是**前置没备成**，**不构成"能力无效"的证据**；
★ 只有**确实选中了**、调完**结果仍未变**，才是"这个能力不行"。★ 两种情形写进返回值的不同字段。

**官方文档与真机不一致时以读数为准，并逐条记账。** ★ 现在这份分歧账本里有 **12 条**，
例如：官方页多处写长度单位是"米"而真机是**文档单位（毫米）**；官方示例让某个选择标记看起来必需、
真机证明**不必需**。

**验证等级五级**：`verified`（**我们自己真机跑过**）/ `source_verified`（来源自己声明跑过、我们未复现）/
`stitched`（并进来了、**从未运行**）/ `indexed`（只有成员索引、无实现）/ `not_implemented`。
★ **禁止**把别人的声明写成 `verified`（那是转述，不是证据）。

## §6 ★ 工具数太多的问题 —— **已由 lean 模式的 preset 解决**

★ 这一段是用户特别要求写清的，因为外部审阅者不知道这个背景。

**问题**：本项目对外有 **448 个工具**。工具一多，宿主（AI 客户端）面对的工具目录就臃肿 ——
既占上下文，又让模型选错。

**结论：这个问题已经解决，且不是靠"砍工具"解决的。**

**机制**（关键理解点）：

```
工具注册表本身**搬不进 preset**（消费方全在宿主平面）
        ↓
preset 能拥有的是这份注册表的**呈现方式**
        ↓
宿主本来就提供按**作用域**设置呈现方式的机制，可选模式含 native / ptc / both，**我们新增了 lean**
```

⇒ ★★ **"按 preset 分别选工具呈现方式"是宿主本来就有的功能** —— 项目前两轮曾判断"做不到 / 要塞进 preset"，
**都是错的**，已在对应工作项的进度字段里**记账更正**。

**交付物（共 5 个文件，已就绪）**：

| 交付物 | 状态 |
|---|---|
| lean 模式实现补丁（**约 34 KB · 8 个文件 +437/−16 行**） | ✅ 可干净应用（试应用检查退出码 0） |
| **按 preset 选的贴入片段（4 行）** | ★ 贴进配置即生效（新会话） |
| 全局整进程开关 | 备选方案 |
| 安装脚本 | ✅ 带自检（实测能正确报出"未安装"） |
| 说明（判据 / 用法 / 限度 / 回滚） | ✅ |

**补的三个缺口**（都是项目自己发现的）：① 该机制的 `mode` 可选值原先只有 `native|ptc|both` ⇒ **新增 `lean`**；
② 非 native 模式一律等待某运行期注入 ⇒ **lean 走立即路径**（否则永久 pending）；
③ ★ 另修一处真 bug：设置呈现方式时**漏注册目录段** ⇒ 在默认部署下 lean preset 拿不到目录段（**项目自己的新测试抓到的**）。

**实测**：宿主侧的工具呈现组件 **9/9 通过**；工具层 **447** 项测试（其中 **1 项为既有失败**）。

**三个重要事实（回答"装上之后会怎样"）**：
1. ★ **源码改动不会被热加载** ⇒ **装上前运行时零变化，要重启才进内存**。
2. ★ **配置的补丁段会被热加载** ⇒ 贴 preset 片段**保存即生效**（仅对新会话）。
3. ★ **装完默认逐字节不变**：呈现模式仍取环境变量，不设就是默认的 native。

只是**那两条被写成"常驻规则"的尝试刚被撤销**。

## §9 技术难点（真正的墙 vs 看起来像墙）

★ 这一节是外部审阅者**最可能误判**的地方：把"后端到不了"与"我还没做对"混为一谈。
本项目把两者**分开记账**。

### 9.1 真墙（架构性，换参数解决不了）

| 墙 | 实测 | 现状 |
|---|---|---|
| **绑定层调不到官方"仅进程内 C++"的指针接口族** | 某钣金接口上的两个成员，**20+ 种参数形态全部失败** | ★ **停**。要过只能换绑定后端或进程内 C++ |
| **曲面创建接口的返回值跨次变化** | 同一个调用**有时成功有时回 `None`**（四轮探针，已排除调用顺序与单例状态）；换用其后继版本**仍然** `None` | ★ 不修返回值，改**让失败可见**（对 `None` **抛带原因的异常**） |
| **实体（边/面）没有可用名字** | 按名字选择边与面，**计数都是 0** | ★ 可行路径是**按对象选**，或**按面上的点**选 |
| **模态弹窗永久冻住调用** | 无人值守挂起的头号原因 | ★ 弹窗护栏（超时 + 子进程 + 三级分类 + 冻住就杀掉） |
| **单实例 COM** | 多进程抢同一连接会死锁 | ★ 运行期只跑一个服务 |

### 9.2 看起来像墙、其实是"我自己调错了"（★ 本项目反省最深的一类）

- **空的 COM 接口参数不能传 Python 的 `None`** ⇒ 报"类型不匹配"，★ 而那个错误**看不出是这个参数的问题**。
  ★ 我因此一度差点得出"选择不可能"的错误结论。正确做法：包成空接口变体。
- **同名接口分属不同族** ⇒ 用错接口时"连**读**都读不到"，★ 看起来像"属性只读"，实际是"接口不对"。
- **探测脚本没按工具层的契约调** ⇒ 同一个错犯过三次，每次"失败"都像能力坏了、实际是调用方传错了对象。

### 9.3 已形成的"止损纪律"

- **同一启发式连续修补 ≥3 次仍不稳 ⇒ 停下回退，把证据写进文档，不要继续调**。
- **探不通就处置（重启/回收），不要"再探一次"** —— 同一个状态反复观察 ≠ 处置。
- **"报信不等于处置"** —— 护栏发现弹窗只报告不算处理完。

### 9.4 三个真正的空白域（护城河）

★ 经核实，**全网空白**的只有三个：**拓扑优化** · **动画导出（AVI）** · **成本估算（Costing）**。
拓扑优化已做出可跑的闭环（目标/约束 → 网格 → 求解 → 数字/图/质量回读 → 证据）；另两个仍是缺口。
