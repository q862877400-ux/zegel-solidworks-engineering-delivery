## §1 背景：为什么"给 SolidWorks 做个 AI 接口"是件难事

★ 冷读者最容易误判的地方在这里 —— 这不是"包一层 REST API"那种活。四个真实约束：

**1. 官方 API 是 COM + 迟绑定（pywin32），很多成员"看着在、其实调不到"。**
官方类型库里有一族接口**标记为"仅进程内非托管 C++"**。★ 本项目实测：`ISketchedBendFeatureData` 的
`AccessSelections` / `SetFixedFace` 在 pywin32 下**20 多种参数形态全部失败**（`类型不匹配`、
或 `服务器出现意外情况 0x80010105`）⇒ 我们把它**当作架构性限制停下来**，不再换参数试（见 §9 事实 47）。

**2. 模态弹窗会永久冻住调用。**
SolidWorks 一旦弹出模态对话框，那个 COM 调用**永远不会返回** —— 这是本项目**无人值守挂起的头号原因**。
★ 我们的处置不是"小心点"，而是搭了一个**弹窗护栏**（`tools/sw_guard.py`）：硬超时 + 子进程隔离 +
执行中每 0.5 秒扫一次窗口 + **把弹窗分三级**（`auto` 自动点 / `needs_llm` 不点并**杀掉那个冻住的调用、把证据交回人** /
`forbidden` 危险词不点）。★ 所有真机命令**一律**走它。

**3. 返回值不可信 —— 这是本项目反复吃亏换来的一条铁律。**
★ 实测例：`SelectByID2` 返回 `false` 而选区计数其实是 1；`RecordLine` **在"录制根本没开"时也返回 `True`**；
`SetSelectedObjectMark` 参数传错**返回 false、不报错、标记静默未设**。
⇒ ★★ 于是本项目规定：**判据必须是"回读"**（调完之后**再读一遍状态**，看它到底变没变），
**不是**看被调成员返回什么（§3）。

**4. SolidWorks 是单实例 COM，多进程抢同一连接会死锁。**
★ 所以运行期**只能有一个** MCP 服务在跑 —— 这也决定了选型：我们只在 MIT 许可的那份上跑，AGPL 的只读思想。

## §3 本项目的核心方法论：**怎么判断"真的做成了"**

★ 这是最该让外部审阅者看懂的一段，也是**刚刚被用户撤掉一部分**的地方（§8 说明为什么撤）。

**判据一律用回读。** 一个能力算不算"验证过"，看的不是"调用没报错"，而是**调用之后再去读一遍状态**：

| 例子 | 不信什么 | 信什么 |
|---|---|---|
| 选中一条边 | `Select4` 的 bool | `GetSelectedObjectCount2(-1)` 的**读数** |
| 相交特征建成 | `PostIntersect` 回的对象 | **特征树增量** + `GetIntersectionsCount()` |
| 插了 BOM 气泡 | `AutoBalloon5` 回的数组 | **`IView::GetNoteCount()` 的前后增量** |
| 草图被隐藏了 | 那个调用的返回值 | `IFeature::Visible` 的**前后读数** |

**"选不上"与"选了也没用"必须分开记。** ★ 选区回读为 0 ⇒ 那是**前置没备成**，**不构成"能力无效"的证据**；
★ 只有**确实选中了**、调完**结果仍未变**，才是"这个能力不行"。★ 两条会写进返回值的不同字段。

**官方文档与真机不一致时以读数为准，并逐条记账。** ★ 现在 `spec.md §五` 有 **12 条**这类分歧，
例如：官方页多处写长度单位是"metres"而真机是**文档单位（mm）**；官方示例让某个 `mark` 看起来必需、
真机证明**不必需**。

**验证等级五级**：`verified`（**我们自己真机跑过**）/ `source_verified`（来源自己声明跑过，我们没复现）/
`stitched`（代码并进来了、**从未运行**）/ `indexed` / `not_implemented`。
★ **禁止**把别人的声明写成 `verified`（那是转述，不是证据）。

## §6 ★ MCP 工具数太多的问题 —— **已由 lean 模式的 preset 解决**

★ 用户特别要求写清这一段，因为外部审阅者不知道这个背景。

**问题**：本仓对外有 **448 个工具**。工具一多，宿主（AI 客户端）面对的工具目录就臃肿 ——
既占上下文，又让模型选错。

**结论：这个问题已经解决，且不是靠"砍工具"解决的。**

**机制**（关键理解点）：

```
工具注册表本身**搬不进 preset**（消费方全在宿主平面）
        ↓
preset 能拥有的是这份注册表的**呈现方式**（presentation）
        ↓
上游既有 `tools.presentAs(mode)` —— 按**作用域**记呈现方式，mode ∈ native | ptc | both | lean
```

⇒ ★★ **"按 preset 分别选工具呈现方式"是上游本来就有的功能** —— 项目前两轮曾判断"做不到 / 要塞进 preset"，
**都是错的**，已在规格 208 的 `goal-bar.md` 里记账更正（D-11）。

**交付物**（在 `D:\AI\DSH-sandbox\deliver\`，共 5 个文件）：

| 文件 | 状态 |
|---|---|
| `lean-mode.patch`（**34,386 B · 8 文件 +437/−16**） | ✅ `git apply --check` 退出 0 |
| `preset-lean-snippet.yml` | ★ **按 preset 选的 4 行贴入片段**（保存即生效，新会话） |
| `lean-tools.patch.yml` | 全局整进程开关 |
| `install.ps1` | ✅ `-Check` 实测报「未装」 |
| `README.md` | 判据 / 用法 / 限度 / 回滚 |

**补的三个缺口**（都是项目自己发现的）：① 该行的 `mode` 联合原先只有 `native|ptc|both` ⇒ **加 `lean`**；
② 非 native 一律等 `ptcRuntime` 注入 ⇒ **lean 走立即路径**（否则永久 pending）；
③ ★ 另修一处真 bug：`presentAs` **漏注册 catalog 段** ⇒ native 默认部署下 lean preset 拿不到目录段（**项目自己的新测试抓到的**）。

**实测**：`agent-tool-presentation` **9/9** 通过；`tools` **447** 项测试（其中 **1 条为既有失败**）。

**三个重要事实（回答"装上之后会怎样"）**：
1. ★ **源码改动不被热加载**（`dsh-hmr` 的 `config.root: []` 是空的）⇒ **装上前运行时零变化，要重启才进内存**。

## §9 技术难点（真正的墙 vs 看起来像墙）

★ 这一节是外部审阅者**最可能误判**的地方：把"后端到不了"与"我还没做对"混为一谈。本项目把两者**分开记账**。

### 9.1 真墙（架构性，换参数解决不了）

| 墙 | 实测 | 现状 |
|---|---|---|
| **pywin32 调不到官方"仅进程内 C++"的指针接口族** | `AccessSelections` / `SetFixedFace` 等 **20+ 种参数形态全部失败** | ★ **停**。要过只能换 `comtypes` 或进程内 C++ 后端 |
| **`IModeler.Create*Surface` 返回值跨次变化** | 同一个调用**有时成功有时回 `None`**（四轮探针，已排除顺序与单例状态）；换了 `*2` 后继仍 `None` | ★ 不修返回值，改**让失败可见**（对 `None` **抛带原因的异常**） |
| **实体（边/面）没有可用名字** | `SelectByID2("Edge1","EDGE")` 与按名选面的计数**都是 0** | ★ 可行路径是**按对象选**（`IEntity::Select4`）或**按面上的点**选 |
| **模态弹窗永久冻住调用** | 无人值守挂起的头号原因 | ★ 弹窗护栏（超时 + 子进程 + 三级分类 + 冻住就 `taskkill`） |
| **单实例 COM** | 多进程抢同一连接会死锁 | ★ 运行期只跑一个 MCP |

### 9.2 看起来像墙、其实是"我自己调错了"（★ 本项目反省最深的一类）

- **空 Dispatch 形参不能传 Python `None`** ⇒ 报"类型不匹配"，★ 而那个错误**看不出是 Callout 的问题**。
  ★ 我因此一度差点得出"选择不可能"的错误结论。正确做法：包 `VARIANT(VT_DISPATCH, None)`。
- **同名接口分属不同族** ⇒ 用错接口时"连**读**都读不到"，★ 看起来像"属性只读"，实际是"接口不对"。
- **探测脚本没按工具层契约调** ⇒ 同一个错犯过三次，每次"失败"都像能力坏了、实际是调用方传错了对象。

### 9.3 已形成的"止损纪律"

- **同一启发式连续修补 ≥3 次仍不稳 ⇒ 停下回退，把证据写进文档，不要继续调**。
- **探不通就处置（重启/回收），不要"再探一次"** —— 同一个状态反复观察 ≠ 处置。
- **"报信不等于处置"** —— 护栏发现弹窗只报告不算处理完。

### 9.4 三个真正的空白域（护城河）

★ 经核实，**全网空白**的只有三个：**拓扑优化** · **动画导出（AVI）** · **Costing**。
拓扑优化已做出可跑的闭环（目标/约束 → 网格 → 求解 → 数字/图/质量回读 → 证据）；另两个仍是缺口。

## §11 术语表（★ 冷读者最需要的）

| 词 | 意思 |
|---|---|
| **能力 / capability** | `scripts/` 里一个干活的函数；登记在 `capabilities.yaml`，带 `level` + `evidence` + `limitations` |
| **挂柜台 / 工具 / tool** | 把能力**声明**成 MCP 工具，让 AI 能直接调 |
| **验证等级 / level** | `verified`（我们真机跑过）/ `source_verified`（来源声明跑过）/ `stitched`（并进来了但从未运行）/ `indexed` / `not_implemented` |
| **回读 / readback** | 调完 API **再读一遍状态**当判据 —— ★ 本项目的立身之本 |
| **探针 / probe** | `tools/` 下的真机证据脚本，**一律**走弹窗护栏 |
| **门禁 / gate** | `release_check.py` 里的 **33 道**自动检查；某道红了就拦发布 |
| **收尾链 / round_chain** | 一条命令 = 生成器 + 门禁 + 聚焦测试（~35 秒） |
| **规格 / spec** | 一次任务一个目录（`specs/NNN-name/`），含 spec / plan / tasks / **goal-bar**（唯一进度字段） |
| **事实 N / known-facts** | `docs/known-facts.md` 里 **559 条**实测结论（编号可被引用，如"事实 47"） |
| **空白域 / 护城河** | 全网没人做过的方向：拓扑优化 / AVI 动画 / Costing |
| **stitched 是失败吗** | ★ **不是**。它是"入口可达 + 调用链成立，但缺可靠的最终结果证据"，★ 每条都写死了下一步 |
