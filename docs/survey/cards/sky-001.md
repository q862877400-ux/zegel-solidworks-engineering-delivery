## 1. 一句话定位

**它不是 LLM，是「工程世界模型」**：不生成文本/代码，而是**直接生成几何状态的序列**（先出整体草图状态，再逐步细化到零件），面向 CAD 与 BIM。

## 2. 技术路径（据官方与媒体陈述）

```
输入（图片 / 文字 / 建筑轮廓 + 需求描述）
      ↓
① 候选生成：先出若干「粗略 3D 备选」，供人挑选           ← 来源：AI Wiki
      ↓
② 层级拆解（composer）：把装配递归拆成越来越小的组件      ← 来源：AI Wiki
      ↓
③ 构建世界模型（construction world model）：
   预测「中间几何状态序列」——依次给出每个零件的 2D 草图与 3D 状态
   · 草图生成用 **DiT 扩散**，两阶段：先在压缩隐空间出整体序列，再重建高分辨率细节
   · 几何表示压缩用 **Matryoshka 自编码器**（套娃式：前几个 code = 整体结构，
     后续 code 逐步补细节）⇒ 用极紧凑的表示规划整条建造序列    ← 来源：01net 报道
      ↓
④ 分层装配：把零件按层级拼成整体                         ← 来源：AI Wiki
      ↓
⑤ 交付：**当前还不是可编辑的参数化 CAD 历史**（官方列为 future work）
```

★ **与 LLM 路线的本质差异**（这是业主问的那句「我就搞不懂他们是什么意思」的答案）：
- LLM 路线：**文本 token → 文本**，用语言或程序**描述**建造过程（如 CadQuery 代码）；
- SKY-001 路线：**几何状态 → 几何状态**，直接预测「下一个几何状态」，不经过文本。
  它的规划顺序也相反 —— 官方说法是「先处理中间几何状态，再处理连接它们的操作」，而语言模型必须先描述操作。

## 3. 技术方案要点（可迁移的机制）

| 机制 | 说明 | 迁移价值 |
|---|---|---|
| **先状态后操作**（states-first, operations-second）| 先规划几何状态序列，再补中间操作 | 与我们「先写规格 IR 再生成代码」同构，但它的状态是几何而非文本 |
| **Matryoshka 自编码器压几何** | 紧凑潜码先定结构、再逐级加细节 | 长序列规划的成本控制手段 |
| **两阶段扩散**（隐空间出整体 → 高分辨率重建细节）| 降低扩散算力 | 独立于 CAD 的通用技巧 |
| 层级拆解（装配→零件） | 与「多智能体分工」不同：它是**结构化的递归拆解** | 对我们 assembly 层有价值 |

## 6. 对我方目标的可用处（机制层面）

1. **「状态先行」的规划范式**：把「先想清几何状态、再补操作」当成规划器的输出顺序 —— 与本仓 `planner.py`（DesignIR → 可编译方案）方向一致，可对照；
2. **数据壁垒路线**：它靠清洗重建的高细粒度工程数据集（自称 20 万零件 + 60 万构建样本 + 3.5 万平面图）；我们不可能复刻，但**「用规则+模板替代数据壁垒」**正是六类路线里 G 类的思路；
3. **反例价值**：它证明「不做可编辑参数化」的产品也能拿高分 —— 而我们目标恰恰是**可编辑、可制造**，所以它的分数不能作为我们的判据。
