# 项目定义（顶层）· 让 DeepSeek 像机械工程师一样干 SolidWorks 的活

> 这份文档定义**项目为什么存在、成功长什么样**。它高于一切手段性文档（`AGENTS.md` 的操作纪律、
> `capabilities.yaml` 的清单、`docs/` 的知识条目）。手段与它冲突时，改手段。
> 创建：2026-10-24 · 依据：业主 2026-10-24 对本项目的口头定义 + `docs/state/` 实测台账。

---

## §1 一句话

> **把「中国机械设计的规范、判据与建模方法」编译成 DeepSeek 能调用、能被机器验收的能力，
> 使一条指令产出的 SolidWorks 模型达到机械工程师的可交付水准：全约束、参数化、可编辑、
> 装配自由度闭合、图样合规、工艺可行。**

这里的关键词是**「编译成能力」**，不是「提供工具」。工具是末端执行器；规范与判据才是本体。

---

## §2 为什么重写：旧框架「集大成 + 建护城河」作为**目的**是错的

旧框架把两件事当成目的：

- **集大成**：把四家外部 MCP 项目的能力广度并入，使单项目可替代四家之和
- **建护城河**：攻「经核实真正全网空白」的拓扑优化 / 动画导出 / Costing

**它错在把「广度」与「稀缺」当成功标准，而不是「工程合格」。** 三条证据（均来自本仓实测台账）：

**① 广度换来了未验证面积，而验收标准没跟上**
工具声明 **501** 条、装饰器 **45** 个（出处：`docs/state/facts/B-tools.md` B-01 · `docs/state/facts/J-runtime.md` J-03）；
但能力台账 **140** 条里 `verified` 只有 **100**、`stitched` **37**、`not_implemented` **3**（出处：`docs/state/facts/C-capabilities.md` C-02）。
⇒ 工具数量与「工程可用」之间没有换算关系；**广度不是资产，已验证面积才是**。

**② 声明层的缝比想象的多**
**79** 条工具存在「函数有、声明面没有」的形参，其中 **45** 条没有 `derived_args` 兜底（出处：`docs/state/facts/K-signature.md` K-04/K-05）；
**5** 个测试文件在收集期就被 `tool_registry.GateError` 阻断（出处：`docs/state/facts/F-tests.md` F-03 · `docs/state/facts/Q3-tests-full.md` Q3-01）。
⇒ 「多少条工具」这个数掩盖了「多少条真能调通」。

**③ 护城河挑的是稀缺性，不是用户价值**
空白域（拓扑/动画/Costing）在台账里是 `not_implemented` 的候选（出处：`docs/state/facts/C-capabilities.md` C-02）。
而机械工程师每天真正要的是：草图全约束、尺寸链、公差标注、标准件选型、装配配合、出图合规 —— **这些恰恰不是空白域，而是必须做对的基本盘**。
⇒ 攻空白域证明的是「别人没做」，不证明「用户能用」。

**结论**：`集大成 + 建护城河` 降级为**手段之一**（取材地图与差异化参考），
**不再是项目目的，也不再是成功判据**。

## §3 新的目的：三层结构（缺一层就不成立）

| 层 | 是什么 | 判据形态 | 当前状态 |
|---|---|---|---|
| **L1 执行层** | MCP 工具：建模/装配/仿真/拓扑/工程图/布线 | 调用成功 + 结果可核 | 501 声明 / 100 verified（出处：`docs/state/facts/B-tools.md` B-01 · `C-capabilities.md` C-02）|
| **L2 规范层** | 中国机械设计标准、选型规则、标注规范、工艺判据 | 结论能指认标准条款 | **薄**：`references/` 22 份 md（出处：`docs/state/facts/N-external.md` N-04）|
| **L3 验收层** | 机器可判的「合格」判据（不是"能跑"） | 门禁可执行、可复算 | **薄**：55 个门禁里多数守代码规范（出处：`docs/state/facts/E-gates.md` E-01）|

**旧框架只做了 L1，把 L1 的规模误当成了项目进展。**
项目的本体是 L2 + L3：**没有规范的执行是瞎干，没有验收的规范是口号。**

## §4 七条工程验收判据（可机器判定，取代「工具数量」）

一条指令产出的成果，按以下七条判「合格 / 不合格」。**这七条是本项目的验收标准**：

| # | 判据 | 可判定的形式 |
|---|---|---|
| **E1** | **草图全约束**（自由度 = 0，以几何约束 + 尺寸约束驱动，非坐标硬拽）| 求解器报 DOF = 0、无欠约束实体 |
| **E2** | **参数化可重建**（改主参数后全模型无错重建）| 重建后特征树错误数 = 0、关键尺寸随参数正确联动 |
| **E3** | **特征树可编辑**（无死特征、无悬空引用、父子关系可追溯）| 特征树无错误/警告、可回溯修改前序草图 |
| **E4** | **装配自由度闭合**（用配合约束表达，无过约束、无欠约束、无干涉）| 配合后剩余 DOF 符合设计意图、干涉检查 0 碰撞、间隙合规 |
| **E5** | **图样合规**（尺寸链完整、几何公差有基准体系、未注公差有声明）| 标注覆盖率、基准齐全、未注公差按标准族声明 |
| **E6** | **工艺可行**（钣金 K 因子/最小折弯半径、焊接坡口、机加余量、铸造斜度之一适用即须通过）| 对应工艺检查项全过 |
| **E7** | **结论可溯源**（每个工程判断能指认规范出处或证据文件）| 引用可点开原文 / 可复算命令 |

**这七条取代**「并入了多少家、攻下多少空白域」。做不到 E1–E7，「广度」不计分。

## §5 L2 规范层要挂什么（标准族，库内已可检索）

> 取证说明：本节标准族**取自本机知识库检索到的现行条款**；取证引擎的推理部分当次不可用（provider 404），
> 因此以下只作**标准族定位**，具体数值与等级须在实现时按原文核验后落地。

- **未注形位公差**：GB/T 1184-1996（[依据 4 通则](http://127.0.0.1:1/__ks_evidence__?doc=doc_01M2FY99M14W9X6H8AJ06AR8PM&page=3&rev=clrev_01M2FY99MT6SRZ2GP9WQH65F82&bbox=50%2C316%2C86%2C331&bboxPage=3)）
- **未注尺寸公差**：GB/T 1804（机械加工面 m 级、非加工面 v 级）· **未注形位公差 K 级**
  （[依据 GB/T 32994-2016 4.1.2](http://127.0.0.1:1/__ks_evidence__?doc=doc_01M2N3X8VQ2DKGAVVHQ3T55WBV&page=5&rev=clrev_01M2N3X8XF808EGH9MXRB7N14Q&bbox=63%2C79.89%2C530%2C92.89&bboxPage=5)）
- **焊接结构未注公差**：GB/T 19804（[依据 GB/T 18160-2025 4.2.3](http://127.0.0.1:1/__ks_evidence__?doc=doc_01M2MC9Y290K01YS08F6PB1596&page=8&rev=clrev_01M2MC9Y2P1S6H0HPWZFRFTTZA&bbox=59%2C136%2C525%2C182&bboxPage=8)）
- **铸件**：GB/T 6414（未注尺寸公差 CT14、加工余量 K 级）（[依据 GB/T 35167-2017 5.1.3](http://127.0.0.1:1/__ks_evidence__?doc=doc_01M2N57MPS96MTC9CNX2VGTHAD&page=5&rev=clrev_01M2N57MT0HPSK8D0P3N1Q2GVK&bbox=67%2C194.86%2C257%2C206.86&bboxPage=5)）
- **制图族**：GB 4458.1 图样画法 · GB 4458.4 尺寸注法 · GB 4457.4 图线
  （[依据 GB/T 15138-1994 §2 引用标准](http://127.0.0.1:1/__ks_evidence__?doc=doc_01M2MBEHTJ2W8R5ZV841TXNPD5&page=3&rev=clrev_01M2MBEHVCRVMHQ23NMSBJCNX5&bbox=66%2C526.89%2C130%2C540.89&bboxPage=3)）
- **几何公差代号与注法**：GB 1182 / GB 1183（同上引用清单）
- 待补族：公差与配合（尺寸公差带与配合选择）、螺纹、键与销、轴承、表面结构、热处理与表面处理、材料牌号

**入库规矩**：未入库的标准，先征得同意再下载入库，入库后以原文核验才可用于作答与门禁。

## §6 现有资产怎么重新定位（不废弃）

| 资产 | 旧定位 | **新定位** |
|---|---|---|
| 501 条工具声明（出处：`docs/state/facts/B-tools.md` B-01）| 「集大成」的战果 | **候选池** —— 只有通过 E1–E7 验证的才计入项目进度 |
| 140 条能力台账（出处：`docs/state/facts/C-capabilities.md` C-02）| 覆盖度指标 | **验证队列** —— `verified` 需按 E1–E7 复核，`stitched` 是待验队列 |
| 四家外部项目克隆 | 并入广度 | **取材地图**（写法与接口选型参考），不再以「并入数」计分 |
| 55 个门禁（出处：`docs/state/facts/E-gates.md` E-01）| 代码规范守护 | **L3 验收层的地基** —— 需扩出「机械判据门禁」（E1–E7 各一条）|
| `docs/state/` 实测台账 | 项目现状记录 | **判据的取证来源**（谁要断言，先给读数与命令）|
| 拓扑/动画/Costing | 护城河 | **普通能力候选**，按用户价值排序，不再因其「空白」而优先 |

## §7 非目标（明确不做）

1. 不以「工具条数」或「并入家数」作为进度指标
2. 不以「全网空白」作为优先级依据
3. 不追求渲染级外观，追求**工程可交付**
4. 不替代工程师拍板：把规范约束住、把抄写自动化，判断仍归人
5. 不越许可红线（AGPL/GPL/无许可只读思想，一抄即废）

## §8 迁移路线（三步，按序）

| 步 | 动作 | 产出 |
|---|---|---|
| **M1** | 把 E1–E7 写成**可执行判据**（每条一个检查器骨架 + 输入契约）| `specs/<新号>-engineering-acceptance/` + 判据草图 |
| **M2** | 选 **一个**域（建议：板类零件 + 简单装配）做**端到端样板**：一条指令 → E1–E7 全过 | 样板零件 + 样板图样 + 判据报告 |
| **M3** | 规范层入库：把 §5 标准族按需下载、切片、接入 L2 查询面 | 规范层可用 + 每条判据能指认条款 |

**不做 M1 就写工具，等于继续用「条数」冒充进展。**
