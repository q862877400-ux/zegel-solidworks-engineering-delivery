### 建议 5 · 白名单的语义拆开

**现状**：铁律 3 把 17 个目录并列为「允许的顶层目录」，其中混了两类：

| 类别 | 目录 | 实测状态 |
|---|---|---|
| **仓库结构** | `.github agents ai_team apps assets docs dotnet examples mcp-server references scripts subskills tests tools` | 14 个，**全部入库** ✓ |
| **产物 / 缓存** | `output` · `.api-signatures` · `.pytest_cache` | `output` 与 `.api-signatures` 已 gitignore；**`.pytest_cache` 既未 ignore 也未入库（唯一「裸的」）** |

**两个问题**：
1. **语义被稀释** —— 「允许的顶层目录」到底指「仓库结构」还是「这台机器上能有的目录」？
   下次有人问「能不能加个 `build/`」时，判据不清。
2. **`.pytest_cache` 会污染 `git status`**（它没被 ignore）。

**建议**：白名单只列**仓库结构目录**（14 个），另起一行列**明确 gitignore 的产物**：

```markdown
顶层**结构**目录只允许这 14 个：`.github` `agents` `ai_team` `apps` `assets` `docs` `dotnet`
`examples` `mcp-server` `references` `scripts` `subskills` `tests` `tools`。
（前 13 个是上游就有的，`tools` 是我们加的。）

另有三类**产物/缓存**目录允许存在于工作树，但必须 gitignore、不入库：
`.api-signatures`（签名索引）、`output`（构建产物）、`.pytest_cache`（pytest 缓存）。
⚠ 当前 `.pytest_cache` **尚未 gitignore** —— 补一条。
```
