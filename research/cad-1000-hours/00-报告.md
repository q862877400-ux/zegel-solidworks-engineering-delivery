## 0. 结论先行

1. **它不是软件、不是模型、也不是 benchmark**。它是**数据供应商发布的「人在 CAD 软件里干活的录屏 + 键鼠事件 + 任务书 + 评分条目 + 成品文件」语料**：509 条任务 / **1,018.1229 小时** / 7 款软件 / 5,455 个公开文件 / **207.18 GiB** / **CC BY-NC 4.0**。【一手】
2. **网上流传的数字全部是旧版**。v1 是 597 工作流 / 1,021.64 h / 10 款软件 / 8,973 文件 / 256.60 GiB；v2 砍到 509 条、去掉 STAAD.Pro 与 D5 Render、**SOLIDWORKS 从 209.04 h 腰斩到 100.91 h**。Hub `lastModified = 2026-11-08`，头部数字「1000 小时」几乎没变，**构成变过一次**。【一手】
3. **对我们最相关的一块只有 ~100 小时**：SOLIDWORKS 114 条 / 100.91 h，含 **149 个 `.sldprt` + 16 个 `.slddrw` + 7 个 `.sldasm`** 真人成品。全库里 AutoCAD 独占 66.3% 时长，建筑+室内+BIM+结构占 79%；**机械 CAD 仅 19.3%**，钣金 6 条 / 0.4%。【一手】
4. **「1,018 小时」是墙钟时长，不是有效操作时长**。子线抽一条 AutoCAD 任务（127.2 min）逐帧旁白，发现约 **16 分钟连续 idle**（"Remained idle…" 重复条目），期间还叠着 WhatsApp 消息与浏览器通知。⇒ 真实可用交互占比明显低于标称。【一手·子线】
5. **事件流被重新采样过，数据集自己写了标记**。**v2 里已经没有原始 `events.json`**，只剩 `frame_events.json`；预览抽样里每条事件都带 `"synthetic": true, "source": "frame_timestamps_sidecar"`，连续数百毫秒坐标不变、只有时间戳在走。⇒ 它不是「原生钩子录下的键鼠轨迹」。【一手（预览抽样）；一手·子线（同一现象）】
6. **评分层不可机判**。`rubrics.json` 是英文自然语言条目，**没有权重、没有容差、没有任何判分代码**（仓库根目录只有 7 个软件目录 + README + .gitattributes）。粒度还按领域漂移：机械任务我抽 5 份，**4 份纯定性**（「large central through bore」「three small circular holes」）；建筑任务子线抽到的那份**写死了英寸尺寸**（7'-4.5" × 10'-0" 等）。准确说法是「**含精确量纲，但不可机判**」。【一手 + 一手·子线】
7. **许可一票否决**：CC BY-NC 4.0。CC 法条把 NonCommercial 定义为「not primarily intended for or directed towards commercial advantage or monetary compensation」；CC 官方 FAQ 另补三条硬话：**内部自用也须守 NC**（「even if the database is not publicly shared」）、**商业目的的文本挖掘/训练不得挖掘 NC 库**、**CC 自己不建议给科研用数据库上 NC**。本项目有宣发材料、是要卖的产品 ⇒ 训练与评测进产品链都越线；读它、学它的结构不越线。【一手】
8. **学术圈还没把它当回事**：arXiv 上零引用（子线检索，含一次 CADWorld 论文 Related Work 逐条核对）；同赛道学术基准 **CADWorld**（200 任务 / FreeCAD / 可执行校验 / 最强 agent 17.5% vs 专家 87.0%）的表格里**没有它**。【一手·子线 + 一手（CADWorld 摘要主控复验）】
9. **发布方真正值钱的不是这份数据，是它自己的评测**：Markov Studios（YC S26，2 人）的 **AutoCAD-Bench**：50 任务、**60/25/10/5 加权 + geometry gate + 完成线 75**、只评最终 `.dwg`、不看过程——**官方自己承认这是缺点**，并自曝一个模型用一条样条替换受控圆弧仍拿到 86.3 分过线。这个「只评成品、不评构建历史」的盲区，**恰好是本项目 E1–E3 的全部内容**。【一手（主控复验研究页）】
10. **今天该做什么**：**不下载、不接入、不进产品链**。可抄的只有结构（任务书三段式、评分权重+门槛的写法）；金标件若真要，**CADWorld 那一套（可执行校验 + 参数结构/约束/工艺状态）比这份语料更对路**，也更能反证我们的 E1–E7 是否真能判。许可与采购由业主拍板。

## 1. 它到底是什么：一条任务里有什么

### 1.1 目录结构（v2 官方 README 原文）

```text
{software}/{task_id}/
├── task_desc.json      # 任务提示词、软件、参考输入路径、期望交付物
├── rubrics.json        # 任务专属评分条目（schema_version 1.0 + requirement 句子）
├── task_overview.pdf   # 任务 + 评分 + 视觉参考合成的人类评审单
├── clip.mp4            # 30 FPS 录屏
├── frame_events.json   # 与视频帧对齐的事件流（带 synthetic 标记）
├── metadata.json       # 时长/帧数/事件数/类别/平台
├── narration.json      # 逐帧自然语言旁白
├── input_files/        # input.ext 或 input_N.ext
└── output_files/       # output.ext / output_N.ext（成品 CAD 文件与导出件）
```

【一手：`/datasets/markov-ai/cad-1000-hours/resolve/main/README.md`，2026-11-10】

### 1.2 抽样解剖：`solidworks/01525920-042f-4ba5-9896-31898fcd7b47`

选它的理由：它是 SOLIDWORKS 任务里**带出图要求**的那种，最能跟我们 E5（图样合规）对照。

**`task_desc.json`（全文要点）**
- task：`Model a flanged mounting bracket with a cylindrical boss and produce its detail drawing in SOLIDWORKS.`
- domain `Mechanical CAD`；application `SOLIDWORKS`
- description：从 `input.pdf` 参考图建**大圆柱凸台 + 45° 斜支管 + 三角安装法兰（三孔）**，单位 mm；再出 A3 图——主视图 1:1、全剖 A-A 1:1、轴测 1:2，标注主要直径/壁厚/孔位；交付原生 SolidWorks 文件
- deliverables：`output_files/output.slddrw`、`output_files/output.sldprt`

**`rubrics.json`（10 条，这是「带精确数值」的少数派）**
> R1 Ø68 外径 / Ø50 通孔；R2 45° 支管 Ø32 / Ø18；R3 三角法兰三孔 + 中心 Ø20 + Ø32 沉孔面；R4 A3 图幅带边框标题栏；R5 主视图 1:1 / A-A 全剖 1:1 / 轴测 1:2；R6 剖面线 + 视图名与比例；R7 标注凸台与支管直径、法兰孔与沉孔、45°、总长 86 mm、孔位 63 与 72 mm；R8 每视图下方标名与比例；R9 标题栏含件名/图幅/图号/比例/张次；R10 主视图有 A-A 剖切符号与中心线

**`metadata.json`（全文）**
```json
{"category":"cad","platform":"windows","total_duration_ms":5309133,"total_frames":159274,"event_count":295839,"fps":30}
```
⇒ 88.5 min；159,274 ÷ 30 = 5,309.1 s **自洽**；事件 ≈ **1.86 条/帧**。

**文件实测**：`clip.mp4` 159.9 MB · `frame_events.json` 75.4 MB · `narration.json` 176.7 KB · `task_overview.pdf` 141.8 KB · `input.pdf` 139.4 KB · 成品 `output.sldprt` 156.7 KB + `output.slddrw` 194.0 KB + `output.pdf` 34.1 KB。
⇒ **成品是真人做的原生 SolidWorks 文件，且配同名 PDF 便于人核**；输入是二维 PDF 参考图，不是三维模型。

## 5. 质量：三处实测问题 + 一处未确认

### 5.1 「1,018 小时」是墙钟时长，不是有效操作时长

子线抽 `autocad/0068344d-9a1e-4b20-89af-847502781666`（127.2 min / 228,968 帧 / 654,463 事件 / 30 fps），逐帧旁白显示：
- 从约 173 s 到约 1130 s（**约 16 分钟**）几乎全是 `Remained idle…` / `No recorded interaction events occurred.` 的重复条目；
- 1300 s 附近叠着 Brave 通知与 WhatsApp 消息（"Fuji internship"）浮在 AutoCAD 上；
⇒ **127 分钟里可用交互占比明显偏低**，全库标称小时数应按同样口径打折看。【一手·子线】

### 5.2 事件流是重采样的，数据集自己标了 `synthetic`

- v1 有 `events.json`（「Timestamped mouse and keyboard input events synchronized with the screen recording」）；**v2 没有它**。
- 预览抽样的 100 行里，每条带 `"synthetic": true, "source": "frame_timestamps_sidecar"`；连续数百毫秒 x/y 不变（915, 750 保持），只有 `source_wall_ms` 偶尔推进。
- 单任务事件 295,839 ÷ 帧 159,274 = **1.86 条/帧** ⇒ 不全是「一帧一条补帧」。

**结论**：v2 提供的是**由帧时间戳侧车推算/插值**的事件流，不是原生钩子记录。**诚实边界**：抽样所见全部标记 synthetic，但**没有下载完整 `frame_events.json`**，不能断言全库 100%。这一点与它「真实键鼠轨迹」的卖点存在张力，需发布方澄清。【一手（预览抽样）；一手·子线（同一现象）】

### 5.3 rubric：含精确量纲，但不可机判

| 抽检任务 | 条目 | 带精确数值？ | 判据形态 |
|---|---:|---|---|
| `solidworks/01525920…`（法兰支架 + A3 出图） | 10 | **是**（Ø68/Ø50/Ø32/Ø18/Ø20/45°/86/63/72/1:1/1:2） | 几何 + 图样均可核 |
| `solidworks/04c5e468…`（剖分夹紧座） | 7 | 否 | 纯定性 |
| `solidworks/051a4b52…`（底座 + 梯形凸耳） | 6 | 否 | 纯定性 |
| `solidworks/06e5b82d…`（弯管 + 椭圆法兰） | 5 | 否 | 纯定性（一处 90°） |
| `solidworks/09e6b3ee…`（机座 + A4 出图） | 8 | 部分（A4/1:10/1:5/DETAIL D） | 图样可核，几何定性 |
| `autocad/0068344d…`（住宅平面） | 8 | **是**（房间英寸尺寸、D1–D10 量纲） | 含量纲，但无容差/权重/判据 |

⇒ 准确表述：**rubric 在不同领域里漂移很大（建筑写死英寸、机械多定性）；无论哪种都没有权重、容差与可执行判据**。仓库里也没有任何评分脚本。【一手 + 一手·子线】

### 5.4 旁白是不是模型生成的：**疑似**，未证实

子线观察：文本第三人称、模板化复述（同一句式重复上百次）、复述系统遥测（"Power-source changes were detected at 62.67s, 63.59s…"）、对模型不可见的意图做推断（`intent` 字段）。这套特征符合「VLM 逐帧读屏后生成」，但**发布方没有公开标注流水线文档** ⇒ 只能说疑似。【一手·子线】
**录屏是真人桌面**：同一任务里有真实的 PDF 导入、`RAY/UNITS/OFFSET/TRIM/COPY/STRETCH/MATCHPROP/HATCH` 等真命令行交互、真实 Windows 通知、中英混合环境 ⇒ 不是合成画面。【一手·子线】

## 6. 许可：CC BY-NC 4.0 到底挡住什么

**许可三处一致**：Hub `cardData.license`、README 末节、数据集页徽章均为 `cc-by-nc-4.0`。**注**：2026-09 的旧第三方快照说「卡片未声明 SPDX」，那是旧快照，**现在已声明**。【一手】

法条（CC BY-NC 4.0 §1(k)、§2(a)(1)、§3(a)）：
> **NonCommercial** means not primarily intended for or directed towards commercial advantage or monetary compensation.

CC 官方 FAQ（2026-11-10 抓取；页面版本 2025-05-13）四条关键句：
1. **判据是用途，不是主体身份**：「if you are a non-profit or charitable organization, your use of an NC-licensed work could still run afoul of the NC restriction, and if you are a for-profit entity, your use of an NC-licensed work does not necessarily mean that you have violated the term.」
2. **数据库版 NC 连内部自用也要守**：「any use of the licensed database or its contents that is restricted by copyright law or sui generis database rights requires compliance with the NC term, **even if the database is not publicly shared**.」
3. **商业目的的文本挖掘被点名**：「If you are conducting text and data mining for commercial purposes, you should not mine NC-licensed databases or other material.」
4. **署名义务内部可免、NC 不免**：「if you are only distributing the material… within your company or organization, you do not have to comply with the attribution requirement.」；另：CC 官方**不建议**把 NC 用在面向科研的数据库上。

落到本项目：

| 用途 | 可否 | 依据 |
|---|---|---|
| 内部读它、写调研、学结构、看它怎么设计任务书 | **可以** | 阅读学习不在许可限制内 |
| 用它**训练/微调要卖的产品** | **不行** | NC + 商业 TDM 明令 |
| 用它**评测要卖的产品**并作为质量证据 | **不行（灰→红）** | 服务于商业优势即触发 NC；FAQ 第 2 条还堵了「关起门来用」这条退路 |
| 把它 `.sldprt`/`.slddrw` 放进我们的回归集（产品的一部分） | **不行** | 同上；随产品分发更不行 |
| 抄 rubric 文本/任务描述进我们的验收包 | **不建议** | 复制受 §3 限制，且 NC 把复制限在非商业 |
| 非商业学术发表 | **大体可行**，需署名 + 标许可 + 指出改动 | §3(a)；营利机构主导时按官方「depends」逐案判断 |
| **隐私/伦理** | **CC 一句都不管** | CC 明文声明许可不覆盖隐私、伦理审查、数据保护；本语料含真实桌面、真实人名与聊天弹窗 ⇒ 需单独评估 |

**业主需要拍板**：① 本项目算不算 commercial use（按 `docs/marketing/` 有宣发材料看，**是**）；② 若要商业用，Hub 卡上**没有**付费/企业授权入口，只能联系发布方（它是卖数据的公司，很可能本来就卖）。

## 7. 对这里的意义：能抄什么、能验什么、别碰什么

### 7.1 与我们现有资产的对照

| 维度 | CAD 1000 Hours | 本仓库 |
|---|---|---|
| 任务清单 | 509 条，每条一目录 | `golden-workflows.yaml` **10 条**（`target_first_pass_rate: 0.90`） |
| 任务声明 | task/domain/application/description/input_files/deliverables | 只有 `required_inputs` + `required_artifacts`，**缺一段能照做的描述** |
| 评分 | rubrics 文字条目，**无判分器** | E1–E7 判据 + 采集器/判定器分离 |
| 金标成品 | **有**：149 `.sldprt` + 16 `.slddrw` + 7 `.sldasm` | **无** |
| 过程证据 | 30 FPS 录屏 + 逐帧事件 + 旁白（含大量 idle） | 真机录屏 + PSR 动作 + 特征数/草图状态时间线 |
| 失败样件 | 无（只有人类正例） | 计划里有坏样件（S1） |
| 机器可判 | 否 | 是（要落到可复算读数） |

**最刺眼的一行是「金标成品」**：他们有 149 个真人做的 SolidWorks 零件 + 16 张工程图，我们一个都没有——但这一块**同时是我们最用不上的**（NC 锁死 + 是 GUI 路线产物）。

### 7.2 它的 rubric 覆盖我们哪条 E（以 §1.2 那份 10 条逐条映射，【推断】）

| 我们的判据 | 该任务的 rubric 能支撑吗 | 缺什么 |
|---|---|---|
| **E1 草图全约束** | **不能** | 只管「有 Ø68 凸台」，不管草图是否完全定义、尺寸是否驱动 |
| **E2 参数化可重建** | **不能** | 无「改主参数后重建」条目；交付成品而非活模型 |
| **E3 特征树可编辑** | **不能** | 无特征树检查项 |
| **E4 装配自由度** | 不适用（单件） | `.sldasm` 输入全库仅 2 个 |
| **E5 图样合规** | **部分能**（R4–R10 全是图样条目） | 不看 GB 制图标准，不查基准/公差/表面结构 |
| **E6 工艺可行** | **不能** | 无工艺条目 |
| **E7 结论可溯源** | **不能** | rubric 不给标准条款，也不给测量方式 |

⇒ **它与 E1–E7 几乎不重叠**：它评「像不像、交齐没交齐」，我们评「模型活不活、图合不合规」。**不能当判据，也不能当判据来源。**

### 7.3 三条可带走的（结构层，不复制内容）

1. **任务书三段式**：`一句话任务 / 一段能照做的描述（依据哪张图、什么单位、要哪几张视图）/ 交付物清单（路径 + 类型 + 一句话）`。我们的 `golden-workflows.yaml` 只有两个字段，缺中间那段。
2. **评分可加权 + 设门槛**：AutoCAD-Bench 的 `0.60/0.25/0.10/0.05 + geometry gate + 完成线 75` 是一个**可直接套到 E5** 的写法（几何/尺寸/注释/版面四维加权，几何设下限防「画得漂亮但错」）。我们的 E5 目前是「逐项绑定核数值」，缺「分级 + 门槛」这套可报分的形态。
3. **成品配一张人看的对照页**：它每个模型任务都给 `.sldprt` + `output.pdf`。我们的 `review_report` 是 JSON + BMP，缺一张能贴给人的对照页。

### 7.4 两条必须记住的教训（都是它自己踩的坑）

- **只评成品会漏掉「作弊」**：AutoCAD-Bench 那个 86.3 分案例（受控圆弧被换成一条 S 形样条仍过线）——**这正是我们 E1/E2/E3（构建方式、参数化、可编辑）要防的东西**。写进我们的 E5 设计：视觉相似度**不能**独立成判据。
- **「有金标 + 有 rubric」不等于「能判」**：509 条任务、1,018 小时、149 个成品件，判分依然要人看。⇒ 我们 S1 建判据时，**别把「有要求文字」当成「有判据」**。

### 7.5 成本（若业主决定要下）

- 总量 207.18 GiB；按小时折算 ≈ **0.2035 GiB/h**（207.18 ÷ 1,018.12）【推断】。
- **SOLIDWORKS 子集**（114 条 / 100.91 h）≈ **20.5 GiB**（同上折算，**未实测**）；单任务动辄 160 MB 录屏 + 75 MB 事件文件。
- 只要「成品文件 + task_desc + rubrics」（不要录屏与逐帧事件）会降到 MB 级，但 Hub **不支持只下目录子集**，要用 `huggingface_hub.snapshot_download(allow_patterns=...)` 按路径过滤。

### 7.6 建议（给业主选项，不替业主拍板）
