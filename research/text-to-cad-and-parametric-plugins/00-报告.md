## 0. 结论先行

你问的这批东西不是一个技术，是**五个**。混在一起谈，就会得出「可靠但死板」这种既对又没用的结论。

| # | 类别 | 你输入的是什么 | 谁在算 | 典型代表 | 今天还活着吗 |
|---|---|---|---|---|---|
| ① | **程序化建模** | 文本程序（几何描述语言） | CAD 内核 | OpenSCAD（2010）、CadQuery（2013）、build123d、ImplicitCAD | 活，且被 AI 一代当成底座 |
| ② | **CAD 内嵌文本程序** | 模型文件里的一段程序 | CAD 自己 | Pro/PROGRAM（1988 起）、NX Knowledge Fusion、CATIA Knowledgeware、Onshape FeatureScript（2015 公布 / 2016 开放）、AutoLISP（1986） | 活，但只在各自生态里 |
| ③ | **参数表 / 规则驱动** | 表格一行 或 一条规则 | 配置引擎 | SolidWorks Design Table、Inventor iLogic（原 Logimetrix，$4300）、DriveWorks（2008 起随 SW 送 Xpress）、Tacton | 活，DriveWorks 是商业主力 |
| ④ | **宏 / API 脚本** | VBA / C# / Python 代码 | 你写的程序调 CAD | SolidWorks VBA 宏（.swp）、Add-in（.dll）、xarial codestack | 活，但跨版本脆弱 |
| ⑤ | **专用零件生成器** | 十几个工程参数 | 内建的齿轮/凸轮数学 | **GearTrax / GearTeq / CamTrax（Camnetics，1998 起）**、KISSsoft（1985）、MITCalc（Excel）、fcgear（2015）、MCAD/involute_gears.scad | 活 |

**你真正在说的大概是 ⑤ 和 ③**——「输入模数齿数压力角，出来一个能加工的真渐开线齿轮」这类东西。这类东西确实早于 AI 二十多年，而且确实「灵活性差、可靠性高」。

但这句话必须拆开验证，因为它一半对一半错：

- **对的部分**：可靠性来自**确定性**（同样输入永远同样输出）、**参数域显式封闭**（超出范围就报错，不会给你一个「差不多能用的」）、**离线可审计**（没有模型权重、没有随机种子）。
  **但「校核」这一条要分开说**：齿轮生成器（GearTrax 一族）做的是**几何**，**不做强度校核**——两份 Camnetics PDF 里 `strength`/`6336`/`AGMA 2101`/`ISO 1328` 全部 0 命中；真正算强度的是 KISSsoft、MITCalc 那一类，或者像论文里那样「GearTeq 建模 + 外接 FEA」。**把「能生成正确齿形」当成「算过强度」，是这条线上最常见的高估。**
- **错的部分**：这类工具**在「生成」上可靠，在「编辑」上不可靠**。Evan Yares 在 2013 年那组文章里给这个现象起了名字——*brittle*（脆）：不是不强，是一碰就碎。参数化模型里父子依赖和意外特征交互无法预防也无法检查，改一个上游尺寸，下游可能整体崩掉。他原话是针对 Pro/E 老用户的：连 PTC 自己的应用工程师，也只能在提前练熟的基准测试件上做出「复杂但 resilient」的模型，而且一旦要求改一个会引起拓扑变化的尺寸，模型照样炸【一手: <https://www.engineering.com/the-problem-is-editing/> · 2013-06-24】。

所以更准确的说法是：

> **这类工具把「从参数到成品」这一段做成了确定性的黑箱，代价是把「参数之外」的自由度全部关掉。**
> 它不是「灵活差一点」，而是**参数域是封闭的**：GearTrax 只能生成它认识的那十几类传动件；超出这个域，你得到的不是「差一点的结果」，而是「没有结果」。这正是它可靠的原因。

**最值得抄的一件事**：它们全部是**「参数 → 校核 → 生成」三段式**，校核在生成之前。今天很多 AI 生成 CAD 的流程是「提示 → 几何」两段式，中间没有校核层——这是结构性倒退，不是进步。

## 2. 五种「文本→几何」到底长什么样

### 2.1 ① 程序化建模：OpenSCAD / CadQuery

- **OpenSCAD**：文本描述 CSG（并/差/交），编译出实体。2010-02-19 首发，GPLv2，作者 Marius Kintel 与 Clifford Wolf【一手: Wikipedia 版本信息页】。它的自我定位就是 *The Programmer's Solid 3D CAD Modeller*。
- **MCAD 库里的 `involute_gears.scad`**：这是「用几十行脚本生成齿轮」最典型的样本，提供 `gear()`、`bevel_gear()`、`bevel_gear_pair()`，参数是齿数、周节或径节、压力角、顶隙、齿厚【一手: <https://app.openscad.org/documentation/manual/MCAD.html>】。
- **CadQuery**：Python + B-rep（OCCT），2013 年起步，Apache-2.0，能输出 STEP（无损），这点比 OpenSCAD 强——OpenSCAD 的 CSG 结果只能出 STL，进不了正经的加工链【一手: <https://github.com/dcowden/cadquery>；一手: FOSDEM 2020 CadQuery 讲稿 <https://archive.fosdem.org/2020/schedule/event/cadquery/attachments/slides/3561/export/events/attachments/cadquery/slides/3561/FOSDEM.pdf>】。
- **cq_gears**：CadQuery 的齿轮库（作者 meadiode，v0.51）。README 自述「Work in progress… Might be unstable, but somewhat usable」，实际能生成直齿/斜齿/人字/内齿/行星/直齿与斜齿锥齿/齿条；要求 **CadQuery 开发版**（2.1 释放版不行）；数学部分借自 OpenSCAD 的 janssen86 齿轮库【一手: <https://github.com/meadiode/cq_gears>】。

**这一类对你最有用的一点**：参数是**代码里的变量**，不是对话框里的数字。所以「生成 200 个规格的齿轮」是一次循环，不是 200 次点击。

### 2.2 ② CAD 内嵌文本程序：Pro/PROGRAM 是最纯粹的样本

Pro/ENGINEER 从 1988 年起就允许在模型里写一段程序，包含 `INPUT … END INPUT`（参数声明）、`RELATIONS … END RELATIONS`（关系式）、`ADD PART …`（按条件增删零件）。一段真实的中文文献里的样例（2005，署名冯晓梅，来源 CAD世界网）：

```
INPUT
HIGH1 NUMBER
DIA   NUMBER
END INPUT
...
D6:1=HIGH1+10+D11:8
D13:1=B:2
D17:1=B:0
END RELATIONS
ADD PART KES-E INTERNAL COMPONENT ID 1
...
```

并且它可以从**当前目录下的一个 txt 文件**读入参数——文献里的做法是建一个 `kd.txt`，里面写 `LENGTH=300 WIDTH=200 …`，程序读文件、跑关系式、自动装配出模具结构；文中还附了 Pro/E 2001 的 trail 文件片段（`#READ FILE / !Enter file name [QUIT]: kd.txt`）【一手（原文摘录）: <https://www.e-works.net.cn/Articles/487/Article29635_1.htm> · 2005-05-12】。

**这条比我原先想的更强**：1990 年代末的 Pro/E 已经能做到「**外部文本文件 → 程序 → 整套模具装配体重建**」。这不是「参数化」，这是**文本驱动的装配生成**。

**Pro/PROGRAM 与 Relations 的区别（最容易被混为一谈的一对）**：

| | Relations（关系式） | Program（Pro/PROGRAM） |
|---|---|---|
| 管什么 | **数值**：符号尺寸/参数之间的方程 | **结构**：有哪些特征、哪些元件存在 |
| 能写什么 | 等式、不等式、注释 | `INPUT/END INPUT`、`IF…ELSE…ENDIF`、`ADD PART…END ADD`、`EXECUTE`、`MASSPROP`、读外部文件、运行时暂停（`INTERACT`） |
| 一句话 | 「D6 = HIGH1 + 10」 | 「如果 A 成立，就装配这个零件；否则装那个」 |

两者常配合使用——上面那段代码就是 Program 里嵌 `END RELATIONS` 段。官方对 Relations 的定义原话：*「Relations (also known as parametric relations) are user-defined equations written between symbolic dimensions and parameters.」*

**这一对区分直接可迁移到 SolidWorks**：SolidWorks 的「方程式/全局变量」相当于 Relations（只管数值），而「配置/设计表」相当于一半的 Program（管特征压缩/解压，但不能写 if-else 逻辑）。**SolidWorks 没有真正的 Program 等价物**——这是它相对 Pro/E 的一个结构性缺失，DriveWorks 和 iLogic 补的就是这一块。

**这就是 1988 年的「text to CAD」。** 输入是一段文本（甚至是一个参数文件），输出是一个装配好的三维模型。区别只在于：它不认识自然语言，只认识它自己的 DSL。

同类：NX 的 **Knowledge Fusion**（`.dfa` 文本，`DefClass` / `(Number Parameter)` 这种语法，2014 年还有人在论坛上贴代码）【一手: StackOverflow 提问原文】；CATIA 的 Knowledgeware（Knowledge Advisor / Expert / Product Knowledge Template）；Onshape **FeatureScript**（2015，把自家建模语言开放给用户）。

### 2.3 ③ 参数表 / 规则驱动

- **SolidWorks Design Table**：Excel 表驱动配置。**表头语法（2024 官方参数汇总页，逐字，大小写不敏感）**：`$comment`、`$description`、`$partnumber`、`$state@feature_name` / `$state@sketch_name` / `$state@sketch_relation@sketch_name` / `$state@lighting_name`（Suppressed/Unsuppressed 或 S/U）、`dimension@feature_name` / `dimension@sketch_name`、`$hw-size@feature_name`（异型孔尺寸）、`$parent`、`$prp@property`（配置特定属性）、`$enable@Relation_ID@equations`、`$user_notes`、`$color`、`$sw-mass`、`$sw-cog`、`$tolerance@dimension_name`。
  **★ 一条常被写错的：`$CONFIGURATION` 这个表头不存在。** 配置名是表格**第一列**从第 2 行起的单元格内容（Auto-create 会自动生成这一列），不在表头语法里。我初稿就写错了这一条。
  全局变量列是 `$VALUE@变量名@equations`（2011 起），留空则继承「打开设计表时激活的那个配置」的值。
  【一手: <https://help.solidworks.com/2024/english/SolidWorks/sldworks/r_Summary_of_Design_Table_Parameters.htm>；一手: SOLIDWORKS 2011 What's New p106–107】
- **Equations / Global Variables**：`Well_Volume = 20000`、`D1@拉伸1 = "高度"`，可以引用其他全局变量和尺寸，可以按配置分别取值，**也可以链接到外部文件**【一手: <https://help.solidworks.com/2026/german/SolidWorks/sldworks/c_global_variables.htm>】。
  **两个关键版本点**：① **「Link to external file」（把方程式/全局变量导成 txt 再导入，勾 `Link to file` 后改 txt 就改模型）是 SOLIDWORKS 2011 才有**，2011 What's New 的章标题就叫 "Sharing Equations Among Models"；② 同版本还给了 `IIf`，可以用方程式控制特征/零部件的压缩状态——**这等于在方程式层面补了一点 Pro/PROGRAM 的 IF 能力**。
  【一手: SOLIDWORKS 2011 What's New p101–102】
- **Configuration Publisher（2009 出现 / 2010 改名）**：官方原话是「Create PropertyManager … **renamed to Configuration Publisher**」，也就是 **2009 年就有、2010 年才改成现在这个名**。把配置包装成一个 PropertyManager 界面，装配时下拉选参数生成新配置；可以发布到 3D ContentCentral（需注册供应商）。**前置条件：模型必须已经有设计表。**【转述（行业媒体 2009-08-26）+ 一手（SOLIDWORKS 2010 What's New）: <https://www.solidsmack.com/cad/solidworks-2010-configuration-publisher-3dcontentcentral/>】
- **iLogic（Inventor）**：本来就是一家加拿大公司 Logimetrix 的独立插件，卖 **$4,300**；Autodesk 2008 年 12 月收购后免费送，Inventor 2011/2012 起内置【一手: cadstudio.cz】。Autodesk 自己给它的定位是「Parametrics 2.0」「logimetric design」——从「用尺寸和方程式驱动几何」升级到「用规则驱动尺寸、方程式、属性、特征、零部件」【一手（Autodesk 白皮书 PDF 原文）: mfgcommunity.autodesk.com/files/34401_34500/34461/file_34461.pdf】。
- **DriveWorks**：SolidWorks 生态里最完整的规则引擎，规则 + 表单 → 生成零件/装配/工程图/文档。**DriveWorksXpress 自 2008 起随每一套 SolidWorks 免费**，2026-01 官方仍写 free【一手（DriveWorks 官方博客）+ 一手（培训 PDF 原文 "part of every SolidWorks 2008 installation"）】。价格：2013 年快照 Solo **$3,600**（首年订阅含）、Pro 模块 **$6,000 起**；2025-12 英国渠道 Pro **£3,876 / 12 个月**。**这是三个不同时点、不同口径的数字，不能互相折算。**

### 2.4 ④ 宏 / API 脚本

SolidWorks 的 VBA 宏（`.swp`）是最低门槛的入口，也是全世界存量最大的一类「CAD 脚本」。再往上是 **Add-in**（.dll，注册进 IDE 的 COM 插件，GearTrax 就是这一类），再往上是 **Macro Feature**——把一段程序做成特征树里的一个特征，随模型重建自动重算。

Macro Feature 有两条硬约束，官方文档写得很死：

1. **重建期间不能引入新特征，也不能有任何用户交互**；
2. **不能用 .NET 宏写 macro feature，必须用 VBA 宏文件（.swp）里的函数**【一手: <https://help.solidworks.com/2026/english/api/sldworksapiprogguide/macro_features/Overview_of_Macro_Features.htm>；<https://help.solidworks.com/2025/english/api/sldworksapiprogguide/Macro_Features/Rebuild_Function.htm>】。

**先给个规模感**：本机保存的官方 API 转储里是 **566 个类型 / 547 个 I\* 接口 / 12,123 个成员页**【实测（本机官方转储）】。这就是「宏/插件」这条路能触达的表面——比任何一个 CAD 菜单都大两个数量级，所以「录一段宏改改」能走很远，也很容易走进一个没人验证过的角落。

**这两条决定了「用宏做参数化生成器」的天花板**：它能改尺寸、能重建已有几何、能读写外部数据库，但**不能在重建时长出新的拓扑结构**。所以真正做「从零生成一个新齿轮」的插件（GearTrax），走的不是 macro feature，是 **Add-in 直接调建模 API 从空零件开始画**。

### 2.5 ⑤ 专用零件生成器：GearTrax 是最完整的标本

Camnetics（美国威斯康星州 Oregon，1998 年起是 SOLIDWORKS Solution Partner）三个产品：

### 2.6 按「文本程度」排一行，这比按产品名排有用

| 层级 | 模型里有多少是文字 | 例子 | 后果 |
|---|---|---|---|
| **全文本** | 100%，几何完全由代码产生 | OpenSCAD、CadQuery、ImplicitCAD | 可 git diff、可 code review、可批量跑 |
| **内嵌程序** | 模型文件里有一段程序 | Pro/PROGRAM、NX KF、FeatureScript | 可读可改，但绑死在自家 CAD 里 |
| **参数表** | 一行数值 | Design Table、Excel + API | 非程序员能改，但表达不了拓扑变化 |
| **规则** | 一条 `if…then` 表达式 | iLogic、DriveWorks rules | 表达力比表强，调试比代码难 |
| **宏 / 插件** | 与模型分离的代码 | .swp 宏、.dll 插件 | 能力最强，绑定最深（版本、位数、注册表） |
| **纯二进制** | 0% | 手工建的模型 | 改不了，只能重建 |

**这张表就是选型的坐标系**：文本越多，可维护性越好、灵活性越强、上手越难、越容易和具体 CAD 版本脱钩。**「可靠」不在这条轴上**——可靠来自校核层和参数域的封闭程度，跟用不用文本没关系。

## 3. 齿轮这条线（重点）

### 3.1 三条不同的技术路线，精度差一个数量级

同样是「输入模数齿数，出一个齿轮」，底下的做法完全不同：

| 路线 | 齿廓怎么来 | 精度 | 代表 |
|---|---|---|---|
| **A. 圆弧近似** | 用几段圆弧拼出齿形 | **低**——只能满足「装配体看着像」 | **SolidWorks Toolbox 自带齿轮** |
| **B. 样条拟合离散点** | 按渐开线公式算一串点，用样条连起来 | 中—高，取决于取点密度 | 大量中文论文与自制宏 |
| **C. 方程式驱动曲线（真参数方程）** | `x=r(cosθ+θsinθ)`、`y=r(sinθ−θcosθ)` 直接进 CAD 的方程曲线 | **高** | 高质量宏与商业插件 |

**A 路线有两条独立实证，一条来自厂商自己，一条来自论文。**

**实证一（最硬，官方原文）**：SOLIDWORKS Toolbox 帮助页写着——*"Toolbox gears are representations for machine design purposes. **They are not true involute gears that you can use for manufacturing.**"* 同一页还写：齿条齿数必须 < 1000；Toolbox 紧固件是近似表示、无精确螺纹，做应力分析一类可能不适用【一手: <https://help.solidworks.com/2024/english/SolidWorks/toolbox/c_toolbox_overview.htm>】。

**注意这句话的分量**：Toolbox **没有精度等级可言**，因为它的定位就是「不可制造的示意件」。任何「Toolbox 齿轮精度 X 级」的说法都不成立。

**实证二（论文）**：论文标题就叫《Parametric Design of Gears Based on Secondary Development of SolidWorks Macros》，摘要里直接写——SolidWorks Toolbox 的齿轮「可设参数少、齿形精度低，只能满足一般虚拟装配」，而参数化宏方法的误差**远小于** Toolbox，原因是「参数化设计的齿廓曲线是渐开线，而 Toolbox 的齿廓用圆弧替代」【一手（摘要原文）: <https://ieeexplore.ieee.org/document/9700016> · WCMEIM 2021】。

**这条是整份报告里最有用的一条。** 它说明：**「SolidWorks 自带」不等于「算得对」。** 一个 2015 年还在用 Toolbox 齿轮出图的工程师，拿到的齿形在数学上就不是渐开线——它改不出现场问题，但只要有人拿它去线切割或做模具，误差就在工件上。

### 3.1.1 【实测】圆弧近似到底差多少——我算了一遍

论文只说「Toolbox 用圆弧替代渐开线，误差大」，没说差多少。我写了个脚本（`proto/exp_involute_arc_error.py`）把这个量算了出来：

方法：取标准直齿（α=20°、ha*=1），在**基圆到齿顶圆**这一段真实渐开线上取 4001 个点；再分别用 N 段圆弧（每段过起点/中点/终点作外接圆）和 N 点三次 Hermite 样条（端点切线用解析值，模拟 CAD 里带相切约束的样条）去拟合；统计**法向最大偏差**。

命令：`python research\text-to-cad-and-parametric-plugins\proto\exp_involute_arc_error.py`

| 模数 / 齿数 | 齿廓弧长(mm) | 1 段弧 | 2 段 | 3 段 | 5 段 | 10 段 | 20 段 | 10 点样条 | 20 点样条 |
|---|---|---|---|---|---|---|---|---|---|
| m2 z20 | 3.48 | **23.4 µm** | 7.88 | 4.20 | 1.91 | 0.65 | 0.22 | 1.47 | 0.41 |
| m4 z17 | 6.62 | **47.0 µm** | 15.8 | 8.40 | 3.81 | 1.31 | 0.44 | 2.97 | 0.83 |
| m1 z40 | 2.33 | **13.0 µm** | 4.41 | 2.36 | 1.07 | 0.36 | 0.12 | 0.78 | 0.21 |
| m8 z12 | 12.2 | **98.2 µm** | 32.6 | 17.3 | 7.84 | 2.69 | 0.91 | 6.29 | 1.79 |

**读法（这一条修正了我自己的初始判断，也修正了对论文的简单读法）：**

1. **「圆弧近似不准」这个说法本身是错的。** 圆弧只要段数够，精度可以做到亚微米——10 段就 0.65 µm，20 段 0.22 µm。
2. **真正决定精度的是段数/点数，不是「圆弧 or 样条」。** 10 点样条（1.47 µm）反而不如 10 段圆弧（0.65 µm）。因为样条在曲率变化剧烈的地方会过冲。
3. **误差随模数近似线性放大约 4 倍**（m1→m8 差了约 7.6 倍）。大模数齿轮用粗圆弧近似，代价是几十到上百微米。
4. 所以论文的结论应当被读成：**Toolbox 用的段数不够**（可能在 1–3 段这个量级，也就是 4–23 µm 级别）。**Toolbox 内部到底几段，我查不到——记为未查证。**

**对你直接的用处**：你如果自己写齿轮生成器，用**参数方程（真渐开线）**成本最低、精度最高，根本不需要考虑分段。用样条的话，**20 点 + 解析切线**是性价比拐点。

### 3.2 SolidWorks 原生能做到什么程度（不买插件）

- **Toolbox（Professional/Premium 才有）**：`Design Library → Toolbox → Standard(ISO) → Power Transmission → Gears`，拖进装配体，填模数/齿数/宽度，一分钟出模型。**但官方定性是「示意件、不是真渐开线、不能用于制造」**【一手: Toolbox 帮助页】。发给没有 Toolbox 的协作方会掉链接，要加工得先转换【转述（经销商博客，附实操截图）: <https://ohmycad.com/en-ca/solidworks-gear/> · 2026-10-01】。
  **齿轮类型的口径**：官方 Toolbox 帮助页只列 `Gears` 一个类别，**不枚举子类型**；「还有 helical / bevel / rack 选项」这一说法来自经销商与教程页，**我无法在一手页面确认**——按未查证处理。所以严格说：**官方只确认了「有 Gears 这一类」，没确认只有直齿。**

**Toolbox 与 PDM 的坑（官方自己写的）**：`Create Configurations` 模式下每加一个尺寸就往主零件加一个配置，**PDM 管理时每加配置就生成一个新文件版本**，官方建议用 PDM cold storage 清旧版本；PDM 下写只读文档必须选 `Error when writing to a read-only document`【一手: <https://help.solidworks.com/2024/english/SolidWorks/toolbox/HIDD_TOOLBOX_USER_SETTINGS.htm>】。
- **方程式驱动曲线**：`草图 → 方程式驱动曲线`，选「参数式」，给 T 的范围和 X(T)、Y(T) 两条式子。**约束：值必须以弧度为单位；用双引号（不带等号）可以把全局变量引进来**【一手: <https://help.solidworks.com/2026/Chinese/SolidWorks/Sldworks/HIDD_DVE_SKETCH_EQCURVE.htm>】。
- **中文文献里的标准做法**：设 19 个全局变量 → 用方程式驱动曲线分别做扫描的路径和轮廓 → 扫描切除 → 圆周阵列，能同时得到渐开线齿面和**齿根过渡曲面**【一手（期刊摘要）: 陈涛《基于 SolidWorks 的渐开线斜齿轮的三维建模》，机械研究与应用 2024, 37(3):55-59, DOI 10.16576/j.ISSN.1007-4414.2024.03.016】。

也就是说：**不装任何插件，纯用 SolidWorks 自带的方程式 + 方程曲线，就能做出真渐开线齿轮。** 代价是每次都要手工把这套流程走一遍，或者把它录成宏。

### 3.3 开源这条路

- **FCGear（2015-10-27 首发为宏，后转为 Gear 工作台）**：FreeCAD 生态，作者 looooo，做渐开线齿轮、齿条、摆线齿轮、锥齿轮【一手: <https://wiki.freecad.org/Macro_FCGear/de>】。这是「免费、可读源码、能改」的最佳样本。
- **MCAD/involute_gears.scad**：OpenSCAD，`gear()` / `bevel_gear()` / `bevel_gear_pair()` / `rack()`【一手: OpenSCAD MCAD 手册】。
  我把它源码抓下来看了（`_evidence/src/involute_gears.scad`），文件头写得很清楚：**Parametric Involute Bevel and Spur Gears by GregFrost，LGPL 2.1，© 2010，thingiverse thing:3575 / thing:3752**【一手: 源码注释】。
  `gear()` 的参数面是 21 个：`number_of_teeth`、`circular_pitch`/`diametral_pitch`（二选一）、`pressure_angle`、`clearance`、`gear_thickness`、`rim_thickness`、`rim_width`、`hub_thickness`、`hub_diameter`、`spokes`、`spoke_width`、`spoke_thickness`、`spoke_square`、`centered_gear`、`centered_hub`、`bore_diameter`、`circles`、`circle_diameter`、`backlash`、`twist`、`involute_facets`、`flat`。
  **★ 一个坑：`pressure_angle` 的默认值是 28°，不是国标/ISO 的 20°。** 这是作者面向 3D 打印齿轮定的默认值，直接拿来出加工图就是错的——**参数默认值本身就是一种「参数域」声明，而且是最容易被忽略的那种**【一手: 源码默认值】。
  另外 `clearance` 的默认是 `0.25 * circular_pitch / pi`，也就是 **0.25 倍模数**——与机械设计手册里常用的顶隙系数 c\*=0.25 一致（**我没有核标准原文，此条记为未查证**）。
- **cq_gears**：CadQuery，B-rep，能出 STEP【一手】。
- **单文件小工具**：如 `sw-involute-gear-calculator`（原 Python，3.0 重写为 C#/WPF），专门算齿轮几何并**输出可粘进 SolidWorks 的参数方程**【一手（README）: <https://raw.githubusercontent.com/umt9/sw-involute-gear-calculator/main/README.md>】。

【转述: cmiw.cn / swbbsc.com 论坛帖】——两家都是论坛帖、无版本号与复现文件，且可能用的是破解版，**不能当定论**。但它与「厂商文档里只有 addendum modification 的自动平衡、没有角变位专项说明」这一空白相互印证。

**价格（2025-01-01 生效）**：GearTrax **US$1,695**、GearTraxPRO **US$1,995**、GearTeq **US$2,395**；年维护 +$250 / +$300 / +$350；教育版 **$95**。

### 3.5 计算与建模分离的那一类：MITCalc / KISSsoft

这两个不是「插件」，是「算完了把模型塞给你」：

- **MITCalc**：整套计算建立在 **Excel** 上，每个计算是一张独立的 Excel 表，用户可以加参数、改系数、互相链接；齿轮、带、链、轴承、弹簧、轴、螺栓、公差全有；**支持把结果直接插进 SolidWorks / Inventor / Solid Edge / Creo，插入的 3D 模型是完全参数化的，且是关联的——插一次，改参数，模型自己变**【一手: <https://www.mitcalc.com/index_zs.htm>】。
  **价格是这一族里最便宜的：€89/年 或 €299 永久**（Excel 工作簿形态，按模块卖）。
- **KISSsoft**：最初是苏黎世齿轮厂 **L. Kissling & Co. AG 的内部计算软件**，1980 年代初开始外销，1985 年以 KISSsoft 之名正式发布；今天隶属 **Gleason Corporation**（全资子公司）【一手: <https://www.kisssoft.com/en/facts/about-us-1>；一手（访谈原文）: <https://www.kisssoft.com/de/products/publications/brochures/der-wichtigste-strom-fur-ideen-sind-die-kunden>，antriebstechnik 2019/12】。
  **它才是「强度校核」这条线上的基准**：约 **100 个模块**；齿轮强度模块 **Z06a 对应 ISO 6336**；与其他软件交换用 GDE v3.2（VDI 2610）/ GAMA / GEMS；**2010 年起内置 Parasolid 内核**，所以它能直接出实体而不只是算数字。价格不公开（未查证）。

**MITCalc 的「插入一次 + 关联更新」是这一族里最好的架构**，比「每次重新生成一个新零件」高一个档次——它不产生零件爆炸。

## 4. 连杆 / 机构这条线

先说一个**对我自己初稿的更正**：我一开始写的是「SolidWorks 从来没有一个连杆综合插件」。**这句话是错的。**

### 4.1 更正：MechGen——一个真实存在过的 SolidWorks 连杆综合插件

UC Irvine 的 **J. M. McCarthy** 团队（McCarthy Design Associates）做过 **Mechanism Generator / MechGen**，是**SOLIDWORKS 官方认可的 Approved Add-in**：

- **MechGen 2.0（2010-05）**：读 SolidWorks 里一个运动件的**5 个任务位置** → 生成一组在容差内近似这些位置的机构 → 动画预览 → 选一个 → **生成实体模型**。官方描述是「与我们的 Mathematica 设计软件配合使用」。
- **MechGen 3.0（2011-10 发布 / 2012 页）**：读 SolidWorks 草图中的**平面 3R 开链**（经过五个任务位置）→ 算出 **Watt-1 六杆**候选 → 预览 → **直接生成 SolidWorks 装配体**插进现有模型。作者 Alex Arredondo 与 Kaustubh Sonawale。
- **价格：完整版 $1,395.00**，教育价另议，有试用版。

【一手: <https://mechanicaldesign101.com/mechanism-generator-2-0/>；<https://mechanicaldesign101.com/blog/page/26/>；<https://mechanicaldesign101.com/product/mechanism-generator-3-trial/>】

**所以准确的结论是：做过，卖过，$1,395，然后没了。** 这比「从来没人做」有意思得多——它说明**这条路在技术上通，在商业上不通**。

国内的做法则是**自己二次开发**而不是买：姜渭（贵州大学）2011 年用 VB + SolidWorks 2007 宏录制做平面四连杆系统，把「算杆长」和「建模」合成一步【转述: 现代机械 2011(3):59-61】；李鸿飞等 2021 年用 VS + C++ 做整机凸轮连杆 CAD 系统，再接 ADAMS + Ansys 做刚柔耦合校核【转述: 包装工程 2021(23):199-206】。

**为什么没成主流【推断，四条】**：
1. **综合本身是非线性多解问题**——五个位置就有成组的解，六杆更是成批候选，必须由人来挑。插件只能在「生成候选」这一段加速，判据仍在设计师脑子里。
2. **价值落点在几何承载，不在求解**——设计师真正要 CAD 干的是「这些杆怎么装、会不会干涉、怎么出图」，这三件事 SolidWorks 本来就会，综合只是前面十分钟。
3. **专业位已被占**——要综合的人买 SAM（€1,775 起）；要仿真的人用 Motion（Premium 已含）/ Adams。
4. **商务成本**——$1,395 + 依赖 Mathematica 做设计端，注定是小众学术产品，没有渠道推力。

### 4.3 一个必须说清的区别：「综合」和「仿真」

- **综合（synthesis）**：输入是「我希望这点走这条曲线 / 经过这五个位置」，输出是**杆长和铰点坐标**。要解非线性方程组，解不唯一。
- **仿真（analysis）**：输入是**已有的几何 + 配合 + 驱动**，输出是速度、加速度、关节力、所需扭矩。

**SolidWorks Motion 属于后者。** 官方教员手册里的例子就是：打开 `4Bar.SLDASM`，让绿色连杆以 45°/s 顺时针转，算其余连杆的角速度和加速度、以及所需扭矩【一手: <https://www.solidworks.com/sw/docs/Motion_Sim_Instructor_WB_2011_CHS.pdf>】。**输入是运动，输出是力。**

这条区别决定了商业格局：**做仿真的活在 CAD 里（因为几何本来就在那），做综合的活在外面（因为它在解方程，不在画图）。**

### 4.4 机构综合的数学：三个名字，三个年份

| 名字 | 是什么 | 谁、哪年 | 证据 |
|---|---|---|---|
| **Freudenstein 方程** | 把四杆的输入角 φ、输出角 ψ 与四个杆长用一个标量代数式连起来（等价于闭环装配条件），把「函数发生」的综合变成解代数方程 | **Ferdinand Freudenstein**（哥伦比亚大学），**1954** 学位论文；**1955-08** 正式发表：*Approximate Synthesis of Four-Bar Linkages*, Trans. ASME **77(6): 853–859** | 【一手: ASME 期刊页】 |
| **Burmester 理论** | 给定动平面若干位置，求「在各位置都落在圆上」的点（圆点/圆心点曲线），从而定出四杆的两个连架铰 | **Ludwig Burmester**（1840–1927），**1886**，《Lehrbuch der Kinematik》，Leipzig: Arthur Felix | 【一手: ZBMath JFM 18.0814.01】 |
| **Chebyshev 节点配置** | 精确点不等分放，按切比雪夫节点放，使区间内最大偏差最小（等幅振荡） | 思想源出 **P. L. Chebyshev**，**1854**《Théorie des mécanismes connus sous le nom de parallélogrammes》；在机构综合教材里被系统化（Hartenberg & Denavit 1964, §5-5） | 【转述: Lund 学位论文；Cornell ecommons 教材正文】 |

> **一条中文文献里的常见错误**：把「切比雪夫精确点配置」直接挂在 Freudenstein 名下。那是**方法组装**（用 Chebyshev 节点 + Freudenstein 方程解），不是切比雪夫提出了 Freudenstein 方程——**两者差 100 年，别合并**。

## 5. 技术解剖：一个「参数→零件」生成器由什么组成

把 GearTrax、fcgear、你的宏、你的 MCP 工具放在一起看，骨架是同一个五层：

```
① 参数层   输入：模数、齿数、压力角、变位系数、材料、精度等级…
              ↓  （这一层决定「参数域」有多宽）
② 校核层   齿面接触强度、齿根弯曲强度、干涉、根切、滑动率…
              ↓  （这一层是「可靠」的真正来源）
③ 几何层   齿廓曲线（渐开线/摆线/圆弧）、齿根过渡、螺旋线、齿顶修缘
              ↓
④ 装配层   中心距、装配约束、相位对齐、干涉检查
              ↓
⑤ 交付层   .swp 宏 / .dll 插件 / 独立 exe / 网页 / STEP 文件
```

**四个组件缺一个，这东西就不成立：**

1. **参数域是封闭定义的**。GearTrax 能接受「齿数 8」还是必须 ≥17？它内部有根切判断。这个判断就是「灵活性差」的来源，也是「不会给你一个错的齿轮」的来源。
2. **判断在生成之前**。GearTrax 功能表里有 Design alerts（三档都有，PDF 逐格核过）；MITCalc 直接说「按 ANSI/ISO/DIN/BS/ČSN/日本标准处理」。**先判，判不过就不给。**——但注意 Design alerts 是**几何层面的提醒**（干涉、根切一类），不是强度校核。
3. **几何是算出来的，不是画出来的**。这是 A/B/C 三条路线的分野（见 §3.1）。
4. **交付形态决定了它的失效模式**：

| 交付形态 | 失效模式 | 证据 |
|---|---|---|
| VBA 宏（.swp） | 换 SolidWorks 版本，类型库优先级变了就 `Compile error: Object library feature not supported` | 【一手: <https://help.solidworks.com/2025/english/api/sldworksapiprogguide/overview/VBA_Macros_Type_Libraries_and_SolidWorks_Upgrade.htm>】 |
| 宏用了新版本 API | 在老版本上跑 → `Run-time error 438 / 445`（SolidWorks 向后兼容，**不向前兼容**） | 【一手: <https://github.com/xarial/codestack/blob/master/solidworks-api/troubleshooting/macros/future-version-apis/index.md>】 |
| Add-in（.dll） | 32/64 位、.NET 版本、注册表注册 | 【转述: GearTrax 手册自述「限于 32 位编译」】 |
| Macro Feature | 重建时不能新增特征、不能交互、不能用 .NET 写 | 【一手: SOLIDWORKS API Help, Overview of Macro Features】 |
| 设计表（Excel） | Excel 链接断 → `Failed to connect. Link may be broken.`（2022 年 5 月 VC++ 2022 redist 14.32.31326.0 引起）；含跨表链接的设计表可能存不上 | 【一手: <https://www.goengineer.com/blog/resolve-solidworks-error-failed-to-connect-link-may-be-broken>；一手: <https://help.solidworks.com/2025/english/solidworks/sldworks/t_Saving_Design_Tables.htm>】 |
| 配置（Configuration） | 数量上去了重建和保存都变慢；且配置之间**没有数学关系**，不能自动维持比例 | 【一手: GoEngineer 2021；转述: 2ds.cn 对比文】 |
| 独立 exe / 网页 | 与 CAD 脱钩，改一次要重新导入 | 【推断】 |

**这张表就是「灵活性差、比较可靠」这句话的真实含义**：每一种形态都把「可能性」换成了「确定性」，而每种确定性都有自己的保质期。

## 6. 「可靠」到底来自哪里（逐条给证据）

| 可靠性来源 | 具体机制 | 证据 |
|---|---|---|
| **确定性** | 同样输入 → 同样几何。没有采样、没有权重、没有温度参数 | 【推断，但为这类工具的定义性质】 |
| **判断内建** | 几何层面（齿廓、根切、干涉提醒）在生成前判，不合格就报错而不是「生成一个差不多能用的」；强度则交给专门软件 | GearTrax 功能表 Design alerts（几何提醒）；MITCalc / KISSsoft 做强度【一手】。**Camnetics 明确不做强度**（PDF 全文 0 命中） |

| **离线** | 不依赖网络、不依赖服务方、不依赖模型版本 | 【推断】 |
| **长期存活** | GearTrax 1998→2026；KISSsoft 1985→今 | 【一手】 |
| **人能读懂** | VB6 代码 / VBA 宏 / Python 脚本，客户自己能改 | 【推断】 |

## 7. 「灵活性差」到底差在哪（同样逐条）

| 局限 | 具体表现 | 证据 |
|---|---|---|
| **参数域封闭** | GearTrax 只认它列的那十几类传动件；形状超出这个清单就无解 | 【一手: 数据表产品清单】 |

## 8. 反证与限制（必须看的一节）

### 8.1 「参数化 = 可靠」这个前提本身被质疑过

Evan Yares 2013 年那组《The failed promise of parametric CAD》是行业里最系统的反证。核心论点：

- 参数化 CAD 的承诺是**模型复用**，而这个承诺**没有兑现**；
- 原因是父子依赖与意外特征交互既无法预防也无法检查；
- 连 PTC 自己的应用工程师，也只能在提前练过的件上做出 resilient 的模型；要求改一个引起拓扑变化的尺寸，照样炸；
- 有经验的高手也一样，只是他们的模型「在你没预料到的参数范围之外」才炸。

【一手: <https://www.engineering.com/the-failed-promise-of-parametric-cad/>；<https://www.engineering.com/the-problem-is-editing/>；收尾篇 <https://www.engineering.com/author/eyares/page/2/> · 2013】

**这条不代表你的判断错，而是要求你把判断说准**：这些插件可靠，是因为**它们每次都是从零生成，而不是在既有模型上编辑**。「生成」是确定的，「改」不是。凡是你打算「让用户在一个已经做好的模型上改参数」，你就进入了 brittle 的地带。

### 8.2 1980–90 年代已经有过一轮「智能 CAD」，失败了

日本学者富山哲男（Tetsuo Tomiyama）在 AI EDAM 上的综述《Intelligent computer-aided design systems: Past 20 years and future 20 years》开头就写：1980 年代初，受专家系统（MYCIN, 1976）鼓舞，工程界做了一大批实验系统，AI 被认为能「完美解决」各类智力活动【一手（摘要原文）: <https://homsy-staging.cambridgecore.org/core/journals/ai-edam/article/abs/intelligent-computeraided-design-systems-past-20-years-and-future-20-years/CC58B36BE174A5F7AF579334216230DB> · 2007-01-22】。

与之配套的 KBE 商业系统大多没有活到今天。**公司沿革本身就是结论**（这里更正一条流传很广的说法）：

| 系统 | 真实沿革 | 备注 |
|---|---|---|
| **ICAD** | ICAD Inc. → **Concentra（1995 IPO）** → **KTI（1998）** → **Dassault（2001 收购）** → 停 | 常见的「ICAD 后改名 Design++/Concentra」**不成立**：**Design++ 是 Design Power, Inc. 的另一个对象模型产品**，与 ICAD 不是同一支 |
| **Intent!** | Heide Corporation → Engineering Intent（1995–2005）；引擎售予 Unigraphics（**1997** 说与 2001 说并存，取 1997，因 KF 随 NX V17=2000-10 首发） | 「1988 年」这个年份**没有证据** |
| **TechnoSoft AML** | 官方写**初始发布 1992**（不是 1988） | Adaptive Modeling Language |
| **Genworks GDL / Gendl** | 至今仍有维护 | 少数活下来的 Lisp 系 KBE |

【一手/转述合并，逐条见 `_evidence/line-text2cad-history.md` §4】

**这一轮的历史教训是：把「知识」写进系统的成本远高于预期，而知识的维护成本随覆盖面线性上升。** 学界对 KBE 的复盘（Verhagen 等 2011）指出四条方法学缺口：知识获取与建模缺乏统一方法、缺少可复用知识库、缺少与 CAD 的双向同步、缺少验证手段。加上商业侧的定价过高（ICAD 时代六位数美元级）与 Dassault 收购后的弃养，这条线就断了。

**对今天的直接含义**：不是「AI 生成 CAD 不行」，而是**「覆盖面一大，维护就压死」**——这条规律和用不用 AI 无关。

### 8.3 每条候选的具体坑

| 对象 | 坑 | 证据 |
|---|---|---|
| SolidWorks Toolbox 齿轮 | 齿廓是圆弧替代渐开线，精度低 | 【一手: IEEE 9700016 摘要】 |

## 10. 对今天有用的结论

### 10.1 该抄的三件事

1. **「参数 → 校核 → 生成」三段式，校核必须在生成之前。**
   **但别把 GearTrax 当校核器**——它做的标准是**齿形**标准（DIN 867、JIS B 1701、ANSI-AGMA 2008-A88、Fellow Stub），两份 Camnetics PDF 里全文检索 `strength` / `6336` / `AGMA 2101` / `ISO 1328` **全部 0 命中**，也就是**它没有任何强度校核声明**；学术论文里也是「用 GearTeq 建模，再做后续 FEA 分析」的分工。真正做强度的是 KISSsoft（ISO 6336）、MITCalc（多国标准）那一类。
   你自己做任何生成器（齿轮、连杆、板件），**先判「这个参数组合合不合法」，再动 CAD**。不合法的输出不是「一个勉强的模型」，而是「一条说清为什么不行的错误」。
2. **关联更新 > 反复重新生成。**
   MITCalc 的做法是「插一次，改参数，模型自己变」，不是「每次都生成一个新零件」。后者会造成零件爆炸、引用混乱。这条对你现在的 SolidWorks 自动化直接可用。
3. **参数域要显式写出来，并且要窄。**
   GearTrax 之所以二十年不出事，是因为它只做它列的那十几类件。**范围越窄，校核越容易做全。** 想覆盖一切的那类系统（KBE）都死了。

### 10.2 别抄的三件事

1. **别用圆弧近似齿廓。** Toolbox 的教训有论文实证。
2. **别把生成逻辑写成 VBA 宏然后指望它跨版本。** 官方文档自己列了类型库失效与向前不兼容两条。
3. **别用「堆配置」代替「写生成器」。** 配置之间没有数学关系，配置一多就慢，而且改一条设计规则要逐个手改。

### 10.3 选型判据（什么时候用哪种）

| 你的需求 | 该用 | 为什么 |
|---|---|---|
| 一批固定规格，规格表已经确定 | 设计表 / 配置 | 最低成本，Excel 谁都会改 |
| 规格连续可变，要算强度 | 生成器（脚本/插件） | 配置做不到连续，也算不了强度 |
| 形状本身就是参数（扇形齿轮、非圆齿轮） | 代码生成（CadQuery/OpenSCAD 路线） | 配置和方程曲线都表达不了拓扑变化 |
| 要给非工程师用 | Configuration Publisher / DriveWorks 表单 | 界面层的价值 |
| 要审计、要复现、要进版本库 | 脚本（文本入 git） | 二进制模型没法 diff，代码可以 |

### 10.4 验收任何一个参数化生成器的五问

拿到一个齿轮/连杆/板件生成器（别人的或自己的），按这五个问题过一遍，能立刻判断它属于哪一档：

1. **参数域写在哪？** 如果写不出来（「支持任意参数」），那它没有校核层。
2. **校核在生成前还是生成后？** 生成后才发现干涉的，等于没有校核。
3. **齿廓/轮廓是算出来的还是拼出来的？** 拼的会有一个说不清的误差。
4. **改参数时是「更新」还是「重建」？** 重建会零件爆炸，更新不会。
5. **它自己声明「不保证什么」吗？** GearTrax 敢在功能表里写 `NOT suitable for manufacturing`，这是成熟的标志。

**五问都答不上来的工具，无论新旧，都不该进产线。** 这条判据和 AI 无关。

### 10.5 今天自己做一个，五条路怎么选

| 路 | 技术栈 | 上手成本 | 稳定性 | 适合什么 |
|---|---|---|---|---|
| **A. VBA 宏（.swp）** | 录制 → 改代码 | 最低（几小时） | **差**：跨版本类型库失效、不能向前兼容 | 一次性批处理、内部小工具 |
| **B. Macro Feature** | VBA（**必须 .swp，不能 .NET**） | 中 | 中：随模型重建自动跑，但**重建时不能新增特征、不能交互** | 需要在特征树里"活着"的参数化特征 |
| **C. C# Add-in** | Visual Studio + xarial **xcad**（MIT） | 高（几天到几周） | **好**：可做 UI、可分发、可版本化 | 要给别人用的工具 |
| **D. Python + COM** | pywin32 / `win32com` | 中 | 中：同一进程内 COM 是 STA，抢连接会死锁 | 自动化流水线、批量出图 |
| **E. 外部生成 + 导入** | CadQuery / build123d → STEP → 导入 SW | 中 | **好**（与 SW 版本解耦） | 几何复杂、SW API 表达不了的东西 |

【依据: SOLIDWORKS API Help（Macro Feature 两条硬约束、VBA 类型库升级问题、向前不兼容）；xarial/codestack、xcad 的定位】

**一句选型建议**：**能用 E 就别用 D，能用 C 就别用 A。** 判据是「这个东西要不要活过下一次 SolidWorks 升级」。

## 12. 对照：今天的 text-to-CAD 长什么样（只为定位，不是评测）

写这一节只是为了把坐标定住，不做产品评测。

### 12.1 这个词是谁造的

- 目前能定位的最早把 **Text-to-CAD / Text2CAD** 当**技术名词**用的是 **2024 年**：NeurIPS 2024 的 **Text2CAD**（「the first AI framework for generating text-to-parametric CAD models using designer-friendly instructions」，基于 DeepCAD 数据集 + Mistral/LLaVA-NeXT 标注）【转述: <https://neurips.cc/virtual/2024/poster/96571>】。
- **我找不到 2024 年之前把它当固定术语使用的原始文献。** 所以这个判断是安全的：**「text-to-CAD」是 LLM 时代的命名，不是 1990s–2010s 的行话。**

### 12.2 但「自然语言 → CAD」这件事，2014 年就有人做过——用的是受控文法，不是学习模型

Autodesk 的两件专利是这个方向的硬证据，都早于 LLM：

- **US11113430B2**《Techniques for using controlled natural language to capture design intent for computer-aided design》——优先权日 **2014-05-09**，授权 2021-09-07，受让人 Autodesk，发明人 **Francesco Iorio、Wei Li、Hyunmin Cheong**。机制：接收用**受控自然语言（CNL）**写的设计问题陈述 → 用 CNL 的词典与句法规则处理 → 产出**可由设计应用执行的 job description** → 生成方案；还提供 CNL UI 帮用户写出合规的句子。
- **US10095217B2**《Natural language user interface for computer-aided design systems》：语音 → 解析 → 求意义（对象 + 对象属性）→ 查 model descriptor 库 → 生成/修改模型。

【一手: <https://patents.google.com/patent/US11113430B2/en>；<https://patents.google.com/patent/US10095217B2/en>】

**这意味着：LLM 换掉的只是「文法层」，不是「文本→几何」这件事本身。** 2014 年的系统要求你说语法合法的句子（「M6 通孔，100 mm 网格，90° 锪 6 mm」这类），系统不「理解」自由文本；今天的 LLM 把这一层拿掉了，但**几何与校核那两层没变**。

### 12.3 「Generative design」在 2010 年代指的是拓扑优化，不是今天这个

- **1993**：Altair 推出 **OptiStruct**，把拓扑优化商品化。技术源头是密歇根大学 **Noboru Kikuchi** 的工作，Altair 创始人 Jim Scapa 雇其研究生 **Jeffrey Brennan** 把它带进公司商品化。
- **2012-11-01**：**solidThinking Inspire 9.0**——把拓扑优化做成设计师可用（给设计空间 + 载荷 → 自动出形状）。
- **2015-09**：Autodesk Research 的 **Project Dreamcatcher** 公开，输入是目标与约束（材料、功能、性能、成本），云端跑生成式设计出候选方案。

【来源见 `_evidence/line-text2cad-history.md` §12】

**一句话**：2010 年代的 generative design 是「**给定设计空间与约束，用优化算法搜索形状**」；2020 年代的 generative AI 是「**给定语言，用学到的分布生成符号**」。**两者差三十年，不共享任何模型。** 把这两个当成同一件事，是当前最常见的术语混乱。

### 12.4 今天的两个样本

- **Zoo（原 KittyCAD）**：2021 年以 KittyCAD 之名成立，2024-01 更名 Zoo；**2024-12-11 开放 Text-to-CAD 公测**；2026 年推出对话式代理 Zookeeper，接的是自家 KittyCAD API 与 Zoo Design Studio，官方定位是「ML-powered research, design, modeling, and review」【一手: <https://docs.zoo.dev/blog/announcing-zookeeper>】。
- 中文百科词条称其当前版本**只支持单个对象生成，不支持组件与装配体**，可导出 STL/PLY/OBJ/STEP/GLTF/GLB/FBX【转述: 百度百科「Text-to-CAD UI」词条】。**这条我没在 Zoo 官方文档里核实，记为未查证。**

**与前面五类相比，缺的是什么？**

| 维度 | 老的那五类 | 今天的 text-to-CAD |
|---|---|---|
| 输入 | 参数 / 程序 / 表 | 自然语言 |
| 参数域 | **显式封闭**（写死在产品里） | 开放，但边界不可预测 |
| 校核层 | **有**（强度、干涉、根切） | 目前普遍没有独立校核层 |
| 确定性 | 同输入必同输出 | 不保证 |
| 失败模式 | 报错 | 生成一个「看着像」的东西 |

**这张表不是判优劣，是判风险位置。** 老工具的风险在「做不到」，新工具的风险在「做到了但不是你要的」。**后一种在生产里更贵。**
