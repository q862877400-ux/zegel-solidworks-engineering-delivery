## 一、结论

| 族 | 几何原语 | 状态 | 可否交付 |
|---|---|---|---|
| 轴（`Shaft_d28_L300`） | 2 · 旋转 360° | **真机建成，L3 全绿** | 形状对，但缺倒角（计划缺口） |
| 齿轮（`SpurGear_m1_z20`） | 1 · 闭合轮廓拉伸 | **无可用生成器** | ❌ 不可 |

齿轮族不可交付的原因不是执行失败，而是**它的生成器被业主明令删除**：`plan_spur_gear`
把渐开线采样成点列、再逐段 `sketch_line` 连直线 —— 那是「折线模拟曲线」，齿面不再是
共轭渐开线、齿根不是真实摆线、段数可调会让同一规格建出不同齿形。
依据：`AGENTS.md` §十四之五（业主 2026-11-07 令「把所有折线模拟曲线的功能删除」）。

## 二、轴族（唯一的通过项）

**真机命令**

```powershell
python -B tools\guard_run.py --timeout 400 -- python -B "research\text-to-cad-and-parametric-plugins\proto\execute.py" --shaft T=120 L=300
```

**真机输出（原文）**

```
plan: Shaft_d28_L300  实体 6  轴线段 1  旋转 360°
预期体积 300084.93 mm³  包围盒 40.00×300.00×40.00
已连接到运行中的 SolidWorks 实例（ProgID: SldWorks.Application）
当前文档: 零件5 (类型: 零件)
execute: Shaft_d28_L300  原语 revolve  草图实体 7
verify: 体积 300084.9 mm³（预期 300084.93，偏差 0.00%）✓
verify: 包围盒 40.00×300.00×40.00（偏差 0.000/0.000/0.000）✓
verify: 三视图 4/4 ✓
VERDICT: OK
```

**参数（全部来自真机输出的参数表）**

| 参数 | 值 | 来源 |
|---|---|---|
| T 传递扭矩 | 120 N·m | 问 |
| L 轴长 | 300 mm | 问 |
| material | 45钢 | 问 |
| shock | none | 问 |
| A 材料系数 | 118 | 查（design_rules.yaml） |
| d_calc | 27.43 mm | 算 `118×(120/9550)^(1/3)` |
| d1 轴颈 | 28 mm | 选（GB/T 2822 向上取整） |
| d2 轴肩 | 40 mm | 算 `28+2×6.0` |
| L1 / L2 | 120 / 180 mm | 算 |
| tau_equiv | 29.6 MPa | 算（交叉校验，落在 10~60 区间 ✓） |

**L3 判据为什么可信**：体积由两条独立路径算出并比对 —— 解析式 `πr₁²L₁ + πr₂²L₂ = 300084.93`，
与 SolidWorks `mass_properties` 回读值（内部单位 m³，强制 ×1e9）`300084.9`。两者对上。
包围盒同理，用 `solid_body_extent_mm`（内部 `GetBodyBox`），**不用** `IFeature.GetBox()`
（官方 Remarks 明写 approximate、不可用于比对）。

**L4 人工目视（已做，发现缺口）**

| 视图 | 结论 |
|---|---|
| isometric | 竖立阶梯轴，上段粗下段细，台阶面清晰，着色正常 ✓ |
| front | 两段矩形，粗段 120 / 细段 180，粗细比 40:28 ≈ 1.43 与参数表一致 ✓ |
| top | 正圆，边缘闭合无缺口 ✓ |
| right | 与 front 一致 ✓ |

**发现的两处缺口（属 `plan_shaft` 计划层，不是执行错误）**：

1. **无倒角** —— 轴肩根部与两端面都没有倒角。实做轴这些位置按惯例必须有（GB/T 6403.4）。
   `plan_shaft` 只画直角台阶。
2. **top 视图无中心线** —— 圆面只有外圆，没有轴线。工程图意义上信息量偏低。

`verify` 的判据只要求「三视图文件生成」，所以这两条**不会被机器判据抓到** —— 这正是
需要人工目视的原因。

## 三、齿轮族（不可交付）

**没有执行失败，是没有生成器。** 时间线：

1. 起初用归档 `archive/inherited-methods/scripts/sw_gear.py` 的 `calculate_external_spur_gear`，
   它返回 `outline_points_m`（离散点列），`plan_spur_gear` 把相邻点连成 `Line`。
   真机确实建成过：`SpurGear_m1_z20`，700 点 / 540 点两版都通过 L3。
2. 但那是**折线模拟渐开线**。业主早已明令禁止（「像什么直接用直线去逼近曲线这种野路子，
   你就全部都改掉」），2026-11-07 再次下令删除全部相关功能。
3. 仓库里本来就有正确实现 `scripts/gear_geometry.py`（`CreateEquationSpline2` 方程式驱动
   的真渐开线 + 真摆线齿根）。真机实测暴露两个未解缺陷：
   - **整圈闭合路线**：120 条曲线全部建成（`curves_ok=120`），但 `FeatureExtrusion3`
     返回 `None`、体积 0。离线审计测出相邻接点最大间隙 **18139 µm**，超差接点 100/120，
     且同一齿的左右齿廓端点完全重合（齿厚为 0，退化成薄片）。
   - **单齿阵列路线**：单齿真曲线拉伸成功（`extrude_tooth=true`，齿体积 34.39 mm³），
     但圆周阵列没增加体积（`after_pattern_volume` 等于单齿体积），中心孔切除也失败。

结论：**在真曲线路线通过「特征建成 + 体积 <1% + 包围盒对上 + 三视图 4/4 + 人工目视」之前，
齿轮族保持 `stitched`，且不得升级为 `verified`，也不得对外提供建模入口。**

`capabilities.yaml` 的 `external_spur_gear_geometry` 首条 limitations 已写明这一点。

## 四、这条禁令怎么防复发

1. **顶层文档**：`AGENTS.md` §十四之五，含「发现即停机溯源」——
   再看到折线方案立刻停手，先查它是抄了归档、外部库还是新写的，定位来源再删。
2. **硬门禁**：`scripts/check_no_polyline.py`，已接进 `release_check`（第 68 道门禁）。
   - AST 扫活跃 `.py`，不是正则 ⇒ docstring 里解释「为什么折线是错的」不误报
   - 判据：不得 `import sw_gear`；不得出现 `outline_points_m` / `involute_segments` /
     `tip_arc_segments` / `root_arc_segments` / `plan_spur_gear` / `SpurGearSpec` 等名字
   - **负例自证**：喂一段已知折线代码必须报出来（实测命中 8 处），否则门禁假绿
   - 追溯区（`archive/`、`docs/history/`、`recon/`、`output/`）不扫
3. **实测**：扫描 1683 个活跃 `.py`，零折线指纹，`VERDICT: OK`。
