# 从分系统到装配级：这套东西在 Agent 思考链里的位置

设计文档 · 2026-11-04 · 配套脚本 `proto/planetary_check.py`（输出 `demo_planetary.txt`）

---

## 0. 结论

你说的对，但要点不在「再往上加一层功能」，而在于：

> **分系统那套东西不升级，只降位——从"产品"变成"推理原子"。**

- 用户说「画个行星齿轮组」时，**问的问题不再是"模数取多少"，而是"要不要自锁、空间紧不紧、要不要大速比"**；
- 分系统（齿轮 / 轴 / 轴承 / 箱体）在 Agent 手里变成**可反复调用的判定器**；
- **装配级不是"多调几次分系统"，是多出一层约束求解**——这一层现在不存在，必须新建。

下面用实测证明：**每个齿轮都合法，行星轮系照样装不上。**

## 1. 三层能力，两个判定器

```
用户意图："画个行星齿轮组，减速 5，装在机器人关节里"
        │
        ▼
┌─────────────────────────────┐
│ ① 拓扑选择（搜索，不是参数） │  NGW 单级？2K-H？定轴+行星？几级？
└─────────────────────────────┘
        │ 选定拓扑
        ▼
┌─────────────────────────────┐
│ ② 分系统求解器 ×N            │  ← 就是 01/02/03/04 那套
│    太阳轮 · 行星轮 · 内齿圈   │    每个都产出自己的 A/B/C 推理表
│    行星架 · 轴 · 轴承         │
└─────────────────────────────┘
        │ 各分系统的参数集
        ▼
┌─────────────────────────────┐
│ ③ 装配级判定器（新增）        │  同心 · 装配 · 邻接 · 传动比
│                             │  干涉 · 自由度 · 均载
└─────────────────────────────┘
        │ 通过
        ▼
   装配体 + 跨分系统推理表（含"我不能满足"的清单）
```

**②是已有的，③是缺的。** 而且 ③ 不能靠"把 ② 的结果拼起来"实现——它解的是另一类方程。

## 2. 实测：分系统全对，装配照样失败

标准单级 NGW 行星轮系，四个耦合条件：

| 条件 | 式子 | 含义 |
|---|---|---|
| **同心** | `z_r = z_s + 2 z_p` | 太阳轮、行星轮、内齿圈必须同轴啮合 |
| **传动比** | `i = 1 + z_r / z_s` | 内齿圈固定、太阳轮输入、行星架输出 |
| **装配** | `(z_s + z_r) / n_p` 必须整除 | 几个行星轮要能均匀插进去 |
| **邻接** | `(z_s + z_p)·sin(π/n_p) > z_p + 2` | 相邻行星轮齿顶不能相碰 |

### 案例 A：客户要减速 5 倍，最常见的 3 个行星轮

```
z_s=20  z_p=30  z_r=80  n_p=3  i=5.000
同心 ✓   传动比 ✓   不根切 ✓
装配 ✗  (20+80)/3 = 33.333   ← 不是整数，装不上
邻接 ✓
⇒ 不能装配
```

**三个齿轮单独看全是合法的标准直齿（z 都 ≥17，同心条件也满足），但配不成一套。**

### 案例 B：改成 4 个行星轮

```
(20+80)/4 = 25 ✓   邻接 35.36 > 32 ✓   ⇒ 可以装配
```

### 案例 C：客户坚持 3 个行星轮 → 反推齿数约束

可解：`z_s = 18, 24, 30, 36, 42, 48, 54, 60`（即 **6 的倍数**）。

原因：`(z_s+z_r) = 5z_s` 要被 3 整除 ⇒ z_s 被 3 整除；`z_p = 1.5z_s` 要整数 ⇒ z_s 被 2 整除。**合起来 z_s 被 6 整除。**

**这条规律，任何一个"分系统自己算"都推不出来**——它只存在于装配条件里。

### 案例 E：更狠的一条——n_p=5 和 6 在 i=5 时**几何上不可能**

i=5 ⇒ `z_p = 1.5 z_s`，邻接条件变成：

```
2.5 z_s · sin(π/n_p) > 1.5 z_s + 2   ⇒   sin(π/n_p) > 0.6 + 0.8/z_s
```

`sin(π/5)=0.588`、`sin(π/6)=0.500`，**都 ≤ 0.6，与 z_s 无关，永远不成立**。

扫描结果印证：`n_p=5 → 0 个可行解，n_p=6 → 0 个可行解`。

**注意这不是「没搜到」，是「解析上不可能」。** 一个只会枚举的工具会说"没有找到"，而 Agent 需要的是"**这条路是死的，别再试**"——这两句话对搜索效率的影响差几个数量级。

## 3. Agent 的深度思考长什么样

**不是一次生成，是一个带判定器的循环：**

```
选一个拓扑 → 调分系统求解 → 装配判定
                              │
              ┌───────────────┴───────────────┐
           通过                              失败
              │                                 │
           出模型            读失败理由（哪条条件、差多少、怎么改）
                                              │
                                     调一个变量 → 回到分系统求解
```

**关键不在于循环，在于每一次循环都能拿到「为什么不行」：**

| 失败 | 差的是一句话还是一组数 |
|---|---|
| 装配条件失败 | `(20+80)/3 = 33.33`，要么把 z_s 改成 6 的倍数，要么改 4 个行星轮 |
| 邻接失败 | `(z_s+z_p)sin(π/n_p)=29.39 < z_p+2=32`，行星轮会碰 |
| 无解 | `sin(π/5)=0.588 < 0.6`，与齿数无关，换 n_p |

**这正是前面四份文档真正的用处**：它们不是"给客户看的界面"，是**给 Agent 看的燃料**。没有这些可读的失败理由，Agent 的"深度思考"就退化成瞎试参数。

## 4. 推理表要升级：从单件到跨分系统

单件推理表（04）的 `来源` 只有 `问/算/选/查/锁/假设`。**装配级要多一个维度：这个参数被谁引用。**

| 参数 | 值 | 来源 | **定义在哪** | **被谁引用** | 改它会怎样 |
|---|---|---|---|---|---|
| `m` | 1.0 | 选 | 装配级（三件共用） | 太阳轮/行星轮/内齿圈 | **三件全变**，同心条件仍成立 |
| `z_s` | 20 | 选 | 太阳轮 | 同心、传动比、装配、邻接 | 四条条件全动 |
| `z_r` | 80 | 算（同心） | 装配级 | 传动比、装配 | 改它 → 同心条件破 |
| `n_p` | 4 | **搜**（离散枚举） | 装配级 | 装配、邻接 | 只能取整数，且受邻接限制 |
| `εα_ps` | 1.67 | 算 | 分系统（太阳轮-行星轮副） | — | 局部量，不影响装配 |

**两条新规则：**

1. **每个参数必须标「定义在哪一层」**。同一个 `m`，在单件里是"这个齿轮的模数"，在行星轮系里是"三件共用的模数"——**改一个，三个一起变**。
2. **冲突必须显式列出**。太阳轮要 `z_s≥17`、同心要 `z_r=z_s+2z_p`、装配要 `(z_s+z_r)` 被 `n_p` 整除——三条合起来可能**无解**，而单件表永远显示"我这件没问题"。

## 5. 什么不能提前定

| 项 | 性质 | 所以怎么问 |
|---|---|---|
| **拓扑**（NGW / 2K-H / 定轴） | **搜索空间**，不是参数 | 问"要不要自锁""空间多紧""速比多大" |
| **行星轮个数 n_p** | **离散枚举**，不是连续参数 | 一般不问，Agent 扫描后给可行集 |
| **级数** | 离散 | 由速比范围和体积约束决定 |
| **模数 / 齿数** | 推导 | 不问 |

**所以装配级的问句层级要再升一档**：

- ✗ 「行星轮要几个？」（客户不懂，工程师也不该被问这个）
- ✓ 「你这个减速，是**空间紧**（要小），还是**要能扛大扭矩**？」
- ✓ 「需不需要**自锁**（停电不会倒转）？」

## 6. 与 SW 项目的接口

| 层 | 形态 | 理由 |
|---|---|---|
| 分系统求解器 | **方法层 Python 模块**（`methods/`），不进 MCP 工具表 | 沿用项目既定判断：「齿轮属【方法】不属【工具】」 |
| 装配级判定器 | 同样是方法层模块 | 它是判定器，不是操作 |
| 对 AI 暴露 | 少量工具：`design_drive_train(intent)` → 方案 + 推理表 + 失败理由 | 工具少，能力厚 |
| 建模 | 复用项目已有的 `sw_part` / `sw_sketch_*` / `sw_assembly` | 不重写几何 |

**一句话**：**能力在方法层，工具层只留薄壳，Agent 在中间反复调。** 这样才既不给工具表塞 40 个齿轮工具，又让 Agent 有东西可想。

## 7. 边界（这次实测没做的）

| 没做 | 后果 |
|---|---|
| **强度 / 寿命** | 全部方案只过了几何与装配条件，**不保证能用** |
| **均载**（行星轮载荷分配） | `n_p=2` 的可行解很多，但两行星轮扭矩分配差、需要浮动设计；本 demo 只判几何 |
| **内齿圈加工限制** | 插齿/拉齿有直径上限，本 demo 没查 |
| **轴承 / 轴 / 箱体** | 完全没进入 |
| **变位** | 全部按 x=0 推，实际行星轮系大量用变位来凑中心距与均载 |
| **同心条件的容差** | 用了精确相等；实际有公差与侧隙 |

**这七条就是「分系统能力」到「可交付设计」之间剩下的一段路。**
