## 0. 顶层一句话

> **不去学"这些零件该怎么设计"，而是去接"前人已经写好的代码"。**
> 让 Agent 的几何来自**别人验证过的实现**，Agent 自己只负责**判断该不该画、按什么参数画、画完对不对**。

一句话的来由：现在的 Agent 会用 SolidWorks，但是**外行**——手会了，脑子没有。

## 1. 五层拆解

### L0 目标
**Agent 像机械工程师一样干活**，而不是像个会用软件的操作员。

### L1 第一原则：站在前人代码上，不从教材重推
- 教材/手册用来**判断与校核**，不用来**从零推几何**。
- 前人代码（生成器/库/算法）用来**产出几何**。
- 二者分工不能混：**几何必须来自代码，判断可以来自书本。**

### L2 分流：买 / 造 / 放
拿到一个零件，先回答三个问题，顺序不能颠倒：

| 顺序 | 问题 | 判据 |
|---|---|---|
| ① | **能不能买？** | 尺寸能不能被一张表穷举 → 能就买 |
| ② | **能不能用现成代码造？** | 几何能不能由参数+公式唯一算出，且已有实现 |
| ③ | **都没有怎么办？** | 非标/多解/无成熟实现 → **登记，放一放，不许硬画** |

### L3 造的实现：四段流水线
```
需求 → 参数（推导 + 校核）
     → FeaturePlan（纯数据：实体 + 特征 + 预期体积）
     → execute（唯一碰 COM 的地方）
     → verify（L3 体积/包围盒，L4 三视图）
```

### L4 交互：怎么问、怎么交代
- 用专业术语先问，`不知道` 就降级，`你定` 就决定并交代；
- 出参数表时每个值标来源（问/算/选/查/锁/假设）；
- **没算什么必须写在最后一屏**。

### L5 集成：进 SW 项目
- 方法层（Python），**不进 MCP 工具表**；
- MCP 只留薄壳；
- 一律先 `stitched`，真机过了才 `verified`。

## 3. 一处自省：哪些不是"前人代码"

你反复强调的是**拿前人代码**。按这条尺子量，本对话里有三类东西：

| 类别 | 内容 | 是否合规 |
|---|---|---|
| **纯前人代码** | 齿轮几何（归档 `sw_gear.py`）、`cq_gears`/FCGear/MCAD 的复用清单、零件源 | ✅ 符合 |
| **前人数据** | 53 项分流的行业依据（mechtool 的 25 个计算工具、MISUMI/Toolbox 的实际能力） | ✅ 符合 |
| **我们自造的** | `02` 语义层、`03` 参数图、`04` 溯源表、`dispatcher` | ⚠️ **这是界面与流程，不是几何** |

**结论**：**几何一个字都没自己推**——全来自归档实现与前人库；自造的部分是**怎么问、怎么交代、怎么分流**，那本来就没有前人代码可抄。

这条边界必须守住：**一旦开始自己推齿形、自己定标准表，就跑偏了。**

| 「买/造/放」三桶可分 | 53 项全部分完，无一项落空；`test_every_triage_row_has_a_declared_route` |

| 「参数能推出来」 | 2 个问题 → 13 行参数表；`test_basic_derivation_hits_center_distance` |
| 「计划能在无 SW 环境验证」 | 24 条测试 0.07 s，全离线 |
| 「失败的路径也说清」 | 无解时给最近可行解与差多少；`test_no_solution_reports_the_nearest_alternatives_not_a_shrug` |
