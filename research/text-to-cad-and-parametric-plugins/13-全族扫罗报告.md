## 0. 结论（十二条）

### ① 开源世界没有中国国标标准件库 —— 三条独立证据

| 证据 | 结果 |
|---|---|
| BOLTS 数据文件全量解析 | **GB = 0 / 76** |
| FreeCAD Fasteners WB 的 192 个 CSV | **`gb*` 前缀 = 0** |
| GitHub 6 组关键词（GB/T fastener、GB 标准件等） | 4 组 total=0；命中的全是「Sponsor to obtain the full data files」空壳仓 |

**推论（对本项目最关键）**：国标符合性**只能靠「国标数据 + 外来数学」拼**，不能指望有一个现成的 GB 开源库。

> **cq_gears 的 `SpurGear(module, teeth_number, ...)` 缺的参数，正好是 GB/T 1356/1357 给的。**
> 这两半天然对得上——数学从 Apache-2.0 库移植，参数表从国标取。

### ④ 但 Toolbox 的 GB 号多数**已废止** —— 这是两种口径的差别

`std.samr.gov.cn` 的公开 JSON 接口（**免登录、无 key、返回 JSON**）可以查任一标准号的全部版本与状态：

```
GET https://std.samr.gov.cn/gb/search/gbQueryPage?searchText=GB%2FT+5782&pageNumber=1&pageSize=20
→ {"total":3, "rows":[{C_STD_CODE:"GB/T 5782-2000", STATE:"废止"}, …, {C_STD_CODE:"GB/T 5782-2025", STATE:"现行"}]}
```

我抽了 40 个号做两种口径的核验：

| 口径 | 结果 | 含义 |
|---|---|---|
| **族口径**：该标准号有现行版本 | 现行 34 / 废止 3 / 未查到 2（**87.5%**） | 「这个族还有现行版」 |
| **版本口径**：Toolbox 记录的那个**年份版本本身**现行 | **现行 3 / 废止 10 / 查无此版 1（21%）** | 「Toolbox 这批件符合现行版吗」 |

### ⑥ 凸轮/槽轮从「无代码」翻案 —— 且不止是「有表有方程」

上一轮我说「凸轮族没有成熟开源实现，放一放」。**这一轮两翻**：

**第一次翻**（上一轮已完成）：有了表与方程
- 嘉立创 4-2-23：**凸轮从动件运动规律方程**（等速/等加速等减速/简谐/摆线 + 组合运动规律）
- 嘉立创 4-2-69/70：**槽轮完整几何计算式 + z=4~18 参数表**（λ、ζ、γ、rA 强度条件 rA≥0.175·pmax·Ed/b、j≤2z/(z−2)、运动系数 τ）

**第二次翻（本次）**：**连轮廓几何的代码也有了，而且是 MIT**

| 库 | 许可 | 覆盖 | 关键价值 |
|---|---|---|---|
| **mechanism**（PyPI v1.1.10） | **MIT** | 连杆分析 + **凸轮轮廓坐标 + SVAJ 图 + 滚子/平底从动件动画** + 直齿轮齿廓 | README 原话：凸轮坐标「可用于加工或导入 SolidWorks」——**与我们的 FeaturePlan 同构** |
| **pylinkage**（PyPI v1.3.0） | **MIT** | **平面连杆尺度综合**：Burmester + Freudenstein 经典综合 + PSO/差分进化优化；出 DXF/STEP | 覆盖 92%、有 Zenodo DOI（10.5281/zenodo.21207486） |
| **4bar_mechanism**（GitHub） | 未核 | 铰链四杆运动学分析 + **Grashof 判据** | 只做分析不做综合——正是我原先说「难」的那一半 |
| **pygeartrain**（GitHub） | MIT（转述） | 摆线/行星齿廓坐标导出到 CAD | 行星轮系缺的摆线齿廓那一块 |

**⇒ 结论改了：连杆与凸轮两族不再是「无代码」，而是「有 MIT 代码 + 缺国标口径」。**
缺的国标部分（运动规律表、许用应力表、槽轮参数表）都已在嘉立创手册里抓到，**接得上**。

**但一处性质差异必须记住**：pylinkage 用的是**元启发式优化**（PSO/差分进化）⇒ **同一输入的结果可能不唯一**。齿轮的生成是确定性的（参数 → 唯一几何），连杆综合是**多解搜索**——所以连杆族的溯源表必须能表达「这是 N 个候选之一，判据是什么」，不能套用齿轮那套「一个值 + 一个来源」的模型。

### ⑦ 同步带轮族解封：GB/T 11361-2018 现行且齿型表已抓

上一轮把它列为唯一阻塞，本轮核实并解决：

- **版本链（std.samr JSON 接口实测）**：GB/T 11361-**1989 废止** → **-2008 废止** → **-2018 现行**（2018-12-28 发布 / 2019-11-01 实施；2025-07-01 复审结论「继续有效」）。归口 TC428 全国带轮与带标准化技术委员会。
- **齿型尺寸表已抓到**：MXL / XL / L / H / XH / XXH 各自的 `bw`（节线宽）、`hg`（齿根高）、`rb`（底圆半径）、`rt`（齿顶圆半径）、`2δ`（齿槽宽）、齿形角 Ψ+1.5°；另有 T 型齿（T2.5/T5/T10/T20）的 S 型/N 型齿型尺寸；以及带轮外径极限偏差、端面圆跳动、平行度、锥度（0.001 mm/mm）、材质/粗糙度/平衡（按 GB/T 11357）、标记规则（`32GBH` = 齿数-带型号-轮宽代号）。
- **注意**：GB/T 11361 只管**梯形齿**（MXL…XXH + T 系列）。**GT2 / HTD / PowerGrip 属美欧体系，无国标可用**，不能用于中国图纸。

### ⑧ Toolbox 的 GB 号找到了，但它是「1990 年代末的快照」——两种口径必须分开说

- **更正我先前的错误**：我曾说「GB 一个标准号都没有」——错。那是因为只扫了项目自己的 `toolbox_index.json`（按零件名组织，天然无号）。对 `ToolboxFiles.index` 做**纯字符串扫描**（不反序列化 BinaryFormatter，与项目安全边界一致）得到 **305 个唯一 GB 号**。
- **★ 但版本口径严重过时**（实测抽样）：

| 口径 | 结果 | 含义 |
|---|---|---|
| 族口径（该标准号有现行版） | 34/40 = 87.5% | 「这个族还在」 |
| **版本口径（Toolbox 记的那个年份版本本身现行）** | **3/14 = 21%** | 「它给的那一版还能用吗」 |

  逐条实测：GB/T 5782 挂 **-2000**（现行 -2025）、70.1 挂 **-2000**（现行 -2008）、276 挂 **-1994**（现行 -2013）、97.1 挂 **-1985**（现行 -2002）。
- **结论**：Toolbox 可作**「GB/T 号 → 零件文件」映射的第一手来源**（省掉人工查表），也可作几何起点；**不可作合规依据**。
- **一处未能核实**：队友报告的「SQLite 里 996 张 GB_* 表」——**本机全盘找不到任何 SQLite/db 文件**（只有 `ToolboxFiles.index` 一个二进制 + swScheduler 调度库）。该数字记为**未查证**。

### ⑨ ★ 嘉立创的授权边界查到了，有一条直接影响我们的用法

《嘉立创机电工坊授权许可协议》原文（已抓取存档）三条关键约束：

1. **「本授权仅限您自身使用，未经创作者及我们书面同意，您不得将本机械图纸、本授权再向第三方授权、转让、共享、租售等。」**
2. **「本协议项下的授权仅对机电工坊社区对应的机械图纸有效，不包含对应的衍生品、改作品或其他途径参考、源引的项目。」**
3. 机械图纸按**单件标注的 CC 协议类型**（CC0 / CC BY / CC BY-SA / CC BY-NC / CC BY-NC-SA）授权；未标 NC 的可商用，未标 ND 的可改作。

**★ 关键未决点**：协议规约的是「**机械图纸**」这一物（描述设计、尺寸、材料、制造工艺的图形化技术文档），**而手册网页版的表格数据是否属于「机械图纸」，协议文本未明示**。按字面读，第 2 条「其他途径参考、源引」也会被排除。

**⇒ 这是必须由业主/法务拍板的事项，不是技术判断。** 在拍板前，我们的用法只能是：**在线查阅 + 自己按标准号回查原文**，不做「把表打包进我们的库」。

**★ 这解释了为什么「本地有 5,725 份国标」对机械族帮助有限**：下载通道被版权挡在门外，**而机械类恰好是采标最深的领域**（齿轮、紧固件、公差、密封、带轮全在 ISO 体系里）。

**★ 同时也解释了嘉立创手册为什么有价值**：**它整理的是国标数值，而采标封锁挡不住第三方转录。**

**绕行方案（代价递增）**：
1. **本地 PDF**——对非采标件有效（弹簧全套、型钢、铝型材、硬度、形位公差、轴承外形、直线轴承、优质碳素结构钢），对采标件无效；
2. **英文 ISO/ASME 原版**——采标国标正文就是翻译件，**尺寸数值一致**，但**表述与术语是国标自己的，不可混用**；
3. **对 PDF 做 OCR**——本机有 OXR（GPU）文本抽取能力，可转纸质标准书或授权 PDF；
4. **商业渠道**——标准书店购买正版，或用厂商/第三方选型图（如同步带轮齿型表）。

> **⚠ 但无论走哪条，「符合国标」的声明只能以国标为准。** ISO 原文只能给数值。

**★ 本地库带来的两个直接可用成果**：

本机已有 `D:\Agent-Studio\Deepseek-Harness\DSH-Data\标准\🇨🇳《国家标准》(35000+ 141G)`，内含 **5,725 份已校验的国标全文**（openstd 5,197 + 水利部 326 + 环保部 130 + 气象局 72 等通道）。

**机制**：openstd 对采标标准的详情页会显示「该标准采用了 ISO、IEC 等国际国外组织的标准，由于涉及版权保护问题，本系统暂不提供在线阅读服务」——**版权把下载通道挡在门外，而机械类恰好是采标最深的领域。**

**⇒ 这解释了嘉立创手册为什么有价值**：它整理的是**国标数值**，而采标封锁挡不住第三方转录。

**⇒ 也给出采标件的绕行方案（代价递增）**：
1. 本机 PDF（仅非采标件可用）；
2. **英文 ISO/ASME 原版**——采标国标正文就是翻译件，**数值一致**（但术语是国标自己的，混用会出错）；
3. **PDF → OCR**（本机 OXR/GPU 能力可用）；
4. 商业渠道（正版标准书店、或厂商/第三方选型图）。

**无论哪条，「符合国标」的声明只能以国标为准。**

## 1.5 ★ 复核总账（规矩五·账二）

**方法**：把 70 个对象 `gb` 字段里出现的**每一个标准号**（共 76 个）逐个送到 `std.samr.gov.cn` 的 JSON 接口独立查询现行版，不复用任何已有结论。脚本 `_recheck.py` 可复跑，结果落 `_recheck_result.json`。

### 复核抓到的三条真错误（已修进 all-objects.jsonl）

| # | 原写法 | 实测现行版 | 处置 |
|---|---|---|---|
| 1 | **GB/T 1239.6-1992**（弹簧许用应力） | **GB/T 23935-2009《圆柱螺旋弹簧设计计算》**（2009-11-01 实施，**全部代替** 1239.6-1992；2025-07 复审结论『修订』，计划 20251402-T-469 征求意见中） | 已替换；新增 `gbt23935-spring` 对象 |
| 2 | **JB/T 5513-1991**（SWC 万向联轴器） | **JB/T 5513-2006**（2007-05-01 实施，代替 1991 版） | 已替换；新增 `jbt5513-2006` 对象 |
| 3 | **GB/T 1243-2006**（滚子链链轮） | **GB/T 1243-2024** | 已替换 |

> **★ 这三条错误有一个共同来源：嘉立创手册的这两页用的正是废止版标准号。**
> 也就是说——**「手册是国标口径」不等于「手册用的版本是现行的」**。手册是快照，标准会换版。

### 两个「无法核实」也如实记了

| 项 | 实测 | 处置 |
|---|---|---|
| **GB/T 11294** | 精确查 total=0；模糊搜 `11294` 只返回 GB 21520-2015（废止） | **编号形式存疑，不猜**。冷弯型钢的现行相关标准另见 GB/T 6723（通用冷弯开口型钢）、GB/T 6728（结构用冷弯空心型钢） |
| **JB/T 5513** | 用国标接口 `/gb/search/` 查行标 → 无匹配 | **不是标准不存在，是查错了接口**：行标走 `/hb/search/`，已验 JB/T 5513-2006 现行 |

### ★★ 由此得到一条流程结论

> **凡引用国标，必须先过一遍「现行版查询」，再决定引用哪一版。**
>
> 顺序不能反：**① 查现行版 → ② 取该版数据 → ③ 标注版本号**。
> 我们此前把「手册里写的是什么」当成了「现行的是什么」——这正是 error 1.4% 的来源。

（脚本 `_recheck.py` 已把这条固化：任何人往 `all-objects.jsonl` 增删对象后，重跑一遍即可。）

7. ★ **「GB/T 3094 = 优质碳素结构钢」——错**，3094 实为《冷拔异型钢管》；优质碳素结构钢是 **GB/T 699-2015**
8. ★ **本地国标库对机械族帮助有限——原以为是「下载不全」，实为「采标封锁」**：缺口与采标 100% 重合（§0 ⑩）

**五条错误都指向同一个方法缺陷：结论下得比证据快。** 修正办法已固化为两个可复跑脚本：
`_recheck.py`（标准号现行版核验）与 `_verify_gb_versions.py`（Toolbox 版本口径审计）。
**以后每个数字都要能复跑。**
