# 嘉立创 FA 插件：模型链反推 —— 最终结论

实测 2026-11-05 · 全程只读，未修改任何厂商文件

---

## 0. 结论：反推不通，而且**账面上根本算不过来**

三条路我都试到了底：

| 路 | 结果 |
|---|---|
| **A. 库内反查**（型号 → zip） | ❌ ID 量级不重叠，0 命中 |
| **B. 短码对撞**（zip 内短名 ∩ 产品短码） | ❌ 17 / 9,485 = **0.2%** |
| **C. 解 zip 读配置** | ❌ **zip 是 WinZip AES 加密的** |

**C 是决定性的**：`compress_type=99`（WinZip AES）+ 加密标志置位，`zipfile.read()` 直接抛
`RuntimeError: File 'GXPA.SLDPRT' is encrypted, password required for extraction`。

**⇒ 这条路必须解密才能走。而解密不是技术问题，是红线问题。**

---

## 1. 三处硬证据

### ① 两套 ID 量级不重叠

```
model/*.zip 文件名         1.08 – 1.42 ×10^18
库内雪花 ID（产品/型号）     1.57 – 2.10 ×10^18
```

不是「查不到」，是**区间不相交**——zip 名来自第三方厂商模型库，跟嘉立创自己的 ID 体系没关系。

### ② 0.2% 的命中恰好是自建件

17 个命中的全是气动件（亚德客 AIRTAC 电磁阀、真空吸盘、气动滑台）——嘉立创自有品牌。第三方厂商件（HIWIN、THK、米思米系）一个都对不上。

### ③ `model/` 是加密缓存，不是明文

```
1083444093834494145.zip → GXPA.SLDPRT
  compress_type=99 (WinZip AES)  flag=0x0801 (encrypted)
  file_size=283,648  compress_size=120,997
```

## 3. 一个附带发现，可能比反推更值钱

这 14 个件的**文件头**全是 `XX XX XX XX 00 00 00 04` 这种形式——**不是 OLE2**
（`D0CF11E0A1B11AE1`），说明它们是 **SolidWorks 2015+ 的新压缩格式**。

而项目自己的 `sw_toolbox_index.py` 里写过一句：Toolbox 的 `.index` 是 BinaryFormatter，
**故意不解析以避免反序列化风险**。这两件事加起来说明：

> **SolidWorks 原生文件的内部结构读不了，但只要有 SolidWorks，就能用 API 读出配置与尺寸。**

也就是说，**「读配置文件」这件事必须走 API，不能走二进制解析**——这跟前面 FeaturePlan 那条线的结论一致。

## 4. 四条还在的路（按代价排序）

| 路 | 做法 | 代价 | 覆盖 |
|---|---|---|---|
| **A** | 用现成 14 个明文件 | 零 | 14 个型号 |
| **B** | GUI 走一遍（`sw_jlcfa_*`） | 已有投入 | 全量 63,234 |
| **C** | **换成公开的替代源**（TraceParts / MISUMI / 3DCC） | 需接新源 | 看源 |
| **D** | 问嘉立创要授权/接口 | 商务 | 全量 |

**C 值得认真考虑**：既然嘉立创这边是加密墙，而前面调研已经确认 TraceParts 有正式 REST API、3DCC 有 SW 原生件——**绕开嘉立创，把「买件」这条路接到真正开放的源上，比啃加密包划算得多。**

---

## 5. 我必须说清楚的一件事

**反推 zip 这条路，到此为止。** 再往前走只有两个方向，都不是我该自行决定的：

1. **要密码**——`DB.zip` 与 `model/*.zip` 的密码在插件里，拿到就是解密厂商加密内容。**这属于红线，我不做。**
2. **继续走 GUI**——已经在做，能用，脆弱。它是**合法的**，因为那是插件自己的正常使用路径。

**所以我的建议是：GUI 保留（它是合法路径），但把工程重心转到 C（接开放源）。**
