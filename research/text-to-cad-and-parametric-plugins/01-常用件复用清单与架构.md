# 机械常用件：现成的「生成器 / 选型器」清单，与「AI 二次开发」的正确落点

调研日期：2026-11-04 · 档位 L2（主题横评）· 证据档：【一手】=官方文档/仓库/许可证原文；【转述】=二手；【推断】=我的判断

---

## 0. 先纠正一个前提：现成的东西有**两类**，不是一类

你说「现成的零件生成器拿来用」——这个方向对，但**必须先把两类分开**，否则会把不该复用的东西复用错：

| 类型 | 本质 | 输入 | 输出 | 典型 |
|---|---|---|---|---|
| **A. 生成器**（generator） | **算几何** | 几何参数（模数、齿数、压力角…） | 一个由公式决定的形体 | 齿轮、链轮、同步带轮、凸轮、弹簧、螺纹、花键、连杆曲线 |
| **B. 选型器**（selector） | **查表 + 决策** | 工况（功率、转速、载荷、寿命） | **从一个标准件目录里选出一个型号**，再取它的模型 | 轴承、联轴器、减速机、电机、导轨、丝杠、型材、密封件 |

**这个区分决定复用方式完全不同**：

- A 类复用的是**算法与公式**——你可以移植、可以重写、可以在 SolidWorks 里重建；错在数学，不在代码。
- B 类复用的是**目录数据与选型规则**——关键资产是**那张表**（型号 → 尺寸 → 额定值），几何只是表的附属。**自己算轴承内部几何是浪费，自己编选型规则是危险。**

一句话：**A 类别自己写几何，B 类别永远不要自己编数据。**

## 3. 四个复用模式，和它们的判据

### M1 原生驱动
直接用 SolidWorks 自带能力（Toolbox、焊件轮廓、钣金）或厂商接口（MISUMI API、TraceParts 下载）。
- **适合**：标准件、型材、管路、钣金。
- **代价**：受制于 Toolbox 的定性（「不是真渐开线」「近似螺纹」）和它的 PDM 坑。
- **注意**：`sw_toolbox_index.py` 的 docstring 已经写明——**Toolbox 索引不含「型号→尺寸」的工程数据**，尺寸是零件文件里的配置，**要拿尺寸得开文件读配置**。

### M2 算法移植 ★主力
**从现成库/标准表里取「数学与参数表」，在 SolidWorks 里用草图 + 特征重建**。
- 移植的是**公式**（渐开线参数方程、链轮齿廓圆弧、弹簧螺旋线），不是代码。
- 得到的模型**有特征树、全约束、可参数化重建**——满足项目 E1–E3。
- 项目里 `sw_gear.py` 就是这个模式：`SpurGearSpec` → 解析计算 → `outline_points_m` → 草图 → 拉伸。

### M3 外部 B-rep 生成 + STEP 导入
用 CadQuery/build123d 出 STEP，导入 SolidWorks。
- **只在「不需要特征树」时用**：比如装配体里的占位件、干涉检查用的简化件、渲染件。
- 原因见 §4。

### M4 只读思想
GPL/AGPL 的东西（FreeCAD Fasteners WB、Pyslvs）**只看它怎么解、不抄代码**。
- 与项目铁律 6 一致：AGPL/GPL 只读思想。

## 4. 一条硬约束：**STEP 导入会杀死参数化**

这是整份报告里最需要你先点头的一条。

STEP 进 SolidWorks 得到的是**哑实体**（dumb solid）：没有特征树、没有草图约束、没有参数、改一个齿数要从头再导一次。而项目的验收判据是 E1–E3（全约束 · 参数化可重建 · 特征树可编辑）。

**所以 M3 只能用在边角料上。** 主力必须是 M2：**复用别人的数学，在 SolidWorks 里重新长出特征树。**

这也解释了一个常见错觉：*「CadQuery 有现成的齿轮库，直接 `export_step` 不就行了」*——对一次性交付可以，对可交付的工程模型不行。

## 5. 架构：把 `sw_gear.py` 的模式推广成注册表

你已经有一个能工作的单体，缺的是**让它可复制**。契约长这样（五个位置，缺一不可）：

```
ComponentSpec      # 参数（带单位后缀，见项目「单位必须出现在名字里」铁律）
      ↓
validate()         # 参数域检查：根切、干涉、超出标准表、几何不可能 → 返回 warnings/errors
      ↓
compute()          # 纯数学：解析尺寸 + 轮廓点/表（不碰 COM，可单测）
      ↓
build(model)       # 在 SolidWorks 里重建：草图 → 特征 → 阵列
      ↓
evidence()         # 可序列化证据：输入、解析尺寸、近似方式、分段数、警告
```

**`sw_gear.py` 已经把这五段都实现了一遍**，包括 `evidence()` 里写明 `"root_form": "radial_transition_plus_root_arc"`（齿根是径向过渡 + 圆弧，不是滚刀 trochoid）——**这就是「知道自己哪里不精确」的正确做法**，应当成为所有族的强制字段。

注册表本身只要三件事：

1. `registry.py`：`register(family, spec_cls, compute, build)`；
2. `families.jsonl`：每族一行，写清「用哪个源、什么许可证、什么模式、缺什么」；
3. 一条**同构测试**：每个族都必须过同一组契约测试（参数域越界要报错、evidence 字段齐、不碰 COM 的纯函数可单测）。

## 6. 「AI 二次开发 → 又可靠又灵活」，哪部分成立，哪部分是陷阱

你的判断**方向是对的**，但要把「灵活」拆成五种，只有前四种能白拿：

| 灵活性来源 | AI 能不能做 | 可靠性影响 |
|---|---|---|
| ① **意图 → 参数**（「做个 2 模 24 齿、配 20 齿、中心距 45」→ spec） | ✅ 强项 | **不降低**：参数最终仍要过 `validate()` |
| ② **参数面扩张**（把封闭参数域打开：加变位、加修形、加自定义齿廓） | ✅ 能做，但产出是**代码**，要人验收 | 中：新增分支要有测试 |
| ③ **组合**（齿轮+轴+轴承+箱体 → 减速机；带轮+带 → 带传动） | ✅ 强项 | **不降低**：组合不改几何内核 |
| ④ **失败解释**（「为什么这个参数不行」） | ✅ 强项 | **提升**：把 warnings 翻成人话 |
| ⑤ **每次重写几何代码** | ⚠️ 能写，但**每次都是新的未测代码** | **灾难性降低** |

**陷阱就在这里**：如果「AI 二次开发」被理解成「每次让 AI 现写一段建模代码」，那你就把确定性内核换成了每次重新采样——**这正是本项目已经踩过的坑**：`sw_gear.py` 写完至今是 `stitched`，从没升到 `verified`。

**正确形态是「确定性内核 + AI 外壳」**：

```
用户说人话
   ↓  ← AI 只在这一层活动（翻译、选型、组合、解释）
[spec 参数集]
   ↓  ← 下面是同一段被测试覆盖的代码，AI 不改它
validate → compute → build → evidence
```

**灵活性来自「参数面和组合的扩张」，不来自「几何代码的重新生成」。** 这条守住了，就能同时拿到可靠和灵活；守不住，就是拿灵活换掉可靠。

## 7. 施工顺序：先做三个族，别一次铺开

### Pilot 1：把齿轮族做成「样板族」
- 把 `sw_gear.py` 从 `stitched` 推到 `verified`（真机跑通 + 尺寸回读），**这是它现在最缺的一步**。
- 按 `cq_gears` 的能力补齐：斜齿 → 内齿 → 齿条 → 锥齿（`cq_gears` 的数学可读，Apache-2.0，可移植）。
- 补 `profile_shift`（变位）——论坛上 GearTrax 被质疑的正是角变位，说明这是真需求点。
- 验收：同一 spec 两次构建 B-Rep 尺寸一致；齿廓与解析渐开线的最大偏差 ≤ 设定值（可用 `proto/exp_involute_arc_error.py` 的算法做判据）。

### Pilot 2：标准件族（M1）
- 走 `sw_toolbox_index` + `sw_misumi`：**选型 → 取文件 → 插入装配 → 回读尺寸**。
- 必须处理 Toolbox 的 PDM 坑（官方：每加一个配置生成一个新文件版本；PDM 下必须选 `Error when writing to a read-only document`）。
- 验收：给定一个型号字符串，能返回「文件路径 + 关键尺寸表」，且装配插入后不脱链。

### Pilot 3：带 / 链族（M2）
- 同步带轮与链轮的齿形都是**标准表 + 圆弧组合**，和齿轮同构但更简单。
- 现成的 OpenSCAD 生成器可读，用来对照参数集（不是抄代码——它们的许可证要逐件核）。
- 验收：齿数 → 节圆直径/外径/齿形，与标准表逐项对上。

**三族做通之后，剩下的族是「填表 + 移植」，不是「重新研究」。**

## 8. 不复现清单（Never hand-build）

下面这些，**任何时候都不要从零推**——要么有标准表，要么有现成库，自己推必错：

1. 螺纹牙型（三角/梯形/管螺纹）
2. 轴承内部几何（滚道、保持架）
3. 齿轮齿廓（渐开线、摆线、齿根 trochoid）
4. 链轮齿形（ANSI/DIN 齿槽形状）
5. 同步带轮齿形（GT2/HTD/T 系列）
6. 弹簧（有效圈数、端部形式、应力修正）
7. 密封件（O 圈沟槽、油封唇口）
8. 花键/键的配合尺寸表
9. 标准件的额定载荷/寿命数据（**必须来自厂商，不能算**）

**判据**：如果这个形状在标准手册里有表 → 抄表；如果没有表但有公式 → 用公式（M2）；如果两者都没有 → 才自己推，并且必须在 `evidence()` 里写明依据。

## 11. 一句话

> **现成的东西不是「一堆零件模型」，是「一批公式和一批表」。**
> 复用公式（M2）、复用表（M1）、只读 GPL 的思想（M4）、少用 STEP 导入（M3）——
> 然后把 AI 严格关在最上面那一层：**它翻译意图、扩张参数面、组合件、解释失败，但永不重写几何内核。**
> 这样才是「又可靠又灵活」，而不是「用灵活把可靠换掉」。
