## 2. 五个设计决定（都是有代价的选择）

### ① 纯几何，不碰 COM
`derive()` 全程不调 SolidWorks，所以可以单测、可以在 CI 里跑、可以在没有 SW 的机器上跑。
**代价**：生成的参数还没变成模型，中间少一段验证（建模那条线以后接）。

### ② 用归档实现做交叉校验
`d = m·z` 我自己算一遍，再调归档的 `calculate_external_spur_gear()` 算一遍，两个数一致才写「交叉校验一致」进表。

> 表里那一行是 `d = m·z；与归档实现 calculate_external_spur_gear 交叉校验一致`

**这是项目「三源互证」在方法层的落地**：同一个数有两个独立来源，才敢写进报告。

### ③ 无解不抛异常，返回可读诊断
```python
d = derive(GearRequest(ratio=3.0, center_mm=30.0))
d.ok            # False
d.diagnostics   # "最接近的可行组合是 m=1/z1=17/z2=51→a=34.00（差 +4.00 mm）…"
```
**不抛异常的原因**：Agent 需要读失败理由再调参，异常会打断这个循环。

### ④ 判据必须显式，不许隐含
`z_min_policy` 是一个参数，两种口径都进表、都写依据。

### ⑤ 未覆盖项强制出现在输出末尾
`render()` 一定会打印【未覆盖】段。**没有这一段，报告就变成了推销。**

## 3. 跑出来一个真问题：z_min 到底是 17 还是 18

| 来源 | 值 | 怎么来的 |
|---|---|---|
| 本机知识库 `直齿圆柱齿轮选型.md` | **17** | 教科书口径 |
| 归档实现 `sw_gear.py` L211 | **18** | `ceil(2/sin²20°) = ceil(17.097) = 18` |

**差一个齿，可行解集合就不一样**：z1=17 和 z1=18 在中心距上差 2 mm。

这就是「同一个判据在两个地方各写一份」的典型后果——**而且谁都没错**：精确极限是 17.097，取 17 是允许轻微根切，取 18 是严格不根切。

**处置**：做成 `z_min_policy` 显式参数，默认 `"kb"`（17），并在表里写清来源。
**建议**：统一到 17，把归档实现改成 17 并在注释里写明 17.097 这个精确值的取整差异。

## 4. 已知缺陷（v0 不掩盖的）

| 缺陷 | 影响 |
|---|---|
| 模数只搜 1~10 | 大模数重载齿轮搜不到 |
| 中心距容差 ±0.75 mm 硬编码 | 应按厂内加工能力配置 |
| 只支持 x=0（标准全齿高） | 行星轮系与凑中心距场合大量需要变位 |
| 无 bore / hub / 键槽 | 只是齿坯，不是零件 |
| warnings 文案直接继承归档实现 | 措辞未审 |
| 强度全缺 | **最大的一条** |

## 5. 下一步三步（按顺序，别并行）

### S1 齿形族扩展：斜齿 → 内齿 → 齿条
- 数学来源：`cq_gears`（**Apache-2.0**，可移植，需在文件头留来源）
- 验收：斜齿 β=15°/30° 的端面/法面模数换算、当量齿数、重合度（端面+纵向）逐项对上；
  内齿的齿顶/齿根圆方向与直齿相反——**这是最容易写反的一处**

### S2 强度层：把【未覆盖】第一条填掉
- 材料与热处理 → [σH]/[σF]（知识库 `70-标准件与选型计算/` + `material_db.yaml`）
- 工况 → K_A/K_V/K_α/K_β
- 反算模数 → 向上取标准值 → **与 S1 的几何推导合并**
- 验收：给定 P、n、i，反算的 m 与知识库样例一致（KB 里已有 z1=20/z2=40/m=3 的实算）

### S3 语义层接线
- `questions()` 从 `params.jsonl` 加载（不硬编码文案）
- 接 L4–L0，按「不知道 / 你定」两种信号分流
- 验收：同一需求，客户路径与工程师路径产出**同一份 rows**，只有措辞不同
