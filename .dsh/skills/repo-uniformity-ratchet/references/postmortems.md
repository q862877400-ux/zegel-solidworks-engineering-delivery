# 留档：我自己制造的回归

配套 `SKILL.md`。**统一化最大的风险不是「没改完」，是「改坏了但门禁是绿的」。** 下面每一条都是真发生过的，且大多在 `ast.parse` 通过之后才暴露。

写报告时这一节必须留 —— 不留等于把坑留给下一轮。

## 1. 批量折行吃掉机器可读指令

- **现象**：按显示宽度折了 121 处注释后，`check_dispatch_byref_guard` 的已核调用点 **323 → 315**，`check_create_definition_site_disposition` 报 2 处未声明站点。
- **根因**：被折的注释里有 `#: dispatch-arg:` / `#: cd-site:` 这类**机器可读指令**，它们靠「一行」承载语义。折行把一行变成两行，第二行不再被解析。
- **规避点**：★ **折行不是纯格式操作。** 通用排除：`^#:\s*[a-z][a-z0-9-]*:` 一律不动。改完**必须重跑所有读注释的门禁**，不能只看 lint。

## 2. 折行脚本把代码吃成注释

- **现象**：45 个 `IndentationError` + 108 处内容违规。
- **根因**：脚本用 tokenize 拿 `COMMENT` token，然后拿 `tok.start[1]` 去索引**整行**并按注释重建。行尾注释所在行的前面还有代码 ⇒ `return None  # 说明` 被重建成 `# eturn None`，**代码消失**。
- **规避点**：只处理 `tok.start[1] == 该行缩进长度` 的行（即整行都是注释）。★ 批量脚本先在小样本上 `git diff` 看一遍再全量跑。

## 3. `ruff format` 静默缩小了门禁覆盖

- **现象**：`ruff format scripts/` 之后，`check_create_definition_site_disposition` 报的站点数 **8 → 6**（数字变小，看起来是「问题变少了」）。
- **根因**：那个门禁的 `cd_calls` 是**行级正则**，format 把一行调用拆成多行后正则不匹配 ⇒ 2 个站点从扫描里**消失了**。
- **规避点**：★ 门禁里凡是「按行找调用」的地方都必须改 AST（`ast.get_source_segment` + 参数节点定位）。改完验证：format 前后站点数**不变**。★ **读数变小要当成警报**，不是成果。

## 4. α-重命名改写了原始 AST

- **现象**：⑤ 的重复组明细里出现 `@@F@@` 之类的占位符标签，分组无法辨认。
- **根因**：`_dup_functions` 在同一棵树上**边遍历边哈希**。哈希外层函数时把它内嵌函数的形参/局部名就地改成了占位符，稍后单独处理那个内嵌函数时读到的已经是改过的名字。
- **规避点**：变换前 `copy.deepcopy(node)`。★ 任何「遍历 + 变换」混在一起的分析器都要先问一句「我改的是谁的树」。

## 5. 改名只改了一半

- **现象**：5 个新 `F821`（undefined name）。
- **根因**：把 `Path as _P` 换成 `Path as _p` 时，替换规则写了 `_P.` 和 `import ... as _P`，漏了裸 `_P`（如 `dict[_P, ...]`）。
- **规避点**：用词边界正则 `\b_P\b`，且**改完真跑**这三个文件（import 一把）。★ 这也顺手把一条「风格违规」变成了真 bug —— 说明批量改名是高危操作，宁少勿多。

## 6. 模块级绑定绑到了函数内 lazy import

- **现象**：`capture_front = sw_gui_modal.screen_png` 在模块加载时抛 `NameError`。
- **根因**：那个模块是**函数内延迟导入**（`_modal()` 里才 import），模块级没有这个属性。`ast.parse` 当然通过 —— 名字解析是运行期的事。
- **规避点**：写一层薄适配 `def capture_front(path): return _modal().screen_png(path)`。★ **`ast.parse` 通过对名字解析零证明**；凡是新写「模块级引用另一个模块的属性」，都要真的 import 一次。

## 7. `%`-format 里的全角右括号

- **现象**：运行期 `ValueError: unsupported format character '?' (0xff09)`。
- **根因**：格式串写成 `（%）` —— 全角右括号不结束格式占位符，`%` 后面跟了个非法字符。
- **规避点**：改成 `（%r）` 这类**完整占位符**；改完**真的执行一次那句 format**。★ 中文代码库里全角括号与 `%`/`f` 相邻是高发区。

## 8. `edit` 吞掉下一个 `def`

- **现象**：`NameError: name '_run_tools_index_fresh_gate' is not defined` —— 一道门禁整个消失。
- **根因**：`edit` 的 `old_string` 结尾多带了一行下一个 `def` 的开头，而 `new_string` 没带 ⇒ 那行被删掉，函数体接到了上一个函数里。
- **规避点**：★ **`old_string` 不要包含紧随其后的下一行 `def`**；改完对目标文件跑 `ast.parse` + 真跑那次校验。

## 9. 把「净收益大」当成「该做」

- **现象**：292 条 `%` → f-string 转换，同目录读数**净只降 13**。
- **根因**：f-string 是**一整条 token**，formatter 拆不开；`%`-格式是多个 token，能折行。中文 + 88 列 + 全转 f-string 三者不可同时满足。
- **规避点**：★ 大批量转换前先做**一批试点 + 量净收益**，别按「转换条数」估效果。试点净收益不达标就退判据（并留档），不要硬做完。

## 通用定则

1. **每次批量改动的自查四道**：`git diff --numstat` 逐文件 → 逐条核对删除行 → 内容守恒（`git show HEAD:<path>` 对比）→ `ast.parse` 全部 `.py`。**有 deletions 就当成自己的 bug 查。**
2. **四道之后还要真跑**：import 模块 / 调用函数 / 点一次 UI / 截图。
3. **读数变小先怀疑尺子**，读数变大先怀疑宽度口径。
4. **同一个启发式连续修补 ≥3 次还「看起来对了」** → 回退 + 把证据写进文档，不要继续调。
5. **提交一律走本仓 commit 协议**（不裸 `git commit -m "<多行>"`）；批量脚本造成删除时按协议显式声明。
