# 五条指标：实现要点、假阳性、裁决分类

配套 `SKILL.md`。这里记的是「尺子怎么做才准」，不是「怎么做才好看」。

## 一条命令的形态

```
python scripts/check_repo_uniformity.py     # exit 0 = 全部通过；非 0 = 有指标超天花板
```

读三样东西：① 每项读数；② 每项天花板（基线）；③ 分组明细（哪几组重复、哪几个文件缺块）。
只读总量看不出下一步做什么，**明细才是工作队列**。

## ① ruff（命名 / 导入 / 循环依赖）

```
ruff check --select E,F,I,N,UP --ignore UP031 --output-format concise <扫描根>
```

**实现要点**

- 扫描根只取**活代码**（SW 仓：`scripts`、`tools`、`mcp-server`），排除构建副本（`resources/skill`）、缓存（`__pycache__`）、归档（`archive`）。★ 把构建副本计进去，读数会随打包次数跳动，尺子立刻失效。
- 子进程必须给 `encoding="utf-8", errors="replace"` —— 中文 Windows 上父进程默认用 GBK 解 UTF-8，会 `UnicodeDecodeError` 而 `stdout` 变 `None`，错误信息指向不了真因。
- 工具不存在时 **FAIL 并说明**，不跳过。

**两档 E501（本仓判据修正）**

- 代码行按 ruff 的 88 列；**散文行（docstring / 长字符串 / 注释）按 120 列**。
- 判「这行是散文还是代码」必须 **tokenize**，不能按「行内有没有 `#`」猜。
- 宽度用**显示宽度**：`unicodedata.east_asian_width(c) in ("W","F")` 的字符算 2 列。★ 本仓一次实测：换了显示宽度后读数从 26,373 变 26,416 —— **按字符数计量会让中文代码库的读数一改就涨**。
- 依据：6,500 条 E501 里 99.6% 是中文散文；88 显示列 ≈ 44 个汉字。

**`UP031` 已退出**：见 `SKILL.md` 的「判据修正」。

## ② pyscn（行块级克隆） —— 信息项

```
pyscn analyze --select clones <扫描根>
```

**实现要点**

- pyscn 对**排版敏感**。为了让「复制到临时目录再规整排版」不改变读数，SW 仓的做法是先 `ast.unparse` 成规范副本再扫（`_canonical_copy`），使读数与排版解耦。
- ★ 即使这样，它仍随每次纯格式改动上下跳：`ruff format` +194、docstring 折行 +39、558 个改名 +39。⇒ **降为信息项**，继续打印、不决定 exit code，并在代码注释里写清降级原因与三次实测数字。

**为什么必须保留**：它是唯一带 Type 1–4 分类的工业级克隆检测，语义级重复（Type 3/4）只有它能给。只是不能拿它当棘轮。

## ③ 契约块（来源块 / 头注释）

自写扫描：每个 `.py` 的文件头必须有本仓规定的那段结构化块（SW 仓：`# ── 来源 ──` 起，六字段 仓库/文件/定位/官方依据/许可/覆盖）。

**为什么能归零**：它是**可批量补齐**的（一次性补 75 个文件），补完守 0 成本极低。⇒ 这类指标不当棘轮，直接要求 **= 0**。

★ 批量补块本身是「只做加法」的操作，但仍要走守恒自查：删除行必须全部是空行/原注释，其他 0 处。

## ④ 跨目录同名文件

自写扫描：同一文件名出现在两个及以上目录 = 重复实现嫌疑。

**为什么能归零**：真重复删一份；真「兼容入口」（转发壳）**登记豁免并写明它转发到哪里**。SW 仓的 `drawing_spec.py` 就是 25 行 `importlib` 转发壳，删了会 `ImportError`。

## ⑤ 跨文件同函数体（最重要，必须自写）

**算法**

1. `ast.parse` 每个文件，遍历所有 `FunctionDef` / `AsyncFunctionDef`。
2. 去 docstring（`node.body` 首元素是常量字符串就丢）。
3. **α-重命名**：只把**局部绑定名**（形参名 + 函数体内绑定的 `Name`）抹成同一占位符；
   **保留**全局引用、常量名、属性名（`.attr` 后面的不动）。
4. `ast.dump` / `ast.unparse` 归一化后取哈希，跨文件同哈希即成组。

**必须注意的三个实现坑**

- ★ **变换前 `copy.deepcopy`**。遍历与哈希用的是同一棵树，就地改名会污染外层函数的组标签（本仓真的踩过：外层函数被哈希时，内嵌函数名已经变成占位符）。
- ★ 局部名字的判定要正确：`for`/`with`/`except`/`import`/赋值目标/推导式变量都是局部的；闭包外层变量不是。
- ★ 宽严校准用**已知正反例**（见 `SKILL.md`），不要凭感觉调。

**裁决分类**（每组必须落进一类）

| 类 | 处置 |
|---|---|
| 真重复（生产代码、同语义） | 收敛到一处，调用点改导入 |
| 转发壳（薄薄一层转调） | 保留；若同名跨目录则登记豁免 |
| 同形不同语义（如各模块的 `main()`/`check()`/`scan()`） | 保留，记「同签名不同语义」 |
| 同代码不同目标（各自读 `__file__` 做自证） | 保留 —— 合并会让自证变成永久假通过 |
| 门禁抓手（dispatch 类本地 `def`） | 保留 —— 见 `negative-verdicts.md` |
| 生成模板的一部分（如 12 个纯抄录文件的 `_require`） | 保留 —— 手改会被下次重生成覆盖 |
| 一次性探针脚本 | 保留（各自独立可跑），但**继续计入基线**，不登记豁免去美化数字 |

## 读数怎么比

- 同一棵树跑两次必须同数；不同树的数只在「本次改动」范围内比较。
- **出现「读数不降反涨」时先怀疑尺子**：宽度口径、工具版本、扫描根、临时副本规整度。
- 每次降低都写进基线的 `_★下调记录`；**收口时天花板 == 实测**。
