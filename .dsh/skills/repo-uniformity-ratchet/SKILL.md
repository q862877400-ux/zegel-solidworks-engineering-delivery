# 仓库统一化棘轮

目标是**整体只有一个口径**：同一个功能只有一份实现，同一个东西只有一个名字，同一类违规只有一条判据。局部整洁是副产品，不是目标。

判据只有一条：**读数在降，且每降一次都有留档。** 感觉「更整齐了」不算。

## 何时用

- 业主说「整个项目要统一化/规范化」「避免局部整洁但整体混乱」「同一个功能多个函数重复实现」「同一个东西不同地方命名不一样」。
- 接手一个仓，门禁很多但各管一摊，得先知道整体到底干不干净。
- 有一大批「风格存量」（成千上万条 lint 违规、上百组重复代码），要可验证地往下削。

## 第 0 步：先造尺子，不要先改代码

判据必须先用数字读得出来，否则做的每件事都无法证明是改进。

★ 反例（SW 仓实测）：那仓已有 50+ 道门禁，**没有一道在看全局一致性**；本机 ruff/flake8/pylint/mypy 一个都没装，也没有 `ruff.toml` / `setup.cfg`。⇒ 若先动手改代码，改完只能说「我觉得整齐了」，说不出「26,378 → 415」。

尺子要同时满足四条，缺一条就不可信：

1. **一条命令出全部读数**，exit code 即判据（接进现有 release gate，不靠人记得跑）。
2. **每条指标能指回权威源**（见下），不自定义标准。
3. **工具不可用时 FAIL，不静默跳过** —— 静默跳过与没跑等价。
4. **读数是幂等的**：同一棵树跑两次同一个数（否则不能比大小）。

## 判据：只接线，不发明

| # | 指标 | 权威出处 | 机械执行 |
|---|---|---|---|
| ① | 命名 / 导入 / 循环依赖 | [Google Python Style Guide](https://google.github.io/styleguide/pyguide.html)（snake_case·PascalCase·导入分组·循环依赖是 code smell） | `ruff --select E,F,I,N,UP` |
| ② | 重复代码（行块级） | [pyscn](https://github.com/ludo-technologies/pyscn) Type 1–4 克隆检测 | `pyscn analyze --select clones` |
| ③ | 本仓文件契约（来源块/头注释） | 本仓 `AGENTS.md` 对应条款 | 自写扫描 |
| ④ | 跨目录同名文件 | 本仓结构白名单条款引申 | 自写扫描 |
| ⑤ | **跨文件同函数体** | Type-2 克隆（重命名标识符后相同），出处同 ② | 自写 AST 归一化哈希 |

★★ ⑤ 是最关键的一条，也是**必须自己写**的一条：② 按行块判，上千组里绝大多数是样板（探针样例、声明式元数据、来源块），噪声大到无法逐组裁决；⑤ 按**函数体**判，组数少一个量级，**直接对准业主的头号关切「同一个功能多个函数重复实现」**。

⑤ 的口径必须是 **α-等价**，不是逐字相等：
- 去 docstring；把**局部绑定名**（`Name` 与形参名）抹成同一占位符；**保留**全局引用与属性名。
- 同文件同名不算（那是重载），只报**跨文件**。
- 判断依据要用**已知正反例校准**：两个「改名后逐字相同」的小工具函数 → 该判重复；已经参数化好的薄转发壳 → 不该判重复；两个 dataclass 的 `__post_init__`（同形不同字段表）→ 不该判重复。

## 基线纪律（棘轮）

基线文件只记**天花板**，不记历史。

- **只许降，不许升。** 每次降低都往 `_★下调记录` 追加一条 `{at, from, to, why}`。门禁判「读数 ≤ 天花板」，超了就是回归。
- **收口时零松弛**：天花板 == 实测值。留余量等于给下一轮发许可证。
- **豁免必须举证**：每条豁免（`allow`）写全 `functions` / `files` / `verdict` / `reason`（≥100 字，说明为什么统一反而更差）/ `evidence`（可复跑的测量）。没有 evidence 的豁免就是放宽。
- **不登记豁免 ≠ 已解决**：暂缓项继续计入基线（它仍是真重复），另外记「待裁决 + 理由」。

## 每轮循环

```
① 跑尺子，读绝对值与分组分布
② 挑「最大且可验证」的一块（不是最容易的一块）
③ 小批改（一批只动一类东西，能一次回滚）
④ 守恒自查（事实 61 四道，见下）
⑤ 重跑尺子 + 相关门禁 + 真跑（不是只 ast.parse）
⑥ 降基线 + 写进报告（含读数、裁决、踩的坑）
⑦ 提交（走本仓 commit 协议）
```

**守恒自查（批量改动必做，四道）：**

1. `git diff --numstat` 逐文件核对规模 —— **出现 deletions 就当成自己的 bug 查**。
2. 逐条核对删除行：必须全部是注释 / 头注释块 / 被合并的函数体，**其他 0 处**。
3. 内容守恒：对既有文件取 `git show HEAD:<path>` 去空白后与现文对比，正文逐字相同。
4. `ast.parse` / `compileall` 全部 `.py`。

★ 这四道是**被事故证明过**的：一个「括号配对 + 就地插入」的脚本制造过 `5 insertions(+), 232 deletions(-)` —— 整个函数连 232 行消失。

★ 第 4 道之后**还必须真跑**：`ast.parse` 通过对「名字解析」与「运行期行为」零证明。见 `references/postmortems.md`。

## 两类裁决，都要实测

### A. 统一反而更差 → 判「不统一」，登记否定裁决

去重不是最高目标。**验证能力 > 去重收益。** 有些「重复」是门禁的抓手：把两份本地 `def` 换成一处导入，等于把「逐条核验每个调用点传进去的成员名」的核验面拿掉了。

★ 实测两次都成立：`_optional_com_member`/`_safe_com_member` 统一后已核调用点 323 → 302（−21）；`_checked` 统一后 327 → 317（−10）、可解析分发口 18 → 16、分发口 37 → 36、不可见 84 → 83 —— 四项棘轮同时破。

⇒ 规约：**动任何 dispatch 类辅助函数之前，先记下这些计数，改完复验；掉一个数就回滚。** 回滚 + 登记否定裁决（带 reason + evidence）比「统一了但核验面变小」正确。详见 `references/negative-verdicts.md`。

### B. 判据本身有冲突 → 改判据，但要有数

判据相冲时不改判据就永远做不完，改了又像在放水。**唯一合法的改法：量出来。**

本仓两次都留了数：
- `E501` 改**两档**（代码行 88 显示列 / 散文行 120 显示列）：6,500 条 E501 里 **99.6% 是中文散文**，而按显示宽度算 88 列 = 44 个汉字。
- `UP031`（`%` → f-string）**退出判据**：292 条转换实测**净只降 13** —— f-string 是一整条 token，formatter 拆不开；`%`-格式能折行。⇒ 中文 + 88 列 + 全转 f-string 三者不可同时满足。

### C. 一个指标噪声太大 → 降为信息项，但继续打印

②（行块克隆）在**每一次纯格式改动下都会涨**：`ruff format` +194、docstring 折行 +39、558 个改名 +39。它衡量的不是「重复实现」。⇒ 保留打印、不再决定 exit code，并在代码注释里写明「降级原因 + 三次实测数字」。**降级要留档，否则下一轮会以为它一直是软指标。**

## 收尾判据

- 尺子 exit 0，且**每一项读数都等于基线天花板**（零松弛）。
- 跨目录同名文件、缺契约块这类「可归零」指标必须是 **0**，不许有存量。
- 重复实现只剩两类：**登记了 evidence 的豁免**，和**明确暂缓且继续计入基线**的（附理由）。
- 报告（`docs/repo-uniformity-report.md` 形态）逐轮留档：读数表、裁决、**我自己制造并修掉的回归**。不留回归记录的报告等于把坑留给下一轮。
- 接进 release gate 并验证**真的会拦**：用 `git show <修复前>:<path>` 取回原文当负例，证明门禁抓得到它真正要抓的形态。

## 反模式

- ❌ 先改代码后造尺子 —— 无法证明任何改进。
- ❌ 把天花板往上抬一格让门禁过。
- ❌ 用「行数/字符数」判宽度 —— 中文代码库必须用 `unicodedata.east_asian_width` 算显示列，否则一改就涨。
- ❌ 批量折行当成纯格式操作 —— 会吃掉 `#:` 之类机器可读指令（本仓一次丢掉 8 个调用点的核验）。
- ❌ 只看 `ast.parse` 就宣布完成 —— 名字解析、函数内 lazy import、`%`-format 全角字符都只在真跑时暴露。
- ❌ 同一个启发式连续修补 ≥3 次「看起来对了」—— 停下回退 + 留证据。
- ❌ 只在门禁里写好用的工具函数，修复脚本里另写一套。
