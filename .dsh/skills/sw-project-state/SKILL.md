# 项目现状台账：怎么读、怎么复核、怎么续记

## 一、三条命令上手（不要通读仓库）

```powershell
cd <仓库根>
Get-Content docs\state\INDEX.md | Select-Object -First 60        # ① 导航：想知道 X → 去哪看
python docs\state\probes\probe_all_specs.py                       # ② 任一维度读数可当场复现
Get-ChildItem docs\state\facts                                   # ③ 15 份事实文件
```

## 二、这套台账是什么

- `docs/state/INDEX.md` —— **入口**：两张导航表（第一轮 A–J 结构信号 / 第二轮 K–O 可证伪的对应关系），
  外加「每个维度最承重的一条读数」与「同一件事、多个读数」对照表。
- `docs/state/facts/<X>-*.md` —— 15 份事实文件，每条含：**观测方式 / 读数 / 证据 / 复现命令 / 未确认**。
- `docs/state/probes/*.py` —— 16 个只读探测器，**每个读数都能一条命令重算**。
- `docs/state/inventory-*.json` —— 机器可读原始读数。
- `docs/state/doc-map.md` —— 232 份文档 × 四个信号（最后提交日 / 被引用数 / 是否逐字重复 / 体积）。

## 三、记录纪律（**这是台账最容易被破坏的地方**）

1. **不判断**：写「A 与 B 的值不同」，不写「A 是错的」；不给优先级、不给修复建议。
2. **不凭记忆报数**：任何数字必须来自探测器或一条可粘的命令；报数时把命令一起给出。
3. **口径要说出来**：测不到的部分写「未确认 + 已试过什么查法」，不要补全。
4. **改了就要重算**：探测器输出的 JSON 与事实文件要一起更新，否则台账比没有更糟。
5. 探测器和事实文件**只写 `docs/state/`**；不要为了记录去改产品代码。

## 四、最容易踩的三个坑（都实测过）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 把「目录是否被 ignore」当「内容是否入库」 | `output` 未命中 ignore，但其中 456 个文件已入库 | 两件事分开测（`git check-ignore` vs `git ls-files`） |
| 把仓库外引用当缺失 | `\swapi\...` 被判「全仓找不到」11 条 | 先解析到 `C:\swapi`（仓库外官方源）再判 |
| 把 `derived_args` 产出的实参当「未暴露形参」 | 79 条虚高 | 按「有无 `derived_args`」拆开（34 / 45） |

## 六、接手后建议的阅读顺序

1. `AGENTS.md` §〇（一句话任务）与 §二（六条铁律）—— 规矩；
2. `docs/state/INDEX.md` §二（每个维度最承重的一条读数）—— 一分钟拿到十个关键事实；
3. 按目标选维度读 `docs/state/facts/<X>-*.md`，**先看该文件的「未确认」段**（那里写着本次没查的）；
4. 要动某块之前，跑一次对应 `probes/` 里的探测器，确认读数与台账一致（不一致就说明台账过期，先更新它）。
