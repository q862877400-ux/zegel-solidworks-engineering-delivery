## 0.0.5 ⭐ 遇到崩溃 / 怪错：先搜社区，别闷头试

**2026-09-27 的教训（本项目最贵的浪费）**：查了 **30 轮官方文档**，
却几乎没搜过"别人是否遇到过并解决"。结果一搜就中：

| 搜到的 | 价值 |
|---|---|
| 官方《Connect to SOLIDWORKS Message Pump (C#)》<br>`help.solidworks.com/2023/english/api/sldworksapiprogguide/Overview/Connect_to_SolidWorks_Message_Pump_Example_CSharp.htm` | 证实**宿主 STA 线程必须有消息泵**——我 30 轮都没意识到，且这是**宿主线程模型**问题，API 文档不讲 |
| CADOverflow《Memory Access Violation Caused by GDI Object Count and Unreleased COM Objects》<br>`cadoverflow.com/t/solidworks-api-memory-access-violation-caused-by-gdi-object-count-and-unreleased-com-objects/972` | 别人遇到过**一模一样的 AccessViolation**，解法：`Marshal.ReleaseComObject` + 立即关文档 + `GC.Collect`/`WaitForPendingFinalizers` |

据此查自己的代码，**当场发现一个真缺陷**：
`Infrastructure\StaExecutor.cs` 的 STA 线程 `foreach` 跑委托，**`PeekMessage` 从未调用**。

### 本项目沉淀的判别法（照着用，别再重走）

1. **同一段代码「有时成功有时崩」⇒ 几乎一定是环境问题，不是参数问题。**
   （本项目铁证：`MeshAndRun()` 成功而 `CreateMesh()` 崩——两者做同一件建网格的事。）
2. **崩溃/AccessViolation ⇒ 先查宿主环境**，别先查参数：
   线程模型（STA/MTA）· 消息泵 · COM 释放 · GDI/句柄累积 · 跨进程 RPC · 许可边界。
3. **每试 2 次仍不对就必须停下来搜一次。** 连续试错说明**方向错了**，不是**参数没猜对**。
4. **报"根因"前自问：这条证据能否区分两种可能解释？** 不能区分就只报"现象 + 尚未排除的可能"。
   本项目我曾**连续 4 次**给出"根因"并被自己的下一步实验推翻。
5. **「曾经能跑、现在崩」⇒ 先查状态累积**（进程未重启 / COM 未释放 / 句柄增长），
   再怀疑代码逻辑。实测本项目 SW 进程句柄曾堆到 **2670**、`open_document` 累计 1138 次。

### 本机抓网页的坑（每次都可能重蹈）

- `web_fetch` 工具对 `help.solidworks.com` / 多数站点会 **403**（出口 IP 被拦）
- ⇒ **本机 `Invoke-WebRequest` / `Invoke-RestMethod` 能 200**，用它抓
- 页面是 Next.js SPA，正文在 `<script id="__NEXT_DATA__">` 的
  `props.pageProps.helpContentData.helpText`（需解 `\u003c` `\u0026nbsp;` `\n` JSON 转义）
- GitHub API 会 403（rate limit）⇒ 用 `gh release view --repo … --json assets`
- CHM 解包：输出目录**路径要短、不能有空格、不能已存在**，否则静默失败 0 文件

## 0.1 官方 API 离线包怎么来的（2026-09-27 实测，可用）

**不要自己爬官网**（`help.solidworks.com` 是 Next.js 单页应用，HTML 里没有正文；
`web_fetch` 出口 IP 403；`r.jina.ai` 需 key）。用现成的离线镜像：

```powershell
# 仓库：pedropaulovc/offline-solidworks-api-docs （专做 SOLIDWORKS API 离线镜像）
gh release view --repo pedropaulovc/offline-solidworks-api-docs --json tagName,assets

# 两个包：
#   SolidWorks.Interop.llms.v*.zip    (~12 MB → 16,254 md)  ← AI 用这个
#   SolidWorks.Interop.xmldoc.v*.zip  (~4.5 MB → 14 xml)   ← 放 redist 目录可让 VS 有 IntelliSense
$u = "https://github.com/pedropaulovc/offline-solidworks-api-docs/releases/download/v3.12.1/SolidWorks.Interop.llms.v3.12.1.zip"
Invoke-WebRequest $u -OutFile C:\swapidoc.zip -TimeoutSec 600 -UseBasicParsing
Expand-Archive C:\swapidoc.zip -DestinationPath C:\swapi -Force
```

**⚠ 覆盖面限制（实测）**：只含**主 `sldworks` 程序集**（566 个类型、含 955 枚举、3,708 示例、
125 页编程指南），**不含 `cosworks`（Simulation）**。
⇒ Simulation 的 API 仍需走 §3 的网页抓取法。

**用法示例**：
```powershell
Get-Content C:\swapi\types\IMotionStudy\CreateByRotateModel.md   # 单个方法的完整文档
Get-Content C:\swapi\types\IAVIParameter\OutputType.md
Get-Content C:\swapi\examples\Create_Buckling_Study_Example_CSharp.md  # ★ 官方示例，最有用
Get-ChildItem C:\swapi\enums\*.md | Where-Object Name -match 'Restraint'   # 找枚举
```

已用它验证：`CreateMotionStudy()` 零参、`CreateByExplode(bool,double,double)`、
`CreateByRotateModel(bool,int,int,int,double,double)`、`IAVIParameter.SaveEntireAnimation` ——
**与我此前按 CHM 修的四处完全一致**。

## 7. 给 AI 的工作建议

1. **动手前先查**，别靠记忆。SolidWorks API 的方法名/参数错一个就全错
   （我曾因 `swAddComponentConfigOptions` 传 2 而间歇失败 15 轮）
2. **签名不确定 → 查 B（网页 API）或 C（反射 DLL）**，不要猜
3. **用法不确定 → 查 A（教程 CHM）**，官方教程通常有完整流程
4. **发现新错误码 → 先反射对应枚举**（`swsTopologyStudyError_e` 等），别按字面猜
5. **改动后必须验证**：每个特征后 `analyze_model(mass_properties)`，
   体积对不上当场停（手册 §六-9）
6. **同步 COM 调用会弹模态框卡死服务**：`CreateMesh`/`RunAnalysis`/`AddRestraint`/
   `IModelDoc2.SelectAt` —— 全部 opt-in，且要有人盯着窗口
