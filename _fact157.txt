| 157 | **砌墙 A 前置：真机探针定了「从 model 取草图对象」只能走**按名取**** —— 而这一条推翻了我本来要写的包装层** —— 2026-10-01（轮 220）。

★★★ **背景**：砌墙阶段 A 从「③草图」开头 —— `scripts/sw_sketch.py` 有 **25 个公开函数没挂**，
而它们**首参全是 `sketch`**（COM 对象），不在既有注入点（`model` / `sw_app` / `study`）里
⇒ 要挂就得先有一层「**从 model 取到 sketch 对象**」的包装。
★ 候选三条路（都有官方或本项目的依据）：
```
A  model.GetActiveSketch2              官方示例 Autodimension_a_Sketch_Example_VB：Set swSketch = swModel.GetActiveSketch2
B  model.SketchManager.ActiveSketch    官方示例 Constrain_Sketch_Example_CSharp：swSketch = swSketchMgr.ActiveSketch
C  model.FeatureByName(名) → GetSpecificFeature2（本项目既有的按名取法）
```

★★★★ **真机实测结果（`tools/probe_sketch_object_routes.py`，SW 2026 SP4.1，PID 41060）**：
```
                       草图打开中      草图已关闭（★ 关键读点）
  A GetActiveSketch2      草图1          **None**
  B ActiveSketch          草图1          **None**
  C 按名取                 草图1          **草图1**  ✓
⇒ ★★★ **草图一关，A 与 B 都取不到；只有 C 还活着。**
⇒ ★★ **所以包装层必须走 C** —— 若照"顾名思义"写成 A/B，就会做出一个
   **"只在草图打开时能用"**的工具；而 AI 的实际用法恰恰是
   「草图建完了，看看里面有什么」⇒ **那时草图已经关闭**。
★ 这正是**先实测再写**的价值：一个靠命名直觉就会选错的分叉。
```

★★ **同轮查出的第二件事（同样改变设计）**：`sw_part._find_cached_sketch_ref` 走的是
**进程内缓存** ⇒ ★ **MCP 调用是独立进程，缓存是空的** ⇒ **那条路不能用于 MCP**。
⇒ 而探针证明的 `FeatureByName + GetSpecificFeature2` 是**无状态**的 ✓

★★★ **第三件：返回值过不了 MCP** —— 那些 `get_*` 返回的是 **COM 对象列表**，
而 MCP 只能传 JSON ⇒ ★ **不能原样挂**。两条候选处置：
```
A 用 `extra_op`（注册器的逃生口，`op(params) -> Any` 自定义后处理）
B ★ 先在 `sw_sketch.py` 里加**"只回读数"的薄函数**（`count_lines(sketch) -> int` 之类），
  再用 `module/function + inject` 挂
⇒ ★ **选 B**，理由：① 保持 `batch1` 立的规矩「**全部声明式，不再用 `extra_op`**」
  （查了它当初不用的原因：**是加了 `inject` 之后就不需要了**，不是它有问题）
  ② 那层薄函数**本身也是能力**（别的代码也能用），而 `extra_op` 把逻辑藏在工具声明里、
     别的代码用不到 ⇒ ★ **能力应落在 `scripts/`，不落在工具声明里**。
```

★ **本轮的产物**：`tools/probe_sketch_object_routes.py`（可复跑）+ `output/sketch-object-routes.json`。
**⇒ 砌墙 A 第一批的设计据此定了**：先在 `sw_sketch.py` 加薄函数，再用 `inject="model"` + `derived_args` 挂。
