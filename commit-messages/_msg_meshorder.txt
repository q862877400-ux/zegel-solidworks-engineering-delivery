fix(simulation): CreateMesh 的参数顺序一直是错的 —— 1950 万单元的真因

## 真因（八次尝试后由官方类型库 CHM 定性）
解包 **VB6 版 API CHM**（`lang\english\api\cworksapivb6.chm`，1.8 MB / 3000 页）——
那里有**每个方法一页的 VBA 签名，含参数名**（反射只给类型，用户手册只讲界面）：

    CosmosWorksLib~CWStudy~CreateMesh.html
      Public Function CreateMesh( _
          ByVal NUnits As Long, _          ' ← 第 1 参是【单位 swsUnit_e】
          ByVal DElementSize As Double, _  ' ← 第 2 参是【单元尺寸】
          ByVal DTolerance As Double _     ' ← 第 3 参是【容差】
      ) As Long

⇒ **第 1 参不是网格类型；后两参的单位是【毫米】。**
⇒ 我们（和我的探针）一直按 `(meshType, tolerance, size)` 传 ⇒ **后两参颠倒**。

## 真机证据（100×60×20 mm 板，SW 2026 SP4.1）
    CreateMesh(0, 4.9339, 0.2467)  → 返回 0，**7,219 个单元**、1 秒      ✓ 正常
    CreateMesh(0, 0.2467, 4.9339)  → 返回 0，**19,509,593 个单元**、233 秒 ✗ 爆炸
反推：单元体积 = 1.2e5 mm³ ÷ 1.95e7 = 0.00614 mm³ ⇒ 边长 0.183 mm，
与「ElementSize 被当成 0.2467」同量级 ⇒ **完全吻合**。
⇒ 这解释了前四次「网格器涨到 20–25 GB、烧 1000–3000 秒」的全部现象。

## 同时更正的另一条
`CreateMesh` 挂在 **ICWStudy** 上；设置成员（`ElementSize`/`Tolerance`/`Unit`/
`ElementCount`/`NodeCount`/`MesherType`/`AutomaticTransition`）在 **ICWMesh**
（`study.Mesh`）上，但那里**没有** `CreateMesh`。
