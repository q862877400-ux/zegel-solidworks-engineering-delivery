## ⚑ 两处推翻前序笔记的发现
1. **事务括号才是关键，不是选择集。** `ICWTopologyStudyManager` 与**每一条**
   `CWTopology*Constraint` 都成对提供 `BeginEdit`/`EndEdit` —— 官方 UI 的每一步在
   API 上都是「一对事务之间的若干 Set*」。**不包事务的 `Set*` 会静默不落地**，
   这正是前序笔记里「约束没落到研究上」的症状。`_edit()` 把它变成强制：
   BeginEdit → 动作 → EndEdit，且 **EndEdit 返回非 0 即抛异常**（异常路径也必调
   EndEdit，否则研究会留在编辑态）。
   前序笔记把 `CreateMassConstraint + SetValue` 判为「走错 API 层级」——
   反射显示这**正是**官方接口。
2. **SolidWorks API 没有「创建选择集」的方法。** 对 sldworks interop 反射
   （1032 接口 / 20627 成员）后，`ISelectionSet` 族只有 GetSelectionSetFolder /
   GetSelectionSetItems / GetSelectionSetItemTypes / RemoveSelectionSet /
   GetSelectionSetByName / GetSelectionSets / RemoveFromSelectionSet
   —— **只读、只删、不能建**。故官方 UI 教程依赖的「预建 Selection Set」路径
   在 API 上不通，夹具与外载必须走「先选好实体再调 Add*」（同 sw_simulation）。
   按铁律 5 未提供建选择集的入口，不编。

## 一处未裁定的冲突（已在模块来源块里显式标注，未默默选边）
`scripts/audit_call_arity.py` 的口径是「`&` 出参不计入 arity」，而
`scripts/sw_simulation.py` 的既有做法是**传占位 `0`**。两者未对齐 ——
本模块沿用既有模式（铁律 1），故 arity 审计把这 11 处报成「存疑」
（sw_simulation 的 6 处同形）。**该冲突应由发布门禁裁定，不由本模块自定。**
