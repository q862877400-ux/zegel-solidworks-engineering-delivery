## 决定性发现：官方类型表里有**两个** Gusset 接口，模块用了错的那个
```
ISMGussetFeatureData    category: Feature Interfaces/**Sheet Metal**  28 属性  ← ★ 才对
IGussetFeatureData      category: Feature Interfaces/**Weldments**    19 成员  ← 模块用的
枚举: `swFmSMGusset` = "**Sheet metal** gusset"（名字里的 SM 就是 Sheet Metal）
```
**两者共有成员只有 3 个**（`AccessSelections` / `ProfileType` / `ReleaseSelectionAccess`）。
原代码设的 4 个属性 —— `Thickness` / `ProfileDistance1` / `ProfileDistance2` / `ProfileAngle`
—— **全部是焊件接口的名字** ⇒ `CreateDefinition(118)` 返回的对象**不是那个接口**
⇒ **对任何成员都没反应**（真机实测：连**读**都读不到）。

## 修法（真机验证：读回全部成功）
```
spec.thickness          → GussetThickness      ✓ 回读 0.002
spec.profile_distance_1 → ProfileHeightDim     ✓ 回读 0.01
spec.profile_distance_2 → ProfileLengthDim     ✓ 回读 0.01
spec.profile_angle      → ProfileAngleDim      ✓ 回读 45.0
（对照组）Thickness / ProfileDistance1 → ✗ 仍失败 ⇒ 证明改对了
```

## 另一个被**否证**的假设（本轮早些时候）

形式**全失败**（`None` / `VARIANT(VT_DISPATCH,None)` / `False`）。
官方文档说它是「取得描述**该特征**的选区」= **编辑**用，**不是创建用**。
⇒ **那个修改已全部撤回**（不让错的东西留在代码里）。

同样否证的还有「mark」假设：`SetSelectedObjectMark(1,1/2/4/0,0)` 与
`SelectByID2(mark=1/2/4/0)` **都返回成功**，但属性仍设不上 ⇒ **mark 不是属性层的真因**。
