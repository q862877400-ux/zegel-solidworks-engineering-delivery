docs: ROADMAP —— 长程施工计划（压缩后先读的那一份）

用户要求：列一份长程计划，含数个小阶段，每阶段都有「要读的文档 / 要做的事 /
验收标准 / 对长计划的调整」，使得**无论何时触发上下文压缩，一路走下去都不忘该改的事**。

## 方法论（查了社区，不是自创）
- Anthropic《Effective context engineering for AI agents》：长程任务三技术
  = compaction / structured note-taking / sub-agents，并明确
  「**Note-taking excels for iterative development with clear milestones**；
  上下文重置后 agent 读回自己的笔记继续」⇒ 本项目对应的是 note-taking。
- GitHub Spec Kit：**Specify → Plan → Tasks → Implement → Converge**，
  「每个阶段产出一份 Markdown 制品喂给下一阶段」+ 质量清单 + 跨制品分析
  ⇒ 采纳「每阶段一个固定 schema 的 Markdown 块」。

## 设计要点
- 落点 D:\AI\SW\docs\ROADMAP.md（工作区，与 AGENTS.md 同层，压缩后必读）
- **与 AGENTS.md 分工**：AGENTS.md = 规矩是什么（每轮注入）；ROADMAP = 怎么走。
  ROADMAP **不重述任何规矩**，只链接（AGENTS.md 自己的 slop 规则：一个事实一个家）
- **§一 游标**是唯一必须维护的字段：当前阶段 / 状态 / 下一步 / 阻塞 / 最近三次交接
- **恢复循环**（压缩后 4 步）：读游标 → 读该阶段「读数」→ 跑该阶段「验收」确认真起点 → 开工
- 三条防腐坏纪律：WIP=1（同时只一个 🟡）；状态只写游标不写散文；
  验收必须是**可跑的命令**（「我检查过了」不算）
- **§四 调整机制**：改后续阶段是允许且鼓励的，规矩是写「调整记录」+ 同步总览表 +
  不许静默删阶段；另给三个「重新规划」触发信号（同阶段 3 次没做完 ⇒ 拆；
  验收判据被证伪 ⇒ 改判据或砍；计划外高价值发现 ⇒ 插新阶段）
- **§五 反模式**：记了 6 条踩过的（地基越挖越深、两处都叫 A1、状态写散文、
  「我检查过了」当验收、改枚举只改一处、门禁绿就当证据）
- **§七 本文件自己的验收**：计划文件里的数字与链接也会过期，给了可跑的自检
  （引用文件是否都在 / 缺口数是否仍是 339 / 游标指向是否存在）
