fix(com): `Int32&` 出参与空 Dispatch 的正确形态 —— 真机裁决，修 18 处潜伏缺陷

## 起因
护城河域「拓扑优化」真机验证时，`CreateNewStudy3(name, 13, 0, 0)` 抛
`类型不匹配 (arg 4)`。逐一试五种候选形态，**只有一种通过**：

    VARIANT(VT_BYREF | VT_I4, 0)   ✓
    VARIANT(VT_I4, 0)              ✗ 类型不匹配
    VARIANT(VT_BYREF | VT_VARIANT) ✗
    VARIANT(VT_EMPTY, None)        ✗
    裸 int / 裸 0                   ✗
    省略该参数                      ✗ DISP_E_PARAMNOTOPTIONAL（「非选择性的参数」）

⇒ 该参数**必需（不能省）**，且必须按引用传 `VT_I4`。

## 这推翻了两处既有认识
1. **本仓库既有做法是错的**：`sw_simulation.create_static_study` /
   `apply_fixed_restraint` / `apply_normal_force` 都传裸 `0` ⇒ **从未跑通过**。
   真机复现：修复前 `create_static_study` 抛类型不匹配；修复后返回
   `(<COMObject>, 'CreateNewStudy3', 0)`。
   ⚠ 而 `capabilities.yaml` 里 `simulation_and_fea` 标的是 `verified` —— **声明与事实不符**。
2. **`audit_call_arity.py` 的口径也不全对**：它算 arity 时排除 `&` 出参是对的，
   但**调用方仍须传一个 byref VARIANT**；「排除」不等于「可省略」。

## 另一族：空 Dispatch 参数（已知事实 12 的实机确认）
    SelectByID2 第 8 参 Callout：裸 None ✗ / create_empty_dispatch_variant() ✓（选区计数 = 1）
    AddRestraint 第 3 参 Object：裸 None ✗ / 空 Dispatch ✓
    AddRestraint 第 2 参 Object：裸 None **可以**（实测 `None, empty ✗`、`empty, None ✗`、
                                                  `None, empty ✓`、`empty, empty ✓`）
⇒ 精确到**哪一参**，不搞「凡 None 都包」。
