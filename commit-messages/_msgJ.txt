## ⚠ 两条「不编」的纪律，各有硬理由
1. **ProgID 查不到，且连「待确认」都不给**
   读 `HKLM:\SOFTWARE\SOLIDWORKS\AddIns`（含 WOW6432Node 镜像）下
   Title/Description 匹配 FeatureWorks 的条目 → **0 条**；反射清单里
   也没有任何加载项回调接口。
   ⇒ 不硬编、不代为取得。
   ⚑ 与 `sw_simulation.py::SIMULATION_ADDIN_PROGID` 的处理**刻意不同**：
   那个 ProgID 有 MIT 项目作佐证（alisamsam/Solidworks-MCP），
   所以能「标注来源 + 显式待确认」；本模块**没有来源可标**，
   给了「待确认」就是给一个无根的字符串化妆。
2. **7 个成员里没有一个是可读属性**（5 个带参方法 + 2 个零参回调），
   所以「回读状态」在反射层面**做不到**。
   ⇒ `read_featureworks_state()` 改为回读**调用侧痕迹**，
   并显式断言不出现 `entity_count` / `recognized_count` / `version` /
   `is_busy` / `last_result` 这类**编造字段**。
   宁可少报，不伪造「读到了」。

## 两个回调成员不封装
`BubbleTipCallback()` / `HelpErrCallback(Int32, String, Int32, String)`
是 SolidWorks 调回宿主的**回调点**，不是脚本 API ⇒ 只在
`CALLBACK_MEMBERS` 里列名，不登记进 `FEATUREWORKS_ARITY`。
测试锁住「不得被导出、不得进 arity 表」。
