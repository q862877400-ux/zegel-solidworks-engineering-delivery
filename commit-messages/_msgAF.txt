feat(app): 新增 sw_sldworks_app.py —— ISldWorks 入口 + 1,966 个枚举字面值

用户指出「ISldWorks 就是用 API 操作 SolidWorks 的东西，这是你自己在用的工具」——
**这条批评是对的**：它是所有脚本的第一步，我只调了 28/333 个成员，
反倒把力气花在 COSWORKS 84 族、PDM 138 族这种次要的边上。

## 模块内容
`scripts/sw_sldworks_app.py`：
- 文档枚举 8 个（第一个/按路径/按名/全部/活动/激活/关闭/进程 ID/语言）
- **用户首选项 8 组读写**（读路径、默认模板、单位制全靠它）
- **选择过滤器 4 个** —— 任何选中的前置
- 错误回读 2 个
- 具名枚举常量 9 张表

## ⚑ 本轮修掉一个卡了我好几轮的**根因**
枚举数值一直缺（`enum_sldworks.txt` 只有 38 字节）。根因不是「官方没给值」，
是 `reflect-enum.ps1` 用了 **`ReflectionOnlyLoadFrom`**，在 .NET Core 上直接抛
"Reflection only loading is not supported on this platform"，**静默产出 0 行**。

改用 `LoadFrom` 重跑 ⇒ **983 个枚举 / 9,263 个字面值**全部拿到
（仍属「读官方程序集」，符合铁律 2）。

本模块据此**机械注入 5 张整表，共 1,966 个字面值**（141/628/828/220/149 项）。
⚑ **整表收下而不是只收常用几项** —— 只收常用等于要求调用方猜数字，违反铁律 4。

## ⚑ 覆盖表加了第三列
发现「直接调」那一列**系统性低估**：模块普遍写成
`_checked(target, member, …)`，成员名是**变量**，静态归因只认字面量 ⇒ 看不见。

⇒ 加 **「护栏可调」** 列（登记在某模块能力表里、且有可达调用路径）。
**护栏可调 ⊇ 直接调**，三列不合并：

| 口径 | 成员 | 族达 100% |
|---|---|---|
| 编目录 | 12,870 / 16,615 | 337 / 701 |
| **护栏可调** | **9,228** | **79** |
| 直接调 | 2,637 | 18 |

ISldWorks 三列：**直接 28 / 护栏 266 / 编目录 286 / 总 333**。

## 刻意不做
- **`SetUserPreferenceStringListValue` 不封装**：官方返回 **Void** 而非 Boolean，
  与同族 8 个返回明确值的不一致 ⇒ 统一返回 bool 会把 Void 变成假 bool。
  留在登记表里。
- **两个错误成员只取计数**：`GetErrorMessages` / `GetLastSaveError` 末位
  全是 by-ref 出参，迟到绑定不保证回写 ⇒ 不提供「取到具体文本」。
- **`swFrameState_e` 不提供**：本机 swconst 里**没有**这个枚举名
  （`get_FrameState` 取值语义查不到）⇒ 按铁律 5 标注缺失，不猜。
