## ⚠⚠ 本批最重要的产出是**分类表**，它修正了评估里的一个乐观估计
第一轮枚举说「32 个模块 / 229 个候选动作函数」，评估说「真实工作量 ~120 个」。
**看清签名之后，这个数是乐观的。** 核心建模域的公开函数按「能否干净暴露」分四类：

| 类 | 判据（**机器可验或可复核**） | 例子 |
|---|---|---|
| **A 直接可暴露** | 只收标量/字符串/bool；宿主靠 inject | `weldment_evidence(model)` |
| **B 需声明式选择解析** | 入参含**坐标/向量**（point/normal/axis/origin）⇒ 违规则 3 | `create_planar_surface(sw_app, point, normal)` |
| **C 需 spec 展平层** | 入参含 **typed spec dataclass** | `create_base_flange(model, sketch_ref, spec: BaseFlangeSpec)` |
| **D 不该暴露** | 纯 getter / 需「取中间对象」的解析 | `get_sketch_segments(sketch)`、`merge_points(sketch, tol)` |

**⇒ 结论**：能**直接**暴露的（A 类）**远少于 120**；
**B/C 两类各自需要一层基础设施**（选择解析层 / spec 展平层），那是**独立工作项**，
不是「多写几条声明」。**D 类不该暴露** —— 暴露 getter 等于把工具的**选择集状态**变成 API
（违规则 3 的精神）；用户要的是「草图完整吗」「改个尺寸」这类**意图**，
那类工具应当**新写**，而不是把 getter 搬出来。

## 分类表的守卫（`tests/test_tool_specs_batch2.py`，10 条）
