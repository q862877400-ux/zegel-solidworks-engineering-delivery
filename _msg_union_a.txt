## 新增 docs/union-conventions.md —— 六条可机器校验的规则
  规则 1 命名   统一 solidworks_<域>_<动作>（现有 `sw_`/无前缀/`vba_` 一律归并）
  规则 2 单位   长度参数必须 `_mm` 结尾、角度 `_deg`，转换只在边界做一次
  规则 3 选择   必须用声明式 selection，禁止裸坐标（含自动设 mark）
  规则 4 等级   五级：verified / source_verified / stitched / indexed / not_implemented
                ★ 最要紧的一条 —— 把「谁跑的」和「跑没跑」分开；
                  明令禁止把 source_verified 写成 verified（那是转述别人的话）
  规则 5 出处   每条并入条目带 provenance{repo(owner/repo 全名), license, files,
                upstream_verified}；许可读**真实 LICENSE 文件**判定，不采信 README 徽章
  规则 6 失败要响 建特征类工具必须 EditRebuild3 + GetWhatsWrong2；禁止静默成功
                （依据：Slacker-LLC 实测「Most failures are silent」、
                  「SketchTrim 成功时返回 False」）

## 新增 scripts/check_union_conventions.py + 接进 release_check
把 doc 里的规则变成**会执行的门禁**（DSH 原则「可校验的不变量挂到会执行的门上」）。
接在成员名门禁之后、bundled 校验之前 —— 后者是已知的上游基线失败，
放它前面才保证这道门跑得到。

## ⚑ 门禁首次运行就抓到真问题（并据此修正了规则本身）
  初次报 FAIL：`requirements_planning`(backend `local-agent`) 与
  `geometry_and_delivery_review`(`local-python`) 标 verified 但 verified_versions 为空。
  核实后确认：这两条是**代理层/本地 Python 层**能力，本来就没有「SolidWorks 版本」。
  ⇒ 规则收紧为「**只在 backends 含 CAD 后端时**要求版本证据」，
    并把这次误报写进门禁 docstring（避免下次又被当成真问题）。
