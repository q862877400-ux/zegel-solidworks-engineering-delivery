## 三条硬知识（全部已回本机反射核实）
1. **0x80020005 DISP_E_TYPEMISMATCH** —— pywin32 迟到绑定**不会**把普通
   Python ``int`` 编到 ``ByRef Long`` 参数里，直接传 int 就报这个错。
   需 ``VARIANT(VT_BYREF|VT_I4, n)``。本模块 `byref_long()` 实现了它，
   pywin32 不可用时回退成普通 int（保住 mock/CI 路径）。
   ⚑ **本机自测**：`byref_long(7)` 实测产出
   `VARIANT(16387, 7)`（16387 = VT_BYREF|VT_I4）。
2. **early-bound 会拒 by-ref** —— gen_py 的强类型代理**拒绝** VARIANT
   by-ref 参数（OpenDoc6 等），必须用 ``dynamic.Dispatch`` 迟到绑定。
3. **.swp 是 OLE2 复合文档**（魔数 d0cf11e0a1b11ae1），把文本改名成
   .swp 会被 SolidWorks 拒而报错只说「文件无效」。

## ⚑ 逐条核出第三方资料的一处笔误
该仓注释称 ``IModelDocExtension.RunMacro2`` 的 nRetval 需同样处理 ——
**接口名是错的**。反射实测（全量 20,627 成员）：
    ISldWorks.RunMacro    3 参 / 无 by-ref
    ISldWorks.RunMacro2   5 参 / 末位 Int32&
⇒ **结论对、接口名错**。已在模块注释里写明，并列出三条 by-ref 声明的
   反射实测对照（GetErrorMessages 3 个 Object& / OpenDoc6 2 个 Int32& /
   RunMacro2 1 个 Int32&），全部与第三方说法一致。
